# ADR-047: 송가는 번호 대신 이름으로 보인다

- 상태: 승인됨 — 구현 완료 (2026-11-19)
- 관련: ADR-046 §4(검색 결과의 송가 표기), ADR-010(북마크 이름), ADR-024 §6(없는 장의 안내), 데이터 저장소 ADR-039(「`books.json` · 송가」, 「송가」)

## 요약

1. **송가의 이름**(§1): 한 송가를 가리키는 곳은 송가 이름(「이사야 셋째 송가」)만 쓴다. 책 이름, 번호, 「장」, 「편」을 붙이지 않는다.
2. **화면**(§2): 상단 바 제목, 송가 고르기 목록, 송가 목록 화면, 앞뒤 이동, 이어읽기, 브라우저 탭 제목, 복사한 글의 출처가 송가 이름이다.
3. **단위를 이름으로 쓰는 곳**(§3): 「장 선택」, 「장 목록」, 「장 이동」 자리는 「송가 선택」, 「송가 목록」, 「송가 이동」이다. 없는 송가는 「성무일과 송가에는 14번 송가가 없습니다」로 알린다.
4. **북마크**(§4): 기본 이름은 「이사야 셋째 송가」, 절을 고르면 「이사야 셋째 송가 1-3」이다. 이미 저장한 이름은 바꾸지 않는다.
5. **송가 이름의 자료**(§5): 데이터 저장소가 `books.json`의 송가 항목에 송가 이름을 둔다. 앱은 장 화면, 전례독서 화면, 검색 어디서나 송가 이름을 이 파일에서만 읽는다.

## 배경

송가 화면의 상단 바가 「성무일과 송가 6장」이었다. 장 단위를 고르는 코드가 송가를 성서의 책처럼 다뤄 번호에 「장」을 붙였기 때문이다. 송가는 번호가 아니라 이름으로 알아보는 본문이라(데이터 ADR-039 「송가」) 「6장」으로는 어느 송가인지 알 수 없다. 검색의 결과와 바로가기 카드는 이미 송가 이름이다(ADR-046 §4).

## 결정

### 1. 송가의 이름

- 한 송가를 가리키는 곳은 송가 이름만 쓴다. 이름에 이미 「송가」가 있으므로 책 이름 「성무일과 송가」를 앞에 붙이지 않는다.
- 번호와 「장」, 「편」은 보이지 않는다. 번호는 주소(`/cant/6`)에만 남는다.
- 까닭: 기도서는 송가를 이름으로 부르고, 전례독서 화면과 검색도 이름으로 적는다(ADR-046 §4).

### 2. 화면

| 곳 | 표기 |
| --- | --- |
| 상단 바 제목, 브라우저 탭 제목 | 이사야 셋째 송가 |
| 제목 옆 단추로 여는 송가 고르기 목록 | 송가 이름 13개. 지금 송가를 표시한다 |
| 송가 목록 화면(`/cant`) | 송가 이름 13개 |
| 본문 아래 앞뒤 이동 | ← 이사야 둘째 송가, 참회송가 → |
| 이어읽기 | 이어읽기: 이사야 셋째 송가 |
| 복사한 글의 출처(장 화면, 절 선택 막대) | 이사야 셋째 송가 1-3 (대한성공회 기도서) |

- 상단 바의 높이와 글씨 크기는 바꾸지 않는다. 가장 긴 이름(「이사야 첫째 송가」, 9자)이 휴대폰 상단 바에 보이던 가장 긴 제목(「성무일과 송가 13장」, 11자)보다 짧다.
- 까닭: 번호로 고르면 어느 송가인지 알 수 없다. 앞뒤 이동도 어디로 가는지 이름으로 보인다. 복사 출처는 전례독서 화면의 송가 출처(「즈가리야 송가 1-3」)와 같아진다.
- 구현은 `topics/liturgical.md` 「지금 동작」의 「송가 장 화면」에 있다.

### 3. 단위를 이름으로 쓰는 곳

- 스크린 리더가 읽는 「장 선택」, 「장 이동」과 없는 주소 안내의 링크 「장 목록」은 송가에서 「송가 선택」, 「송가 이동」, 「송가 목록」이다.
- 없는 번호의 주소(`/cant/14`)와 검색의 구절 표기(`송가 14:1`)는 「성무일과 송가에는 14번 송가가 없습니다」로 알린다.
- 까닭: 「장」, 「편」을 붙이지 않으면 이 자리에 쓸 단위가 없다. 송가를 세는 낱말은 「송가」다.

### 4. 북마크

- 송가 전체를 저장한 북마크의 기본 이름은 송가 이름(「이사야 셋째 송가」)이다. 절을 고르면 이름 뒤에 절을 적는다(「이사야 셋째 송가 1-3」). 검색 결과 줄의 표기(「모세송가 1」)와 같다.
- 북마크 읽기 화면의 제목도 같은 표기다.
- 이미 저장한 북마크의 이름(「송가 6장」)은 바꾸지 않는다.
- 까닭: 저장한 이름은 사용자가 고칠 수 있는 글이라 앱이 고쳐 쓰지 않는다.

### 5. 송가 이름의 자료

- 데이터 저장소가 `books.json`의 송가 항목에 장 번호마다 송가 이름(`titles`)을 둔다(데이터 ADR-039 「`books.json` · 송가」). 이름은 송가 원문 제목에서 뒤의 라틴어 이름을 뗀 것이다.
- 앱은 송가 이름을 이 파일에서만 읽는다. 장 화면, 북마크, 복사 출처, 전례독서 화면의 송가 이름, 검색의 결과와 카드가 모두 그렇다. 검색 메타 파일과 송가 장 파일의 제목에서는 이름을 읽지 않는다.
- 검색은 화면과 따로 도는 스크립트(검색 워커)가 맡는데, 워커는 이 파일을 따로 받지 않는다. 앱이 받아 둔 이 파일의 송가 이름을 검색할 때마다 워커에 넘긴다. 앱이 이 파일을 받지 못했으면 넘기지 않아 송가 결과에 이름만 빠지고, 다음 검색 전에 앱이 이 파일을 다시 받는다.
- 까닭: 송가 고르기 목록, 앞뒤 이동, 북마크 이름은 그 송가의 장 파일을 받기 전에 이름이 있어야 한다. 앱은 `books.json`을 늘 받아 둔다. 읽는 곳이 하나여야 같은 송가가 화면마다 다른 이름으로 보이지 않고, 라틴어 이름을 떼는 규칙도 데이터 저장소 한 곳에만 둔다. 검색에 이름을 넘기면 같은 파일을 두 번 받지 않고, 받지 못했을 때 다시 받는 일도 앱 한 곳이 맡는다.

## 검토한 대안

- **번호를 남긴다(「성무일과 송가 6」)**: 「장」만 빼고 숫자 격자도 그대로 둔다. 채택 안 함 2026-11-19 · 이유: 번호로는 어느 송가인지 알 수 없다. 재검토 조건: 없음.
- **앞뒤 이동을 「이전 송가」, 「다음 송가」로 적는다**: 이름이 길어도 링크 길이가 같다. 채택 안 함 2026-11-19 · 이유: 어디로 가는지 이름으로 보이는 편이 낫다. 재검토 조건: 없음.
- **상단 바를 높이거나 글씨를 줄인다**: 긴 이름이 들어가게 한다. 채택 안 함 2026-11-19 · 이유: 송가 이름이 지금 제목보다 짧아 필요 없다. 들어가지 않는 제목은 상단 바가 짧은 이름으로 바꾸는 방식이 이미 있다. 재검토 조건: 송가가 늘어 휴대폰 상단 바에 들어가지 않는 이름이 생길 때.
- **화면마다 가까운 파일에서 이름을 읽는다**: 검색은 검색 메타 파일(`search-meta.json`)에, 전례독서 화면은 이미 받은 송가 장 파일의 제목에 이름이 있어 따로 받을 파일이 없다. 채택 안 함 2026-11-19 · 이유: 읽는 곳이 셋이면 한 곳의 표기가 바뀔 때 화면마다 이름이 달라질 수 있고, 장 파일의 제목에서 라틴어 이름을 떼는 규칙이 앱에도 하나 더 있어야 한다. 장 화면은 검색 메타 파일을 쓸 수 없다. 검색할 때만 받기 때문이다. 재검토 조건: 없음.
- **검색 워커가 `books.json`을 직접 받는다**: 워커가 검색 메타 파일과 함께 받아 이름을 읽는다. 채택 안 함 2026-11-19 · 이유: 앱이 이미 받아 둔 파일을 검색할 때 한 번 더 받고, 받지 못했을 때 다시 받는 처리를 워커에도 따로 두어야 한다. 검색 화면은 검색하기 전에 이 파일을 받아 두므로 넘길 이름이 있다. 재검토 조건: 앱이 책 목록 없이 검색을 시작하는 일이 생길 때.
- **송가 이름을 앱 코드에 적는다**: 데이터를 바꾸지 않아도 된다. 채택 안 함 2026-11-19 · 이유: 데이터와 어긋날 수 있다. 기도서 차례대로 송가 번호를 다시 매겼을 때 번호를 코드에 적은 곳이 엉뚱한 송가를 가리킨 일이 있다(데이터 ADR-039의 송가 본문 절). 재검토 조건: 없음.
- **이미 저장한 북마크 이름도 새 표기로 바꾼다**: 옛 이름 「송가 6장」이 남지 않는다. 채택 안 함 2026-11-19 · 이유: §4의 까닭. 재검토 조건: 없음.
