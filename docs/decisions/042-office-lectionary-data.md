# ADR-042: 성무일과 전례독서 데이터

- 일시: 2026-11-10
- 상태: 제안됨 (사용자 확인 대기). 데이터와 파서는 이 제안대로 데이터 저장소 PR anglican-kr/common-bible-data#72에 구현해 두었다
- 관련 ADR: ADR-036(전례일 키와 교회력 정의 표), ADR-037(감사성찬례 전례독서 데이터. 레코드 모델, 성구 문법, 절 실존 검사를 이어받는다), ADR-039(데이터 저장소. 전례시편 `lps`와 성무일과 송가 `cant`), ADR-010(북마크 절 범위 문법), ADR-003(데이터 저장소. 칠십인역 이중 절 번호), ADR-021(콘텐츠 해시 매니페스트)
- 원료: 대한성공회 기도서 508-554쪽 「성무일과 전례독서」. 사용자가 2026-11-09에 쪽을 스캔해 주었다(24장)

## 맥락

성무일과(아침기도와 저녁기도)는 로드맵의 Phase 4다(`docs/architecture.md` §11). 지금까지 데이터와 엔진은 감사성찬례만 다뤘다. ADR-037은 성무일과를 범위 밖에 두었고, 서울교구 기사 가운데 아침기도와 저녁기도 기사를 「성무일과 원료」로 따로 빼 두었을 뿐이다. 성무일과의 데이터를 정한 결정은 아직 없다. 이 ADR이 처음이다.

사용자가 기도서의 「성무일과 전례독서」 표를 스캔해 주었다. 표는 날마다 아침기도와 저녁기도의 시편을 정하고, 해 1과 해 2의 독서를 구약, 서신, 복음 순서로 정한다. 날짜로 정한 줄과 주요축일의 아침, 저녁 독서도 있다. 사용자는 이 표로 성무일과 전례독서 데이터를 만들어 달라고 요청했다.

표는 미국 성공회 1979년 기도서(BCP 1979)의 매일 전례독서(Daily Office Lectionary)와 같은 계열이다. 기도서 508쪽 서문이 「세계교회가 함께 사용하는 2년 주기의 매일 전례독서」를 썼다고 밝히고, 해 규칙과 시편 기호도 BCP 1979와 같다. BCP 표를 bcponline.org에서 직접 내려받아(2026-11-10) 절 단위로 견주었다. 대림부터 연중 34주까지의 독서 2,279개 가운데 2,184개(95.8%)가 BCP의 같은 칸과 일치했고, 주요축일과 12월 26-28일의 독서 112개 가운데 99개가 일치했다(§7). 나머지는 공동번역의 절 번호가 영어 성경과 다른 곳, 한국 기도서가 조정한 곳, 기도서의 인쇄 오류다. 독서는 RCL 계열 독서표(미국 성공회 포함)와 맞는 쪽을 따르기로 한 기존 결정(2026-10-24, 교회력 주제 문서 「확정 사실」)이 여기에도 적용된다.

## 범위

- **한다**: 표가 정한 시편과 독서를 데이터로 만들고 검증한다. 데이터가 받쳐 줄 날짜 찾기의 키(§5)까지 정한다.
- **하지 않는다**: 성무일과 예식문(기도문, 응답, 송가 선택, 본기도), 날짜에서 줄을 찾는 엔진, 화면. Phase 4의 ADR이 정한다. 앱은 이 데이터를 아직 받지 않는다.

## 기도서 표의 구조

기도서가 적은 것을 쪽 번호와 함께 모았다. 해석하지 않고 옮겼다.

- **해 1과 해 2**(508쪽): 해 1은 대림 1주일이 시작되는 해의 끝자리가 짝수인 해에, 해 2는 홀수인 해에 쓴다. 예로 2004년 대림 1주일부터는 해 1이고 2005년 대림 1주일부터는 해 2다. 470쪽 「전례독서 년도구분」의 주간구분 열도 같다(2004/2005는 1해, 2005/2006은 2해).
- **하루의 독서는 셋**(508쪽): 1독서(구약), 2독서(서신), 복음. 기도에서 둘까지 읽으면 복음을 포함한다고만 적고, 아침과 저녁에 어떻게 나눌지는 적지 않았다.
- **시편**(508쪽): 앞부분은 아침기도, 뒤는 저녁기도다. 표에서는 빨간 ◆로 나눈다. 한쪽이 없으면 `–`로 적는다.
- **기호**: 대괄호 `[ ]`는 시편 한 편을, 소괄호 `( )`는 절을 생략할 수 있다는 뜻으로 보인다. 기도서에는 이 기호의 설명이 없고 BCP 1979의 규칙(「Concerning the Daily Office Lectionary」)이 그렇게 정한다(미결 1). 독서 칸의 「또는」은 다른 선택지, 시편 칸의 `*`는 조건이다(「* 토요일이면 시편 136」).
- **12월 17일부터 1월 12일까지**(511쪽 빨간 안내): 해당 날짜의 독서를 쓴다. 대림 4주는 표에 없고 대림 3주에는 토요일 줄이 없다. 12.17-12.24가 날짜 줄이다.
- **12월 26일부터 31일까지**(512쪽 빨간 안내): 축일을 지키는 경우가 아니면 아래 본문을 쓴다(미결 2).
- **성령강림주일과 삼위일체주일의 주간**(508쪽, 525쪽 빨간 안내): 해당 연중주간 독서를 쓴다.
- **축일**(508쪽): 성무일과 독서는 그날의 축일 독서와 다르므로 축일을 지키면 축일 본기도에 나오는 독서를 쓴다(미결 3).
- **대체**(508쪽): 성무일과 독서를 주간 감사성찬례 독서로 대체할 수 있다.
- **구성**: 대림 1-3주(509-511쪽), 12.17-12.24, 성탄 전일부터 성탄 2주일과 1.2-1.12, 공현일 전일과 공현일(512-514쪽), 재의 수요일과 그 뒤의 목, 금, 토, 사순 1-5주, 성주간(514-519쪽), 부활주간과 부활 2-7주(519-525쪽), 성령강림과 삼위일체(525쪽), 연중 1-34주(525-550쪽), 주요축일(551-554쪽).

연중 1-34주의 머리에는 날짜 구간이 찍혀 있고(「연중2주 (1.14-1.20)」), 연중 6-9주는 구간이 둘이다(「연중6주 (2.11-2.17 또는 5.8-5.14)」). 이 구간은 `liturgical/ordinal-weeks.txt`의 구간표와 같다. 470쪽 주석이 「연중 6-9주일은 공현 후 연중주일이나 성령강림 후 연중주일이 되기도 한다」고 적어, 한 주의 독서 한 벌을 두 구간에 함께 쓴다.

## 결정

### 1. 옮겨 적은 원문을 데이터 저장소에 두고, 파서가 그 원문을 읽는다

- 쪽은 데이터 저장소 `liturgical/prayer-book/office-readings/`에 스캔 한 장당 파일 하나(`p510-511.md`)로 옮겨 적는다. 감사성찬례 표(`weekday-readings/`)와 같은 방식이다. 인쇄된 그대로 옮기고 해석하지 않는다. 읽을 수 없는 곳은 `[판독]`, 인쇄 오류로 확인한 곳은 `[오자]` 줄을 남긴다(사용자 교정 2026-11-05).
- 이 폴더는 **파서의 입력이다**. 기존 `prayer-book/` 문서는 대조용이라 파서가 읽지 않았지만, 성무일과 표는 다른 원료가 없고(서울교구 기사는 아침, 저녁기도를 싣지 않는다) 손으로 다시 입력하면 같은 표가 둘이 되어 어긋난다. 그래서 옮겨 적은 글이 곧 입력이다.
- **인쇄 오류는 원문에 그대로 두고, 원문의 표시 줄이 바로잡는다.** `[오자] 「인쇄된 조각」 => 「바른 조각」 (근거)`는 바로 앞 자료 줄의 조각을 바른 조각으로 고쳐 읽게 하고, `[번호] 「인쇄된 조각」 => 「읽을 조각」 (근거)`는 인쇄된 표기가 그 번호 체계에서는 맞지만 공동번역과 번호가 다를 때 읽을 절만 바꾼다(라벨은 인쇄 그대로다). 근거와 고친 값이 같은 자리에 남고, 파서가 앞 줄에서 그 조각을 찾지 못하면 멈춘다. 근거가 앞뒤 날의 연속 독서나 BCP뿐이고 실물 확인 전이면 고치지 않고 `[메모]`로 확인을 청한다. 이번에 `[오자]` 6건과 `[번호]` 3건이 있다.

### 2. 산출 파일 `lectionary/office-readings.json`

- 형식은 ADR-037 §1의 `eucharist-readings.json`과 같다. `_meta`, `_vocab`, `entries` 평면 배열이다. 파일은 하나이고(들여쓰기 포함 약 1.5MB, gzip 약 65KB. 감사성찬례 파일은 약 1.3MB, 62KB), 전례독서 화면이 아니라 Phase 4가 받는다. 서비스 워커는 `/data/lectionary/` 접두사를 데이터 캐시로 보내므로 앱 코드 변경이 없다(ADR-037 §7).
- 파서는 `liturgical/parse_office_readings.py`다. 입력은 옮겨 적은 원문과 `bible/*.json`(절 실존 검사), `ordinal-weeks.json`과 `sanctoral.json`(조인 검사)이다. 산출은 이 파일과 검증 보고서 `liturgical/office-readings-report.txt`다. 성구 해석은 `readings.py`와 `parse_readings.py`의 함수를 다시 쓴다(`parse_commons.py`가 이미 그렇게 한다).

### 3. 레코드: 한 레코드는 날 하나와 해 하나다

날짜 찾기와 화면이 레코드 하나만 읽으면 되도록, ADR-037처럼 해를 키의 한 축으로 둔다. 해 1과 2에 같은 시편은 레코드마다 되풀이해 적는다(약 120KB, 파일의 8%). 레코드는 804개이고(해가 있는 날 380일의 760개, 해가 같은 날 44개), 읽을 칸은 4,019개다.

```json
{
  "id": "advent-1-sat-c1",
  "kind": "temporal", "season": "advent", "week": 1, "type": "weekday", "weekday": "sat",
  "date": null, "name": null, "cycle": 1,
  "title": "대림1주",
  "readings": [
    { "slot": "psalm", "office": "morning", "bookId": "lps", "label": "시편 20, 21:1-7(8-13)",
      "refs": [ { "chapter": 20, "verseSpec": "all" },
                { "chapter": 21, "verseSpec": "1-13", "optional": "8-13" } ] },
    { "slot": "psalm", "office": "evening", "bookId": "lps", "label": "시편 110:1-5(6-7), 116, 117",
      "refs": [ { "chapter": 110, "verseSpec": "1-7", "optional": "6-7" },
                { "chapter": 116, "verseSpec": "all" }, { "chapter": 117, "verseSpec": "all" } ] },
    { "slot": "first",  "office": "day", "bookId": "isa",    "label": "이사 4:2-6",     "refs": [ { "chapter": 4,  "verseSpec": "2-6" } ] },
    { "slot": "second", "office": "day", "bookId": "1thess", "label": "1데살 4:13-18",  "refs": [ { "chapter": 4,  "verseSpec": "13-18" } ] },
    { "slot": "gospel", "office": "day", "bookId": "luke",   "label": "루가 21:5-19",   "refs": [ { "chapter": 21, "verseSpec": "5-19" } ] }
  ],
  "_source": { "pages": [509] }
}
```

- **`cycle`**: 1, 2, 또는 `null`이다. `null`은 두 해가 같다는 뜻이다(주요축일, 전일과 전야, 부활주일). 값은 §4가 정한다. 감사성찬례의 `year`(가, 나, 다해와 홀수, 짝수해)와 따로 둔다. 같은 이름의 해를 다른 규칙으로 셀 수 있어서다(§4).
- **전례일 키**: `kind`, `season`, `week`, `type`, `weekday`, `date`, `name`은 ADR-036 §4의 어휘를 그대로 쓰고, `type`에 `eve`(전일, 전야)를 더한다. 격자 줄(대림 1주 토요일)은 `temporal`에 절기, 주, 요일이다. 사순은 재의 수요일과 그 뒤의 목, 금, 토를 0주(`lent-0-*`), 성주간을 6주(`lent-6-*`)로, 부활주간을 부활 1주(`easter-1-*`)로 둔다. 날짜 줄(12월 29일)은 `sanctoral`에 `type: "weekday"`와 `date`(`MM.DD`)다. 날짜 축일은 `sanctoral`에 `type: "feast"`이고 `id`가 월별 축일 표(`sanctoral.json`)의 `id`와 같다. 이름 있는 날(성탄절, 성령강림주일)은 `temporal`에 `name`이고, 승천일이나 성지주일처럼 격자 자리가 있으면 그 자리의 레코드에 `name`을 단다(`easter-6-thu-c1`의 `name`은 「승천일」).
- **`readings` 칸**: `slot`은 `psalm`, `first`, `second`, `gospel`(ADR-037 §1과 같은 이름)이고, `office`는 `morning`, `evening`, `day`다. 격자 줄의 독서 셋은 하루의 것이라 `day`이고, 시편은 아침과 저녁이 따로다. 주요축일과 12월 26-28일, 성주간과 부활주일의 일부 독서는 아침, 저녁에 따로 있어 `morning`, `evening`이다. 전일과 전야는 저녁기도뿐이라 모든 칸이 `evening`이다. 시편은 `bookId: "lps"`(ADR-037 §3)이고 한 칸에 시편 여러 편을 `refs` 여럿으로 담는다. 시편 칸이 하나뿐이고 ◆가 없는 줄은 `office: "day"`다.
- **`slot`은 책의 종류로 정한다**: 구약과 외경은 `first`, 신약의 서신, 사도행전, 요한 묵시록은 `second`, 복음서는 `gospel`이다. 칸의 위치로 정하지 않는다. 성 토요일은 2독서가 아침과 저녁에 따로 있어 한 줄에 칸이 어긋나고, 주요축일의 2독서가 복음서인 줄(성 요셉의 마태 1:18-25)이 있어서다. 해가 있는 격자 줄은 `first`, `second`, `gospel`이 하나씩 있어야 하고(테스트가 확인한다), 같은 `slot`과 `office`가 한 레코드에 둘 있으면 오류다.
- **`optional`**: 생략할 수 있는 절(소괄호)과 생략할 수 있는 시편 한 편(대괄호, `"optional": "all"`)을 `refs` 한 항목의 필드로 적는다. 감사성찬례는 괄호가 있으면 짧은 형과 긴 형을 두 세트로 펼쳤다. 성무일과는 괄호가 있는 칸이 329곳(시편 291, 독서 38)이라 펼치면 레코드가 크게 늘고, 시편의 괄호는 「생략해도 된다」는 뜻이라 짧은 형이 대안이 아니다. 그래서 `refs`에 긴 형을 적고 `optional`로 생략할 수 있는 부분만 표시한다(읽는 절과 겹치면 읽는 절이 먼저다: `68:1-20(21-33), 24-35`의 `optional`은 `21-23`). 기본값을 어느 쪽으로 보일지는 앱이 정한다(미결 1).
- **`or`**: 「또는」이 있는 칸은 `or` 배열에 같은 형식의 항목을 넣는다(「야고 4:13-17 또는 5:7-11」, 「시편 59, 60 또는 33」). 37곳이다. 뒤 조각이 책 이름을 생략하면 앞 조각의 책을 잇는다.
- **`when`**: 조건 덧말이 있는 칸은 조건 칸을 따로 두고 `when`을 단다(`{ "weekday": "sat" }`). 조건이 맞으면 같은 `slot`과 `office`의 조건 없는 칸을 대신한다(「* 토요일이면 시편 136」). 6곳이다.
- **`partial`**: 인쇄된 「중」(「사무하 23:13-17중」, 「에제 1:1-14, 24-28중」)은 절 일부만 읽는다는 뜻으로 보이나 절 경계를 알 수 없어, 절 전체를 읽는 것으로 두고 `partial: true`를 단다(미결 8).
- **`label`**: 인쇄된 표기를 공백만 정리해 적는다. 화면과 복사에 쓴다. 그래서 검색창이 구절로 읽지 못하는 표기가 있다(미결 10).
- **`eve_of`와 `eve_of_name`**: 전일과 전야 레코드가 가리키는 날이다. `eve_of_name`은 인쇄된 이름(「성탄절」)이고 `eve_of`는 그 날의 `id`에서 해 표시(`-c1`)를 뗀 것이다. 그리스도의 성체일처럼 이 표에 레코드가 없는 이동 축일이면 `eve_of`가 `null`이다. 고정일 축일의 전야는 `date`에 전날을 적는다(주의 봉헌 전야는 02.01).
- **`_source.pages`**: 옮겨 적은 쪽이다. 같은 날이 두 곳에 있으면 모두 적는다(12월 26-28일은 512쪽과 554쪽에 있다). 내용이 같아야 하고, 다르면 오류다.
- **`id`**: 해가 있는 날은 `{날의 id}-c{cycle}`이다. 격자 줄은 `{season}-{week}-{요일}`, 날짜 줄은 `d{MMDD}`, 날짜 축일은 월별 축일 표의 `id`(`d0125-사도-성-바울로의-회심`), 이름 있는 날은 `coords.slugify_name`으로 만든 이름(`성탄절`), 전일과 전야는 `eve-{이름}`이다.

### 4. 해 규칙

`cycle`은 **그 날이 속한 전례년이 시작된 해**의 홀짝이다. 대림 1주일이 시작된 해가 짝수이면 1, 홀수이면 2다.

- 2026-11-10은 2025년 대림 1주일(2025-11-30)에 시작한 전례년이므로 `cycle: 2`다. 2026-11-29(대림 1주일)부터 2027-11-27까지는 `cycle: 1`이다.
- 달력 해의 홀짝이 아니다. 12월(대림)은 달력 해와 반대가 되므로 이 점을 틀리기 쉽다. 연중, 사순, 부활은 달력 해가 홀수이면 1이어서 감사성찬례 주간 독서의 해(485쪽: 해당 연도의 끝자리가 홀수이면 1)와 같다. 대림 평일은 감사성찬례 주간 독서가 해를 가르지 않아 충돌이 없다.
- 기준은 기도서 470쪽 「전례독서 년도구분」이다. 2004/2005부터 2042/2043까지 39줄의 주간구분이 모두 이 규칙과 같다. 데이터 저장소 테스트가 이 표와 규칙을 대조한다.
- 계산은 Phase 4 엔진이 맡는다. 감사성찬례 엔진이 이미 대림 1주일 날짜를 구하므로(ADR-037 §6) 같은 값을 쓴다.

### 5. 날짜에서 줄을 찾는 키와 기도서가 정한 규칙

엔진은 Phase 4 ADR이 정한다. 이 ADR은 레코드의 키가 그 엔진이 필요한 것을 모두 담도록 한다.

- **연중 주간**은 `ordinal-weeks.json`의 구간으로 정한다. 머리에 찍힌 구간이 구간표와 같음을 파서가 확인한다. 연중 6-9주는 구간이 둘이지만 레코드는 한 벌이다.
- **12.17-1.12**는 `date`로 찾는다(§기도서 표의 구조). 대림 3주일이 12월 17일인 해, 성탄 후 주일, 주의 세례주일처럼 주일과 겹치는 경우의 순서는 엔진이 정한다(미결 4).
- **성령강림과 삼위일체 주간**은 `name`으로 찾는 날(전일, 주일)과 연중 주간(그 밖의 날)으로 나뉜다.
- **전일과 전야**는 다음 날이 그 축일인 날의 저녁기도에 쓴다. `eve_of`와 `date`가 그 날을 가리킨다.
- **날짜 축일**은 `sanctoral.json`과 `id`가 같다. 이름 있는 날(성탄절, 공현일, 성령강림주일)은 달력 표의 이름과 다르게 적혀 있어(「성삼위일체대축일」, 「공현대축일」) 달력 표와 잇는 일은 엔진 ADR이 맡는다(미결 9).

### 6. 성구 문법

감사성찬례 성구 문법(`readings.py`의 `parse_reference`)을 그대로 쓰고, 성무일과에만 있는 표기를 더한다.

- **시편 칸**: 쉼표로 나뉜 조각은 시편 한 편씩이다. `N`은 한 편 전체, `N:절`은 그 편의 절이다. 조각에 콜론이 없고 하이픈이 있으면(`68:1-20(21-23), 24-35`의 `24-35`) 앞 시편의 이어지는 절이다. 감사성찬례 시편 칸과 달리 쉼표 뒤의 숫자 하나는 절이 아니라 시편이다(`110:1-5(6-7), 116, 117`).
- **독서 칸**: 괄호를 지닌 절을 읽는 절과 선택 절로 나누고(`요한 14:(1-7)8-17`, `루가 (1:1-4)3:1-14`), 한 장짜리 책(`필레 1-25`, `2요한 1-8`)을 읽고, 「또는」 뒤의 책 이름 생략을 잇는다. 장이 정해진 뒤의 홑 숫자는 절이다(`1고린 4:8-20(21)`). 숫자로 시작하는 책 이름(`1요한`)이 앞 칸 끝의 숫자와 헷갈리지 않게 칸 단위로 먼저 나눈다.
- **줄 앞의 라벨**: 칸마다 `[아침]`, `[저녁]`(아침기도나 저녁기도), `1`, `2`, `1, 2`(해)가 붙을 수 있다. 칸의 라벨이 줄의 기본값을 덮고, 라벨 없는 칸은 줄의 첫 라벨의 아침이나 저녁을 잇는다. 성지주일, 성 금요일, 성 토요일, 부활주일이 이 방식으로 읽힌다.
- **절 번호**: 데이터의 `number`(공동번역)와 인쇄된 번호가 다르면 `[번호]` 줄로 처리한다. 다니엘 3:98-100은 칠십인역 번호(ADR-003의 `alt_ref`)라 `number` 31-33이고, 요나 1:17과 말라기 4장은 영어 성경 번호라 공동번역은 요나 2:1과 말라기 3:19-24다. 546쪽 「요나 2:1-10」도 영어 번호로 보고 공동번역 2:2-11을 읽는다. 전날의 「요나 1:1-17」이 영어 번호이고, BCP의 같은 날이 Jonah 1:17-2:10이며, 공동번역 번호로 읽으면 2:11이 어느 날에도 읽히지 않기 때문이다(2026-11-11, data#75). 같은 표기가 519쪽(부활주간 월요일)에서는 공동번역 번호다.
- **데이터에 없는 절**: 호세아 13:14, 이사야 41:6-7, 욥기 28:28, 민수기 23:19는 데이터 저장소의 「인쇄본 대조 대기」 결번이다. 오류가 아니라 보고서의 경고로 두고, 그 목록에 없는 결번은 오류다.

### 7. 검증

파서와 테스트(`tests/test_office_readings.py`, 26개)가 다음을 확인하고, 하나라도 어긋나면 빌드가 실패한다(ADR-037 §2의 기준을 따른다).

1. 모든 성구가 해석되고, 책, 장, 절이 **절 단위로** 실제 있다. 장의 마지막 절만 보면 가운데 빠진 절을 놓친다(ADR-037 §2의 교훈).
2. 해가 있는 격자 줄은 1독서가 구약과 외경, 2독서가 서신 종류, 복음이 복음서다.
3. 주의 구성: 대림 1-3주, 사순 0-6주, 부활 1-7주, 연중 1-34주의 요일마다 해 1과 해 2의 레코드가 있다(대림 3주에는 토요일이, 사순 0주에는 주일, 월, 화가 없다). 날짜 줄 21일, 전일과 전야 15개, 날짜 축일 28개가 빠짐없다.
4. 연중 주 머리의 날짜 구간이 `ordinal-weeks.json`과 같다. 날짜 축일이 월별 축일 표에 있고 등급이 주요축일이거나 대축일이다.
5. 해 규칙이 470쪽 표의 39줄과 같다.
6. 같은 날이 두 쪽에 있으면 내용이 같다.
7. 커밋된 JSON이 원문에서 다시 만든 것과 같다(어긋남 검사).

**옮겨 적기의 정확성**은 테스트가 아니라 작업 방식으로 확인했고, 그 결과를 데이터 저장소 보고서(`liturgical/prayer-book/reports/2026-11-10-office-readings-vs-bcp.md`)에 남겼다.

- **두 번 따로 옮겼다.** 서브에이전트 여덟이 스캔 24장을 두 벌로 옮기고, 서로의 결과를 보지 못하게 했다. 24쌍 1,367줄이 숫자 하나 다르지 않았다(쉼표 뒤 공백만 세 줄 달랐다).
- **독립된 자료와 견줬다.** 두 번 옮긴 글이 같아도 같은 방식으로 틀릴 수 있다. 「1요한」의 「1」이 앞 칸 끝에 밀려 인쇄된 곳 넷을 두 벌이 모두 밀린 그대로 옮겼고, 절 실존 검사와 칸 종류 검사와 BCP 대조가 모두 이 곳을 짚었다.
- **눈가림으로 세 번째 읽었다.** BCP와 달랐던 독서 94칸과 시편 6칸을 옮긴 값을 알려 주지 않고 따로 읽게 했고, 100칸이 모두 옮긴 값과 같았다. BCP와 다른 것은 읽기 오류가 아니라 인쇄된 차이다.
- BCP와 다른 곳은 오류가 아니라 공동번역의 절 번호, 한국 기도서의 조정, 인쇄 오류 가운데 하나다. 보고서가 갈래별로 모았고 사람이 읽는다. CI는 돌리지 않는다.

### 8. 파이프라인과 캐시

- `build.yml`과 `pipeline.yml`의 `paths`에 `liturgical/prayer-book/office-readings/**`와 파서를 넣고, 단계에 `python liturgical/parse_office_readings.py`를 교회력 표 파서들 다음, 매니페스트 앞에 넣는다. 보고서를 자동 커밋과 어긋남 검사 목록에 더한다.
- `gen_manifests.py`는 `lectionary/*.json`을 모두 매니페스트에 넣으므로 바꾸지 않는다. 앱은 이 파일을 요청하지 않아 사용자에게 보이는 변화가 없다.
- 앱 저장소의 유닛과 e2e는 바뀌지 않는다.

## 검토한 대안

### 저장 위치

- **A. 별도 파일 `office-readings.json` (채택)**: 해 축이 다르고(1, 2와 가, 나, 다), 하루에 시편이 둘이며, 감사성찬례 화면이 쓰지 않는 데이터를 받지 않는다.
- **B. `eucharist-readings.json`에 합친다**: 채택 안 함 2026-11-10 · 이유: 감사성찬례 레코드의 해 축(`year`)이 달라 조회 키가 섞이고, 전례독서 화면이 성무일과 데이터를 받게 된다 · 재검토: 없음.

### 레코드 하나가 담는 것

- **A. 날 하나와 해 하나 (채택)**: 조회 키가 하나이고 ADR-037과 같다. 시편이 두 해에 되풀이된다.
- **B. 날 하나가 두 해를 함께 담는다(`readings: { "1": […], "2": […] }`)**: 채택 안 함 2026-11-10 · 이유: 시편을 한 번만 적어 얻는 용량이 작고(약 120KB), 감사성찬례와 레코드 모델이 달라진다 · 재검토: 용량이 문제가 되면.

### 입력 방식

- **A. 옮겨 적은 원문이 입력 (채택)**: 같은 표를 한 번만 적는다. 인쇄 오류의 근거가 원문과 같은 자리에 남는다.
- **B. 원문과 별도로 손으로 쓰는 표 파일을 둔다(`ordinal-weeks.txt` 방식)**: 채택 안 함 2026-11-10 · 이유: 같은 내용을 두 번 적어 어긋날 수 있다. `ordinal-weeks.txt`는 짧아 옮겨 적은 글과 구별할 필요가 없었다 · 재검토: 표가 바뀌어 원문과 갈라질 때.
- **C. 인쇄 오류를 파서 코드의 교정 표에서 고친다**: 채택 안 함 2026-11-10 · 이유: 인쇄된 값, 바른 값, 근거가 원문과 코드에 나뉜다. 원문의 표시 줄은 근거를 옆에 두고, 코드가 못 찾으면 멈춘다 · 재검토: 없음.
- **D. BCP 1979 표를 내려받아 데이터 원료로 쓴다**: 채택 안 함 2026-11-10 · 이유: 기도서가 기준이다(사용자 결정 2026-10-24). BCP는 영어 성경 번호이고 한국 기도서가 조정한 곳이 있어 대조에만 쓴다 · 재검토: 없음.

### 괄호 선택 구절

- **A. `optional` 필드 (채택)**: 한 레코드가 긴 형만 담고 생략할 수 있는 부분을 표시한다.
- **B. 감사성찬례처럼 짧은 형과 긴 형을 두 세트로 펼친다**: 채택 안 함 2026-11-10 · 이유: 괄호가 있는 칸이 329곳이라 레코드가 크게 늘고, 시편의 괄호는 「생략해도 된다」는 뜻이라 짧은 형이 대안이 아니다 · 재검토: 앱이 세트 모델만 읽을 수 있을 때.

### 칸의 종류

- **A. 책의 종류로 정한다 (채택)**: 성 토요일과 주요축일의 줄도 같은 규칙으로 읽힌다.
- **B. 줄 안의 칸 위치로 정한다**: 채택 안 함 2026-11-10 · 이유: 성 토요일은 아침과 저녁의 2독서가 두 칸에 나뉘고, 주요축일의 2독서는 복음서일 수 있다 · 재검토: 없음.

### 해의 이름

- **A. `cycle` 1과 2 (채택)**: 감사성찬례의 `year`와 규칙이 다르다(§4).
- **B. `year`에 `I`, `II`를 쓴다**: 채택 안 함 2026-11-10 · 이유: 같은 필드에 두 규칙이 섞여 12월 날짜에서 엔진이 틀린 해를 고른다 · 재검토: 없음.

## 미결 사항

1. **괄호의 뜻**: 기도서 508쪽에는 `[ ]`와 `( )`의 설명이 없다. BCP 1979는 시편에서 대괄호는 시편 한 편, 소괄호는 절을 생략할 수 있다고 하고, 독서에서 소괄호는 길게 읽을 수 있는 권장 구절이라고 한다(두 쪽의 기본값이 반대다). 한국 기도서가 같다고 보는 것이 맞는지 확인이 필요하다. 사용자나 사제에게 묻는다.
2. **12월 26-31일 안내문**: 「축일을 지키는 경우가 아니면 아래 본문을 사용한다」가 이 줄들(성 스테파노, 사도 성 요한, 죄 없는 아기들)을 가리키는지, 12.29-12.31 평일 줄만 가리키는지 확인이 필요하다. 12.26-28은 주요축일 표(554쪽)에도 같은 내용으로 있다.
3. **축일의 독서**: 508쪽은 「축일을 지킨다면 축일 본기도에 나오는 독서를 사용한다」고 적고, 551-554쪽은 주요축일의 아침, 저녁 독서를 따로 적는다. 둘의 관계(주요축일 표가 이 문장의 예외인지)를 사제에게 묻는다.
4. **12.17-1.12와 주일**: 날짜 규칙이 주일에도 적용되는가(대림 3주일이 12.17인 해, 대림 4주일, 성탄 후 주일). Phase 4 엔진 ADR에서 정한다.
5. **아침과 저녁의 독서 나눔**: 기도서는 독서 셋을 어떻게 나눌지 적지 않았다. BCP는 아침 둘, 저녁 하나를 권한다. Phase 4에서 정한다.
6. **인쇄 오류, 번호 환산, 실물 확인**: 보고서의 항목을 사용자가 실물에서 확인한다. 538쪽 「요한 2:2-12」(앞뒤 날과 BCP로 보아 2:1-12), BCP와 숫자 「1」 하나만 다른 525쪽 「묵시 19:4-6」(BCP 19:4-16), 530쪽 「마태 6:1-16」(BCP 6:1-6), 538쪽 「로마 4:7-12」(BCP 14:7-12), 549쪽 연중 33주 화요일 저녁 시편 「94」(다른 여섯 쪽은 「94, [95]」), 같은 시편 줄의 절 번호가 쪽마다 다른 곳(보고서 표)이다.
7. **BCP와 다른 곳**: 보고서에 모은 곳 가운데 사제 확인 질문지에 넣을 항목을 사용자가 정한다.
8. **「중」의 뜻과 절 경계**: 「사무하 23:13-17중」과 「에제 1:1-14, 24-28중」이 절의 어느 부분인지. 지금은 절 전체를 읽는 것으로 두었다.
9. **이름 있는 날과 달력 표 잇기**: 기도서 성무일과 표의 이름(「성탄절」, 「공현일」, 「성령강림주일」, 「승천일」)을 달력 표의 이름과 잇는 방식은 Phase 4 엔진 ADR에서 정한다.
10. **표기와 검색창**: 인쇄된 표기는 1,957개이고, 「요나 2:1-10」은 519쪽과 546쪽의 저장값이 달라 둘로 세면 1,958개다. 이 가운데 검색창이 구절로 읽지 못하는 것이 82개 있다. 생략 표시(소괄호, 대괄호)나 「중」이 든 표기 73개, 쉼표 뒤의 숫자가 장인 시편 목록 1개(`시편 107:31-43, 108`), 장 번호 없이 적는 한 장짜리 책 4개(`2요한 1-8`), 기도서의 번호를 공동번역 번호로 바꾼 곳 4개(`말라 4:1-6`)다. 감사성찬례 표기는 모두 읽힌다(ADR-005). 성무일과 화면이 생기면 복사한 표기를 검색창에 쳤을 때 읽게 할지 정한다. 후보는 셋이다. 검색 문법이 생략 표시, 「중」, 한 장짜리 책을 읽게 한다. 복사에 쓰는 표기를 괄호 없는 긴 형으로 만든다. 지금처럼 인쇄된 모양을 그대로 둔다. 그때까지 앱의 표기 시험(`tests/unit/search-worker.data.test.js`)은 이 82개만 대조에서 빼고 나머지 1,876개를 저장된 장과 절과 대조한다(감사성찬례나 성인 공통 독서에도 같은 저장값으로 있는 317개는 그쪽 표기로 이미 대조되므로 한 번만 센다).
