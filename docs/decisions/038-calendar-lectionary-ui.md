# ADR-038: 교회력 캘린더 · 전례독서 뷰 · 검색 이원화 UI

- 일시: 2026-07-04
- 상태: **승인됨 — 구현 중** (렌더 기반 완료 2026-07-27 · A3 독서 뷰 완료 2026-10-12 · 캘린더 탭 A2 · 검색 이원화 A4 남음)
- 관련: ADR-037(전례독서 데이터·엔진 — 본 UI의 입력), ADR-036(본기도·좌표), ADR-035(북마크 읽기 뷰 — 렌더 패턴 원형), ADR-029/030/031(탭 바·모핑·탭 히스토리), ADR-032(오버레이·뷰 레이어), ADR-033(검색 옵션), ADR-034(라우팅 분할)

## 배경

ADR-037의 데이터·엔진 위에 얹는 세 UI: ① 교회력 캘린더 탭, ② 전례독서 본문 뷰, ③ 검색 이원화(성서 본문 / 전례독서). 모두 기존 확장 지점(라우팅 `parsePath`/`route`, 탭바 `syncTabBarActive`, `appendVerses` 렌더, 검색 워커 메시지)을 따른다.

## 결정

### 1. 캘린더 탭 — 홈 옆 두 번째 위치

`index.html` `#tab-bar`에 `<a data-tab="calendar" href="/calendar">`를 **홈 바로 다음(두 번째)**에 추가. 노트 탭(비활성 숨김)은 보존 — 나중에 부활 예정. `tabbar.js syncTabBarActive`의 세그먼트 매핑에 `calendar` 추가(폭·인디케이터는 개수 기반 자동). 아이콘은 기존 스트로크 스타일(광학 크기 정규화 규칙 준수) 캘린더 글리프.

### 2. 캘린더 뷰 — 월간·주간·목록 3뷰 (`js/app/calendar.js` 신규)

- **라우트**: `/calendar`(월간, 이번 달) · `/calendar/YYYY-MM`(월간) · `/calendar/w/YYYY-MM-DD`(주간) · `/calendar/list`(목록 — 오늘부터 교회력일 아젠다). `routing.js parsePath()` 분기 + `route()` 디스패치(ADR-034 관례).
- 상단에 **뷰 전환 세그먼트**(월간|주간|목록). 이전/다음 이동 + "오늘" 버튼.
- 순수 함수 `buildMonthGrid`·`buildWeekStrip`·`buildAgendaList`(ADR-013 유닛 대상) — 엔진 `resolveDate`를 주입받아 셀/행 데이터를 만든다.
- 셀/행 = 날짜 + 대표 교회력일명(고유명 우선, 격자 좌표는 주일만 `대림1주` 표기) + 절기색 점. **색은 MVP에서 season 파생색** — ADR-036 §8 명시 `color`가 2차에서 채워지면 교체(뷰 주석으로 한계 명시).
- 셀/행 탭 → `/lectionary/YYYY-MM-DD`. 데스크톱도 동일 전체화면 뷰(ADR-035 `/read` 선례 — 드로어 폴백 없음).

### 3. 전례독서 본문 뷰 (`js/app/lectionary.js` 신규)

- **라우트 — 날짜 기반이 정본**: `/lectionary`(오늘) · `/lectionary/YYYY-MM-DD`. 상태는 쿼리 `?obs=&track=&set=&collect=`. **보조 라우트** `/lectionary/d/<slug>`(ADR-037 안정 슬러그) — 날짜 없는 검색 결과의 착지점이라 **A4(검색 이원화)에서 구현한다**(2026-10-12 — 그전엔 뷰의 「잘못된 날짜」 안내). 근거: 날짜 URL은 공유 즉시 의미가 확정되고 엔진이 좌표를 재계산하므로 데이터 개정에도 안정.
- **탭 분류: 캘린더 탭 소속** — 캘린더에서 날짜를 골라 들어가는 하위 화면이므로 캘린더 컨텍스트 유지(ADR-035의 `/read`=홈 선례와 다른 선택 — 봉독 자체가 목적인 `/read`와 달리 이 뷰는 날짜 탐색의 하위).
- **본문 순서: 본기도 → 제1독서 → 시편 → 제2독서 → 복음.**
- **본기도 블록 — 두 축을 구분한다**:
  - 같은 관측일의 **자유선택 대체안**(`collect_no`) → **세그먼트 탭**으로 택1(`?collect=N` — 목록의 N번째). 탭 패턴은 `views.js buildSegmentTabs`(구분 탭 `buildDivisionTabs` 의 슬라이드 인디케이터를 빼낸 공용 함수).
  - 서로 다른 관측일이 겹친 날(당일 + 성인축일 + 교회 축성일/축복일)에도 **고른 관측일의 본기도만** 보인다(사용자 결정 2026-10-12 — 「검토한 대안 — 본기도 열거 범위」). 엔진이 관측일별로 키잉해 주므로(ADR-037 §6, 2026-09-17) 뷰는 스위처로 고른 원소를 찾을 뿐 재조회하지 않는다 — 다른 관측일의 본기도는 그 칩을 골라야 보인다.
  - **송영은 앱 상수 3종** 중 고른 본기도의 `ending`(없으면 A) 하나를 **본기도 끝에 1회만** 부착(ADR-036 §3 — A·B 의 선택 원칙은 설계서 미결37. 시편 끝의 영광송과 별개 용어).
- **독서 렌더 — ADR-035 경로 재사용**: 필요한 장 JSON 전부 선로드(중복 제거) → stale 체크 → 동기 DOM 커밋(`bookmark-read.js` 패턴). 독서별 섹션 제목(label) + refs의 장별 `<article>` + `appendVerses(…, {hideCites:true})`(장 경계 병합·절 부분집합). 절 필터 로직(`_specCoversVerse` 등)은 `verse-spec.js`(leaf)로 승격 export해 bookmark-read와 공유(복제 금지).
- **계응 시편 조판**: `lps` 장의 `response` 세그먼트(응답 반행)·`versicle` 절(무번호 ¶)을 `appendVerses`가 additive로 처리 — 응답 반행 시각 구분 + `◯` 표지. **영광송 상수는 `appendVerses` 가 아니라 독서 뷰(A3)가 붙인다**(2026-07-27) — 편 낭송 끝 1회이므로 발췌 단위가 정해지는 자리가 그쪽이다. 송가는 시편 장/절 표기 옆에 명칭 병기(예: `루가 1:46하-55, 성모송가`).
  - **렌더 기반은 독서 뷰보다 먼저 구현했다**(2026-07-27). `appendVerses` 가 계응 시편을 그리지 못하면 독서 뷰의 시편 슬롯이 성립하지 않기 때문이다 — `response`(응답 반행 + 선창 끝 `◯`)·`versicle`(`¶`)·`section`(`(N)` 소제목) additive 처리, `_specCoversVerse`·`_chapterMaxVerse` 를 `verse-spec.js` 로 승격. 영광송 부착은 이 렌더 기반에 들지 않는다(위).
  - **절 인스턴스 식별**(2026-07-27 — 예정에 없던 선행 과제). 절 부분집합 렌더의 중복 제거 키가 번호 기반이어서 같은 번호의 절이 유실되고 있었다(77개 장 130절 — 전례시편 69편의 `¶` 구절, 에스델 4장 31절). 이 상태로 독서 뷰를 얹으면 시편의 `¶` 구절이 화면에서 사라진 채로 굳는다. `verse-spec.js` 에 `verseInstanceKey(s)` 를 두고 렌더·중복 제거·DOM id 가 같은 키를 쓰게 했다.
- **대안 세트·트랙 전환**: `set_total>1` 은 세 갈래다(사용자 결정 2026-10-12, 설계서 미결38 닫힘 — 아래 「구현」 · 「검토한 대안 — 대안 세트의 표시」): 「또는」 대안은 세그먼트 「독서 1 · 2」(완전한 세트를 통째로), 조건부 세트는 조건이 라벨(「…로 지킬 때」), 괄호 선택 구절 세트는 바탕에 합쳐 긴 본문 + 〔 〕 주석. `reading_track` 1/2 존재 시 "독서 1/독서 2" 토글. **트랙은 마지막으로 고른 것을 localStorage 에 기억해 날짜 · 해와 무관하게 기본값으로 삼는다**(사용자 결정 2026-10-13 — 「한번 선택하면 계속 일관성 있게 같은 트랙이 기본값」. ADR-036 §2 독서 연속성을 해를 넘어 잇는 꼴이고, 바꾸려면 「독서 1 · 2」 세그먼트를 다시 누른다 — 버린 전례년 단위 기억은 「검토한 대안 — 트랙 기억의 단위」). **공통 독서**(엔진이 `common: "<분류>"` 표지를 얹은 그룹 — 고유 독서 없는 성인, ADR-037 §6, 2026-09-17)는 세그먼트와 본문 제목에 분류 라벨을 캡션으로 병기한다(예: 「순교자 공통 독서」) — 기도서의 공통을 그 성인의 고유로 오인하지 않게. 라벨은 `commons.classes[분류].label`.
- **관측일 스위처** — 후보 관측일이 여럿이면(축일∧평일 겹침 등) 헤더 아래 관측일 스위처 칩(`?obs=`). 표시 순서는 ADR-037 §6 — ① 축일/재일 → ② 이동 축일 → ③ 나머지. **칩은 후보 전부를 항상 노출**하고 `official` 은 **초기 선택**일 뿐이다 — 전례상 사용되지 않는 후보(축일에 밀린 연중 독서)도 모두 노출하고, 앱이 낮은 등급을 숨기거나 한 이름으로 합쳐 내지 않는다(ADR-036 §7 밀린 독서 보존 · 설계서 §5.5 · ADR-037 §6). 독서자의 목적에 맞는 선택은 사용자 몫.
  - **성인이 둘 이상인 날짜**(2026-09-17, 사용자 확정): 각 성인의 본기도·독서를 **모두 생성**하고(고유 또는 공통 — ADR-037 §6), 어느 것을 볼지는 스위처로 **독자가 고른다**(03.01 삼일절 ∧ 데이빗 · 08.15 성모안식 ∧ 광복절 · 09.29 미카엘 ∧ 설립 기념일 · 12.31 실베스터 ∧ 위클리프 — 양쪽 다 본문이 있는 쌍).
  - **기념일 후보**(2026-09-17): 칩에는 남되 본기도·독서가 빈 결과라 본문 자리에 「기념일 — 본문 없음」을 그린다(설계서 §2 · §5.6 — 01.01 세계평화 기도일 · 09.14 성가수도회 · 11.01 초대주교). 초기 선택이 아니다(→ 설계서 R-6.1-ineligible).
  - **사계재 후보**(2026-09-17 — 지향, → 설계서 R-6.1-ineligible): 후보로는 남되 초기 선택이 아니다. 칩은 교구 달력처럼 제목 성격(「동계재 (성직자의 성소)」)으로 그리고, 고르면 성소 본기도·독서(금요일은 성직후보자·수도자 두 세트)를 보인다 — 서울교구 2024 면이 인쇄한 것과 같은 화면이다. **사계재 칩을 고르면 헤더 색은 그 후보의 색(`observance.color` 자)이다** — 「재일 독서를 읽을 때만 자색, 어차피 선택 독서」(2026-09-17). 그날 자체의 색(`resolved.color`)도 자다 — 축일이 이기면 축일 색이 대표이고 `colors` 가 [자, 축일 색]으로 병기한다(2026-10-10 사용자 결정 — 책자 2025 · 2026 대로, → 설계서 R-6.4-ember-color). 색 필드는 셋이다(2026-10-10 사용자 결정 — 버린 꼴은 「검토한 대안 — 병기 색의 자리」) — `color` 는 그날의 대표색 하나, `colors` 는 병기 목록(사계재 날 축일이 이기면 둘, 책자의 [자/백] 순), `colorAlt` 는 선택 대체색(장미색 · 청색 — 데이터 `color_alt` 와 같은 `null | 스칼라 | 배열` 3형, 대림 3주일은 둘 다)이다. 병기를 그리는 뷰는 `colors` 를 읽는다 — 병기가 없는 날은 `[color]` 다.
- **선택 봉헌 · 옮겨진 축일 · 명절 — 두 독서를 나란히**(2026-09-19 사용자 확정). 옮길지는 지역 교회 사제가 정하는데 **독자는 그 결정을 모를 수 있다.** 그래서 앱이 설정으로 정하지도, 한쪽을 기본으로 깔고 다른 쪽을 링크로 숨기지도 않고 — **두 독서를 선택지로 나란히 내어 독자가 고르게 한다**(버린 안은 「검토한 대안 — 선택 봉헌 · 옮겨진 축일의 표시」). 어느 쪽이 `official` 인지는 표시하되 선택을 대신하지 않는다. `activated` 는 v1 에서 빈 집합이다(설계서 미결15).
  - **당일**(예: 8.6 주의 변모): 「주의 변모 독서」 / 「가까운 주일로 옮겨 지키는 경우 — 이날은 평일 독서」를 설명과 함께 나란히. 목적지는 엔진이 `nearby_sunday` 로 계산한 날짜다 — 2026 은 오는 주일 8.9, 2024 는 직전 주일 8.4, 2025 는 8.3; 문구도 「오는」·「지난」을 계산 결과대로 쓴다.
  - **목적지 주일**(2026 이면 8.9): 「연중 19주일 독서」 / 「주의 변모 독서(8.6 에서 옮겨 지키는 경우)」를 나란히(엔진의 `optional` 후보).
  - **규칙상 옮겨진 축일이 도착한 날**(예: 12.7 니콜라)도 같은 꼴 — 그날의 후보들을 선택지로 낸다.
  - **명절**(설·추석 — 설계서 미결29): 명절이 승자인 날도 그날의 평일 독서를 나란히 낸다. 책자가 세 해(2024·2025·2026) 여섯 사례에서 초기 독서를 고유·평일로 번갈아 두었고, 네 사례에서는 다른 쪽을 병기했다 — 2026 두 사례는 한쪽만 실었다(사례별 표기는 검토 문서 X-11 · X-12 와 보관 문서의 설계서 미결29 절). 초기 선택이 갈리므로 두 독서를 항상 낸다.

**구현(A3 — 2026-10-12, #346).** `js/app/lectionary.js` 가 본 ADR §3 을 구현한다 — 순수 모델(`buildLectionaryModel`: 초기 선택 · 트랙 · 세트 · 본기도 · 칩 라벨 · 두 독서 카드 · 헤더 색 · URL)과 DOM 렌더를 갈랐고(`LECTIONARY_MODEL` 마커 블록이 유닛 대상), 모든 컨트롤이 링크라 전역 `<a>` 인터셉터가 이동한다(뒤로 · 공유 · 키보드 그대로). 엔진은 `optionalDestOf` 노출 하나만 더했다. 구현하며 정한 것은 아래다 — 2026-10-12 에 사용자가 하나씩 확정했다(coding-pitfalls §21, 원장 `docs/changes/2026-10-12-lectionary-view.md`).

- **초기 선택은 `official` 이되, 승자의 독서가 공통(`common`)뿐이면 그날의 격자(주일 · 평일) 독서가 초기 독서다** — 책자대로(사용자 확정 2026-10-12, 설계서 미결25 닫힘). 헤더의 제목 · 대표색은 여전히 승자(그날)다; 본기도는 고른 칩의 것이라 초기 화면에는 격자의 본기도가 보인다(아래 「본기도는 고른 관측일의 것만」 — `collectsFor(selected)`, 유닛 「사계재 날」 케이스). 9.16 니니안 · 10.12 윌프리드가 실례.
- **본기도는 고른 관측일의 것만** 보인다(사용자 결정 2026-10-12) — 대체안은 세그먼트 「본기도 1 · 2 · 3」, 송영은 고른 본기도의 `ending`(없으면 A) 하나. 같은 날의 다른 관측일(성인축일 · 축성일 …) 본기도는 그 칩을 골라야 보인다 — 엔진 `findCollects` 의 ② 축(서로 다른 관측일이 겹쳐 따라오는 본기도)은 열거하지 않고 관측일별 키잉만 쓴다 — 칩이 고른 원소를 찾는 데(버린 열거안은 「검토한 대안 — 본기도 열거 범위」).

- **대안 세트는 세 갈래**(사용자 결정 2026-10-12, 설계서 미결38 닫힘): 「또는」 대안(대안이 있는 슬롯만 바꾼 완전한 세트 — ADR-037 §1; 파서 표지 「원본 세트 N」이든 표지 없음이든)은 세그먼트 「독서 1」「독서 2」로 통째로 고른다 · 조건부 세트는 조건이 라벨(「…로 지킬 때」 꼴로 통일)이고 바탕은 관측일 이름 · 괄호 선택 구절 세트(한 슬롯만 더 긴 세트)는 세그먼트에 올리지 않고 바탕에 합쳐 **긴 본문 + 선택 구절 〔 〕 + 「짧게 읽으면 …」 주석**으로 그린다(`readingOptions` · `optionalVerseTest`). 제목이 갈리면 제목으로.

- **절 발췌는 번호만으로 고르지 않는다**(2026-10-13 자체 리뷰 — `selectVerses` · `trimHalfVerses`): 다른 장에서 옮겨 실린 절(`chapter_ref` — 이사 40 의 41:6-7)은 뺀다. 번호 체계가 둘인 장(다니 3 — 그리스어 추가 본문 `lxx_only` 24~90 ∧ 히브리 뒷부분 24~33)은 spec 이 그리스어에만 있는 번호를 덮으면 그리스어 체계(히브리 절은 `alt_ref` 로), 아니면 히브리 체계다 — 「다니 3:25, 34-43」(사순 3주 화)은 아자리야의 기도, 「다니 3:14-20, 24-25, 28」(사순 5주 수)은 히브리 본문(로마 성서정과 Dn 3:25, 34-43 · Dn 3:14-20, 91-92, 95 와 같다). 두 결과가 RCL(NRSV 번호) 계열 독서표와 같은 본문이라 이 규칙으로 **완결**이다(사용자 결정 2026-10-13 — 「RCL 과 일치하면 완결」: 사순 3주 화는 잉글랜드 CW 「Song of the Three 2, 11-20」, 사순 5주 수는 CW 「Dan 3.14-20, 24-25, 28」). 데이터의 다니 3 참조는 이 둘뿐이고, 새 참조가 생기면 실데이터 테스트가 멈춘다. 반절(상 → `a` · 하 → `b`)은 그 절이 정확히 두 줄로 그려졌으면 그 줄만(데이터의 두 줄 절 22곳은 줄 경계가 곧 상/하 경계 — 성령강림 「시편 104:35하」), 한 줄 · 세 줄 이상 절은 절 전체. 에스델 4:17 의 하위 절은 설계서 미결39 그대로(4:17 인스턴스를 다 그린다).
- **본기도 · 대안 세트의 순서와 `?collect=`**(2026-10-13 자체 리뷰): 한 날짜에 다른 관측일의 것이 섞여 오면(5.1 노동자의 날 ∧ 사도 성 필립보와 성 야고보 — 설계서 미결18 · 35) 고른 관측일 이름의 것을 앞에 둔다 — 5.1 은 사도 축일이 먼저이고, 지역 축일인 노동자의 날은 독자가 원하면 고른다(사용자 결정 2026-10-13). **독서 세트와 본기도가 같은 제목으로 1:1 짝지어지는 날은 「독서 · 본기도」 단추 하나가 둘을 함께 고른다**(사용자 결정 2026-10-13 — 「대안 독서는 사도 축일, 본기도는 노동자의 날」 같은 교차 조합은 없다; 실데이터에서는 5.1 과 사계재 금요일 넷 — 2025~2028 전수, `linkCollects`). 그날은 `?set=` 이 본기도까지 정하고 `?collect=` 는 읽지도 쓰지도 않으며, 본기도 칸에 따로 세그먼트가 없다. 단추 라벨은 제목을 가르는 짧은 이름(「성직후보자」 · 「수도자」 — 버린 두 세그먼트 꼴은 「검토한 대안 — 짝지어진 독서와 본기도의 선택」). `?collect=` 는 본기도 목록의 몇 번째(1부터 — `?set=` 과 같은 규칙)이고, `collect_no` 가 겹치면 라벨은 제목에서 다른 낱말(사계재 금요일 「성직후보자」 · 「수도자」).
- **두 독서 카드는 독서가 있는 후보끼리만** — 성탄 8일의 도착일(12.27~29) · 1.6 의 격자처럼 본문이 빈 후보로는 카드를 내지 않는다. 명절이 주일이면 격자 카드는 「이날의 주일 독서」. 공통 독서 세그먼트에는 「… 공통 독서」 캡션(위 §3).

### 3-1. 표시 라벨 규칙 — 트랙·주기 병기

데이터의 `title`은 주기·트랙 표기를 뺀 정규화 이름(ADR-036 §2)이다. 따라서 **전례독서 엔트리를 이름으로 나열하는 모든 자리**에서는 표시 계층이 라벨을 조합한다:

- **라벨 = `title` (+ 주기 라벨) (+ `독서 N`)** — `reading_track`이 비-null이면 반드시 트랙을 병기한다. 예: `연중10주 (가해, 독서 1)` / `연중10주 (가해, 독서 2)`. 이 규칙이 없으면 트랙 1·2가 같은 이름으로 표시돼 구분할 수 없다.
- 적용 자리: **캘린더 목록(아젠다) 뷰**에서 하루의 독서 세트를 나열할 때, **검색 결과 카드**, **관측일 스위처 칩**. (월간·주간 셀은 대표 교회력일명만 — 트랙 구분은 셀에 넣지 않고 독서 뷰의 토글이 담당.)
- **독서 뷰 본문 제목에는 트랙을 표시하지 않는다** — 트랙 선택은 상단 "독서 1/독서 2" 토글이 담당하므로 본문 제목까지 반복하지 않는다.
- 검색 결과에서 같은 교회력일의 두 트랙이 모두 매치되면 한 카드로 묶고 매치된 트랙을 표기(예: "독서 1·2 포함"), 한 트랙만 매치되면 그 트랙을 병기(예: "독서 2에 포함") — 질의한 성구가 어느 트랙 독서인지가 유용한 정보다.

### 4. 검색 이원화

- **검색 화면 상단에 탭** — `[성서 본문 | 전례독서]`. URL `?mode=lectionary`(기본 bible) — ADR-031 탭 복원·공유 일관성을 위해 상태를 URL에 인코딩(ADR-033과 동일 원칙). `search.js renderSearchView/renderSearchResults`에 mode 분기; lectionary 모드에서는 책 픽커 대신 안내 placeholder("교회력일 이름 또는 창세 1:1").
- **워커 확장**(`search-worker.js`): `{type:"search", mode:"lectionary", q}` — ① 장절 질의면 기존 `tryVerseRef`(보강된 별칭 포함)로 파싱 후 `search-lectionary.json`의 `cov` 스캔 → 포함하는 교회력일 목록, ② 아니면 `names` 부분 문자열 매치(별칭 포함). 결과 카드 = 교회력일 라벨 + 매치 슬롯 표시 + `/lectionary/d/<slug>` 링크.
- 기존 성서 검색 경로(청크·RLE·`in:` 토큰)는 무변경.

### 5. SW·캐시

`sw.js cacheNameFor`에 `/data/lectionary/` → DATA_CACHE 라우팅 추가. 무효화는 bible-manifest 편입(ADR-037 §7)으로 ADR-021 흐름 자동.

## 검토한 대안

버린 선택지는 여기에 「날짜 · 이유 · 근거 · 재검토 조건」과 함께 남긴다(설계서 §1.4 편집 원칙).

### 캘린더 탭 배치
- **A. 홈 옆 두 번째 신규 탭 (채택, 사용자 결정)** — 노트 탭은 보존(나중 부활). 노트가 숨김 상태라 실표시 4탭 유지.
- B. 노트 탭 자리 대체 — 노트 부활 시 재배치 필요. 기각.

### `/lectionary` 탭 분류
- **A. 캘린더 탭 (채택)** — 날짜 탐색의 하위 화면.
- B. 홈 탭(ADR-035 `/read` 선례) — 봉독 맥락은 같으나 진입·복귀 동선이 캘린더. 기각.

### 독서 뷰 URL
- **A. 날짜 정본 + 슬러그 보조 (채택)** — 공유 안정 + 검색 착지 모두 해결.
- B. 슬러그 단독 — "오늘의 독서" 진입마다 좌표 계산 후 리다이렉트 필요. 기각.

### 검색 이원화 UI
- **A. 검색 화면 상단 탭 (채택, 사용자 결정)** — 한 화면에서 축 전환.
- B. 별도 검색 뷰(/calendar 내 검색) — 검색 동선 분산. 기각.

### 선택 봉헌 · 옮겨진 축일의 표시
- **A. 두 독서를 선택지로 나란히 (채택 2026-09-19, 사용자 확정)** — 본 ADR §3.
- **B. 앱 설정으로 옮길지 정한다** — 기각 2026-09-19 · 이유: 옮길지는 대개 지역 교회의 사제가 정하는데 독자는 그 결정을 모를 수 있다 · 재검토: 본당 설정이 생기면(설계서 미결15 — 엔진의 `activated` 계약은 그때를 위해 남긴다).
- **C. 기본 독서 + 대안 링크(한쪽을 기본으로 깔고 다른 쪽은 링크로)** — 기각 2026-09-19 · 이유: B 와 같다 — 독자가 사제의 결정을 모를 수 있으므로 숨긴 쪽이 그날의 실제 전례일 수 있다 · 재검토: B 와 같다.
- 「`official` 만 / 후보 전부」 설정 — 기각 2026-09-17 → ADR-036 「검토한 대안 — 밀린 독서의 노출」.

### 병기 색의 자리
- **A. `colors` 배열을 새로 둔다 (채택 2026-10-10, 사용자 결정)** — 본 ADR §3 · 설계서 §5.5. `color` 는 그날의 대표색 하나, `colors` 는 그날의 병기 목록(병기가 없으면 `[color]`)이다 — 사계재 날의 색(설계서 미결26)이 어느 모델로 닫히든 같은 꼴로 담을 수 있어 골랐다. 그 미결은 모델 (b) 로 닫혔다(2026-10-10): 격자가 이기는 사계재 날의 `color` 는 절기색이 아니라 자이고, 축일이 이기면 `color` 는 축일 색 그대로 `colors` 가 자를 병기한다(값의 규칙은 → 설계서 R-6.4-ember-color). 픽스처 README 가 이미 `colors` 키로 병기 기대값을 적고 있었다.
- **B. `colorAlt` 를 병기 둘째 색으로 재사용** — 기각 2026-10-10 · 이유: `colorAlt` 는 데이터 `color_alt` 와 같은 뜻(선택 대체색 — 대림의 청색 · 대림 3주일과 사순 4주일의 장미색)이라 한 필드가 두 뜻을 갖게 되고, 대림 · 성모 날의 병기처럼 대체색과 병기 색이 한 날에 함께 필요하면 담을 자리가 없다. 병기가 셋 이상이면(사계재 + 축일 + 절기) 아예 못 담는다 · 재검토: 없음.
- **C. 정하지 않고 `colorAlt` · `colors` 를 다 열어 둔다** — 기각 2026-10-10 · 이유: 타입이 결정을 미루는 대신 소비자(A2 · A3)가 어느 쪽을 읽을지 모호해진다 · 재검토: 없음.

### 구현 순서
- **A. 렌더 기반 → 독서 뷰 → 캘린더 탭 → 검색 (채택 2026-07-27)** — 본 ADR 「후속」.
- **B. A2(캘린더 탭) → A3(독서 뷰) → A4(검색)(원안)** — 기각 2026-07-27 · 이유: 캘린더 셀이 전부 `/lectionary/…` 로 링크하므로 캘린더를 먼저 내보내면 배포본에 죽은 링크가 생기고, 계응 시편을 그리지 못하면 독서 뷰의 시편 슬롯이 성립하지 않는다 · 재검토: 없음.

### A3 와 A2 사이의 진입점
- **A. URL 과 탭 분류만 (채택 2026-10-12, 사용자 확정)** — 캘린더 탭(A2)이 설계된 진입이고 바로 다음 PR 이다. 그사이 홈에 임시 카드를 두면 A2 에서 다시 걷어야 한다.
- **B. 홈 책 목록에 「오늘의 독서」 카드** — 기각(잠정) 2026-10-12 · 이유: 홈 화면 변경이 내비 · 접근성 e2e 를 건드리고 A2 뒤 제거 비용이 든다 · 재검토: A2 가 늦어지면.
- **C. 캘린더 탭 버튼만 먼저(오늘의 독서로)** — 기각(잠정) 2026-10-12 · 이유: 탭 바 폭 · 아이콘 · e2e 가 A2 몫이고, 캘린더 아이콘이 독서를 여는 것은 뜻이 어긋난다 · 재검토: 없음.

### 두 독서 나란히의 꼴
- **A. 카드 둘 + 본문 하나 (채택 2026-10-12)** — 설명을 단 카드 둘을 나란히 두고 고른 쪽의 본문을 아래에 그린다(본 ADR §3 「구현」).
- **B. 두 본문을 동시에 그린다** — 기각(잠정) 2026-10-12 · 이유: 길이가 두 배이고 세트 · 트랙 · 본기도 대체안 축과 곱해져 상태가 늘어난다 · 재검토: 사용자가 비교 봉독을 원하면.

### 본기도 열거 범위
- **A. 고른 관측일의 본기도만 (채택 2026-10-12, 사용자 결정)** — 본 ADR §3 「구현」. 다른 관측일의 본기도는 그 칩을 골라 본다.
- **B. 같은 날 함께 지키는 관측일(`proper` · `transferred_in` · `commemorated`)의 본기도를 뒤따라 열거** — 기각 2026-10-12(PM 잠정안이었다) · 이유: 사용자 결정 — 한 화면에 한 관측일의 본기도만 · 재검토: 사제가 「당일 + 성인축일 본기도 열거」를 요구하면(ADR-036 §3 의 전제).
- **C. 후보 전부(밀린 · 떠난 · 켜지 않은 선택 봉헌 · 사계재 포함)** — 기각 2026-10-12 · 이유: 그날 드리지 않는 본기도까지 열거된다 · 재검토: 없음.

### 트랙 기억의 단위
- **A. 마지막 선택 하나를 날짜 · 해와 무관하게 기본값으로 (채택 2026-10-13, 사용자 결정)** — 본 ADR §3 · 「구현」.
- **B. 전례년마다 따로 기억(`{"<전례년>": 1|2}`) — 그해 첫 선택이 그해의 기본값** — 기각 2026-10-13(#346 이 잠시 구현했다) · 이유: 사용자 결정 — 「한번 선택하면 계속 일관성 있게 같은 트랙이 기본값」. 해가 바뀔 때마다 독서 1 로 돌아가 다시 골라야 했다 · 재검토: 해마다 트랙을 바꿔 쓰는 교회 관행이 확인되면.

### 전례시편 복사의 출처 · 표기
- **A. 출처는 「(대한성공회 기도서)」, 전례 표기 ◯ · ¶ · 「(N)」은 남긴다 (채택 2026-10-13, 사용자 결정)** — 본 ADR §3 「구현」.
- **B. 출처 괄호 없이 「전례시편 23:1-2」만** — 기각 2026-10-13(자체 리뷰의 잠정안이었다 — 「(공동번역성서)」가 틀려서 뺐다) · 이유: 사용자 결정 — 번역을 밝힌다 · 재검토: 없음.
- **C. 전례 표기를 복사에서 뺀다**(`docs/known-issues.md` §4 의 다른 갈래 — 제거 목록에 세 클래스) — 기각 2026-10-13 · 이유: 사용자 결정 — 「모두 표시하는 게 활용도가 높을 것」(주보 · 전례 용도) · 재검토: 일반 독자용 복사를 따로 요구하면.

### 짝지어진 독서와 본기도의 선택
- **A. 「독서 · 본기도」 단추 하나로 함께 (채택 2026-10-13, 사용자 결정)** — 본 ADR §3 「구현」. 독서 세트와 본기도가 같은 제목으로 1:1 짝지어지는 날(5.1 · 사계재 금요일)만이고, 「또는」 독서 1 · 2 와 본기도 1 · 2 · 3 처럼 제목으로 갈리지 않는 대안은 여전히 따로 고른다.
- **B. 「대안 독서」 · 「본기도」 세그먼트를 따로** — 기각 2026-10-13(자체 리뷰가 둔 꼴이었다) · 이유: 사용자 결정 — 교차 조합(사도 축일 독서 + 노동자의 날 본기도)이 없으므로 두 번 누르게 할 까닭이 없고, 한쪽만 바꾸면 쓰지 않는 조합이 화면에 생긴다 · 재검토: 교차 조합을 쓰는 사례가 확인되면.

### 대안 세트의 표시
- **A. 세 갈래로 다르게 — 「또는」 대안은 「독서 N」 세그먼트, 조건부는 조건이 라벨, 괄호 선택 구절은 바탕에 합쳐 긴 본문 + 〔 〕 (채택 2026-10-12, 사용자 결정)** — 본 ADR §3 「구현」.
- **B. 세트마다 「1안 · 2안」 번호 라벨 + `set_note` 캡션 줄** — 기각 2026-10-12(PM 잠정안이었다) · 이유: 세그먼트만 보고 무엇이 다른지 알 수 없고, 괄호 선택 구절은 본문이 같은데 세트를 둘로 보인다 · 재검토: 없음.
- **C. 괄호 선택 구절 세트를 별도 세트로 두고 짧은 본문을 기본으로** — 기각 2026-10-12 · 이유: 사용자 결정 — 긴 본문을 중심으로 싣고 짧은 본문이 어디까지인지 주석으로 · 재검토: 없음.
