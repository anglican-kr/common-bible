# ADR-028: 디자인 시스템 — 토큰 단계 + HIG 정렬

- 일시: 2026-06-02
- 상태: 승인됨 — 구현 완료 (2026-06-02)
- 관련 ADR: ADR-023(토글 스위치), ADR-024(책 목록 탭과 헤더 내비), ADR-025(스크롤 elevation), ADR-022·027(인용과 주석), ADR-029·030(하단 탭 바)
- 권위 문서: 루트 [`DESIGN.md`](../../DESIGN.md)

## 맥락

`css/style.css`(4,800줄+)는 **색상만** CSS 변수로 토큰화되어 있었다. `:root` / `[data-theme="dark"]` / `[data-color-scheme]`의 3중 구조로 잘 정리된 팔레트였다. 그러나 그 밖의 시각 속성은 모두 그때그때 정한 값(ad-hoc)이었다.

- **타이포 스케일이 없었다**: `0.65rem`부터 `1.6rem` 사이에 14개가 넘는 글자 크기가 기준 없이 섞여 있었다.
- **간격 스케일이 없었다**: `0.15rem`부터 `4rem` 사이에 20개가 넘는 rem 값이 자리마다 제각각이었다.
- **elevation이 없었다**: 그림자가 `0.08 → 0.12 → 0.18 → 0.25`라는 **드러나지 않은** 단계로만 있었고 토큰이 아니었다. 다크 모드 보강도 컴포넌트마다 손으로 했다.
- **컨트롤과 터치 영역이 들쭉날쭉했다**: `28px·32px·44px·2.2rem·2.4rem`이 섞여 있었다. 일부 헤더 아이콘 버튼은 기본 글자 크기에서 약 40px라 **Apple HIG의 최소 탭 영역 44pt에 못 미쳤다**.

새 UI 작업마다 「이 간격이 맞나, 이 글자 크기가 다른 곳과 같나」를 매번 짐작해야 했고, 일관성이 작성자의 기억에 기댔다. 하나의 권위 있는 기준이 필요했다.

방향은 사용자와 합의했다. (1) 시각 회귀를 줄이는 **토큰 층과 점진 치환**(전면 재작성이 아니다), (2) 성경 **본문은 Serif와 넉넉한 행간을 유지**하고 chrome UI에만 Apple HIG를 적용, (3) 간격은 **px 기반 8pt 그리드**(HIG와 맞고, 글자 크기 설정과 따로 논다).

## 결정

### 1. `:root`에 토큰 단계를 더한다 — 더하기만 하고 하위 호환을 지킨다

기존 토큰 이름(`--bg`…, `--radius`, `--shadow`, `--max-width`)은 **그대로 둔다**. 새 토큰만 더한다.

- **반경** `--radius-xs(4) /sm(6) /(8) /md(10) /lg(12) /modal(14) /xl(16) /pill(999)`. 기존 코드에서 실제로 쓰던 값에 맞추므로 바꿔도 회귀가 없다.
- **elevation** `--shadow-1(=--shadow) /2 /3 /sheet /4`. 라이트 값은 기존의 드러나지 않던 단계를 문서에 적은 것이다. **다크는 `[data-theme="dark"]`에서 같은 토큰을 더 무거운 alpha로 저절로 바꾼다.** ADR-025가 헤더에만 손으로 하던 다크 보강을 모든 표면으로 넓힌 것이다.
- **간격(8pt px)** `--space-0_5(2) …/4(16) /6(24) /8(32) /10(40) /12(48)`.
- **타이포(rem)** `--font-2xs(0.7) … /2xl(1.6)`, `--leading-tight … loose`. rem으로 둔 이유는, 설정의 글자 크기가 루트 폰트를 바꾸면 타이포가 함께 커지고 작아져야 하기 때문이다(Dynamic Type).
- **컨트롤** `--touch-target(44) · --control-h(36) · --control-h-sm(28) · --icon-btn(40)`.
- **모션** `--duration-fast(0.18) /base(0.25) /slow(0.4) · --ease-out`. `--duration-fast`는 2026-06-03에 0.15s로 바꿨다(§7).
- **내비(예약)** `--tabbar-h(49) · --tabbar-icon(24) · --sidebar-w(260) · --nav-z(30)`. 아래 「적응형 내비게이션」의 뒤 구현이 쓰기로 했다. 지금 CSS가 실제로 쓰는 것은 `--nav-z`뿐이다.

### 2. 간격은 px, 타이포는 rem

HIG의 8pt 그리드를 따르되 **레이아웃(간격)과 콘텐츠(글자)를 나눈다**. 그래서 사용자가 글자 크기를 키워도 패딩과 여백은 그대로다. 이것이 HIG에 맞는 동작이다(레이아웃은 타이포가 아니라 기기와 화면에 따른다). 본문 가독성에 영향이 없도록 본문 영역의 패딩은 조심스럽게만 바꾼다.

### 3. 처음에는 값이 같은 곳부터 바꿨다

처음에는 전면 재작성 대신 눈에 잘 띄는 곳만 토큰 참조로 바꾸기로 했다. 토큰 값이 기존 값과 **정확히 같은** 곳부터 바꿨다(회귀 0). 헤더 스크롤 그림자(`--shadow-3`), 모달(`--radius-modal`·`--shadow-4`), 바텀 시트(`--radius-xl`·`--shadow-sheet`), 팝오버(`--radius-lg`)다. 나머지 그때그때 정한 값은 그대로 두고, `DESIGN.md`가 정한 스케일을 보고 뒤의 작업이 차츰 맞춰 가기로 했다. 뒤에 이 방식을 넘어서 전부 토큰으로 맞췄다(§7, §9).

### 4. HIG 44pt 터치 영역 — 헤더 아이콘 버튼 보강

기본 글자 크기에서 약 40px이던 헤더의 뒤로/북마크 아이콘 버튼을 `2.45rem`(18px 루트에서 약 44px)으로 키웠다. HIG 최소 탭 영역을 만족하면서 rem 스케일은 지킨다. 크기가 고정된 컨트롤(오디오 재생 버튼)은 `min-width/min-height: var(--touch-target)`로 바닥을 깐다.

### 5. HIG에서 일부러 벗어나는 곳을 문서에 적는다

- 본문은 `Noto Serif KR`과 line-height 1.8을 유지한다(성경 가독성과 전례 전통). HIG가 권하는 본문 산세리프 대신이다.
- **frosted glass는 아래쪽과 위에 겹쳐 뜨는 표면에 쓴다**(오디오 바, 절 선택 바, 검색 스크림의 `backdrop-filter: blur`). **헤더만** 솔리드로 두고 스크롤 elevation(`--shadow-3`)으로 깊이를 보인다. iOS 툴바 색 자동 추출과 PWA status bar가 따라오지 않는 문제를 피하기 위해서다(ADR-025). 곧 「frosted glass를 아무 데도 쓰지 않는다」가 아니라, 위쪽과 아래쪽을 다르게 다루는 iOS HIG를 따른 것이다.

`DESIGN.md` §11에 적용과 이탈을 표로 적었다.

### 6. 테마색을 칠하는 범위를 좁힌다 (2026-06-03)

색상 스킴(`[data-color-scheme]`)이 **chrome 전체**(버튼, 링크, 포커스 링, 토글, 활성 상태 등 `--accent`를 쓰는 약 100곳)를 함께 물들이던 동작을 멈췄다. 테마색은 읽기 화면의 절제된 시그니처 강조로만 쓴다. chrome은 브랜드 없는 중립 톤으로 두어, 어떤 스킴을 골라도 본문 읽기 경험에만 영향이 가게 한다.

토큰 구조를 둘로 나눴다.
- **`--theme`**(신규): 스킴을 따르는 유일한 강조색이다. 진한 채도로 맞추고, 정한 곳에서만 참조한다. 기존 `--accent`의 스킴별 값을 그대로 이어받았다(네이비/빨강/초록/보라 × 라이트/다크).
- **`--accent` / `--accent-light`**: 이제 **고정 중립 차콜/회색**이다(라이트 `#3a3a42` / 다크 `#b8b8c2`). `[data-color-scheme]` 블록에서 더는 덮어쓰지 않으므로, 어떤 테마색을 골라도 chrome 톤은 그대로다. 라이트/다크 전환만 따른다.
- 기존 `--verse-num` · `--paragraph-mark`(스킴별로 옅게 만든 변형) 토큰은 지우고 `--theme`로 합쳤다. 사용자가 「진한 채도로 통일」로 정했다. 절 번호와 단락 기호가 전보다 또렷해졌다.

구현은 `--accent`를 쓰는 곳을 건드리지 않고(저절로 고정된다), 정한 곳만 `--theme`로 다시 가리켜 회귀를 줄였다. DESIGN.md §2를 고쳤다.

**다크 대비 보정:** `--accent`가 다크에서 밝은 회색(`#b8b8c2`)이 되면서, accent 채움 위에 `color: #fff`를 쓰던 chrome 컨트롤(toolbar, 팝오버, 장 격자, 이어 읽기 배너, 검색 쪽 넘김 등 약 17곳)의 흰 글자 대비가 무너졌다. 이것을 코드에 이미 많이 쓰이던 **`color: var(--bg)`**로 맞췄다. 라이트에서는 크림, 다크에서는 네이비로 저절로 뒤집혀 양쪽 모두 AA를 확보한다. 빨간 파괴 동작 버튼(삭제, 캐시 비우기)만 `#fff`를 유지한다(Bugbot 리뷰 PR #180 반영).

**테마색을 칠하는 곳은 그 뒤 몇 번 바뀌었다.**
- 2026-06-03: 절 번호, 단락 기호, FAB, 오디오 플레이어의 네 곳으로 정했다.
- 2026-06-05: 오디오 플레이어(재생 버튼 배경, 진행바 채움, thumb와 thumb 링, 재생 속도 버튼 테두리, 글자, 호버)를 `--accent`(고정 중립 차콜)로 바꿨다. 오디오 바는 아래쪽 chrome 표면(frosted glass)에 얹힌 컨트롤이라, 스킴의 시그니처보다 chrome 톤을 맞추는 편이 자연스럽다고 보았다. 재생 버튼 아이콘은 그대로 `--bg`라 차콜과 밝은 회색 배경 양쪽에서 대비를 지킨다. `css/style.css`의 `.audio-play-btn`·`.audio-progress`(채움·`::-webkit-slider-thumb`·`::-moz-range-thumb`)·`.audio-speed-btn`에서 `--theme`를 `--accent`로 바꿨다. FAB는 ADR-030(모핑 탭 바)에서 검색 FAB를 모두 지우면서 **이미 없어진** 항목이었다(문서에만 남아 있었다). 그래서 그때 테마색은 **절 번호와 단락 기호 두 곳에만** 남았다. DESIGN.md §2를 고쳤다.
- 2026-06-09(1.6.0, #248): 오디오 재생 버튼과 이어 읽기 배너의 채움을 다시 `--theme`로 되돌렸다. 글래스 바 위의 컬러 강조점과 주요 행동(CTA) 배너로 쓰기 위해서다(`css/style.css`의 두 규칙 주석).
- 교회력과 전례독서를 더하면서(ADR-037, ADR-038) 응송과 계응 표시(`.responsory-mark`, `.versicle-mark`)와 전례독서의 꺾쇠(`.lect-bracket`)도 `--theme`를 쓴다.
- 읽기 본문과 따로, 하단 탭 바는 활성 탭과 검색, 접힌 홈 아이콘에 `--theme`를 시그니처로 쓴다. 이것은 ADR-030의 탭 바 결정이고, 이 절의 읽기 본문 범위와 상관없다.

지금 `DESIGN.md` §2는 읽기 본문의 테마색을 절 번호와 단락 기호 두 곳으로 적고, 오디오 플레이어는 2026-06-05에 뺐다고 적는다. 위의 2026-06-09 이후 변경이 반영되지 않았다. 나중에 바뀐 코드가 기준이므로 `DESIGN.md`를 코드에 맞춘다(known-issues §28).

### 7. 토큰을 전부 쓴다 — 스케일에 맞춘다 (2026-06-03)

§3은 「값이 정확히 같은 곳만」 먼저 바꾸는 방식이었다. 뒤의 UI 리팩터링에서 **그때그때 정한 값을 가장 가까운 토큰으로 모두 맞춰**, `css/style.css` 전체가 토큰을 따르게 했다(사용자 합의 「스케일 스냅」). 토큰과 정확히 같지 않던 값은 조금씩 바뀌었다(시각 회귀는 작다).

- **타이포**: font-size 108곳을 `--font-*`로, line-height를 `--leading-*`로 바꿨다.
- **간격**: margin/padding/gap 193곳을 `--space-*` 8pt(px)로 바꿨다. calc/env/위치 지정, 그리드를 넘는 값, 기능상 남겨 둔 값(3rem, 6rem 등), 읽기 칼럼 패딩은 조심스럽게 뺐다.
- **반경**: 34곳을 `--radius-*`로 바꿨다. 아주 작은 값(2px 손잡이, 1px 진행바)은 그대로 두었다.
- **elevation**: 토큰과 정확히 같은 것만 `--shadow-*`로 바꿨다(나머지는 포커스 링과 여러 겹 직접 만든 그림자). 이 부분은 뒤에 §9가 넓혔다.
- **모션**: 토큰을 실제 쓰임에 맞게 고친 뒤 맞췄다. `--duration-fast`를 0.18에서 **0.15s**로 바꾸고, `--duration-instant(0.1)`·`--ease-standard(cubic-bezier(0.4,0,0.2,1))`를 새로 두었다. 지속 시간 64줄을 맞췄다. CSS 기본 `ease`, 스피너, 한 번만 쓰는 곡선은 그대로 두었다.
- **새 토큰** `--icon-btn-touch(2.45rem)`: rem 스케일의 헤더 아이콘 상자다(18px 루트에서 약 44px, Dynamic Type을 따른다). `.title-back-btn`·`.title-bookmark-btn`·`#cite-sheet-back`·`#cite-sheet-close`가 함께 쓴다. 고정 px인 `--touch-target`과 역할이 다르다.

함께 고친 버그: 인용 시트 머리의 높이가 back 버튼을 켜고 끌 때 바뀌던 문제를, 닫기 버튼을 `--icon-btn-touch`로 맞춰 해결했다(HIG 44px 터치 영역도 만족한다). DESIGN.md §3·4·5·8·9를 고쳤다.

### 8. DESIGN.md 문서 정리 — PWA 실행 환경, 상태, theme-color (2026-06-06)

코드에는 이미 있지만 권위 문서(`DESIGN.md`)에 빠져 있던 영역을, 토큰 정리와 함께 문서에 적어 하나뿐인 기준(SSOT)과 코드의 차이를 메웠다. 새 결정이 아니라 **이미 있는 구현을 문서에 적은 것**이다.

- **§2 danger 표면 변형 토큰**: `--danger-text`/`--danger-border`(다크에 맞춰 바뀐다)를 표와 규약에 반영했다(바로 앞 커밋의 토큰을 문서에 적었다).
- **§2 상태바 색상(theme-color)**: `index.html`의 `media`로 나뉜 meta 두 개(첫 그리기의 기본값)와, `settings-ui.js` `updateThemeMetaColor()`가 둘을 같은 값으로 덮어써 명시 토글을 반영하는 설계를 적었다. **theme-color는 `--bg`를 따르고 스킴과 상관없다**(chrome 중립).
- **§6 상태 컴포넌트**: 로딩(`.loading`), 오류(`.error`, `--danger-text`), 빈 상태(`.search-empty-state`·`.bm-empty`), 업데이트 토스트(`#sw-update-toast`)를 목록에 더했다.
- **새 §12 PWA 실행 환경**: 실행 모드(browser/standalone/iOS, `install.js`가 기준), 네트워크와 오프라인, 서비스 워커 업데이트 흐름(ADR-021), **일부러 들이지 않은 칸**(전체 스켈레톤 로더, 명시적 오프라인 표시)을 적었다.
- §11 HIG 표에 행을 더했다(PWA 상태바 동기화, 실행 모드에 맞추기의 2행).

코드 변경은 없다(문서와 ADR만). 참조한 토큰, 클래스, ID, 함수 이름은 `css/style.css`, `js/`와 대조해 확인했다.

### 9. elevation을 모두 단계에 맞추고, 허용한 이탈을 문서에 적는다 (2026-06-06)

§7(2026-06-03)은 elevation을 **「토큰과 정확히 같은 것만」** `--shadow-*`로 바꾸고, 나머지 직접 만든 그림자는 그대로 두었다. DESIGN.md를 하나뿐인 권위로 **엄격히 따른다**는 방침에 따라, 남아 있던 직접 적은 그림자 값 **17곳을 가장 가까운 단계로 모두 맞췄다**(시각 변화를 받아들였다. 이 영역에서는 §7의 「정확히 같은 것만」을 넘어섰다).

- **맞춘 단계**: 토글 노브, 구분 탭 인디케이터, 오디오 재생(쉬는 상태)은 `--shadow-1`. 장 팝오버, 당겨서 새로 고침, 업데이트 토스트, hover로 들리는 효과는 `--shadow-2`. 주석 툴팁, 코치마크, 끌 때의 그림자는 `--shadow-3`. 모바일 시트는 `--shadow-sheet`. 구분 탭 인디케이터의 **다크 그림자 덮어쓰기는 지웠다**(토큰이 다크에서 저절로 짙어진다).
- **새 토큰 `--shadow-drawer`**(`-4px 0 24px`): 데스크톱 사이드 패널(인용 시트, 북마크 드로어)은 오른쪽에 붙어 있어 그림자가 **왼쪽으로** 가야 하는데, 다섯 단계에는 그 방향이 없었다. 단계로 해결할 수 없는 경우라 **토큰을 하나 새로 두고** DESIGN.md §5에 적었다. 같은 값을 쓰던 두 패널을 이 토큰으로 맞췄다(중복 제거).
- **다른 축의 허용한 이탈을 DESIGN.md에 적는다**: 단계에 맞출 수 없는(단계와 축이 다른) 값을 「지금 없음」이나 「예외」가 아니라 **명시적으로 허용한 것**으로 적었다. 아주 가는 반경(트랙과 thumb의 `1-2px`, `--radius-xs` 바닥보다 작다, §5), 본문 인라인 표시의 `em` 상대 크기(칩, ※ 앵커, 교차 참조, `kbd`, §3), 계속 돌거나 한 번 도는 keyframe 애니메이션 주기(스피너 0.7-0.9s, 런치 페이드 2s, §9)다.

남은 box-shadow 값은 elevation이 아닌 관용구뿐이다(포커스 링 `color-mix(--accent …)`, 스와치 윤곽 링, 활성 안쪽 막대, `--glass-inset`). `--bg`를 따르는 theme-color, danger 채움 위의 `#fff`(유일한 예외), division-tab의 무채색, `#1a1a2e`(런치와 accent 글자) 등은 §2에 이미 적은 의도된 이탈임을 확인했다. 유닛과 tsc에는 영향이 없고(CSS와 문서만), DOM이 그대로라 e2e에도 영향이 없다.

### 10. iOS의 자동 글자 확대를 막는다 — rem 기준 하나로 (2026-06-10)

§2는 타이포를 rem으로 두어 「글자 크기 설정이 루트 폰트를 바꾸면 전체가 함께 커지고 작아지게」 했다. 그런데 `text-size-adjust`를 정하지 않아, iOS Safari가 기본값(auto)으로 **가로 모드에서 본문 덩어리만 저절로 키우고** 있었다. rem인 절 번호(`--font-2xs`)와 em인 인라인 표시(`.cite-chip` 0.78em · `.parallel-anchor`/`.note-anchor--variant` 0.65em)는 따라 커지지 않아 크기가 어긋났고, 본문은 한눈에 들어오지 않을 만큼 커졌다(사용자 보고).

`html`에 `text-size-adjust: 100%`(와 `-webkit-` 접두)를 넣어 자동 확대를 끈다. 이제 타이포 스케일은 §2의 뜻대로 **rem 기준(루트 폰트와 글자 크기 설정) 하나로만** 움직이고, 세로와 가로 모드가 같다. 가로 모드에서 저절로 커지던 시인성은 없어지지만 글자 크기 설정으로 대신하고, 그때는 본문, 절 번호, 표시가 비율을 지키며 함께 커진다. `none`이 아니라 `100%`라 사용자의 핀치 줌은 그대로다(WCAG 2.1 AA · 1.4.4). DESIGN.md §3 규약에 반영했다. CSS 한 줄 변경이라 유닛과 tsc에 영향이 없고, DOM이 그대로라 e2e에도 영향이 없다. 실기기 가로와 세로 확인을 권한다.

## 적응형 내비게이션 (모바일 구현 완료 — ADR-029)

처음 계획은 화면 내비를 HIG 적응형 방식으로 바꾸는 것이었다. **모바일(≤768px) 하단 탭 바**(왼쪽부터 홈, 검색, 북마크, 노트, 설정의 5탭, `--tabbar-h` 49px, safe-area, 활성=`--accent`)와 **데스크톱(≥769px) 사이드바**(`--sidebar-w` 260px)다. `노트`는 아직 없는 새 기능 자리였다. 지금 위쪽 헤더의 아이콘 버튼과 검색 FAB가 이 목적지들로 옮겨 갈 예정이었다.

이 ADR에서는 **레이아웃 토큰을 예약하고 `DESIGN.md` §7에 규격을 적는 데까지만** 했다. 실제 탭 바와 사이드바, 라우팅 재편, 노트 기능은 따로 ADR과 PR로 진행하기로 했다. 그래서 이번 헤더 정리는 44pt 터치 영역과 토큰화 같은 무난한 수준에 그치고 구조는 건드리지 않았다(곧 바뀔 영역에 지나치게 쏟지 않으려는 것이다).

모바일 하단 탭 바는 [ADR-029](029-mobile-tab-bar.md)로 구현했다(2026-06-03). 4탭(홈, 검색, 북마크, 설정), 전체 화면 라우트 뷰, iOS 2026 Liquid Glass다. `노트`와 데스크톱 사이드바는 뒤의 일이다. 실제 구현은 이 계획과 몇 가지가 다르다. 탭 수(5에서 4), 활성 표시(아이콘 `--theme`와 56px 원형 인디케이터의 테마색 틴트, ADR-030 후속⁴. 처음의 `--accent` 중립에서 테마색으로 옮겼다), 스크롤할 때 줄이기는 채택하지 않음(iOS 27 회귀 반영) 등이다. 권위는 ADR-029와 030이다.

## 검토한 대안

- **전면 리디자인(HIG 정석)**: 타이포, 간격, 컴포넌트 모양을 적극적으로 다시 설계한다. 효과는 크지만 4,800줄 CSS의 시각 회귀 위험이 높고 여러 ADR을 고쳐야 한다. 토큰 층과 점진 치환으로 같은 일관성을 낮은 위험으로 얻을 수 있다고 보고 미뤘다.
- **문서만 쓰기(코드 무변경)**: 권장 스케일을 `DESIGN.md`에만 적으면 코드와 문서가 바로 어긋난다. 토큰을 `:root`에 실제로 넣어 코드가 따르게 했다.
- **본문까지 시스템 산세리프로 통일**: iOS 네이티브 느낌은 강해지지만 성경 본문의 전통적 가독성이 약해진다. 본문 Serif를 유지하기로 했다.
- **rem 기반 간격 유지**: 글자 크기 설정에 따라 간격도 함께 커진다. 그러나 8pt 그리드와 어긋나고, 레이아웃이 콘텐츠 크기에 따르는 HIG답지 않은 동작이다. px 8pt로 나눴다.
- **값이 같은 곳만 토큰으로 바꾸기 (2026-06-03까지)**: 처음 방식이다(§3). 채택 안 함 2026-06-03 · 이유: 뒤의 UI 리팩터링에서 사용자와 「스케일 스냅」에 합의해, 그때그때 정한 값을 모두 가장 가까운 토큰으로 맞췄다(§7). elevation은 2026-06-06에 같은 방향으로 넓혔다(§9).

## 영향

- `css/style.css`: `:root`(와 다크)에 토큰 블록을 더하고, 대표 컴포넌트부터 차츰 바꿨다. 토큰을 더하기만 해서 값이 그대로이므로 시각 회귀가 없다. 다크 모달과 시트의 그림자는 elevation 일반화로 조금 더 짙어졌다(의도한 개선).
- 새 `DESIGN.md`(루트): 디자인의 하나뿐인 권위 기준.
- `docs/architecture.md` 부록 A · `CLAUDE.md` 현재 상태 갱신.
- 유닛 테스트와 tsc에는 영향이 없다(CSS와 상관없다). DOM 구조가 그대로라 e2e 영향도 적다.
