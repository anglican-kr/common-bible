# ADR-048: 휴대폰의 검색 입력창은 검색 화면 위쪽에 둔다

- 상태: 승인됨 — 구현 중
- 관련: ADR-030 §3, §6(검색 모핑과 하단 입력. 이 ADR이 대체한다), ADR-033 D3(책 선택의 「적용」과 포커스), ADR-031(탭별 위치 복원), ADR-014(최근 검색)

## 요약

1. **입력창의 자리**(§1): 휴대폰의 검색 입력창은 검색 화면 위쪽의 입력창 하나다. 탭 바의 검색 원형은 입력창으로 바뀌지 않는다(모핑하지 않는다).
2. **검색 원형을 누르면**(§2): 검색 화면이 아닌 곳에서는 검색 화면으로 가기만 하고, 검색 화면에서는 위쪽 입력창으로 포커스를 옮긴다. 포커스가 입력창으로 옮겨 갈 때까지 키보드는 뜨지 않는다.
3. **키보드 내리기 단추**(§3): 두지 않는다. 키보드는 검색하거나(Enter) 입력창 밖을 누르면 내려간다.
4. **검색어 지우기**(§4): 위쪽 입력창의 ⊗는 검색어를 지우고 키보드를 내리며, 포커스를 같은 입력창의 깔때기(책 선택)로 옮긴다.

## 배경

ADR-030 §3은 검색 원형을 누르면 탭 바가 하단 입력창으로 바뀌고(모핑), 키보드가 뜨면 입력창을 키보드 위로 올리기로 했다. 그런데 아이폰에서 최근 검색 화면의 입력창을 누르면, iOS가 키보드에 가려지는 입력창을 보이려고 페이지를 위로 밀어 화면이 튀었다가 돌아왔다. 키보드가 뜨기 전에 기억한 높이로 입력창을 먼저 올려 보았으나 아이폰에서 그대로였다. 위쪽 입력창은 키보드에 가려지지 않아 iOS가 페이지를 밀 까닭이 없다. 검색 화면에는 이미 위쪽 입력창이 있고, 지금은 모핑 중에만 숨긴다.

## 결정

### 1. 입력창의 자리

- 휴대폰의 검색 화면은 위쪽 입력창(책 선택 깔때기, 책 칩, 입력, 검색어 지우기)을 늘 보인다. 하단 탭 바는 다른 화면과 같은 모양이고, 검색 원형이 지금 탭으로 표시된다.
- 하단 입력창, 키보드 위로 입력창을 올리는 처리, 검색 모드(모핑)를 없앤다.
- 까닭: 입력창이 화면 위쪽에 있으면 키보드에 가려지지 않아 iOS가 페이지를 밀지 않는다. Apple Music도 검색 입력창을 위에 둔다. 엄지가 닿기 어려운 불편은 남는다.

### 2. 검색 원형을 누르면

| 지금 있는 곳 | 검색 원형을 누르면 |
| --- | --- |
| 검색 화면이 아닌 곳 | 검색 화면으로 간다. 마지막 검색(검색어와 결과, 스크롤 위치)이 있으면 그 화면이다(ADR-031). 입력창에 포커스를 주지 않아 키보드가 뜨지 않는다 |
| 검색 화면 | 위쪽 입력창으로 포커스를 옮겨 키보드를 띄운다. 결과를 내려 보던 중이면 맨 위로 올린 뒤 옮긴다 |

- 검색 화면을 그릴 때 입력창에 저절로 포커스를 주지 않는다. 키보드는 사용자가 입력창이나 검색 원형을 눌러 포커스가 입력창으로 옮겨 갈 때만 뜬다.
- 책 선택 시트의 「적용」은 ADR-033 D3대로다. 검색어가 없으면 다시 그린 위쪽 입력창에 포커스를 주고, 찾았으면 다시 그린 입력창의 깔때기에 포커스를 준다.
- 까닭: 다른 화면에서 검색 원형을 누르는 것은 검색 탭으로 가는 일이라 다른 탭과 같게 동작한다. 지난 결과를 보러 왔을 때 키보드가 결과를 가리지 않는다. iOS는 누른 동작과 같은 실행 흐름에서 포커스를 줄 때만 키보드를 띄우므로(ADR-030 §6), 검색 화면에 이미 있는 입력창으로 포커스를 옮기는 두 번째 누름이 키보드를 확실히 띄운다.

### 3. 키보드 내리기 단추

- 하단 입력창 오른쪽의 키보드 내리기 단추(X)를 없앤다. 위쪽 입력창 옆에 「취소」 단추도 두지 않는다.
- 까닭: 키보드는 검색하면(Enter) 내려가고, 결과 화면을 누르거나 스크롤해도 내려간다. 입력창이 위에 있어 키보드가 결과를 가리는 일이 드물다.

### 4. 검색어 지우기

- 위쪽 입력창의 ⊗는 검색어를 지우고 최근 검색 화면으로 돌아가며 키보드를 내린다. 입력 중에 지워도 같다. 포커스는 다시 그린 입력창의 깔때기로 옮긴다.
- 까닭: 입력 중에 지우는 것도 검색을 그만두는 뜻이다. 지우기 단추는 검색어가 없으면 숨겨져 포커스가 그 자리에 남을 수 없고, 깔때기는 「적용」이 포커스를 돌리는 자리와 같다(ADR-033 D3). 하단 입력창에서 정한 동작(ADR-030 §3)을 옮긴 것이다.

## 검토한 대안

- **하단 입력창을 두고 키보드가 뜨기 전에 기억한 높이로 올리기**: 채택 안 함 2026-11-19 · 이유: dev에 올려 아이폰에서 보니 화면이 튀는 동작이 그대로였다. 원인을 가리려면 진단판이 필요했고, 위쪽 입력창은 원인과 상관없이 튀지 않는다 · 재검토: 하단 입력을 다시 쓰자는 의견이 나오면.
- **검색 원형을 누르면 검색 화면으로 가며 바로 입력창에 포커스 주기**: 채택 안 함 2026-11-19 · 이유: 위쪽 입력창은 화면을 그린 뒤에 생겨, iOS에서는 첫 누름에 키보드가 뜨지 않을 수 있다. 지난 결과를 보러 왔을 때도 키보드가 결과를 가린다 · 재검토: 없음.
- **위쪽 입력창 옆에 「취소」 단추 두기(iOS 앱의 방식)**: 채택 안 함 2026-11-19 · 이유: 키보드는 검색하거나 화면을 눌러 내릴 수 있고, 단추가 입력창의 폭을 줄인다 · 재검토: 키보드를 내리기 어렵다는 의견이 나오면.
