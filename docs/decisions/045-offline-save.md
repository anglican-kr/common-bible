# ADR-045: 오프라인 저장은 성서 본문과 교회력 자료를 한 스위치로 저장한다

- 일시: 2026-11-18
- 상태: 승인됨 — 구현 완료 (2026-11-18)
- 관련: ADR-021(콘텐츠 해시 매니페스트), ADR-041 §1(설정 섹션), ADR-041 §7(ⓘ 설명), ADR-001(오프라인 우선), ADR-037 §5(전례독서 검색 색인)

## 요약

1. **저장하는 자료**(§1): 성서 본문, 성서 검색 자료, 교회력 자료를 함께 저장한다. 오디오와 앱이 아직 쓰지 않는 성무일과 독서표는 넣지 않는다.
2. **설정의 줄**(§2): 시스템 섹션의 「백업 & 동기화」 위에 「오프라인 저장」 스위치 한 줄을 두고, 줄 아래에 크기와 진행을 숫자로 적는다.
3. **받기**(§3): 켜면 아직 저장하지 않은 파일만 한 번에 6개씩 받는다. 앱을 닫거나 인터넷이 끊기면 멈추고, 다시 열거나 연결되면 남은 것만 받는다.
4. **자료가 바뀌었을 때**(§4): 켜 둔 동안에는 앱을 열 때 고친 파일만 다시 받는다.
5. **저장 공간**(§5): 받기 전에 남은 공간을 확인하고, 모자라면 스위치를 끈 채 알린다. 켤 때 브라우저에 오래 보관해 달라고 요청한다. 아이폰 Safari 탭에서는 홈 화면 앱에서 켜라고 안내한다.
6. **끄기**(§6): 확인 창에서 「삭제」를 누르면 저장한 자료를 지우고 끈다. 「캐시 초기화」도 스위치를 끈다.
7. **저장과 동기화**(§7): 스위치는 기기마다 따로이고 동기화하지 않는다.
8. **크기 목록**(§8): 데이터 저장소가 파일마다 저장 크기와 압축 크기를 적은 목록을 매니페스트와 따로 만든다.

## 배경

장 본문, 검색 자료, 교회력 자료는 처음 쓸 때 서비스 워커가 기기에 저장한다(ADR-021). 그래서 한 번도 열지 않은 장과 날은 오프라인에서 열리지 않는다. 온라인에서 한 번도 열지 않은 캘린더를 오프라인에서 열면 「교회력 자료를 불러오지 못했습니다」가 나온다. 오프라인에서 쓰려는 사람이 미리 모두 받아 둘 방법이 없었다(known-issues §43).

데이터가 고쳐지면 앱은 고친 파일을 지워 두고, 그 파일을 처음 쓸 때 다시 받는다. 그래서 한 번 연 장도 데이터가 고쳐진 뒤에는 오프라인에서 열리지 않는다.

## 결정

### 1. 저장하는 자료

- 성서 본문(`/data/bible/`), 성서 검색 자료(`search-ot.json`, `search-nt.json`, `search-dc.json`, 성시의 `search-lit.json`, ADR-046 §6), 교회력 자료(`/data/lectionary/`)를 함께 저장한다. 받을 파일과 크기는 크기 목록(`bible-sizes.json`, §8)에서 얻는다.
- 성무일과 독서표(`office-readings.json`)는 앱이 아직 쓰지 않아 빼고, 성무일과 화면을 만들 때 더한다.
- 오디오는 넣지 않는다. 지금처럼 재생할 때 받는다.
- 까닭: 전례독서 화면은 독서 본문을 성서 장 파일에서 읽는다. 교회력 자료만 저장하면 오프라인에서 날은 열려도 독서 본문이 없다. 검색 자료를 함께 저장해야 인터넷 없이도 성서를 찾는다. 전례독서 검색의 색인은 교회력 자료에 있다. 오디오는 따로 저장 한도를 두고 오래 듣지 않은 파일부터 지우므로(오디오 캐시), 모두 받아 두는 일과 맞지 않는다.

### 2. 설정의 줄

- 시스템 섹션에서 「백업 & 동기화」 위에 「오프라인 저장」 스위치 한 줄을 둔다. 브라우저 탭으로 열어 「앱 설치」 줄이 보이면 그 아래다. 데스크톱의 설정 팝오버도 같다.
- 줄 아래의 글에 상태를 적는다. 크기는 「용량」이나 「데이터 크기」 같은 말 없이 숫자만 적는다. 숫자는 기기에 저장되는 크기(압축을 푼 크기)이고, 1MB를 1,000,000바이트로 세어 소수 첫째 자리까지 적는다.

| 상태 | 스위치 | 줄 아래의 글 |
| --- | --- | --- |
| 꺼짐 | 끔 | 성서 본문과 교회력 자료 17.5MB |
| 저장 중 | 켬 | 저장 중 7.0MB / 17.5MB(진행 막대) |
| 모두 저장됨 | 켬 | 17.5MB 모두 저장됨 |
| 인터넷 연결이 없음 | 켬 | 인터넷에 연결되면 이어서 저장합니다. 7.0MB / 17.5MB(멈춘 진행 막대) |
| 서버에서 받지 못함 | 켬 | 일부 자료를 받지 못했습니다. 앱을 다시 열면 이어서 저장합니다. 7.0MB / 17.5MB(멈춘 진행 막대) |
| 공간이 모자람 | 끔 | 기기의 저장 공간이 모자라 저장하지 못했습니다. 공간을 비운 뒤 다시 켜 주세요.(경고 색) |

- ⓘ 설명(ADR-041 §7의 부품)은 「성서 본문과 검색 자료, 캘린더와 전례독서에 쓰는 교회력 자료를 기기에 저장해 인터넷에 연결되지 않아도 모든 장과 모든 날을 볼 수 있게 합니다. 성서 본문 9.1MB, 검색 자료 6.3MB, 교회력 자료 2.1MB이고, 받을 때는 압축되어 약 5MB입니다. 오디오 파일은 재생할 때 다운로드됩니다.」다. 크기는 §8의 목록에서 계산한다. 「약 5MB」는 압축 크기의 합을 MB 단위의 정수로 반올림한 값이다.
- 아이폰 Safari 탭(홈 화면 앱이 아닌 창)에서는 설명의 끝 문장 앞에 「Safari에서 7일 넘게 열지 않으면 저장한 자료가 지워질 수 있습니다. 홈 화면에 추가한 앱에서 켜면 오래 보관됩니다.」를 넣는다.
- 스크린 리더에는 받기의 시작, 끝, 멈춤, 실패를 알린다. 시작은 「오프라인 저장을 시작합니다」이고, 나머지는 줄 아래의 글과 같은 문장이다. 진행 막대는 지금 값을 읽을 수 있는 진행 표시 요소(`<progress>`)이고, 스위치는 줄 아래의 글을 설명으로 갖는다.
- 까닭: 한 줄이 함께 저장하므로 교회력 자료만 켜고 성서 본문을 빠뜨리는 일이 없다. 크기를 적으면 받기 전에 얼마나 드는지 안다. 줄 아래의 숫자는 남은 공간의 확인(§5)과 같은 크기라야 공간이 모자랄 때의 안내와 어긋나지 않고, 받을 때의 양은 그보다 작아 설명에 따로 적는다. 1MB를 1,000,000바이트로 세는 것은 아이폰의 저장 공간 화면과 같은 단위다. 받지 못한 까닭이 인터넷인지 서버인지에 따라 다시 받는 때가 달라 글을 나눈다.

### 3. 받기와 이어 받기

- 스위치를 켜면 목록 가운데 아직 저장하지 않은 파일만 받는다. 읽으며 이미 저장된 장은 다시 받지 않고, 진행은 이미 저장한 크기부터 센다.
- 한 번에 6개씩 받는다.
- 앱이 직접 받아 저장하고, 저장이 끝난 파일만 진행에 센다.
- 받는 동안 설정을 닫거나 다른 화면으로 가도 계속 받는다.
- 앱을 닫으면 멈추고, 스위치가 켜져 있으면 앱을 다시 열 때 남은 것만 받는다. 인터넷이 끊기면 멈추고, 연결되면 남은 것만 이어서 받는다. 인터넷이 없을 때 켜도 「인터넷 연결이 없음」 상태로 기다린다.
- 서버가 오류로 응답한 파일은 그 자리에서 다시 시도하지 않고 멈춘다. 다음에 앱을 열 때 남은 것을 다시 받는다.
- 까닭: 아이폰 Safari와 Firefox에는 앱이 화면에 없을 때 이어 받는 기능(Background Fetch)이 없다. 한꺼번에 1,500개를 요청하면 그사이 사용자가 연 장의 요청이 뒤로 밀린다. 서비스 워커는 받은 파일을 저장하는 일을 기다리지 않아, 공간이 모자라 저장에 실패해도 앱이 알 수 없다. 서버 오류는 앱이 고칠 수 없으므로 되풀이해 요청하지 않고, 다시 받는 때를 앱을 열 때(§4)로 둔다.

### 4. 자료가 바뀌었을 때

- 스위치가 켜져 있으면, 앱을 열 때 매니페스트를 견주어 바뀐 파일을 지운 뒤(ADR-021) 지운 파일과 새로 생긴 파일을 받는다. §3과 같은 받기이고 줄 아래의 글도 같다.
- 까닭: 켜 둔 동안에는 모든 장과 날이 오프라인에서 열려야 한다. 견주기 전에 받으면, 막 받은 새 파일을 바뀐 파일로 보고 지운다.

### 5. 저장 공간과 오래 보관 요청

- 받기 전에 남은 공간을 확인한다(`navigator.storage.estimate()`). 남은 파일을 받기에 모자라면 받지 않고, 스위치를 끈 채 「공간이 모자람」을 보인다. 받는 중에 저장이 공간 부족으로 실패해도 같다. 이 확인을 하지 못하는 브라우저(iOS 16 이하)에서는 저장이 실패할 때 안다.
- 공간이 모자라 멈춰도 그때까지 받은 파일은 지우지 않는다. 다시 켜면 남은 것만 받는다.
- 스위치를 켤 때 브라우저에 저장한 자료를 오래 보관해 달라고 요청한다(`navigator.storage.persist()`). Firefox는 이때 허락을 묻는 창을 띄운다. 결과는 화면에 적지 않는다.
- 까닭: 받은 파일은 읽으며 저장된 장과 같은 곳에 있어 가를 수 없으므로, 지우면 읽던 장까지 지워진다. 공간을 비우려면 「캐시 초기화」를 쓴다. 기기의 공간이 모자라면 브라우저가 사이트의 자료를 지울 수 있는데, 오래 보관을 허락받은 자료는 지우지 않는다. 허락 창이 스위치를 켠 바로 그때 떠서 무엇을 묻는지 알기 쉽다. Safari와 Chrome은 사용자에게 묻지 않고 스스로 정하므로, 결과를 적어도 사용자가 할 일이 없다. 아이폰 Safari는 7일 동안 열지 않은 사이트의 자료를 지우지만 홈 화면 앱의 자료는 지우지 않는다. 그래서 Safari 탭에서만 안내한다. 브라우저마다의 규칙과 출처는 `docs/topics/cache-release.md` §43에 있다.

### 6. 끄기와 캐시 초기화

- 스위치를 끄면 확인 창을 띄운다. 북마크를 삭제할 때의 확인 창과 같은 부품이다. 제목은 「오프라인 저장 끄기」, 본문은 「기기에 저장한 성서 본문과 교회력 자료 17.5MB를 삭제할까요? 삭제한 뒤에는 인터넷에 연결되어야 이 자료를 볼 수 있습니다. 북마크와 설정은 지우지 않습니다.」, 단추는 「취소」와 빨간 「삭제」이고, 창이 열리면 포커스는 「취소」에 있다. 본문의 크기는 지금 저장된 크기이고, 받는 중이면 그때까지 받은 크기다.
- 창이 열린 동안 스위치는 켜진 채다. 「취소」는 아무것도 바꾸지 않고, 받던 것은 계속 받는다. 「삭제」는 받기를 멈추고 §1의 자료를 기기에서 지운 뒤 스위치를 끈다. 읽으며 저장된 장도 함께 지워진다.
- 시스템 섹션의 「캐시 초기화」는 스위치도 끈다.
- 까닭: 저장을 끄면 저장한 것이 없어지는 것이 스위치의 뜻과 맞다. 지우면 되돌릴 수 없어 확인한다. 「캐시 초기화」는 기기에 저장한 자료를 모두 지우는 동작이다. 스위치가 켜진 채면 앱을 다시 열자마자 모두 다시 받아 초기화와 어긋난다.

### 7. 저장과 동기화

- 스위치의 상태는 기기에 저장하고, 백업 & 동기화로 보내지 않는다.
- 까닭: 받은 자료는 그 기기에만 있다. 동기화하면 다른 기기가 묻지 않고 받기를 시작한다. 아이폰에서는 Safari 탭과 홈 화면 앱이 저장한 자료를 나눠 쓰지 않아, 같은 기기 안에서도 스위치가 따로다.

### 8. 크기 목록

- 데이터 저장소의 매니페스트 생성기(`scripts/gen_manifests.py`)가 `bible-manifest.json`과 같은 파일들의 크기를 `bible-sizes.json`에 적는다. 파일마다 저장 크기(`sizes`, 압축을 푼 바이트 수)와 서버와 같은 수준(6)으로 gzip 압축한 크기(`gzip_sizes`)다. `bible-manifest.json`은 바꾸지 않는다.
- 앱은 이 목록을 오프라인 저장의 줄을 그릴 때와 받을 때만 읽는다.
- 까닭: 받기 전에 크기를 알아야 줄 아래의 글과 공간 확인을 할 수 있다. 매니페스트는 앱을 열 때마다 받아 기기에 저장하므로, 크기를 넣으면(1.3배가 된다) 오프라인 저장을 쓰지 않는 기기도 그만큼 더 받는다. 매니페스트의 해시 칸(`entries`)의 값에 크기를 섞으면 옛 앱이 모든 파일을 바뀐 것으로 보고 지운다. 압축 크기의 합은 설명의 「약 5MB」를 자료가 바뀌어도 맞게 하려고 둔다.

### 9. 구현 단계

1. 데이터 저장소 PR: 크기 목록(§8).
2. 앱 PR: 설정의 줄, 받기와 이어 받기, 바뀐 파일 다시 받기, 확인 창, ⓘ 설명의 닫기 단추 맞춤(ADR-041 §7).

## 검토한 대안

### 섹션마다 한 줄

성서 섹션에 성서 본문을, 전례독서 섹션에 교회력 자료를 한 줄씩 두는 안이다(2026-11-17 시안). 전례독서 화면이 성서 장 파일을 읽으므로, 교회력 자료만 켜면 오프라인에서 독서 본문이 없다. 두 줄의 관계를 설명해야 하고 크기도 둘로 나뉜다. 자료가 커져 나눠 받아야 할 때 다시 본다.

### 검색 자료를 빼는 안

6.0MB를 덜 받지만 인터넷 없이 성서를 찾지 못한다(2026-11-17). 검색 자료가 크게 늘면 다시 본다.

### Wi-Fi에서만 받기

연결 종류를 알려 주는 기능(Network Information API)이 Safari와 Firefox에 없어, 모든 브라우저에서 같게 동작하지 않는다(2026-11-18, MDN). 받을 때의 양은 약 5MB다. 이 기능이 Safari에 생기면 다시 본다.

### 앱을 닫아도 받기

Background Fetch는 앱을 닫아도 브라우저가 받는 기능이지만 Safari와 Firefox에 없다(2026-11-18, MDN). Safari에 생기면 다시 본다.

### 공간이 모자랄 때 받은 것을 지우기

받은 파일과 읽으며 저장된 장을 가를 수 없어 읽던 장까지 지워진다(2026-11-18). 받은 파일을 다른 저장소에 두면 같은 장을 두 번 저장하게 된다.

### 매니페스트에 크기 칸을 두기

`bible-manifest.json`에 `sizes` 칸을 더하는 안이다(2026-11-18). 매니페스트가 151KB에서 198KB로 커지고, 앱이 켤 때마다 받아 저장하는 이 파일을 오프라인 저장을 쓰지 않는 기기도 다룬다. 크기를 앱이 켤 때마다 써야 할 일이 생기면 다시 본다.
