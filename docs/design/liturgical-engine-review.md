## 1. 범위와 읽는 법

**왜 비교하나.** 대한성공회 기도서(2004)의 교회력 규칙을 코드로 옮긴 공개 구현은 없다. GitHub 안팎을 뒤져 나온 것은 로마가톨릭(romcal · calendarium-romanum · LiturgicalCalendarAPI), 미국·북미 성공회(dailyoffice2019 · lectionarypage), 영국 성공회(Almanac for Common Worship), RCL 도구, 그리고 국내 감리회 연표뿐이다. 그래서 이 문서가 견주는 것은 **규칙의 내용이 아니라 메커니즘**이다 — 날짜를 어떻게 계산하고, 후보를 어떻게 모으고, 동률을 어떻게 깨고, 이동을 어떻게 추적하고, 그 전부를 어떻게 검증하는가.

**판정 어휘 넷.**

| 판정 | 뜻 |
|---|---|
| **채택** | 설계에 더한다. 반영 위치와 비용을 적는다 |
| **확증** | 설계가 이미 그렇게 하고 있다. 외부 근거만 얹는다 — 바꿀 것 없음 |
| **기각** | 다르게 하는 이유를 적는다. 규칙이 다르거나 이 저장소의 결정과 충돌한다 |
| **보류** | 데이터 저장소 작업이나 사제 확인이 먼저다 |

**열 의미.** 「반영 위치」는 설계서 절 번호(§4.6) 또는 미결 번호(미결17). 「비용」은 엔진 코드 · 데이터 저장소 · 테스트 · 문서·ADR 중 어디를 건드리는가.

**한 줄 결론.** 설계의 골격 — 순수 leaf 모듈, 연도 단위 이동 패스, 후보 전부 보존, 선택 봉헌의 `optional` 비참여 — 은 네 외부 구현 어느 것과 견줘도 같거나 더 정교하다. 가져올 것은 **검증 방식 · 표현 어휘 · 미결 근거** 세 갈래이고, 먼저 할 셋은 ① 1900~2100 이동 골든 덤프 ② §7 실제 연도 케이스의 JSON 픽스처화 ③ 기간 축 `spansOf(year)` 다. 재검증에서는 설계서 주장이 전부 데이터와 일치했고(본 문서 §4.1), 대신 **설계서가 아직 정하지 않은 규칙 여섯**이 드러났다(본 문서 §4.3) — 이 문서의 가장 실질적인 수확이다.

**`spansOf(year)` 를 `periods.json` 에 넣지 않는 이유.** `data/lectionary/periods.json` 의 `_meta.model` 은 「품계 비교에 참여하지 않는 겹침 표시 — 고정 본기도·전례색·품계 없음」이고 항목은 고정 `MM.DD` 다(2026-09-05 실측 1건, 그리스도인 일치 기도 주간). 보호 기간은 품계에 참여하고(합성 guard) 부활절 기준이라 그 표의 계약과 스키마 둘 다에 맞지 않는다 — 넣으려면 규칙 문법과 파서가 데이터 저장소에 생겨야 한다. romcal 도 `periods` 를 코드로 계산한다. `LITURGICAL_CORE` 안의 순수 함수 하나가 성주간 · 부활 8일 · 성탄 8일 · 승천~성령강림 전날 · 12.17~24 · 성탄절기(소재일 제외용)를 앵커에서 만들고, §6.3 ① · §6.4 · §6.5 가 그것을 함께 본다. `ResolvedDate.periods` 는 지금처럼 데이터 오버레이(배너용)로 남긴다.

> **개정 (2026-09-13)** — 「기간 축」 채택이 **설계서 §4.10 `spansOf(year)` 로 반영**됐다. 표의 「반영 위치」 열이 가리키던 「신설 제안」은 이제 실재하는 절이다. 소비자 셋(§6.3 ① 소재일 제외 · §6.4 색 가드 · §6.5 `guard`)이 각자 날짜를 비교하던 것을 그 함수 하나를 보도록 고쳤고, `ResolvedDate.periods`(데이터 오버레이)와는 다른 축임을 §4.10 이 명시한다. 체크리스트 5.6 의 정본이 「본 문서 §3.1」에서 「설계서 §4.10」으로 옮겨진다.

### 4.3 설계 공백 — 설계서가 아직 정하지 않은 규칙

각각 체크리스트(본 문서 §5) · 질문지(§6) · 후속(§7)에 연결한다.

1. **격자와 같은 좌표에 temporal 행이 겹친다.** temporal 표의 행 대부분이 `season/week/type` 을 갖는다(2026-09-05 실측 18행). 그중 **성지주일 · 대림1주일은 격자 절기 주일과 prec 2 동률**, **사계재 4행은 격자 feria 와 prec 8 동률**이다(성지주일 `lent/sunday` 2 vs 격자 사순 주일 2 · 하계재 `fast` 8 vs 격자 연중 평일 8). 승자가 색을 정하므로 결과가 갈린다 — 성지주일 홍 vs 격자 자, 하계재 자 vs 격자 녹. §5.5 는 ① 격자와 ④ 규칙 파생을 둘 다 후보로 올리고, §6.2 ④ `id` 사전순이 승자를 정한다. **공존인가 대체인가, 동률은 누가 이기나**를 §5.5 에 적어야 한다. 제안은 §3.3 의 범주 사다리 — temporal 규칙일 > 격자.
2. **12.25 세 행(성탄 낮·밤·새벽) 전부 prec 1.** `official` 은 `id` 사전순(`d1225-성탄-낮` < `밤` < `새벽`)의 우연으로 낮이 된다. 날짜 뷰의 기본 = 낮, 밤·새벽은 `proper` 대안이라는 **명시 규칙**이 필요하다 — 미결12(1:N 좁히기)와 같은 날짜다.
3. **prec 7 동률이 실재한다 — 7건.** 02.14 발렌틴 ∧ 키릴·메토디우스 · 03.01 데이빗 ∧ 삼일절 · 05.03 성 십자가 발견 ∧ 성 프란시스 수도회 · 06.09 에프렘 ∧ 콜룸바 · 08.05 도미닉 ∧ 오스왈드 · 09.04 대 그레고리 ∧ 여성선교센터 개관 · 12.31 실베스터 ∧ 위클리프. 미결6 의 「실제로 겹치는 사례가 없으면 문제도 없다」 갈래는 닫혔다 → Q5.
4. **precedence 가 null 인 temporal 행은 6.** 주의 변모 주일(E−49, 색 백) · 성 토요일 · 가정주일 · 평화통일주일 · 맥추감사주일 · 여성선교주일. 데이터 `note` 가 가정·평화통일을 「강조 주일 — 절기 주일을 밀어내지 않음」으로 정의하니 성 토요일까지 다섯은 의도다. **주의 변모 주일은 다르다** — 사순 직전 주일의 정체(변모 독서)인데 null 이면 `official` 은 격자 연중 주일이고 색은 녹이 된다. 지위 확인(본 문서 §6 부수) + §6.1 의 「`precedence: null` 후보는 collects 3건」 서술을 temporal 6행까지 넓힐 것.
5. **명절 ∧ 연중 주일.** 설이 주일인 해 2027·2030·2034·2037·2040·2050, 추석이 주일인 해 2032·2035·2039·2042 — 전부 연중 주일이다. 명절(prec 0)이 이기고 주일 후보는 `proper` 로 남아야 한다(「밀린 독서 보존」). §7 에 이 케이스가 없다 → 본 문서 5.10.
6. **미결16 「2026년 두 건」은 일곱 건이다.** 1.25 사도 바울로 회심(B, 주일) → 1.26 · 5.14 마티아 → 5.15 · 5.31 성모 방문 → 6.1 · 10.18 루가(B, 주일) → 10.19 · 12.6 성 니콜라(C, 대림2주일) → 12.7 · 12.27 사도 요한 → 12.28 · 죄 없는 어린이들 → 12.29. 그리고 **2026-12-27 이 미결17 을 지금 판정한다** — 연쇄 모델이면 요한 12.28 · 어린이들 12.29, 건너뜀 모델이면 요한 12.29 · 어린이들 12.28. 2027 을 기다릴 필요 없이 2026 교구 달력 12월로 결정된다.

```json
    { "date": "2027-12-27", "expect": { "status": "transferred_in", "id": "d1226-성-스테파노", "from": "2027-12-26", "displacedBy": "grid:christmas-1-sunday" } },
    { "date": "2027-12-29", "expect": { "status": "omitted", "id": "d1229-토마스-베켓", "displacedBy": "d1228-죄-없는-어린이들의-순교" } }
  ]
}
```

- `displacedBy` 는 **정확한 id** 로 쓴다(생략부호 금지 — 그러면 픽스처가 계약을 검증하지 못한다). 위 2027-12-26 은 성탄 후 첫 주일이라 `grid:christmas-**1**-sunday` 다 — 성탄절기 주일은 데이터에 주차가 있다(실측: `christmas/1/sunday` · `christmas/2/sunday` 가 독서·본기도 양쪽에 있다). `week: null` 일 때만 `x` 를 쓴다(성주간 평일 등).
- `skip` 은 데이터 대기(미결13), `applies.since/until` 은 기도서 개정이나 사제 확인으로 규칙이 바뀐 **발효 연도**에만 쓴다.
