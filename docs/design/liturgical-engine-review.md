## 1. 범위와 읽는 법

**왜 비교하나.** 대한성공회 기도서(2004)의 교회력 규칙을 코드로 옮긴 공개 구현은 없다. GitHub 안팎을 뒤져 나온 것은 로마가톨릭(romcal · calendarium-romanum · LiturgicalCalendarAPI), 미국·북미 성공회(dailyoffice2019 · lectionarypage), 영국 성공회(Almanac for Common Worship), RCL 도구, 그리고 국내 감리회 연표뿐이다. 그래서 이 문서가 견주는 것은 **규칙의 내용이 아니라 메커니즘**이다 — 날짜를 어떻게 계산하고, 후보를 어떻게 모으고, 동률을 어떻게 깨고, 이동을 어떻게 추적하고, 그 전부를 어떻게 검증하는가.

**판정 어휘 넷.**

| 판정 | 뜻 |
|---|---|
| **채택** | 설계에 더한다. 반영 위치와 비용을 적는다 |
| **확증** | 설계가 이미 그렇게 하고 있다. 외부 근거만 얹는다 — 바꿀 것 없음 |
| **기각** | 다르게 하는 이유를 적는다. 규칙이 다르거나 이 저장소의 결정과 충돌한다 |
| **보류** | 데이터 저장소 작업이나 사제 확인이 먼저다 |

**열 의미.** 「반영 위치」는 설계서 절 번호(설계서 §4.6) 또는 미결 번호(미결17). 「비용」은 엔진 코드 · 데이터 저장소 · 테스트 · 문서·ADR 중 어디를 건드리는가.

**한 줄 결론.** 설계의 골격 — 순수 leaf 모듈, 연도 단위 이동 패스, 후보 전부 보존, 선택 봉헌의 `optional` 비참여 — 은 네 외부 구현 어느 것과 견줘도 같거나 더 정교하다. 가져올 것은 **검증 방식 · 표현 어휘 · 미결 근거** 세 갈래이고, 먼저 할 셋은 ① 1900~2100 이동 골든 덤프 ② 설계서 §7 실제 연도 케이스의 JSON 픽스처화 ③ 기간 축 `spansOf(year)` 다 — 셋째는 설계서 §4.10(2026-09-13), 둘째는 `tests/fixtures/liturgical/`(2026-09-20)로 반영됐고 첫째는 PR 3 의 몫이다(부록 A). 재검증에서는 설계서 주장이 전부 데이터와 일치했고(본 문서 §4.1), 대신 **설계서가 아직 정하지 않은 규칙 여섯**이 드러났다(본 문서 §4.3) — 이 문서의 가장 실질적인 수확이다.

### 4.3 설계 공백 — 설계서가 아직 정하지 않은 규칙

각각 체크리스트(본 문서 §5) · 설계서 §9 미결 · 갱신 규칙(본 문서 §7)에 연결한다. 여섯 모두 그 뒤 정해졌거나 미결로 넘어갔다 — 항목마다 조사 당시의 관찰을 두고 **현재 결론**을 잇되, 버린 판정은 「기각」으로 남긴다.

1. **격자와 같은 좌표에 temporal 행이 겹친다.** temporal 표의 행 대부분이 `season/week/type` 을 갖는다(2026-09-05 실측 18행). 그중 **성지주일 · 대림1주일은 격자 절기 주일과 prec 2 동률**, **사계재 4행은 격자 feria 와 prec 8 동률**이다(성지주일 `lent/sunday` 2 vs 격자 사순 주일 2 · 하계재 `fast` 8 vs 격자 연중 평일 8). 승자가 색을 정하므로 결과가 갈린다 — 성지주일 홍 vs 격자 자, 하계재 자 vs 격자 녹. 조사 당시 설계서 §5.5 는 격자와 규칙 파생을 둘 다 후보로 올리고 `id` 사전순이 승자를 정했다. **현재 결론**: 둘은 **공존한다**(후보 둘, 대체 아님 — 설계서 §5.5 · C-5.5-3). 성지주일 · 대림1주일은 범주 사다리로 temporal 이 이긴다(→ R-6.2-tie-ladder — 본 문서 §3.3 채택, C-6.1-10). 사계재 4행은 **승자 자격이 없는 후보**다(→ R-6.1-ineligible — 사용자 확정 2026-09-17, 미결23 닫힘, C-6.1-11; 근거는 서울교구 2024 · 2025 · 2026 달력 12월 면 X-5 · X-6 · X-7). 기념일도 같은 자리다(미결24 닫힘 2026-09-17, C-6.1-12). 사계재 날의 색은 잠정이다 — 「그날은 절기색(녹), 사계재 본문을 읽을 때만 자색」(→ R-6.4-ember-color, 사용자 확정 2026-09-17)이 본 문서 §3.4 표 「사계재 색」 행의 긴장을 그 구분으로 풀었으나, 2026 책자가 사계재 날을 [자] · [자/백]으로 인쇄해 2026-09-18 다시 열렸다(미결26 — X-8 · C-6.4-3). 승자 자격 결정은 그대로다. **기각**(2026-09-17): 사계재도 사다리로 temporal 이 이긴다 — 조사 당시 본 문서 §3.3 의 제안 그대로였으나 교구 달력 2025 · 2026 면이 사계재 날에 평일 독서를 인쇄해 어긋난다(X-5 · X-6). 2024 면은 반대로 사계재 독서를 그날 독서로 인쇄했다(X-7) — 그 방식은 승자를 바꾸지 않고 후보 선택으로 지원한다(→ R-6.1-ineligible). 재검토 조건과 다른 기각 갈래는 설계서 미결23.
2. **12.25 세 행(성탄 낮·밤·새벽) 전부 prec 1.** `official` 은 `id` 사전순(`d1225-성탄-낮` < `밤` < `새벽`)의 우연으로 낮이 된다. 날짜 뷰의 기본 = 낮, 밤·새벽은 `proper` 대안이라는 **명시 규칙**이 필요하다 — 미결12(1:N 좁히기)와 같은 날짜다. **현재**: 범주 사다리로도 갈리지 않는다(셋 다 sanctoral 고정일 — → R-6.2-tie-ladder 「사다리가 가르지 못하는 것」) — 미결1 · 미결12 에 열려 있다(C-6.1-8).
3. **prec 7 겹침이 실재한다 — 7건, 그중 동률은 축일 ∧ 축일 5쌍.** 5쌍은 설계서 R-6.1-prec7-tie-pairs; 축일 ∧ 기념일 2쌍(05.03 성 십자가 발견 ∧ 성 프란시스 수도회 · 09.04 대 그레고리 ∧ 여성선교센터 개관)은 기념일이 승자 자격이 없어 동률이 아니다(설계서 R-6.1-ineligible). **현재**: 미결6(잠정 — 둘 다 본문을 내고 독자가 고른다, 사용자 확정 2026-09-17; 남은 물음은 기본 선택 순서, C-6.1-9). **기각**: 미결6 의 「실제로 겹치는 사례가 없으면 문제도 없다」 — 겹침이 실재한다.
4. **precedence 가 null 인 temporal 행은 5.** 주의 변모 주일(E−49, 색 백) · 성 토요일 · 가정주일 · 평화통일주일 · 맥추감사주일. 데이터 `note` 가 가정·평화통일을 「강조 주일 — 절기 주일을 밀어내지 않음」으로 정의하니 성 토요일까지 넷은 의도다. 조사 당시에는 여성선교주일까지 6 이었다 — 2026-10-10 에 기념일로 정해져 빠졌다(해마다 본기도·독서가 고정되지 않아 이름 줄로만 — 설계서 미결35, data#27). **주의 변모 주일은 다르다** — 사순 직전 주일의 정체(변모 독서)인데 null 이면 `official` 은 격자 연중 주일이고 색은 녹이 된다. 조사 당시 설계서 §6.1 은 「`precedence: null` 후보는 collects 3건」이라 적었다. **현재**: 그 서술을 temporal 6행까지 넓혔고(설계서 §6.1), 변모 주일의 지위는 데이터 그대로 맞다 — 선택 독서이고 승자가 아니다(2026 책자 2.15, 2026-09-18 — X-10 · C-6.1-7).
5. **명절 ∧ 연중 주일.** 설이 주일인 해 2027·2030·2034·2037·2040·2050, 추석이 주일인 해 2032·2035·2039·2042 — 전부 연중 주일이다. 명절(prec 0)이 이기고 주일 후보는 `proper` 로 남아야 한다(「밀린 독서 보존」). 설계서 §7 · 픽스처에 이 케이스가 없다 → 본 문서 §5.10 C-6.1-4.
6. **미결16 「2026년 두 건」은 여덟 건이다**(2026-09-19 안나와 요아킴 승격 반영) — 목록은 설계서 미결16 의 구체 예, 기대값은 픽스처 T-2026-01-26-paul-conversion · T-2026-05-15-matthias · T-2026-06-01-visitation · T-2026-07-27-anna-joachim · T-2026-10-19-luke · T-2026-12-07-nicholas · T-2026-12-28-john-chain. **현재**: 여섯 건은 2026 책자로 확인됐다(X-10). 마지막 둘(12.27 요한 · 어린이들)이 미결17 을 판정할 것으로 보았으나(연쇄면 요한 12.28 · 어린이들 12.29, 건너뜀이면 요한 12.29 · 어린이들 12.28) **2026 달력 12월 면과 책자가 12.26 에서 끝나 미판정이다**(2026-09-18 확인 — 미결17, 2027 책자로).

2026-09-20 채택. 케이스는 `tests/fixtures/liturgical/{transfers,optionals,winners}.cases.json` 에 있고 스키마 · id 규칙 · 소비 방법의 정본은 [그 README](../../tests/fixtures/liturgical/README.md)다 — 이 부록이 제안한 모양(LiturgicalCalendarAPI `LitCalTest.json` 계열, 예: `christmas-triad-chain-2027` 의 2027-12-26 연쇄)에 `kind` · `group` · `canon` · `checks` · `source` · `status` 를 더했다. 제안에서 바뀐 것:

- id — 자유 문자열 대신 `T-2027-12-27-christmas-triad` 꼴(README 「id 규칙」).
- `rule`(전사 위치 — 「주요축일 나-1」) — `canon`(R- 정본 마커 · 설계서 절)과 `source`(외부 근거)로 나눴다.
- `applies.since/until`(기도서 개정이나 사제 확인으로 규칙이 바뀐 **발효 연도**) — README 스키마에 없다. 필요해지면 README 에 더한다.

제안의 두 원칙은 그대로 계약이 됐다 — `displacedBy` 는 **정확한 id** 로 쓴다(생략부호 금지 — 그러면 픽스처가 계약을 검증하지 못한다), `skip` 은 데이터 · 책자 대기에만 쓴다(미결13). 격자 id 규칙은 설계서 §5.5 다 — 성탄절기 주일은 데이터에 주차가 있어 2027-12-26 은 성탄 후 첫 주일 `grid:christmas-1-sunday` 이고(실측: `christmas/1/sunday` · `christmas/2/sunday` 가 독서·본기도 양쪽에 있다), `week: null` 일 때만 `x` 를 쓴다(성주간 평일 등).
