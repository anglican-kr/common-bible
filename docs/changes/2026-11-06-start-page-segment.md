## 요약

사용자 요청으로 설정 화면의 세 곳을 고쳤다(ADR-041 §2, §9, ADR-023 §2).

- 맨 위의 선택 상자를 테마와 같은 세그먼트(값을 고르는 단추 묶음)로 바꿨다. 두 단추의 폭이 같고, 묶음의 폭은 글자 크기와 테마의 세 단추 묶음과 같다.
- 화면 문구 「시작 페이지」를 「시작 화면」으로 바꿨다. 개인정보처리방침과 문서, 코드 주석도 함께 고쳤다.
- 「외경」의 상태 설명(구약에 포함, 별도 섹션에 표시)을 이름 아래에서 이름 오른쪽으로 옮겼다. 외경 행의 높이가 다른 토글 행과 같아졌다.

## 확정 · 근거

- **단추 폭을 `grid`로 나눴다.** `flex: 1`로는 왼쪽 테두리가 없는 단추가 1px 좁아 두 단추가 99.5px과 98.5px이었다. 같은 규칙을 쓰는 글자 크기와 테마의 묶음도 첫 단추만 1px 넓었는데, 이제 66px씩으로 같다.
- **`flex-wrap`으로 설명을 옮겼다.** 한 줄에 들어가지 않으면 설명이 이름 아래로 내려가 스위치와 겹치지 않는다. `.settings-label`의 최소 폭이 이름과 설명 사이를 벌려 토글 행에서만 0으로 두었다.
- **저장 키와 코드 이름은 바꾸지 않았다.** 저장 키 `bible-start-page`와 동기화 이름 `startPage`를 바꾸면 이미 고른 값을 옮기는 코드가 필요한데, 사용자에게 달라지는 것이 없다. `START_PAGES`, `loadStartPage`, `saveStartPage`도 이 키와 짝이라 그대로 두었다.
- **선택 상자 코드를 지우지 않았다.** `makeSelectRow`(선택 상자 행을 만드는 함수), `.settings-select`, 목록을 연 채 누른 Esc의 처리는 다음 단계의 세례명과 소속교회(ADR-041 §5, §6)에 쓴다. 지금은 화면에서 쓰는 곳이 없어, Esc 시험은 시험 안에서 선택 상자를 팝오버에 넣어 확인한다.
- **값이 넷이 되면 부품을 다시 정한다.** 11rem에 셋까지 들어가고, 기도서와 성무일과를 더해 넷이 되면 「전례독서」와 「성무일과」가 칸을 넘는다(측정 2026-11-06). 2026-11-05에는 값이 늘 것을 보고 선택 상자로 정했으나, 사용자가 지금의 모양을 먼저 골랐다. ADR-041 「검토한 대안」에 재검토 조건으로 적었다.
- **「읽던 페이지에서 시작」은 그대로 두었다.** 요청한 문구가 아니고, 시작 화면과 다른 항목이다.

## 검증

- 유닛 `node --test tests/unit/*.test.js`: 1,515건 모두 통과. 타입 검사 통과(작업 폴더에 `tsc`가 없어 원래 폴더의 것으로 실행).
- 문서 검사(`tests/unit/docs-*.test.js`): 원장을 더한 뒤 다시 실행해 통과.
- e2e: 작업 폴더의 앱을 8091 포트로 띄우고 포트만 바꾼 사본으로 실행해 458건 모두 통과. 새 시험은 저장과 숨김, 고른 단추를 다시 눌렀을 때, 세 묶음의 폭과 단추 폭, 외경 설명의 자리를 본다.
- 폭 390px, 320px과 데스크톱에서 글자 크기 16-24px로 재어, 세 묶음의 폭과 오른쪽 끝이 같고 묶음마다 단추 폭이 같은 것을 확인했다. 외경 설명은 이름 오른쪽 8px에 있고, 320px에 가장 큰 글자에서도 줄이 바뀌지 않으며 스위치와 겹치지 않는다.
- **하지 못한 것:** Safari와 아이폰 실물로는 보지 못했다. 작업 환경에 없다.
