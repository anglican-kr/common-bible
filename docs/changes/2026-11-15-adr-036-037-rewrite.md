## 요약

ADR-036(교회력 데이터 모델, 우선순위, 전례색)과 ADR-037(전례독서 데이터, 교회력 엔진)을 ADR-038과 같은 틀(요약, 배경, 결정, 검토한 대안)로 다시 썼다. 함께 세 ADR에서 「결정 기록」과 「구현 기록」 표를 없앴다.

- ADR-036: 결정과 까닭만 남기고, 우선순위와 옮김, 색의 자세한 동작은 설계서의 규칙 마커로 가리켰다. 데이터 파이프라인의 지금 동작은 `docs/topics/liturgical.md`의 「교회력 데이터」로 옮겼다.
- ADR-037: 엔진 절(§6)은 함수가 무엇을 받아 무엇을 돌려주는지만 남기고, 동작의 세부는 설계서 절과 규칙 마커로 가리켰다. 전례시편 문법의 요약은 지우고 기준인 데이터 저장소 ADR-039를 가리킨다. 원본 데이터 결함의 예 둘도 지웠다.
- 분량: ADR-036 97,194바이트에서 91,165바이트, ADR-037 40,250바이트에서 36,526바이트, ADR-038 133,661바이트에서 116,451바이트
- known-issues §12.1(ADR에 남은 낡은 사실)을 닫았다.

## 확정 · 근거

- 사용자 결정(2026-11-15):
  - ADR-036, 037을 새 원칙으로 다시 쓰되 main과 충돌하지 않게 한다. 그래서 PR #566에 커밋하지 않고 있던 두 ADR의 수정(ADR-036 §2 「번호 붙은 주일은 「N주일」로 맞춘다」, ADR-037 §5 예시)을 이 PR로 옮기고 #566에서는 뺐다. 데이터는 데이터 저장소 PR #77이 맞췄다.
  - 「결정 기록」 표는 쓸모가 없으면 없앤다. 따져 보니 하는 일 셋(누가 정했나, 언제 정했나, 부딪칠 때 나중 것 고르기)을 모두 다른 곳이 한다. 사용자 결정인지는 「규칙은 사용자가 정한 것」이라는 원칙이, 날짜는 원장과 git이 맡고, 부딪치면 본문을 고친다. 사제 확인과 기도서 대조 같은 근거는 본문에 까닭으로 남는다. 같은 종류의 내력인 「구현 기록」 표도 함께 없앴다. 구현 단계의 진행은 주제 문서의 「지금 동작」이 맡는다.
  - 전례시편 문법 요약과 원본 데이터 결함의 예 둘을 지운다.
  - known-issues §12.1을 닫는다.
- 두 ADR은 작성 에이전트가 ADR-038을 본보기로 하나씩 다시 썼고, 이끄는 세션이 검사를 다시 돌리고 본문을 읽어 검토했다. 다른 문서와 코드 주석이 인용하는 이름(「밀린 독서 보존」, 「잠정 순번 id 를 키로 쓰지 말 것」, 「개인은 표시, 공적 전례는 불변」, 「슬롯 배정」, 「세트 번호」 등)은 모두 새 본문에서 찾아진다.
- 다시 쓰며 지금과 맞게 고친 것:
  - ADR-036 상태 줄을 「데이터 구현 완료」에서 「구현 중」으로 바꿨다. 지역 축일의 `scope` 오버레이(B2)가 남았다.
  - ADR-036 §7 규칙 5의 「절기 주일보다 후순위인 주요축일」을 표로 쓰며 「그 주일보다 후순위인 주요축일」로 적었다. 연중 주일의 경우까지 한 줄로 읽히게 한 것이고, 테스트 C-6.1-4d의 이름과 같다.
  - ADR-036 §9의 「2051년 이후만 건너뛴다」를 「표에 없는 해에는 건너뛴다」로 고쳤다. 표의 해를 찾는 코드(`lunarDatesOf`)가 2025년 전에도 빈 결과를 낸다.
  - ADR-036에서 엔진이 `priority_group`을 읽는다는 대목을 뺐다. 설계서 §6.1은 엔진이 읽지 않는다고 적는다.
  - ADR-037 §1의 JSON 예시 제목을 데이터 PR #77 뒤의 「연중10주일」로 맞췄다. 주제 문서 「결정」의 ADR-037 이름을 제목과 맞췄다.
- 일부러 바꾸지 않은 것: 제목 줄, 절 번호, 「미결 사항」 목록의 번호와 형식(문서 검사가 본다), 「검토한 대안」 항목의 형식. ADR-036의 영명축일 등급 「축일(prec 7, `commemoration`)」은 지금 값과 맞지 않을 수 있지만, 영명축일이 범위 밖(설계서 미결36)이라 그대로 두었다.
