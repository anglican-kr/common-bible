## 요약

주석 툴팁(`#note-tooltip`)을 연 채 툴팁 바깥을 누르지 않고 화면이 바뀌면, 툴팁이 새 화면에 열린 채 남아 상단 바 밑에 숨었다(known-issues §50 해소). 표지가 옛 화면과 함께 사라져 툴팁이 화면 맨 위에 놓였고, 표지를 따라 자리를 다시 잡던 스크롤과 창 크기 처리기, 크기 감시(`ResizeObserver`)도 다음 누름이나 Esc까지 남았다.

이제 라우터(`routing.js`의 `route()`)가 시작할 때, 열린 창을 모두 닫는 자리(`closeAllOverlays`) 바로 뒤에서 툴팁을 닫는다. 새 화면을 그려 라우터가 끝날 때도, 툴팁의 표지가 문서에서 사라졌으면 닫는다. 라우터가 자료를 기다리는 동안 옛 화면이 남아 그 틈에 연 툴팁이 있기 때문이다(아래 「리뷰 반영」 2회차). 닫는 함수는 원래 있던 것이다. 설정 「인용·주석 표시」를 끌 때 쓰던 `citations.js`의 `_hideNoteTooltip`을 `hideNoteTooltip`으로 이름을 바꿔 꾸러미(`window.appCitations`)에 더했다. ADR-022 §6(툴팁은 Esc나 바깥을 누르면 닫힌다)과 ADR-034 5b(화면이 바뀌면 라우터가 열린 창을 모두 닫는다) 안의 버그 수정이라 ADR은 고치지 않았다.

## 확정 · 근거

- **포커스를 옮기지 않는 닫기를 쓴다**(구현하며 정함). Esc와 바깥 누름이 쓰는 `closeNoteTooltip`은 닫은 뒤 표지로 포커스를 돌린다. 화면이 바뀔 때 그 표지는 떠나는 화면에 있어 곧 사라지고, 포커스를 받으면 옛 화면이 스크롤될 수도 있다. 새 화면의 포커스는 다른 화면 전환 때와 같다. 같은 화면을 다시 그리는 링크면 라우터가 누른 링크의 짝으로 돌려주고(ADR-031 §5), 새 화면이 포커스를 두기도 하며(홈 탭은 읽던 책), 뒤로 가기와 앞으로 가기는 페이지 처음에서 시작한다. 그래서 포커스를 그대로 두는 `hideNoteTooltip`을 부른다. 탭 바의 캘린더, 북마크, 설정으로 옮기면 누른 탭이 포커스를 지닌다.
- **툴팁을 오버레이 목록에 넣지 않는다**(구현하며 정함). `closeAllOverlays`는 `createOverlay`로 만든 창만 닫는다. 툴팁에는 막(scrim), 포커스 가두기, 포커스 되돌리기가 없어, 목록에 넣으려면 그 기능을 모두 끈 오버레이를 따로 만들어야 한다. 있던 닫기를 그 옆에서 한 줄로 부르는 편이 간단하다. `route()`가 다른 모듈을 부르는 방식대로 창 객체의 꾸러미로 부른다(`window.appCitations?.hideNoteTooltip()`). `routing.js`는 `citations.js`를 가져오지(import) 않는다.
- **끝날 때는 표지가 사라진 툴팁만 닫는다**(리뷰 2회차, 구현하며 정함). 시작할 때 닫아도, 라우터가 성서 목록을 기다리는 동안에는 옛 화면이 그대로라 그 틈에 툴팁을 열 수 있다. 그래서 `route()`가 끝날 때(최신 `route()`일 때만) 같은 함수를 `hideNoteTooltip({ ifAnchorGone: true })`로 한 번 더 부른다. 표지가 문서에 남아 있으면 닫지 않으므로, 새 화면에서 연 툴팁은 그대로다. 시작할 때의 닫기는 둔다. 장의 자료를 받는 동안(불러오는 중 화면) 표지 없는 툴팁이 떠 있지 않게 하기 때문이다.
- **뒤로 가기와 앞으로 가기 말고도 툴팁이 남는 화면 전환이 둘 있었고, 함께 고쳐졌다.**
  - 같은 주소를 다시 그릴 때(`window.route()`). 동기화로 받은 설정이 화면을 바꾸면 `redrawIfSyncedSettingsChanged`가 부른다.
  - 휴대폰 탭 바의 아이콘을 누를 때. 툴팁 바깥을 누르면 닫는 처리(`citations.js`의 `initCiteSheet`가 단 누름 처리기)는 누른 대상이 `HTMLElement`가 아니면 아무것도 하지 않는다. 탭 바의 탭은 아이콘뿐이라 누른 곳이 거의 늘 아이콘(SVG 요소)이다.
- **링크를 눌러 옮길 때는 고치기 전에도 닫혔다.** 장의 이전과 다음, 전례독서의 날짜 이동, 데스크톱 상단 바의 「성서」와 「캘린더」는 툴팁 바깥 누름이 닫았다. 단추의 처리기가 `route()`를 먼저 시작하는 상단 바의 두 탭은 이제 `route()`가 먼저 닫고, 문서의 링크 처리(`routing.js`)를 거치는 장과 전례독서의 링크는 여전히 바깥 누름이 먼저 닫는다. 어느 쪽이든 포커스와 스크롤 위치는 고치기 전과 같았다(아래 「검증」).
- **고치지 않은 것.** 바깥 누름이 SVG 대상을 받지 않는 것은 화면을 옮기지 않는 누름에도 해당한다. 데스크톱에서 툴팁을 연 채 상단 바의 설정 단추 가운데(아이콘)를 누르면 설정 팝오버가 열리고 툴팁도 그대로 있다. 이 PR은 화면 전환만 고친다.

## 검증

- **재현**(고치기 전, Chromium, 작업 폴더 서버 포트 8093). 휴대폰 폭(390×844)과 데스크톱(1280×800)에서 열왕기상 4장에서 5장으로 간 뒤 「사천」의 툴팁을 열고 뒤로 가면, 4장 화면에 툴팁이 열린 채 위쪽 8px에 놓였다. 툴팁 아래쪽(58.5px)이 상단 바 아래쪽(휴대폰 60px, 데스크톱 62.9px)보다 위라 툴팁이 통째로 상단 바에 가렸다. 툴팁이 단 처리기 둘(스크롤, 창 크기)과 크기 감시 하나가 그대로였고, 스크롤하면 처리기가 툴팁의 자리를 다시 썼다.
- **경우별 확인.** 확인 스크립트로 두 화면 크기에서 고치기 전과 뒤를 쟀다. 툴팁이 열려 있는지, 툴팁이 열 때 만든 처리기와 크기 감시가 남았는지, 포커스, 스크롤 위치다.

  | 경우 | 고치기 전 | 고친 뒤 |
  | --- | --- | --- |
  | 장에서 뒤로 가기, 앞으로 가기 | 남음 | 닫힘 |
  | 장에서 같은 주소 다시 그리기 | 남음 | 닫힘 |
  | 전례독서에서 캘린더로 뒤로 가기, 전례독서 두 날 사이에서 뒤로 가기 | 남음 | 닫힘 |
  | 병행 본문 ※의 툴팁(사무하 5장)에서 뒤로 가기 | 남음 | 닫힘 |
  | 휴대폰 탭 바의 홈, 캘린더, 북마크, 설정 | 남음 | 닫힘 |
  | 장의 다음 링크(누름, Enter), 전례독서의 날짜 이동(누름, Enter), 데스크톱 상단 바의 「성서」와 「캘린더」 | 닫힘(바깥 누름) | 닫힘 |

  - 고친 뒤에는 모든 경우에 처리기와 크기 감시가 남지 않았다. 포커스와 스크롤 위치는 고치기 전과 같았다. 뒤로 가기는 떠날 때의 스크롤로 돌아갔고(휴대폰 300px. 데스크톱은 219px인데, 툴팁을 열지 않고 뒤로 가도 219px이다), 전례독서의 날짜 이동은 누른 다음 날 단추로 포커스가 돌아왔으며, 탭 바는 캘린더, 북마크, 설정이면 누른 탭이, 홈이면 읽던 책이 포커스를 지녔다.
  - 툴팁을 연 적이 없거나 Esc로 닫은 뒤의 `route()`는 툴팁에 아무 일도 하지 않았다. 툴팁 요소를 만들지 않았고, 데스크톱 검색창과 휴대폰 캘린더 탭에 둔 포커스를 옮기지 않았다. 페이지 오류는 없었다.
- 유닛: `node --test tests/unit/*.test.js` 1991건 통과(데이터 서브모듈을 받은 작업 폴더). 툴팁은 화면 좌표와 화면 전환을 다뤄 유닛 시험이 없고 e2e가 맡는다(`citations.test.js`의 주석).
- 타입 검사: `tsc -p tsconfig.json --noEmit`, `tsc -p tsconfig.worker.json --noEmit` 통과.
- e2e(포트 8093, Chromium):
  - 새 시험 6건(`test_note_tooltip.py`). 뒤로 가기(휴대폰, 4장의 자료를 붙잡아 두고 장이 오기 전에 닫혔는지도 본다), 앞으로 가기(데스크톱), 전례독서에서 같은 주소 다시 그리기(데스크톱), 탭 바의 캘린더 아이콘(휴대폰, 누른 탭이 포커스를 지닌다), 성서 목록을 붙잡아 둔 전례독서에서 장으로 옮기는 동안 옛 화면에서 연 툴팁(휴대폰, 데스크톱. 새 화면에서 연 툴팁은 끝날 때의 닫기가 닫지 않는다)이다. 툴팁이 열릴 때 만든 처리기와 크기 감시를 페이지에서 기록해, 열 때 생겼는지와 닫은 뒤 모두 풀렸는지 본다. 응답은 붙잡아 두었다가 풀어 주므로 시간에 기대지 않는다.
  - 변이 검사: 시작할 때의 닫기를 빼면 뒤로 가기 시험이, 끝날 때의 닫기나 그 안의 표지 확인을 빼면 성서 목록을 붙잡아 둔 시험 2건이 실패하고 나머지는 통과한다. 시작할 때의 닫기가 `closeNoteTooltip`(포커스를 표지로 돌리는 닫기)을 부르게 바꾸면 탭 바 시험만 실패한다(포커스가 탭에 남지 않는다). 두 닫기를 모두 빼면(dev) 새 시험 6건이 실패한다.
  - 고른 파일과 까닭: `test_note_tooltip.py`(고친 동작, 14건), `test_cite_sheet.py`(같은 모듈의 인용 시트, 5건), `test_lectionary_cites.py`(전례독서의 툴팁과 설정, 12건), `test_navigation.py`(`route()`가 그리는 장 화면과 실패 화면, 32건), `test_tabbar.py`(탭 바의 이동과 포커스, 26건), `test_a11y_keyboard.py`(포커스 복귀, 11건), `test_liturgical_lazy_load.py`(캘린더와 전례독서를 다시 그리는 `route()`, 11건), `test_lectionary_view.py`(`route()`가 끝나는 전례독서 화면과 포커스 복귀, 107건). 218건 통과.

## 리뷰 반영

1회차(`/code-review medium --fix`, 이번 변경의 결함 없음, 전부터 있던 것 하나, 사소한 것 둘):

- **SVG 아이콘을 누르면 화면이 바뀌지 않는 한 툴팁이 남는다는 지적은 전부터 있던 것이라 넘겼다.** 바깥 누름 처리기(`citations.js`의 `initCiteSheet`)가 `HTMLElement`가 아닌 대상을 받지 않는 문제로, 위 「고치지 않은 것」과 같다.
- **툴팁 안에 포커스가 있을 때 화면이 바뀌면 포커스가 페이지 처음으로 간다는 지적은 재현됐지만 동작은 고치지 않았다.** 사무하 4장에서 5장으로 가 ※ 툴팁을 열고 그 안의 참조 단추에 포커스를 둔 채 뒤로 가면, 고치기 전에는 포커스가 상단 바 밑에 남은 툴팁의 단추에 있었고, 고친 뒤에는 페이지 처음이다(다음 Tab이 「본문 바로가기」, 휴대폰과 데스크톱). 옛 화면의 다른 컨트롤에 포커스가 있었을 때와 같다. 다만 코드 주석, 주제 문서, 위 「확정 · 근거」의 「새 화면이 포커스를 정한다」는 뒤로 가기와 맞지 않아 「다른 화면 전환 때와 같은 곳으로 간다」로 고쳤다. 같은 문장의 탭 바 포커스도 바로잡았다. 홈 탭은 읽던 책에 포커스를 둔다(고치기 전과 같다).
- **`parallels.js`의 주석이 툴팁이 닫히는 길에 화면 전환을 적지 않았다.** 리뷰가 더했다.
- 리뷰와 따로, 고치기 전(`routing.js`의 닫기 줄을 응답에서 뺀 판)과 뒤를 휴대폰(390×844)과 데스크톱(1280×800)에서 견줬다. 위 표의 경우에 더해 인용 시트를 연 채 뒤로 가기, `route()`가 셋 겹칠 때, 북마크 모아 읽기(`/read`)로 옮길 때, 설정 「인용·주석 표시」를 끌 때, `citations.js`를 받지 못했을 때(고친 뒤만)다. 고친 뒤 모든 경우에 툴팁이 닫히고 처리기와 크기 감시가 풀렸다. 포커스와 스크롤은 위 ※ 경우 말고는 고치기 전과 같았다. 뒤로 간 다음 설정 팝오버를 열고 누른 첫 Esc는 팝오버를 닫고 설정 단추로 포커스를 돌렸다. 페이지 오류는 없었다. 변이 검사(닫기 줄을 빼면 새 시험 4건 실패, `closeNoteTooltip`으로 바꾸면 탭 바 시험만 실패)도 다시 확인했다.
