## 요약

휴대폰에서 책 선택 시트를 가장 낮게 끌어내리면 칩이 하나도 보이지 않았다(아이폰 보고 2026-11-19). 이제 칩 두 줄과 「적용」 단추가 보이는 높이 아래로는 내려가지 않는다. ADR-033 「책 선택 시트의 구분 탭」에 적었다.

## 확정 · 근거

- 원인: 시트는 놓은 높이가 화면 높이의 30%보다 낮으면 30%로 돌아온다. #605가 구분 탭 줄을 더한 뒤로는 손잡이, 머리, 탭 줄, 「적용」 줄만 해도 아이폰에서 약 240px(홈 표시줄 자리 포함)이고, 높이 852px 화면의 30%는 256px이라 칩이 들어갈 자리가 없었다. #605의 코드 리뷰가 이 경우를 짚었지만 디자인을 정할 일이라 남겨 두었다.
- 후보 셋(칩 두 줄에서 멈춤, 칩 한 줄에서 멈춤, 끌어서 높이를 바꾸지 않기)을 보였고, 사용자가 칩 두 줄을 골랐다(2026-11-19).
- 구현하며 정함:
  - 가장 낮은 높이는 놓을 때마다 시트의 부분(손잡이, 머리, 탭 줄, 「적용」 줄, 홈 표시줄 자리, 칩 두 줄과 위아래 여백)을 재어 정한다. 글자 크기를 바꾸면 이 높이도 바뀐다. Chromium의 393×852 화면에서 337px(약 40%), 375×667 화면에서 337px(약 51%)이다. 아이폰에서는 홈 표시줄 자리만큼 더 높다. 아래 여백까지 넣어 셋째 줄의 윗부분이 조금 보이고, 목록이 더 있다는 것을 알 수 있다.
  - 끌기 함수(`attachSheetDrag`)에 시트마다 가장 낮은 높이를 넘기는 `minHeight`를 더했다. 놓을 때의 판정(`dragReleaseAction`)은 가장 낮은 높이를 받되 기본은 30%다. 닫히는 선(20%)은 그대로다. 인용 시트와 북마크 시트는 바뀌지 않는다.

## 검증

- 유닛 `node --test tests/unit/*.test.js`: 1,952개 통과(새 시험 1개: 가장 낮은 높이를 넘기면 돌아오는 선만 바뀌고 닫히는 선은 그대로). `npm run typecheck` 통과.
- e2e(작업 폴더 서버 8091): 새 시험 `test_book_filter_sheet_rests_where_two_rows_show`(375×667, 393×852)가 30% 근처에서 놓으면 둘째 줄 칩과 「적용」 단추가 다 보이고, 10%에서 놓으면 닫히는지 본다. 같은 시험을 고치기 전의 dev 사이트에 돌리면 두 크기 모두 실패한다. `test_search.py`와 `test_cite_sheet.py`(인용 시트는 30% 그대로) 109개가 통과했다.
- 393×852 휴대폰 크기에서 끌어내린 화면을 찍어 칩 두 줄을 눈으로 보았다. 아이폰의 홈 표시줄 자리는 Chromium에서 0이라 실기기 확인이 남았다.
