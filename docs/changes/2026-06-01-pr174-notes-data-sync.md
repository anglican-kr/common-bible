# feat: 노트 데이터·동기화 계층 (ADR-026 Stage 1a-①)

## 개요

ADR-026 노트 기능의 **데이터·동기화 계층**(1a-①). **사용자 노출 UI는 다음 PR(1a-②)** — `/notes`는 아직 Stage 0 플레이스홀더입니다. base = `release/1.6.0`.

## 설계 (ADR-026 §4.1 개정 반영)

**Drive 우선 + per-note 파일 + 가벼운 인덱스**
- `notes-index.json`(메타: title·date·updatedAt·hash, 본문 없음) + `note-<id>.json`(노트 1개). 노트 1개 편집 → 그 파일 + 인덱스만 업로드.
- **변경 감지 = `updatedAt`(편집 시각) + 콘텐츠 `hash`** 조합. hash=동일성/변경 판정, updatedAt=충돌 LWW 순서. 둘 다 변해도 hash 같으면 수렴, 다르면 승자 유지 + 패자 `(사본)` 복제(무손실).
- **해시 비용 최소화**: 자동저장은 IDB+dirty만, 해시는 동기화 시 더티 노트에 1회.

**로컬 = 폐기 가능 IDB 캐시** `common-bible-notes`(notes/tombstones/synced/meta). iOS 축출돼도 Drive에서 복원.

**내구성 4겹**: ①디바운스+blur→IDB ②`visibilitychange→hidden`·`pagehide` 즉시 flush(iOS는 beforeunload 불신) ③동기 localStorage 드래프트 보증 ④재실행 복원. notes-store가 소유, 에디터는 `beginEditing/endEditing`로 버퍼 게터만 등록.

**동기화 = B′ 하이브리드**: FSM의 `SYNC_DONE` 직후 `notesStore.syncWithToken(_token)` 훅 한 줄(fire-and-forget). 무거운 인증·재시도는 FSM 한 곳, notes-store는 UI용 가벼운 status만.
