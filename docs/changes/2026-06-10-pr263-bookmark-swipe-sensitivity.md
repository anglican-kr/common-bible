# fix: 북마크 스와이프 민감도 일관화 (ADR-010 개정)

## 배경

북마크 행 스와이프가 "어떤 땐 과민, 어떤 땐 둔감"하게 동작하던 문제. 분석 결과 좌/우 임계값 자체는 대칭이었고, 비일관성의 실체는 세 가지 별개 메커니즘이었다.

## 변경 내용

순수 판정 로직을 `SWIPE_GESTURE` 마커 블록(`_classifySwipeAxis` · `_swipeReleaseVelocity` · `_resolveSwipeRelease`)으로 분리하고 핸들러는 결과만 적용한다 (ADR-013 패턴).

1. **분류 (과민·둔감 양쪽 원인)** — 기존엔 첫 5px 이동에서 `|Δx| > |Δy|` 1px 차이로 모드가 영구 확정됐다. 엄지 접촉 노이즈가 스크롤을 스와이프로 가로채거나(과민), 첫 5px이 살짝 수직이면 이후 수평 100px도 무시됐다(둔감). → 슬롭 5→8px(`SWIPE_SLOP_PX`) + 수평 판정 각도 편향 ×1.2(`SWIPE_ANGLE_BIAS`). 애매한 대각 콘 안이면 미분류로 다음 샘플 대기. 수직 우세 시 즉시 스크롤 양보는 기존 유지.

2. **플릭 (둔감)** — 커밋·스냅이 거리만 봐서 빠른 플릭이 안 먹혔다. → release 시 최근 100ms 표본 속도를 80ms 투영 후 스냅 임계 적용. 짧은 플릭으로 열기/닫기가 가능하되, **플릭은 커밋(full-swipe 실행)으로 승격되지 않는다** — 삭제 실행은 거리 게이트 유지.

3. **재그랩 커밋 (방향 비대칭으로 체감되던 원인)** — full-swipe 커밋을 절대 오프셋(`baseOffset + Δx`)으로 판정해, 이미 열린 행(±88px)을 재그랩하면 같은 방향 ~40px에 삭제가 실행되고(과민) 반대 방향은 132px이 필요했다(둔감). → 커밋은 제스처 자체의 Δx가 commitPx를 넘어야 하고, 절대 오프셋이 reveal을 지났어야 한다(반대 패널에서 중앙만 갓 넘긴 긴 당김의 오발 방지).

방향별 임계 차등은 두지 않았다 — 비대칭 체감의 실체가 재그랩 베이스 오프셋이었기 때문.
