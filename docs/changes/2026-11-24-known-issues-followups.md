## 요약

known-issues 셋을 고치는 작업에서 찾았지만 그 PR의 범위 밖이라 고치지 않은 문제 열둘을 known-issues §61-§72로 적었다. 방문이 2건씩 기록되던 것(§46, PR #650)에서 다섯, 검색의 실패 화면(§48, PR #651)에서 일곱이다. 사용자가 할 일로 적어 두고 나중에 고치기로 했다(2026-11-24). 코드는 바꾸지 않았다.

## 확정 · 근거

- **적어 두고 나중에 고친다**(사용자 결정 2026-11-24). §61-§65는 PR #650의 구현 에이전트가, §66-§72는 PR #651의 구현 에이전트와 리뷰 에이전트가 보고한 것이다. 본문의 사실은 두 PR의 원장과 측정에서 옮겼다. 건수(§65, §72), e2e에 가로채는 곳이 없다는 것(§61), 검색 워커가 실패한 요청을 기억하는 코드와 오류에 검색 번호가 없는 코드(§66, §67, §68)는 dev `913b12a`에서 다시 확인했다.
- **§61은 PR #650이 머지된 뒤에 고치는 것이 좋다.** 그 PR이 더하는 e2e가 흉내 낸 태그를 실어 방문을 세므로, 모든 컨텍스트에서 구글 요청을 가로채는 장치는 그 시험과 함께 동작해야 한다. 그때까지는 측정 ID가 바뀐 브랜치에서 e2e를 돌릴 때 e2e 사본에서 수집 요청을 가로챈다. 지금 측정 ID가 바뀐 브랜치는 dev와 PR #650의 브랜치, 그리고 문서만 바꿔 e2e를 돌리지 않는 이 PR의 브랜치다(`git merge-base --is-ancestor 913b12a <브랜치>`, 2026-11-24). PR #649와 #651의 브랜치는 dev를 합치면 해당한다.
- **사용자가 정할 것이 있는 항목**: §62는 향상된 측정의 스크롤을 끌지, §63은 운영에 낸 뒤 보고서에서 유입 경로를 본 다음에 정하고, §64는 ADR-041의 대안 F를 다시 검토할지다. §66은 실패한 검색 자료를 다음 검색에서 다시 받게 할지, §69는 자료가 아닌 실패의 글을 따로 둘지, §71은 검색 실패 화면의 폭을 다른 실패 화면에 맞출지다.
- **§70과 §71의 일부는 PR #651의 실패 화면에서 생긴다.** 그 PR이 머지되기 전의 dev에는 그 화면이 없다. 본문에 PR 번호를 적어 가렸다.
- **주제 문서의 새 항목은 파일 끝에 두었다.** 열려 있는 PR #650이 `topics/platform.md` 「남은 일」의 §46 줄을, PR #651이 `topics/search.md` 「남은 일」의 §48 절을 지우므로, 그 곁에 넣으면 머지할 때 겹친다.
- 주석 툴팁 작업(PR #649)에서 찾은 범위 밖 문제는 그 리뷰가 끝난 뒤에 적는다.

## 검증

- `node --test tests/unit/docs-*.test.js`: 23건 가운데 22건 통과, 1건은 데이터 서브모듈이 없는 작업 폴더라 건너뜀(설계서의 사실 블록 대조). 번호 대장과 주제 문서의 정의가 맞는지, 경로와 링크가 있는지를 본다.
- §65의 건수: `pytest tests/e2e --collect-only -q`가 910건(38파일), `test_copy.py` 35건, `test_calendar_view.py` 108건, `test_a11y_axe.py` 15건이다. 유닛 1991건은 데이터 서브모듈을 받은 작업 폴더에서 2026-11-23에 돌린 값이다.
- §61: `git grep -n -i "googletagmanager\|google-analytics\|analytics.google" origin/dev -- tests/e2e`가 0건이다.
- §72: `css/style.css`의 `:hover` 119번 가운데 `@media (hover: hover)` 블록(15개) 안이 20번, 밖이 99번이다(중괄호를 세어 블록의 범위를 가렸다).
- §71: PR #651의 구현 에이전트가 찍은 휴대폰 390px 폭의 실패 화면에서 제목과 부제가 낱말 가운데서 나뉘는 것을 보았다.

## 리뷰 반영

1회차(`/code-review medium --fix`, 사소한 것 넷, 문서만 바꾼 PR이라 코드 지적은 없음):

- **§64의 제목이 본문과 달랐다.** 제목은 재검토 조건을 이미 만족한다고 적었는데, 본문은 PR #650이 머지되어야 만족한다고 적었다. 제목을 할 일(「다시 검토할지 정한다」)로 바꿔 머지 순서와 상관없이 맞게 했다. 대장, 주제 문서, 이 원장의 표 세 곳이다.
- **측정 ID가 바뀐 브랜치의 목록이 실제와 달랐다.** 이 PR의 브랜치도 `913b12a`를 담고 있다. 문장을 실제 목록으로 고쳤다.
- **e2e를 돌릴 때의 대비가 「남은 일」에만 있었다.** e2e를 돌리는 세션이 읽는 `docs/workflow.md` 「작업 중 함정」의 e2e 사본 항목에 한 문장을 더했다.
- **파일 끝에 빈 줄이 하나 더 있었다.** `topics/platform.md`와 `topics/liturgical.md`에서 지웠다.

1회차에 중요한 지적이 없어 리뷰를 멈췄다. 그 뒤 PR #651의 리뷰가 끝나 §66-§72를 더했다(문서만).
