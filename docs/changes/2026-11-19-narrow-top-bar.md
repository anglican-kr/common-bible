## 요약

너비 320px 휴대폰에서 글자 크기를 22나 24로 키우면 생기던 문제 두 가지를 고친다.

- 긴 장 제목(「마카베오하 15장」, 「이사야 첫째 송가」, 「1데살로니카 5장」, 「전례시편 119편」) 옆의 ⌄가 북마크 단추에 가렸다. 이제 들어갈 때까지 제목 글씨만 한 단계씩 줄인다(`architecture.md` §4.5).
- 장 고르기 목록이 15rem(글자 크기 24에서 360px)으로 고정되어 화면 양옆이 잘렸다. 이제 화면 폭에서 양옆 16px을 뺀 폭을 넘지 않는다.

## 확정 · 근거

- 송가를 이름으로 보이는 작업(#598)을 확인하다 찾았다. 「이사야 첫째 송가」만이 아니라 같은 길이의 장 제목과 숫자 격자의 고르기 목록도 똑같았다.
- 제목을 어떻게 할지 후보 셋(글씨만 줄이기, 말줄임, 두 줄로)을 보였고, 사용자가 글씨만 줄이기를 골랐다(2026-11-19). 말줄임은 장 번호를 자르고(「마카베오하 1…」), 두 줄은 상단 바를 높여 본문을 밀어낸다.
- 후보를 보일 때는 「한 단계 작게」라고 했는데, 재어 보니 320px에 글자 크기 24에서는 한 단계(`--font-md`)로 모자랐다. 제목 212px, 단추 앞의 자리 170px, 한 단계 줄여 186px이었다. 그래서 들어갈 때까지 두 단계(`--font-base`)까지 줄인다. 22에서는 한 단계로 들어간다. 375px부터는 줄지 않는다.
- 제목만 겹쳤다. 장 목록, 검색, 북마크, 설정 화면의 제목은 같은 조건에서 겹치지 않아 장 제목(꺾쇠가 있는 제목)만 잰다.
- 처음 연 화면에서는 고친 뒤에도 겹쳤다. 웹 글꼴이 늦게 와도 휴대폰의 제목 줄은 크기가 그대로라 크기 감시가 알아채지 못했다. 글꼴을 다 받으면 다시 잰다.
- 짧은 명칭이 없는 장 제목(구약, 송가)은 이전에는 재지 않았다. 이제 모든 장 제목을 잰다.

## 검증

- 유닛 `node --test tests/unit/*.test.js`: 1,950개 통과. `npm run typecheck` 통과.
- e2e(작업 폴더 서버 8093): `test_top_bar.py` 41개(새 시험 7개: 320px에 글자 크기 22, 24의 긴 장 제목 넷, 390px에서는 줄지 않음, 320px에 24의 고르기 목록 둘), `test_book_name_swap.py`, `test_navigation.py`, `test_liturgical_render.py`, `test_features.py`, `test_a11y_keyboard.py` 75개 통과.
- 휴대폰 화면(320px에 24, 390px에 18)을 찍어 제목과 고르기 목록을 눈으로 보았다. 장 제목 다섯과 장 목록, 검색, 북마크, 설정 제목의 겹침을 320px(18, 22, 24)과 375px(24)에서 재었다.
