## 요약

버전을 2.2.8에서 2.2.9로 올린다(`scripts/release.py patch`). 2.2.8 뒤에 아이폰에서 월간 달력이 내려올 때 상단 바 아래에 어두운 선이 비치던 문제의 수정(#677)이 들어간다. pre-release를 내면 CI가 dev.anglican.kr에 올리는 배포(#678)는 개발용이다.

이 릴리스는 #678의 첫 실행이기도 하다. 머지한 뒤 서버 저장소의 `prerelease.sh`로 pre-release를 만들면 CI `deploy-dev.yml`이 dev.anglican.kr에 올린다(ADR-052 §4).

아래 「릴리스 노트 초안」은 머지한 뒤 GitHub Release에 그대로 쓴다. 「변경 사항」은 `python3 scripts/changelog.py 2.2.8 HEAD`의 출력이고, 끝의 비교 링크만 2.2.9 태그를 가리키게 고쳤다.

## 확정 · 근거

- **버전은 2.2.9이다.** 운영(`https://bible.anglican.kr/version.json`)이 2.2.8과 앱 커밋 `b728ebc`를 내려 준다(2026-11-28에 확인). 열린 PR은 없었다.
- **노트의 짜임**(`docs/writing.md` 「릴리스 노트」). #677은 2.2.8에 나간 월간 달력에서 생기던 문제라 「버그 수정」이다. 문구는 세 가지 가운데 사용자가 골랐다(2026-11-28).
- **노트에 넣지 않은 것.** #678(배포 CI)은 사용자가 겪는 변화가 없다.
- **릴리스마다 하는 정리**(CLAUDE.md 「지식 베이스 루프」 3번).
  - 2.2.8 뒤의 원장은 #677, #678의 것이다. 새 ADR은 없다. ADR-051 §3과 ADR-052 §4를 제자리에서 고쳤다(#678).
  - `docs/index.md`와 실제 파일, 링크, 번호 대장은 문서 검사가 본다(통과). 끝나서 `archive/`로 옮길 설계 문서는 없다.
  - 200줄을 넘긴 주제 문서는 `docs/topics/liturgical.md`(801줄), `sync.md`(224줄), `design-system.md`(221줄), `platform.md`(215줄)다. 2.2.8 뒤에 늘어난 것은 `design-system.md`(209줄에서 221줄, #677의 pitfalls §44)뿐이다. 2.2.7과 같이 이번에는 나누지 않는다.

## 검증

버전 파일 둘을 2.2.9로 바꾼 커밋에서 점검했다.

- `node --test tests/unit/*.test.js`: 2,001건 통과(실데이터 시험 포함). 타입 검사 `tsc -p tsconfig.json --noEmit`와 `tsc -p tsconfig.worker.json --noEmit`: 통과. `scripts/test_changelog.py`와 `scripts/test_release.py` 44건: 통과.
- e2e(작업 폴더에서 띄운 서버 8097, `/version.json`이 2.2.9임을 확인): 버전과 관련된 `test_update_toast.py`와 `test_liturgical_lazy_load.py` 20건 통과. #677의 화면 e2e는 그 PR에서 돌렸다.
- CSP 점검은 돌리지 않았다. 2.2.8 뒤로 `index.html`, `sw.js`, 통계 태그는 바뀌지 않았다.
- 배포는 #678의 CI로 dev에 올리고, `dev`와 운영의 `version.json`이 2.2.9인지 실제 사이트에서 확인한다. 실제 아이폰에서 #677을 확인하는 것은 dev에 올린 뒤 사용자가 한다.
