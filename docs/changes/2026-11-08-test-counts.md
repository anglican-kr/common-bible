## 요약

`tests/README.md`의 시험 건수가 여러 줄에서 실제와 달랐다. 시험을 더한 PR들이 건수를 고치지 않고 지나간 것이 쌓였고, #523 검토와 #522-#526 작업 중에 드러났다. 사용자가 다시 세기로 했다(사용자 결정 2026-11-07). 파일마다 다시 세어 표의 열한 줄과 머리 두 줄을 고치고, 세는 방법을 표 아래에 적었다.

`docs/workflow.md` 「작업 중 함정」에 쌓은 브랜치의 squash 메시지를 모으는 법을 적었다. #524는 머지 전의 #522 브랜치 위에서 시작했는데 #522가 squash로 들어갔다. 그래서 CLAUDE.md의 표준 명령이 #522의 원래 커밋 여섯까지 모았고, 앞 PR의 마지막 커밋부터 세게 하자 이번에는 main을 합친 커밋을 거쳐 들어온 다른 PR의 커밋까지 모았다. 브랜치 줄기만 따라가게(`--first-parent`) 해서 #524 자신의 커밋 여섯만 모았다(2026-11-08).

## 확정 · 근거

- **세는 방법**(구현하며 정함): 유닛은 파일마다 `node --test <파일>`이 보고하는 시험 수, e2e는 `pytest <파일> --collect-only -q`가 모으는 건수다(매개변수마다 따로 센다). 데이터 서브모듈을 받은 작업 폴더에서 셌다. 접근성 검사 파일(`test_a11y_axe.py`)은 선택적 의존성(`axe-playwright-python`)이 설치되어 있어 13건을 모았다.
- **결과**: 유닛은 36파일 1,477건에서 38파일 1,663건으로, e2e는 32파일 475건에서 32파일 595건으로 고쳤다. 표에 없는 시험 파일이나, 없는 파일을 가리키는 줄은 없었다.
- **그대로 둔 것**: 「실측 (2026-10-22)」 단락은 그날 전체 e2e를 돌린 기록이라 고치지 않았다.

## 검증

- 유닛: 파일마다 센 건수의 합(1,663건)이 `node --test tests/unit/*.test.js`의 전체 건수와 같다. 건너뜀과 실패는 0이다.
- 표의 파일 이름을 실제 시험 파일 목록과 견주어, 빠진 파일과 없는 파일이 없음을 확인했다(일회성 스크립트, 커밋하지 않음).
- `node --test tests/unit/docs-*.test.js`: 통과.

## 갱신한 문서

- `tests/README.md`: 표의 건수 열한 줄과 머리 두 줄, 세는 방법 한 문장.
- `docs/workflow.md`: 「작업 중 함정」에 쌓은 브랜치의 squash 메시지.
