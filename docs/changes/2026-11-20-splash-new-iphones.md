## 요약

아이폰 홈 화면 앱을 열면 흰 화면이 한동안 보이던 문제를 고쳤다. iOS가 시작 이미지(`apple-touch-startup-image`)를 보이지 않았기 때문이다. `index.html`에 `apple-mobile-web-app-capable` 메타 태그가 처음부터 없었고, 시작 이미지 목록에 새 아이폰 세 크기(402×874, 420×912, 440×956)도 없었다. 태그와 세 크기를 넣고, 시작 이미지에서 런치 스크린으로 넘어갈 때 십자가의 크기와 높이가 바뀌지 않게 맞췄다. ADR-007 §8.

## 확정 · 근거

- **흰 화면.** 사용자가 dev 앱을 열 때 흰 화면이 오래 보인다고 알렸다(2026-11-20). dev는 서비스 워커가 `index.html`을 서버에서 먼저 받아(`sw.js`의 `IS_DEV`) 첫 화면이 늦게 그려지는데, 그동안 iOS가 시작 이미지 대신 흰 화면을 보였다. firt.dev(2026-10-13)는 매니페스트가 있어도 이 태그가 있어야 시작 이미지가 보인다고 한다. Apple 문서로는 확인하지 못했다. 태그와 세 크기를 넣은 dev에서 흰 화면이 사라졌다(사용자 확인).
- **십자가의 크기.** 시작 이미지가 보이자, 런치 스크린으로 넘어갈 때 십자가가 갑자기 커졌다가 흐려졌다(사용자 확인). 이미지는 옛 로고를 화면 짧은 변의 25%로, 런치 스크린은 2026-04-18에 바꾼 SVG를 30vmin으로 그렸기 때문이다. 생성기가 `index.html`의 런치 스크린 SVG를 읽어 같은 크기로 그리게 하고 16개를 모두 다시 만들었다. 뷰박스 밖으로 조금 나가는 부분도 페이지처럼 그려지게, 십자가 상자 전체 크기로 그린다.
- **주소의 `?v=2`.** 서버가 시작 이미지를 하루 동안 캐시하게 해, 주소가 같으면 휴대폰이 옛 그림을 보일 수 있다. 생성기의 `SPLASH_VERSION`으로 주소에 `?v=2`를 붙였다.
- **십자가의 높이.** 크기가 맞자, 넘어갈 때 십자가가 조금 내려갔다(사용자 확인). 시작 이미지는 상태 표시줄까지 덮는데 페이지는 상태 표시줄 아래에서 시작해서다. 기기별 상태 표시줄 높이를 표로 두지 않고, `js/pre-fetch.js`가 첫 페인트 전에 화면과 페이지의 높이 차이를 재어 그 절반만큼 십자가를 올린다. 이미 `<head>`에서 동기로 실행되는 스크립트라 새 파일도, CSP 변경도 필요 없다.
- **남은 깜빡임은 그대로 둔다**(사용자 결정 2026-11-20). 넘어가는 순간 화면 전체가 아주 짧게 깜빡인다. iOS가 시작 이미지를 치우는 순간이라 앱 쪽에서 막을 곳이 없다.
- **일부러 바꾸지 않은 것.** 시작 이미지는 어두운 것 하나뿐이다. 런치 스크린은 라이트 모드에서도 다크 배경이라(ADR-007 §1) 밝은 이미지가 필요 없다. 마스크 아이콘(`icon-512-maskable.png`)은 생성기가 다시 만들어도 픽셀이 같아 그대로 두었다.

## 검증

- 유닛 `node --test tests/unit/*.test.js`: 1,964개 통과(새 `pre-fetch.test.js` 4개 포함). `npm run typecheck` 통과.
- e2e: 런치 스크린이 닫히기를 기다리는 `test_bookmark_read.py` 3개와 `test_search.py`의 `test_search_url_refresh_navigates_and_dismisses_launch_screen` 통과.
- Chromium에서 시작 이미지와 런치 스크린을 겹쳐 보았다. 십자가의 너비와 높이 차이가 1-3px이었다.
- Chromium을 홈 화면 앱처럼 꾸며(화면 높이 874px, 페이지 높이 812px) 재었다. 십자가의 한가운데가 페이지 위에서 375px로, 화면 한가운데(437px에서 상태 표시줄 62px를 뺀 자리)와 같았다. 보통 브라우저에서는 406px로 움직이지 않았다.
- 아이폰 실기기(dev `bible-2.2.1-f9d1a9f-dirty`, 2026-11-20): 흰 화면이 사라졌고, 넘어갈 때 십자가의 크기와 높이가 그대로였다. 넘어가는 순간의 짧은 깜빡임만 남았다.
