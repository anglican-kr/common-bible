## 요약

아이폰 홈 화면 앱을 열면 흰 화면이 한동안 보이던 문제를 고쳤다. iOS가 시작 이미지(`apple-touch-startup-image`)를 보이지 않았기 때문이다. `index.html`에 `apple-mobile-web-app-capable` 메타 태그가 처음부터 없었고, 시작 이미지 목록에 새 아이폰 세 크기(402×874, 420×912, 440×956)와 요즘 아이패드 여섯 크기도 없었다. 태그와 아홉 크기를 넣고, 시작 이미지에서 런치 스크린으로 넘어갈 때 십자가의 크기와 높이가 바뀌지 않게 맞췄다. ADR-007 §8.

## 확정 · 근거

- **흰 화면.** 사용자가 dev 앱을 열 때 흰 화면이 오래 보인다고 알렸다(2026-11-20). dev는 서비스 워커가 `index.html`을 서버에서 먼저 받아(`sw.js`의 `IS_DEV`) 첫 화면이 늦게 그려지는데, 그동안 iOS가 시작 이미지 대신 흰 화면을 보였다. firt.dev(2026-10-13)는 매니페스트가 있어도 이 태그가 있어야 시작 이미지가 보인다고 한다. Apple 문서로는 확인하지 못했다. 태그와 세 크기를 넣은 dev에서 흰 화면이 사라졌다(사용자 확인).
- **십자가의 크기.** 시작 이미지가 보이자, 런치 스크린으로 넘어갈 때 십자가가 갑자기 커졌다가 흐려졌다(사용자 확인). 이미지는 옛 로고를 화면 짧은 변의 25%로, 런치 스크린은 2026-04-18에 바꾼 SVG를 30vmin으로 그렸기 때문이다. 생성기가 `index.html`의 런치 스크린 SVG를 읽어 같은 크기로 그리게 하고 16개를 모두 다시 만들었다. 뷰박스 밖으로 조금 나가는 부분도 페이지처럼 그려지게, 십자가 상자 전체 크기로 그린다.
- **주소의 `?v=2`.** 서버가 시작 이미지를 하루 동안 캐시하게 해, 주소가 같으면 휴대폰이 옛 그림을 보일 수 있다. 생성기의 `SPLASH_VERSION`으로 주소에 `?v=2`를 붙였다.
- **십자가의 높이.** 크기가 맞자, 넘어갈 때 십자가가 조금 내려갔다(사용자 확인). 시작 이미지는 상태 표시줄까지 덮는데 페이지는 상태 표시줄 아래에서 시작해서다. 기기별 상태 표시줄 높이를 표로 두지 않고, `js/pre-fetch.js`가 첫 페인트 전에 화면과 페이지의 높이 차이를 재어 그 절반만큼 십자가를 올린다. 이미 `<head>`에서 동기로 실행되는 스크립트라 새 파일도, CSP 변경도 필요 없다.
- **남은 깜빡임은 그대로 둔다**(사용자 결정 2026-11-20). 넘어가는 순간 화면 전체가 아주 짧게 깜빡인다. iOS가 시작 이미지를 치우는 순간이라 앱 쪽에서 막을 곳이 없다.
- **일부러 바꾸지 않은 것.** 시작 이미지는 어두운 것 하나뿐이다. 런치 스크린은 라이트 모드에서도 다크 배경이라(ADR-007 §1) 밝은 이미지가 필요 없다. 마스크 아이콘(`icon-512-maskable.png`)은 생성기가 다시 만들어도 픽셀이 같아 그대로 두었다.

## 검증

- 유닛 `node --test tests/unit/*.test.js`: 1,964개 통과(새 `pre-fetch.test.js` 4개 포함). `npm run typecheck` 통과.
- e2e: 런치 스크린이 닫히기를 기다리는 `test_bookmark_read.py` 3개와 `test_search.py`의 `test_search_url_refresh_navigates_and_dismisses_launch_screen` 통과.
- Chromium에서 시작 이미지와 런치 스크린을 겹쳐 보았다. 십자가의 너비와 높이 차이가 1-3px이었다.
- Chromium을 홈 화면 앱처럼 꾸며(화면 높이 874px, 페이지 높이 812px) 재었다. 십자가의 한가운데가 페이지 위에서 375px로, 화면 한가운데(437px에서 상태 표시줄 62px를 뺀 자리)와 같았다. 보통 브라우저에서는 406px로 움직이지 않았다.
- 아이폰 실기기(dev `bible-2.2.1-f9d1a9f-dirty`, 2026-11-20): 흰 화면이 사라졌고, 넘어갈 때 십자가의 크기와 높이가 그대로였다. 넘어가는 순간의 짧은 깜빡임만 남았다. 상태 표시줄 자리는 런치 스크린이 보이는 동안 시작 이미지와 같은 색이고, 그 뒤 평소 색으로 돌아갔다(사용자 확인).

## 리뷰 반영

1회차(`/code-review medium`, 10건).

- **고침.** 생성기가 십자가 상자의 크기와 비율을 `css/style.css`의 `#launch-screen svg`에서 읽는다(5번, 6번). 전에는 CSS의 값을 손으로 옮겨 적어, CSS만 바꾸면 이미지가 옛 크기로 나왔다. 기기 목록의 `dpr`도 다시 계산하지 않고 그대로 쓴다(리뷰가 고침). 다시 만든 그림 17개는 전과 픽셀까지 같았다.
- **고침.** `launchShift`는 창의 너비가 화면 너비와 같을 때만 십자가를 올린다(3번). 아이패드에서 다른 앱과 화면을 나눠 쓰는 창은 시작 이미지가 없는데, 높이 차이가 100px보다 작으면 십자가가 가운데에서 벗어났다.
- **고침.** books.json 시험이 받는 주소와 프로미스를 본다(7번, 리뷰가 고침). JSDoc의 `@param`을 한 줄에 하나씩 적었다(9번).
- **고치지 않음.** 4번(Chrome이 `apple-mobile-web-app-capable`을 낡은 태그로 경고)은 Chromium 148의 콘솔과 문제 목록(Issues)에 나오지 않아 재현되지 않았다. 8번(전역 이름 `launchShift`)은 겹치는 이름이 없고 시험이 이 이름을 읽는다. 10번(앱 안에서 다시 읽을 때도 십자가를 올림)은 그때 십자가가 화면 한가운데에 있어 어색하지 않다.
- **고침.** 요즘 아이패드 여섯 크기(744×1133, 810×1080, 820×1180, 834×1112, 834×1210, 1032×1376)를 더했다(1번, 권장안을 사용자가 고름). 크기는 Apple Human Interface Guidelines 「Layout」의 기기 화면 크기 표에서 읽었다. 이 표는 2026-09-09에 빠져 2026-06의 사본(Wayback Machine)을 썼다. 이미지는 22개가 되었고, 전부터 있던 16개는 다시 만들어도 그대로였다. 아이패드 실기기로는 확인하지 못했다.
- **고치지 않음.** 2번(아이폰 12 mini 이미지는 맞는 기기가 없다는 지적)은 빼는 쪽을 권했고 사용자도 골랐지만, 위 표가 12 mini와 13 mini를 360×780으로 적어 리뷰의 근거(375×812로 알림)와 맞지 않았다. 둘 가운데 어느 쪽인지 기기로 확인하지 못해, 남겨 두어도 손해가 없는 이미지를 그대로 두었다.
