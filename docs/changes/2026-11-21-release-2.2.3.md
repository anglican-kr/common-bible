## 요약

버전을 2.2.2에서 2.2.3으로 올린다(`python3 scripts/release.py patch`). 2.2.2 뒤에 검색할 책을 한 번에 빼는 「모두 지우기」(#622), 하단 알림이 탭 바를 가리지 않고 한 열에 쌓이는 것(#623), 전례독서 검색의 다른 이름이 들어간다. 다른 이름은 `연중34주일`과 `연중1주일`(데이터 #89, 포인터 #624)과 절기 이름(데이터 #90, 포인터 #626)이고, 결정은 #621과 #625가 적었다.

아래 「릴리스 노트 초안」은 머지한 뒤 GitHub Release에 그대로 쓴다. 「변경 사항」은 `python3 scripts/changelog.py 2.2.2 HEAD`의 출력이고, 끝의 비교 링크만 2.2.3 태그를 가리키게 고쳤다.

## 확정 · 근거

- **버전**(사용자 지시 2026-11-21): 2.2.3이다. 태그, GitHub Release, dev 배포, 운영 배포는 하나씩 사용자에게 묻는다.
- **노트의 짜임**(구현하며 정함, `docs/writing.md` 「릴리스 노트」).
  - 「기능 개선」: 절기 이름으로 찾기(데이터 #90), `연중34주일`과 `연중1주일`로 찾기(데이터 #89), 「모두 지우기」(#622). 모두 있던 검색을 더 낫게 바꾼 것이다. 「모두 지우기」는 2.2.2에 나온 책 알약에 더한 단추라 새 기능이 아니라 기능 개선으로 보았다.
  - 「버그 수정」: 2.2.2에도 있던 문제다. 업데이트 안내가 탭 바를 가리고 다른 안내와 겹치던 것(#623).
  - 「새 기능」은 없다.
- **노트에 넣지 않은 것.** #622의 별칭 표를 받기 전에 ×를 누르면 친 `in:`이 남던 문제는 사용자가 겪기 어려운 경합이라 넣지 않는다. #623의 스낵바 그림자와 글자 크기의 작은 차이(토큰으로 옮김)도 넣지 않는다.
- **릴리스마다 하는 정리**(CLAUDE.md 「지식 베이스 루프」 3번).
  - 2.2.2(2026-11-21) 뒤의 원장은 #621, #622, #623, #625의 넷이다(#624와 #626은 자동 포인터 PR이라 원장이 없다). 새 ADR은 없고, ADR-044 §3과 ADR-049 §3이 고쳐졌다.
  - 검색 주제 문서 「남은 일」의 「절기 이름의 별칭」은 데이터 #90의 색인이 포인터 #626으로 들어와 끝났다. 이 PR에서 「지금 동작」의 「이름 검색의 다른 이름」에 절기 이름을 옮기고 그 항목을 지웠다. 비슷한 말 항목의 「위 항목이 들어오면」도 지금의 문장으로 고쳤다.
  - `docs/index.md`와 실제 파일, 링크, 번호 대장은 문서 검사가 맞는지 본다(통과). 새 설계 문서는 없다. 200줄을 넘긴 문서(DESIGN.md, ADR-044, `docs/design/lectionary-search.md`)는 전부터 넘었고 이번에 몇 줄씩만 늘었다.

## 검증

버전 파일 둘을 2.2.3으로 바꾼 상태에서 점검했다.

- `node --test tests/unit/*.test.js`: 1,972건 통과. 타입 검사: 통과. 작업 폴더에 `node_modules`가 없어 원래 폴더의 `tsc`(7.0.2)로 `npm run typecheck`와 같은 두 설정을 돌렸다(`package-lock.json`은 main과 같다).
- CSP 점검: `python3 -I tools/csp/csp_sweep.py http://localhost:8093`(서비스 워커 막음)과 `--sw`(켬) 모두 위반 0종. 건너뛴 단계는 이 브라우저에서 할 수 없는 데스크톱 오디오 재생 하나다(2.2.2와 같다).
- e2e(작업 폴더 서버 8093): 160건 통과. 버전과 관련된 `test_update_toast.py`(9, #623이 더한 하단 알림 시험 포함)와 `test_liturgical_lazy_load.py`(11), 이번 판에서 바뀐 `test_tabbar.py`(26, #623)와 `test_search.py`(114, #622와 데이터 #89, #90의 새 색인)다. 기능 PR들의 e2e 결과는 그 원장들에 있다.
- 휴대폰 화면의 헤드리스 Chromium으로 8093 서버에서 노트의 검색을 확인했다. `성주간` 7건(성지주일부터 성 토요일), `대림절기`와 `대림절` 36건, `사순절기`와 `사순절` 53건, `성탄절기` 24건, `부활절기` 52건, `연중시기` 259건이고, `연중34주일`과 `연중1주일`은 왕이신 그리스도 주일과 주님의 세례가 맨 앞이다. 콘솔 오류는 없었다.
- 배포한 뒤 dev의 `version.json`이 2.2.3인지 실제 사이트에서 확인한다.

## 갱신한 문서

- `docs/topics/search.md`: 「지금 동작」의 「이름 검색의 다른 이름」에 절기 이름을 더하고, 「남은 일」에서 「절기 이름의 별칭」을 지우고 비슷한 말 항목의 문장을 고쳤다.

## 릴리스 노트 초안

### 기능 개선

- 전례독서 검색에서 절기 이름으로 그 절기의 날을 모두 찾을 수 있습니다. ‘성주간’으로 찾으면 성지주일부터 성 토요일까지 일곱 날이 나오고, ‘대림절기’, ‘성탄절기’, ‘사순절기’, ‘부활절기’, ‘연중시기’로 찾으면 그 절기의 날이 모두 나옵니다. ‘사순절’이나 ‘대림절’로 찾아도 됩니다. 지금까지는 ‘성주간’으로 찾으면 성주간 월요일부터 수요일까지만 나왔습니다.
- 전례독서 검색에서 ‘연중34주일’로 찾으면 왕이신 그리스도 주일이, ‘연중1주일’로 찾으면 주님의 세례가 맨 앞에 나옵니다. 지금까지는 그 주의 평일만 나왔습니다.
- 검색할 책을 두 권 이상 골랐으면 책 알약 줄 끝의 ‘모두 지우기’를 눌러 고른 책을 한 번에 빼고 모든 책에서 다시 찾을 수 있습니다. 지금까지는 알약의 ‘×’를 한 권씩 눌러야 했습니다.

### 버그 수정

- 휴대폰에서 “새 버전이 있습니다” 안내가 화면 아래의 탭 단추를 가리고, 북마크나 동기화의 안내와 겹쳐 뜨던 문제를 고쳤습니다. 이제 안내는 화면 아래의 단추와 막대 위에 차례로 쌓이고, 같은 안내는 하나만 보입니다.
