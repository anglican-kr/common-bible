# docs: ADR-015 클라이언트 스토리지 전략

## 요약

Phase 2h에서 IndexedDB가 처음 도입되며 클라이언트 스토리지 메커니즘이 4종(localStorage / sessionStorage / IndexedDB / Cache API)으로 늘었으나 어디에 무엇을 둘지에 대한 단일 기준 문서가 없었다. 이미 코드가 자리잡은 분리 형태를 **사후 명문화**하고, 앞으로의 추가가 같은 분류 안에 들어오도록 결정 트리·키 카탈로그를 박아두는 ADR.

## 핵심 결정

| 메커니즘 | 용도 | 두지 않는 것 |
| --- | --- | --- |
| localStorage | 사용자 설정, 동기화 메타·세션 플래그, 동기 접근 KV (북마크 v2 doc 포함) | 자격 증명, 암호 키, 대용량 바이너리 |
| sessionStorage | OAuth PKCE 콜백 일회성 상태 (탭 수명 + 단일 사용 후 폐기) | 영구 데이터 |
| IndexedDB | 비공개 자격 증명·암호 키 전용 (`extractable: false` AES-GCM CryptoKey + 암호화 refresh token) | 평범한 사용자 KV |
| Cache API | 정적 자산 (`shell-*` / `data-*` / `audio-*` / `fonts-*` 4개 캐시 독립 bump) | 사용자 데이터 |
| Cookies | **사용 안 함** | — |

검토한 대안은 (A) 모두 localStorage(평문 refresh token + non-extractable CryptoKey 직렬화 불가로 기각), (B) 모두 IndexedDB(첫 페인트 동기 경로 깨짐 + ADR-013 vm 하네스 의존성 증가로 기각), (C) 메커니즘별 책임 분리(채택, 기존 코드 그대로).

## 포함 내용

- `docs/decisions/015-storage-strategy.md` 신규
  - localStorage 카탈로그 (설정 동기화 / 로컬 전용 / 북마크 v2 / 동기화 메타 4그룹)
  - sessionStorage 카탈로그 (`bible-drive-redirect-state-pkce`)
  - IndexedDB 카탈로그 (`bible-drive-sync` DB · `keys`/`tokens` store)
  - Cache API 4개 캐시 정책
  - 키 네이밍 컨벤션 (`bible-*` 케밥, `-v2` 버저닝)
  - 새 데이터 추가 시 결정 트리
  - 미결: 북마크 v2 → IDB 승격 임계, `navigator.storage.persist()`, quota 모니터링
- ADR-010·011·014와 교차 참조
