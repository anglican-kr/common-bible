# docs: 교회력 데이터 현실 반영 + 엔진 설계서 신설 — 사계재 조인 절반 해소·성 목요일 대축일 확정

데이터 저장소가 엔진(A1) 착수 전에 결손을 메우는 동안 앱 쪽 기록이 따라가지 못했다. 설계서가 「엔진이 견뎌야 할 데이터 현실」로 못박아 둔 항목들이라, 그대로 두면 **이제 존재하지 않는 제약에 맞춰 구현하게 된다.**

> **이 설명은 리뷰를 거치며 결론이 바뀐 항목이 있어 갱신했다.** 아래가 현재 상태다.

## 밑바탕 세 커밋

- `4c93857` 낡은 서술 정정 — 전례시편 편집 완료·KASI 음력 입력 완료
- `7883aae` **교회력 계산 엔진 설계서 신설** — 모듈 배치·API·알고리즘·조인 전략·테스트 계획. 전 11개 JSON 을 전수 집계해 ADR 서술과 실제 데이터의 차이를 §5.2 에 못박았고, 실측이 초안을 세 곳에서 반증해 정정했다.
- `ee9da67` ADR-037 미결5(격자 빈 칸)·ADR-036 미결12(사계재 규칙 열) 해소 반영

## data PR#17 반영 — 사계재

| | 종전 | 지금 |
|---|---|---|
| 사계재 본기도 `weekday` 보유 | 6 / 16 | **16 / 16** |
| 사계재 독서 | 17 | 20 |
| `_review` | 21 | **0**(대신 `_note` 1) |
| 본기도 전체 | 338 | **328** |

요일 배정이 기도서로 확정됐다 — **수=성직자 · 금=성직후보자·수도자(2본) · 토=모든 신자**, 네 계절 공통.

**ADR-036 미결13 은 「절반 해소」다.** 요일 배정은 닫혔지만 **계절 식별자가 없다** — 사계재 계절이 temporal·본문 양쪽 모두 한국어 `name` 안에만 있어(`coord_name: null`·`season: null`) 오늘의 조인은 이름 부분문자열에 기댄다. 명시적 기계 키가 데이터 쪽 후속 과제다.

## data PR#20 반영 — 성 목요일 = **대축일**

처음 PR#17 에서 「성 금요일과 같은 등급」으로 **대재일**을 넣었으나, 리뷰가 저장소의 정본 전사(대재일 = 재의 수요일·성 금요일 둘뿐)와 충돌한다고 잡아 **대축일로 정정**했다.

```
성 목요일   rank=principal  prec=1  type=feast  color=red
성 금요일   rank=principal  prec=1  type=fast   color=red
```

성삼일 첫날이라 품계는 같지만 **재일은 아니다**. 색은 홍색 그대로(전사가 성주간 전체를 홍색으로 두고 성 목요일을 이름까지 열거). 등급 칸이 품계와 참회를 함께 정하는 현 모델에선 대축일이 유일한 답이고, 품계·참회 분리는 산출 스키마 정비 때 볼 것으로 적었다.

## 리뷰가 드러낸 설계 공백 — §9 미결 8~11

설계서가 답을 갖고 있지 않던 자리를 지어내지 않고 미결로 올렸다:

- ~~**8. 주일 주기(A/B/C) 기준 연도**~~ **해소** — **2026년 = 가해**(사용자 확정). 유도 규칙(`N % 3` → 1 A · 2 B · 0 C)과 대림 경계 네 날을 회귀 케이스로 적었다.
- **9. 옮겨온 축일을 목적지에서 찾는 경로가 없다** 🔴
- **10. 주님의 세례가 좌표를 둘 요구한다** 🔴
- **11. `findReadings` 에 성인 공통 폴백이 없다** 🔴 — `commons.json` 은 분류별 독서를 이미 갖고 있다(7분류 22세트). 데이터가 아니라 **조회 규칙**이 없다.

그 밖에 거부된 promise 영구 캐시, 구체성 점수가 `collect_no` 대체안을 삼키던 서술, 조회 함수가 좌표만 받아 이름일·고정일 본문에 닿지 못하던 시그니처를 고쳤다. `national` 4건 조인은 실측으로 **미결7 쪽이 틀렸음**이 드러나 해소했다(음력 두 건이 `date` 조인에서 빠졌던 것).

## 문서만 바뀌지 않는다 — 검증과 자동화가 함께 들어간다

리뷰가 일곱 라운드에 걸쳐 계속 지적을 낸 원인이 **같은 수치가 여러 문서에 흩어져 있고 사람이 한두 곳씩 고친다**는 것이라, 손으로 맞추는 데서 끝내지 않았다.

- **`tests/unit/docs-data-consistency.test.js` 신설** — 설계서 §5.2 의 ```facts 블록(35키)이 「현재 실측」의 단일 정본이고, 이 테스트가 `data/lectionary/` 에서 직접 계산한 값과 양방향으로 견준다(문서가 측정 못 하는 키를 주장해도, 측정 가능한 키가 블록에서 사라져도 실패).
- **`sync-data.yml` 에 대조 단계 추가** — `data/` 는 비공개 서브모듈이라 공개 저장소의 Unit tests 잡에는 체크아웃되지 않는다(없으면 skip). 실제로 도는 자리는 로컬과 여기 — **포인터가 올라가 문서가 낡는 바로 그 순간**이다. 어긋나면 PR 을 열기 전에 멈춘다.
- **`data` 서브모듈 포인터 16커밋 갱신**(`6808bbe` → `ca05b26`) — 위 테스트가 첫 실행에서 잡았다. 문서는 328 collects 를 말하는데 앱이 물고 있던 데이터는 334 였다. 앱이 실제로 읽는 파일 중 바뀌는 것은 `bible-manifest.json` 5줄뿐이다(`books.json`·`search-*`·`bible/` 무변).

자동으로 안 올라갔던 원인은 data 저장소 쪽 결함이라 따로 잡았다 — [data#21](https://github.com/anglican-kr/common-bible-data/issues/21) · [data#22](https://github.com/anglican-kr/common-bible-data/pull/22).
