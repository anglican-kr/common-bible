# fix: 1.5.4 SW 셸 캐시 stale 문제 + 1.5.5 릴리스

## 증상

1.5.4 로 업데이트한 사용자가 하단 푸터에는 `공동번역성서 1.5.4` 가 보이지만 설정 팝오버에는 1.5.4 신규 기능인 **"업데이트 [지금 확인]"** 행이 안 보임. 같은 릴리스의 팝오버 세로 스크롤 CSS 도 함께 빠짐.

즉 SHELL_CACHE 이름은 `shell-1.5.4` 로 바뀌었는데, 그 캐시 안에 들어간 `js/app/settings-ui.js` 본문은 1.5.3 이하 버전.

## 원인 분석

`version.json` 만 fresh 한데 같은 SHELL_CACHE 의 JS·CSS 는 stale 한 패턴은 — release 마다 바이트가 변하는 `version.json` 만 매 응답이 새 etag 라 통과되고, 안정 URL 의 `/js/app/settings-ui.js` 같은 파일은 등록된 etag·max-age 가 그대로라 CDN/엣지/origin 어느 단에서 200 + 옛 바이트로 응답 — 으로 가장 잘 설명됨.

`sw.js` 의 install 핸들러는 `{ cache: "reload" }` 로 fetch 하지만, 이 옵션은 **브라우저** HTTP 캐시만 우회. 그 위 단의 stale 응답은 그대로 받아들여 SHELL_CACHE 에 저장됨 → 새 SW 가 활성화되어도 옛 코드가 실행.

## 변경

`sw.js` install 핸들러에서 각 셸 URL 을 `<url>?v=<APP_VERSION>` 으로 fetch 해 중간 캐시 키를 강제로 새로 만들고, `cache.put` 은 쿼리 없는 원본 Request 로 저장 (페이지 런타임 요청 매칭 보존).

원자성: 모든 fetch 를 먼저 await 한 뒤 한꺼번에 put — `cache.addAll` 의 all-or-nothing 시맨틱 유지. 중간 fetch 실패 시 SHELL_CACHE 는 이전 상태 그대로.

## 회복 경로

- 이번 fix 는 1.5.5 SW 의 install 시점에 효력 발생. 현재 1.5.4 stale 캐시에 갇힌 사용자도 1.5.5 SW 가 install·activate 되는 순간 자동 회복.
- 즉시 회복 원하면 설정 팝오버의 **"캐시 초기화"** 버튼 (모든 캐시 삭제 + SW unregister + 새로고침).

## 후속 검토 (이 PR 범위 외)

근본은 nginx 응답 헤더 (`common-bible-server` 저장소). `/js/**`, `/css/**`, `index.html`, `sw-version.js` 에 `Cache-Control: no-cache` 또는 짧은 `max-age` 로 일관 정책 검토 필요.
