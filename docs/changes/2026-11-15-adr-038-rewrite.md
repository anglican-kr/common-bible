## 요약

ADR-038(교회력 캘린더, 전례독서 화면, 검색 이원화)을 새 틀로 다시 썼다. 결정을 날짜순 목록으로 늘어놓아 읽기 어렵다는 사용자 지적에서 시작했다.

- 맨 앞에 「요약」을 두었다. 각 절은 결정을 먼저 쓰고, 조건마다 동작이 다른 것(탭을 누른 곳에 따라 가는 곳, 주소, 보기 전환, 후보마다 보이는 곳, 라벨)은 표로 바꿨다.
- 본문에서 뺀 결정의 날짜와 출처 107줄은 절마다 나눈 「결정 기록」 표로, 상태 줄의 구현 단계는 「구현 기록」 표로 모았다.
- 구현 세부(측정값, 브라우저 사정, 함수 이름과 저장 키)는 `docs/topics/liturgical.md`의 「지금 동작」으로 옮겼다.
- 결정 본문(§1-§5)은 77,690바이트에서 58,394바이트가 됐다. 결정 기록이 더해져 ADR 전체는 134,753바이트에서 133,700바이트다.
- `docs/topics/liturgical.md`의 「지금 동작」을 기능이 생긴 날짜순이 아니라 기능별 소제목 18개(교회력 엔진, 캘린더, 전례독서 화면, 소속교회와 세례명, 모듈 로드, 교회력 데이터)로 다시 묶고, 바뀐 내력을 덜어냈다. 126,200바이트(534줄)에서 95,593바이트(436줄)가 됐다.
- `docs/writing.md`에 「ADR의 틀」(틀, 규칙, 수명)과 번역 투 규칙을 적고, CLAUDE.md 「ADR 워크플로우」와 `docs/index.md`의 ADR 설명을 수명 규칙에 맞췄다. `docs/topics/README.md`에 「지금 동작」의 틀(기능별로 묶고 내력은 적지 않는다)을 적었다.
- `docs/writing.md`의 규칙마다 붙어 있던 「(사용자 교정, 날짜)」 같은 출처를 지우고, 맨 앞에 「규칙은 모두 사용자가 정하거나 교정한 것이고, 언제 왜 정했는지는 원장과 git에 있다」는 한 줄을 두었다. 「용어」 표의 「근거」 칸도 뺐다. `coding-pitfalls.md` 대장의 같은 제목 여섯도 맞췄다.

## 확정 · 근거

- 사용자 결정(2026-11-15):
  - ADR은 결정을 날짜순 목록으로 쓰지 않고 「요약, 배경, 결정, 검토한 대안, 결정 기록, 구현 기록」의 틀로 쓴다. 긴 ADR(036, 037, 038)을 하나씩 다시 쓰고 038부터 한다.
  - 구현 세부는 ADR 안의 하위 항목으로 두지 않고 주제 문서로 옮긴다. 앞부분(§1, §2)을 먼저 보이고 모양을 확인받은 뒤 나머지로 넓혔다.
  - ADR의 수명: 같은 방향 안의 결정은 제자리에서 고치고, 방향이 바뀌면 새 ADR을 쓴다. 한 ADR에는 결정 하나를 둔다. 설계 문서의 미결이 정해지면 ADR로 옮긴다. ADR이 설계 문서, 지금 동작, 변경 이력의 일까지 떠맡아 길어졌다는 진단에서 나왔다.
  - Y 문장 요약과 「초안」 상태처럼 나이가드 이후 방법론의 장치는 더하지 않는다. 조사는 했다(나이가드 2011, MADR 4.0.0, 구글 설계 문서, adr.github.io, ecADR, 아키텍처 조언 과정, 디아탁시스).
  - §3-1의 라벨 표를 지금 구조에 맞췄다. 주간 보기는 없고 캘린더 목록의 줄은 독서 세트와 트랙을 늘어놓지 않으므로, 「월간과 주간의 칸」과 「캘린더 목록에서 독서 세트를 늘어놓을 때」 줄을 고쳤다. 라벨의 예는 데이터 PR #77 뒤의 제목 「연중10주일」로 맞췄다.
- 사용자 교정(2026-11-15): 번역 투(「범위 밖:」 같은 쌍점 머리말, 「맞은 독서」 같은 낱말 단위 직역, 「권장은 …」 문형)를 쓰지 않는다. 전례독서 검색 설계서(PR #566)를 다듬다 나온 교정이고, 규칙은 이 PR의 `docs/writing.md`에 적었다.
- 일부러 바꾸지 않은 것: 제목 줄, 절 번호, 다른 문서와 코드 주석이 「ADR-038 §3 「전례일 스위처」」처럼 인용하는 소제목(인용 약 300곳), 「검토한 대안」 이하의 본문. 다만 「후속」 절 뒤에 잘못 붙어 있던 「목록 위쪽에 줄을 더하는 때」는 「검토한 대안」 안으로 옮겼다.
- 「결정 기록」을 절마다 나눈 까닭: 한 표의 「절」 칸에 「§3」을 적으니 문서 검사가 ADR-038과 설계서 양쪽에 있는 번호라는 경고를 127건 냈다. 절마다 표를 나누고 소제목에 「(이 문서 §3)」을 한 번 적어 경고를 main보다 적게 했다.
- 「고유 독서가 있는데 글로 보이는 날」의 셈은 ADR이 52일, 주제 문서가 33일로 어긋나 있었다. 52일은 #473 때 센 값이고, #476 뒤에 주제 문서만 다시 셌다. ADR에서 빼고 주제 문서에 그 내력을 남겼다.
- §3부터 §5까지는 작성 에이전트가 §1, §2를 본보기로 다시 썼고, 이끄는 세션이 검사를 다시 돌리고 본문을 읽어 검토했다.
- 사용자 결정(2026-11-15): 주제 문서의 「지금 동작」에서 바뀐 내력은 최대한 덜어낸다. 언제 결정했는지, 더 이상 유효하지 않은 것은 버린다. 「지금 동작」도 날짜순일 까닭이 없다. 규칙 문서의 「(사용자 교정, 날짜)」 꼬리표도 필요 없다. 사용자가 `docs/writing.md`의 일부를 직접 지운 뒤 이어서 마저 정리했다.
- 「지금 동작」에서 덜어낸 것(작성 에이전트가 세고, 이끄는 세션이 검토했다):
  - 결정 날짜와 출처 84곳, 항목 제목의 날짜 59곳. 남은 날짜는 동작의 예나 측정 조건이다.
  - 예전 동작을 말하는 문장 69곳, 테스트 줄 38개, 앱과 데이터 PR 번호 36개와 리뷰 이력, 이 주제와 무관한 곁가지 5건
  - 더 이상 맞지 않는 사실 39건. 예: 주간 보기, 트랙 세그먼트와 「독서 1 · 2」 세그먼트, 「선택 봉헌은 독서 카드 두 장」, 연쇄 범위 규칙, 「· 기념만」 표시, 「대안 세트 세 갈래」, 독서와 본기도 레코드 수(906건 등)처럼 그 뒤 데이터가 바뀐 셈, ADR의 「52일」. 지금 코드나 데이터 버전 `9f65ea1`로 맞는지 확인한 것만 남겼고, 새로 센 값은 문서에 더하지 않았다.
- 다른 문서가 이름으로 가리키는 항목(「부활 8일 평일의 축일은 책자대로 그날 지킨다」 등)은 굵은 항목 이름으로 남겼다. ADR-038과 함정 §24가 가리키던 옛 항목 이름은 새 소제목으로 고쳤다.
