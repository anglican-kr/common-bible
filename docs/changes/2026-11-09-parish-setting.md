## 요약

설정의 전례독서 섹션에 소속교회를 고르는 선택 상자를 더한다(ADR-041 §6, §7, §9). 교회 이름이 아니라 데이터 본당 표의 교회 식별자(data#69)를 저장하고 동기화한다. 소속교회 앱 작업을 나눈 세 PR의 첫째라 고르기와 저장만 한다. 고른 교회의 축성일 화면과 교구 설립일 본기도는 다음 PR이다(ADR-041 §11).

## 확정 · 근거

- **앱 작업은 작은 PR 셋으로 나눈다**(사용자 결정 2026-11-09). 이 PR만으로는 고른 교회가 화면을 바꾸지 않는다. ⓘ 설명(「교회 축성일과 교구설립일에 그날의 전례독서와 본기도를 보여줍니다.」)이 사실이 되려면 다음 두 PR이 필요하므로, 운영 배포는 세 PR이 모두 들어간 뒤가 좋다.
- **ADR-041 §6의 「32자」는 셈이 틀렸다.** 0, o, 1, l, i를 빼면 숫자 8자와 소문자 23자로 31자이고, 데이터(data#69)도 31자로 만들었다. ADR을 고쳤다.
- 목록을 받는 동안(「불러오는 중」), 받지 못했을 때(「목록 없음」과 행 아래 안내), 저장한 값이 목록에 없을 때(「선택 안 함」으로 보이되 지우지 않음)의 동작은 구현하며 정한 방침이다. 사용자가 고른 것이 아니다. ADR-041 §9에 적었다.
- **동기화가 숫자처럼 생긴 식별자를 바꾸는 문제를 막았다.** 옛 키의 설정을 동기화 저장소로 옮길 때 값을 JSON으로 읽어, `2345e6`은 2345000000이 되고 `2e9999`는 「null」로 쓰인다. 지금 식별자 152개에는 이런 값이 없지만 새 교회의 값은 그럴 수 있어, 소속교회 값은 그대로 옮긴다. 앱이 그대로 옮기므로 데이터 쪽에서 이런 값을 막는 검사는 넣지 않았다.
- 소속교회와 백업 & 동기화의 ⓘ 단추는 같은 부품(`makeInfoButton`)이다. CSS를 바꾸지 않으려고 「drive」가 들어간 기존 클래스를 그대로 쓴다. 그래서 단추를 클래스로 찾던 동기화 e2e 하나가 단추 둘을 만나 실패했고, 접근 가능한 이름으로 찾게 고쳤다. 두 단추 모두 여는 설명을 `aria-controls`로 가리킨다.
- 개인정보처리방침의 기기 내 저장과 Drive 동기화 항목에 소속교회를 더하고 최종 수정일을 바꿨다(ADR-041 §8).
