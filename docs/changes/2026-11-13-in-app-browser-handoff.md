## 요약

메신저나 SNS 앱에서 공유된 링크를 누르면 그 앱 안의 브라우저(인앱브라우저)로 열린다. 여기서는 「홈 화면에 추가」를 쓸 수 없는데, 앱은 인앱브라우저를 구분하지 않아 iOS에서는 따라 할 수 없는 Safari 안내를, Android에서는 눌러지지 않는 설치 단추를 보였다.

이제 인앱브라우저를 UA로 알아보고, 전환 주소를 아는 앱(카카오톡, 라인, 네이버, 인스타그램, 페이스북)에서는 첫 화면을 그린 뒤 기기의 브라우저로 옮긴다. 보고 있던 주소를 그대로 넘긴다. 옮기지 못한 경우와 이름을 모르는 웹뷰에서는 설치 안내 모달이 「브라우저에서 열기」와 「주소 복사」를 보인다. 결정은 ADR-008 §7에 있다.

## 확정 · 근거

- **자동 전환은 사용자 결정이다**(2026-11-13). 설치 안내를 열었을 때만 내보내는 방법을 권했으나 사용자가 자동 전환을 골랐다. 버린 선택지는 ADR-008 「검토한 대안」에 적었다.
- **전환은 첫 화면을 그리고 문서를 다 읽은 뒤에 한다.** 처음에는 모듈이 실행되자마자 전환했는데, 테스트 브라우저(Chromium)에서 남은 스크립트가 실행되지 않아 빈 화면이 남았다. 첫 화면 뒤로 옮기자 이번에는 `load` 이벤트가 끝나지 않았다. 전환이 실패해도 본문이 남도록, 시작 코드의 맨 끝에서 부르고 `load`를 기다린다.
- **이름을 모르는 웹뷰는 자동 전환하지 않는다.** `intent://`를 처리하지 않는 Android 웹뷰는 본문 대신 오류 화면을 보인다.
- **탭 세션에서 한 번만 시도한다.** 전환한 뒤에도 인앱브라우저의 화면은 뒤에 남는다. 사용자가 돌아와 새로 고칠 때 다시 다른 앱으로 넘어가지 않게 한다. 시도를 기억할 수 없으면(`sessionStorage`를 쓸 수 없으면) 전환하지 않는다.
- **인앱브라우저를 자동 안내 대상에 넣었다.** 이것은 작성자가 정했다. 전환이 실패하면 사용자가 아무 안내도 받지 못하기 때문이다. 첫 방문에는 뜨지 않는 기존 규칙을 그대로 따른다.
- **실기기에서 확인하지 못했다.** 전환 주소는 널리 쓰이는 방법이지만 이 환경에서는 실제 앱으로 시험할 수 없다. 특히 iOS의 `x-safari-https://`는 Apple이 문서로 밝히지 않았다. 주제 문서의 「남은 일」에 적었다.

## 검증

- `node --test tests/unit/*.test.js`: 1,722개 통과(인앱브라우저 10개 추가). `npm run typecheck` 통과.
- `pytest tests/e2e/test_install_guide.py`: 24개 통과(인앱브라우저 4개 추가). 다른 e2e 파일은 돌리지 않았다. 바꾼 코드는 설치 모듈과 시작 코드의 마지막 한 줄이다.
- 테스트 브라우저에서 UA를 바꿔 손으로 확인했다. 카카오톡(Android)과 네이버(iOS) UA에서 본문이 그려진 뒤 전환을 한 번 시도하고 모달에 두 단추가 나온다. 이름을 모르는 웹뷰 UA에서는 전환을 시도하지 않고 「주소 복사」만 나온다. Safari UA에서 `?openExternalBrowser=1`이 붙은 주소로 열면 쿼리가 주소에서 지워진다.
- 실제 카카오톡, 라인, 네이버, 인스타그램, 페이스북 앱에서는 확인하지 못했다.
