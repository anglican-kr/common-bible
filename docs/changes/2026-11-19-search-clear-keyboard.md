## 요약

휴대폰 하단 검색 입력창의 검색어 지우기(⊗)가 키보드를 새로 띄우지 않는다. 입력 중이라 키보드가 떠 있었으면 입력에 포커스를 남기고, 결과를 보던 중처럼 키보드가 없었으면 포커스를 같은 입력창의 깔때기(책 선택)로 옮긴다. ADR-030 §3과 「검토한 대안」을 고쳤다.

## 확정 · 근거

- 사용자 요청(2026-11-19): 검색 결과 화면에서 검색창의 ⊗를 누르면 검색어가 지워지고 최근 검색 목록으로 돌아가는데, 그때 키보드가 올라오지 않으면 좋겠다. 아이폰에서 본 것이다. 원인은 지우기 단추가 늘 입력에 포커스를 주던 것(`tabbar.js`, 처음 구현부터의 동작)이다.
- 구현하며 정한 것(제안, 사용자 확인 전)
  - 입력 중에 지우면 입력에 포커스를 남긴다. 키보드가 이미 떠 있으니 새로 띄우는 것이 아니고, 지운 뒤 바로 새 검색어를 친다.
  - 키보드가 없을 때는 포커스를 깔때기로 옮긴다. 지우기 단추는 검색어가 없으면 숨겨져 포커스가 그 자리에 남을 수 없고, 아무 데도 두지 않으면 포커스가 페이지 맨 앞으로 떨어진다(WCAG 2.4.3). 책 선택 시트의 「적용」도 휴대폰 키보드가 결과를 가리지 않게 깔때기로 포커스를 돌린다(ADR-033 D3).
  - 입력에 포커스가 있었는지는 단추의 `pointerdown`에서 읽는다. 탭이 포커스를 옮기기 전이다. 키보드로 단추를 누르면 `pointerdown`이 없어 깔때기로 간다.
  - 데스크톱 상단 바의 검색어 지우기(`search.js`)는 그대로 입력에 포커스를 준다. 화면 키보드가 없다.

## 검증

- `npm run typecheck` 통과, `node --test tests/unit/*.test.js` 1,957개 통과.
- e2e `test_tabbar.py` 18개를 작업 폴더 서버(8091)에서 돌려 통과했다. 새 시험 `test_clear_keeps_the_keyboard_as_it_was`는 결과 화면에서 지우면 포커스가 깔때기로 가고, 입력 중에 지우면 입력에 남는지 본다. 고치기 전의 `tabbar.js`로 돌리면 실패한다.
- 아이폰의 화면 키보드는 이 환경에서 볼 수 없다. dev에 올린 뒤 실기기에서 확인한다.
