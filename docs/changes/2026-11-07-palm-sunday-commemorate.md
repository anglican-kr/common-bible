## 요약

성지주일에 걸린 축일을 생략하지 않고 그날 기념한다. 2023-2050년에서 바뀌는 날은 2027년과 2032년의 3월 21일 두 날이다. 그날 제목은 성지주일이고, 제목 아래 회색 줄에 토마스 크랜머 축일이 새로 보인다. 독서, 본기도, 색은 성지주일의 것 그대로다. 캘린더의 달 칸은 그대로이고, 주간과 목록 줄의 흐린 「토마스 크랜머 · 생략」은 보통 글 「토마스 크랜머」가 된다.

성주간의 평일에 걸린 축일은 전처럼 생략한다. 엔진은 생략에 쓰는 기간을 새 구간 `holyWeekAfterPalm`(성지주일 다음 날부터 성 토요일까지)으로 나눴다. 설계서 R-6.1-prec7-omit, R-6.3-holy-week-guard, ADR-036을 따른다.

## 확정 · 근거

- **기념으로 바꾼 근거는 규정이다**(사용자 결정 2026-11-07). 교회력 규정 「축일」은 성주간과 겹치면 생략한다고 적고, 같은 절에 「지역고유축일이나 절기주일에 지켜야 한다면 기념한다」고 적는다. 데이터는 성지주일을 절기주일로 두므로 그날에는 두 문장이 함께 적용되고, 사용자는 뒤 문장을 따르기로 했다. 성주간의 평일은 절기주일이 아니어서 생략만 적용된다.
- **검토용 책자의 차이로 데이터를 고치지 않는다는 결정(pitfalls §22)과 부딪히지 않는다.** 근거가 규정이고, 데이터 표는 바꾸지 않았다.
- **「2027 책자는 크랜머를 싣지 않았다」를 문서에서 근거로 쓰지 않는다.** 이 문장은 2026-10-12에 받은 판에만 맞다. 사용자가 본 수정 검토본은 3.21에 크랜머를 기념일로 적었다. 그 판의 파일은 받지 못해 대조하지 않았다.
- **폴리갑은 바꾸지 않는다.** 기도서와 데이터의 날짜는 2.23이다. 10-12 저장본은 2.23, 3.9, 3.23, 4.6의 화요일 칸(14, 16, 18, 20쪽의 같은 좌표)에 이름을 적었다. 이 반복은 이미 초안 오류로 기록해 두었고, 사용자가 본 판은 3.23의 이름을 지웠다.
- **일부러 바꾸지 않은 것.** 「성주간 X요일」 이름과 색 보호는 `holyWeek`를 그대로 쓴다. 주요축일의 처리와 옮김 계산도 바꾸지 않았다.
- **사제 확인은 남았다.** 성지주일을 규정의 「절기주일」로 보는 것은 데이터의 분류이고, 규정 문서에는 절기주일의 정의가 없다. 설계서 미결46에 물음을 더했다.

## 검증

- 유닛 `node --test tests/unit/*.test.js`: 1,556건 통과, 실패 0(원장을 더한 뒤 다시 실행했다).
- 타입 검사 `npm run typecheck`: 통과.
- 전후 비교: `tools/booklet/engine-dump.mjs`로 1900-2100년 73,414일을 main과 이 브랜치에서 덤프해 견줬다. 바뀐 날은 성지주일 6일(1937, 1948, 2027, 2032, 2100년의 토마스 크랜머, 1940년의 패트릭)이고, 달라진 값은 그 성인의 상태(`omitted`에서 `commemorated`)뿐이다. 그날의 대표, 색, 전례독서 목록, 옮김 결과(기준 파일 포함)는 그대로다.
- 화면: 실제 앱을 Chromium으로 열어 확인했다. 2027-03-21과 2032-03-21은 제목 성지주일, 이름 줄 「토마스 크랜머(캔터베리 대주교, 전례개혁자, 순교자, 1556년) 축일」, 본기도 하나다. 2035-03-21(성주간 수요일)에는 이름이 없다.
- e2e `tests/e2e/test_lectionary_view.py`: 78건 통과. 바뀐 결과가 보이는 곳이 전례독서 화면과 캘린더의 줄인데, 캘린더는 코드를 바꾸지 않았고 줄의 값은 실데이터 유닛으로 확인해 이 파일만 실행했다.
