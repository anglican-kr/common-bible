## 요약

교회력 설계서(`docs/design/liturgical-engine.md`)를 장마다 파일 하나로 나눴다. 장 파일 아홉 개는 `docs/design/liturgical-engine/` 아래에 있고, 옛 파일에는 머리(제목, 상태, 구현 파일, 관련 ADR)와 목차만 남겼다. 글자를 그대로 옮겼다. 문장을 고친 곳은 검토 중에 받은 교정 둘(§1.1 목적 문장, 「계약」의 풀이)이 닿은 곳뿐이다. 절 번호, 규칙 마커, 미결 번호도 그대로다. known-issues §24에서 설계서 본문을 고쳐 쓴 뒤에 하기로 한 일이다(#414).

문서 검사 테스트 셋과 사실 토큰 도구는 목차와 장 파일을 차례로 이어 붙여 설계서 하나로 읽게 고쳤다. 검사가 실패하면 위치를 이어 붙인 글의 줄이 아니라 장 파일의 줄로 보여 준다.

## 확정 · 근거

- **옛 경로는 목차로 남겼다**(사용자 결정, 2026-10-24). 머지된 원장 36개가 이 경로를 가리키고, 머지된 원장은 고칠 수 없다. 파일을 지우면 그 링크가 열리지 않는다.
- **파일 이름은 장 번호와 내용 낱말로 지었다**(사용자 결정, 2026-10-24). `01-overview.md`부터 `09-open-items.md`까지다. 순번만으로 짓지 않는다는 원장 이름 규칙과 맞췄다.
- **큰 장은 더 나누지 않았다**(사용자 결정, 2026-10-24). §6과 §9가 크지만 이번에는 장 단위로만 나눴다.
- **§1.1 목적 문장은 사용자가 고쳤다**(사용자 교정, 2026-10-24). 엔진이 계산하는 것을 「무슨 날」에서 「어떤 전례일」로, 독서와 본기도를 찾는 단위를 「그 좌표」에서 「각 전례일」로 바꿨다. 조회 함수가 좌표를 받지 않는다는 §1.3의 넷째 항목과도 맞는다. 사용자 요청으로 같은 쓰임 다섯 곳(「그날이 무슨 날인가」)도 「어떤 전례일인가」로 맞췄다. `architecture.md` 두 곳, 교회력 주제 문서, 설계서 §3.5, 엔진 코드의 `resolveDate` 주석이다. 정의 표와 본문 표를 이름이나 좌표로 잇는다는 문장은 데이터의 조인을 말하므로 두었다.
- **「계약」은 그대로 두고 처음 나오는 곳에 풀이를 붙였다**(사용자 결정, 2026-10-24). 사용자가 뜻을 물었다. 「약속」이나 「명세」로 바꾸는 안은 채택하지 않았다. 「약속」은 개발 용어와 이어지지 않고, 「명세」는 ADR-037 §6의 제목 「엔진 명세」와 겹친다. 풀이는 문서마다 처음 나오는 곳 한 번이다. 설계서는 한 문서로 보아 §1.3에만 붙였다. 검토 문서, ADR-011, 013, 036, 037, 038, `tests/README.md`, 픽스처 README에도 붙였다. 코드 주석은 개발자가 읽는 자리라 두었다.
- **옮기면서 바꾼 글자는 링크 세 줄이다.** §7의 픽스처 README 링크, §9 머리와 미결16의 보관 문서 링크다. 폴더가 한 단계 깊어져 경로 앞에 `../`를 하나 더 붙였다.
- **옛 경로로 가리키는 곳은 그대로 두었다.** 목차가 남아 계속 열리기 때문이다. `CLAUDE.md`의 §1.4 인용, ADR-037 머리의 링크, 검토 문서의 링크, 엔진 코드 머리의 §3.4 주석이다. 엔진 코드 주석은 설계서 §3.2의 파일 골격이 글자 그대로 인용하므로, 주석을 고치면 설계서의 글자도 바꿔야 한다. 「설계서 §N」처럼 이름으로 가리키는 곳은 문서 검사가 장 파일을 합쳐 찾으므로 고치지 않았다.

## 검증

- 줄 비교(`python3 scripts/docs_facts_snapshot.py --diff main WORKTREE --from 'docs/design/liturgical-engine.md' --into 'docs/design/liturgical-engine.md' --into 'docs/design/liturgical-engine/*.md'`)에서 옛 줄 1,253개 가운데 1,247개가 그대로 있다. 빠진 여섯은 위의 링크 세 줄과 교정이 닿은 세 줄(§1.1, §1.3, §3.5)이다. 교정을 받기 전에 장 파일을 이어 붙여 옛 파일과 `diff`로 견주어, 링크 경로 말고는 같음을 확인했다.
- 교회력 사실 토큰 비교(`--diff main WORKTREE --strict-counts`)에서 사라진 토큰, 줄어든 토큰, 새 토큰이 모두 0이다.
- 일반 토큰 비교(`--docs 'docs/*.md' --docs '*.md' --kinds general --strict-counts`)에서 줄어든 토큰은 0이다. 사라진 토큰 하나(「그날이 무슨 날인가」)는 `architecture.md`에서 위의 교정대로 바꾼 인용이다.
- 장 파일에 없는 절(§99)을 일부러 넣어, `docs-crossref.test.js`가 실패 위치를 `06-rank-transfer-color.md:10`으로 보이는 것을 확인하고 되돌렸다.
- 유닛 테스트(`node --test tests/unit/*.test.js`) 1,366개 가운데 1,365개가 통과했다. 1개는 원래 건너뛰는 미결13 픽스처다. `npm run typecheck`도 통과했다.
- e2e는 돌리지 않았다. 앱 코드는 엔진의 주석 한 줄만 바뀌었다.
