# feat: 헤더 북마크 아이콘 토글 삭제 + 삭제 확인 모달

## 요약

모바일 읽기 화면에서 **이미 북마크된 장**의 헤더 북마크 아이콘(채워진 아이콘)을 다시 누르면 **삭제 확인 모달**을 띄워 그 장의 북마크를 제거할 수 있게 했습니다. 북마크가 없는 장이면 기존대로 '이 장 저장' 모달이 열립니다 — 채워진/빈 아이콘 토글과 동작이 일치합니다.

> **질문에 대한 답**: 기존에 커스텀 확인 모달은 **없었습니다.** 파괴적 삭제는 모두 네이티브 `window.confirm()`을 쓰고 있었습니다. 이번 PR에서 테마·포커스 트랩이 적용된 공용 확인 모달을 추가하고, 스와이프 행 북마크 삭제·폴더 삭제도 같은 모달로 통일했습니다.

## 변경 내용

- **헤더 북마크 토글** (`js/app/bookmark.js` `buildBookmarkHeaderBtn`): 모바일 + 장 맥락에서 클릭 시 `findExistingChapterBookmarks()`로 **클릭 시점 상태를 재확인** — 북마크가 있으면 삭제 확인, 없으면 저장 모달.
- **공용 확인 모달** `#bm-confirm-modal` (`role="alertdialog"`): `openConfirmModal({ title, message, confirmLabel, onConfirm })` + `closeConfirmModal()`. 포커스 트랩, 기본 포커스는 안전한 '취소', 확인 버튼은 파괴색 `#c0392b`. z-index 76/77로 드로어·저장·병합 모달 위에 스택.
- **`window.confirm()` 제거**: 스와이프 행 북마크 삭제 · 폴더 삭제를 공용 모달로 마이그레이션.
- 한 장에 북마크가 여러 개면(장 전체 + 절 범위) 함께 삭제 — 채워진 아이콘은 장 단위 토글이기 때문. 확인 문안은 순수 함수 `_chapterDeleteMessage()`로 분리.

## 테스트

- **유닛**: `_chapterDeleteMessage` 2케이스 추가 — 전체 591 케이스 통과, `tsc --noEmit` 0 error.
- **e2e**(로컬 전용): 토글 삭제/취소/추가 시나리오 3건 추가, 기존 스와이프·폴더 삭제 테스트를 공용 모달 흐름으로 갱신. 모바일 스와이프 `_open_drawer` 헬퍼는 헤더 버튼 의존을 끊고 `window.openBookmarkDrawer()`로 직접 열도록 수정(PR #190 이후 모바일에서 헤더 버튼이 더 이상 드로어를 열지 않던 사전 회귀도 함께 정리).
