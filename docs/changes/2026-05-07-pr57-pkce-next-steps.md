# feat: GIS 제거 + PKCE redirect로 인증 흐름 일원화 (Phase 2h 단계 4)

## 요약

데스크탑·Android·iOS를 PKCE Authorization Code + refresh token 단일 경로로 통일. ADR-011이 처음부터 지시했던 흐름으로 회귀하면서 GIS Token Client / Implicit Flow / FedCM 의존을 모두 제거한다.

설계 문서: `docs/design/pkce-migration.md` §7. ADR: `docs/decisions/011-bookmark-sync.md` §Phase 2h §단계 4 결과.

## 핵심 변경

- **state-machine.js**: `INITIALIZING`/`IDENTIFYING`/`AUTHENTICATING` 상태 + 관련 GIS 이벤트 제거. `enable()`은 silent refresh fire-and-forget만, 토큰 없으면 비동기 NEEDS_CONSENT 폴백. 401 reauth는 silent refresh 실패 시 NEEDS_CONSENT 직행 (legacy GIS/iOS 분기 제거). `_isUserActivelyReading`/active-reading defer 로직 제거 (refresh token 기반 silent 갱신은 UI 방해 없음).
- **transport.js**: GIS wrapper 7종 + Implicit Flow 함수 제거. PKCE 함수는 canonical 이름 인계 (`beginRedirectAuthPKCE` → `beginRedirectAuth`, `consumeRedirectCallbackPKCE` → `consumeRedirectCallback`, `RedirectCallbackResultPKCE` → `RedirectCallbackResult`). sessionStorage 키 값은 단계 4 배포 시점 in-flight callback 보호 위해 `bible-drive-redirect-state-pkce` 유지. `revokeToken`을 `oauth2.googleapis.com/revoke` 직접 fetch로 재구현.
- **drive-sync.js**: `signIn()`이 머신 dispatch 없이 `T.beginRedirectAuth` 직접 호출 (DISABLED → silent refresh fire 직후 race window에 USER_CONSENT_REQUEST가 무시되는 케이스 회피). `signOut()`이 `refreshStore.clearRefreshToken()`도 수행. IIFE PKCE 단일 분기. `_pollGis` / `_startPollingGis` / `__pendingRedirectToken` 제거.
- **index.html**: `<script async src="https://accounts.google.com/gsi/client"></script>` 제거. CSP에서 `accounts.google.com`을 `script-src` / `style-src` / `frame-src` / `connect-src`에서 제거 (`frame-src` 디렉티브 자체 삭제).
- **types.d.ts**: 죽은 GIS 타입(`GsiTokenClient`, `GsiCredentialResponse`, `GoogleIdentityServices` 등) 제거. `SyncState`/`SyncEvent`/`SyncMachine` 신규 코드에 맞춰 정렬.

## 호환성 / 마이그레이션

- 기존 사용자: cold start 1회 NEEDS_CONSENT 통과 후 PKCE redirect로 재인증. sync 데이터(북마크/설정/읽기 위치)는 별도 store에 있으므로 손실 없음.
- IDB에 저장된 refresh token은 단계 4 코드가 그대로 사용 (단계 3 머지 후 새로 연결한 사용자는 깜박임 없이 silent refresh로 IDLE 진입).
- 단계 4 PR은 **원자 머지 필수**. 부분 revert 불가 (state machine GIS 가정 + GIS 코드 제거가 동시에 발생).

> [!NOTE]
> **High Risk**
> High risk because it removes all GIS/Implicit/FedCM authentication paths and simplifies the sync state machine around PKCE + refresh tokens, affecting login, token refresh, and sign-in/out behavior across all platforms.
> 
> **Overview**
> Unifies Drive Sync authentication across desktop/Android/iOS to a single **OAuth Authorization Code + PKCE redirect + refresh-token** flow, removing all GIS Token Client, FedCM/One Tap, and Implicit Flow code paths.
> 
> The sync state machine is simplified (drops `INITIALIZING`/`IDENTIFYING`/`AUTHENTICATING` and related GIS events), with `enable()` now doing fire-and-forget silent refresh from IndexedDB and falling back to `NEEDS_CONSENT` when no refresh token exists; 401 recovery now uses silent refresh and otherwise parks in `NEEDS_CONSENT`. Multiple race guards were added so `disable()`/`signOut()` reliably prevents in-flight refresh/code-exchange results from re-enabling sync.
> 
> Frontend wiring is updated to match: `drive-sync.js` consumes only PKCE callbacks and `signIn()` performs a direct `beginRedirectAuth()` navigation (not machine dispatch), `signOut()` clears the refresh token store, `transport.js` removes GIS wrappers and makes PKCE APIs canonical (rename + `silent` field removal) and revocation uses direct `oauth2.googleapis.com/revoke` fetch. `index.html` removes the GIS script tag and tightens CSP by dropping `accounts.google.com` and `frame-src`. Types and unit/e2e tests are updated to reflect the new state/event set and to replace GIS stubs with a PKCE `FakeOAuth` redirect + `/token` exchange simulator.
