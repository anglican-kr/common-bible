## 요약

설정 「시스템」 섹션에 「오프라인 저장」 스위치를 둔다. 켜면 성서 본문, 성서 검색 자료, 교회력 자료(성무일과 독서표 뺌, 1,506개 17.2MB, 받을 때 약 4.9MB)를 기기에 받아, 한 번도 열지 않은 장과 날도 인터넷 없이 열린다(known-issues §43 해소). 결정은 ADR-045이고, 설정 섹션의 표와 ⓘ 설명의 닫기 단추 자리는 ADR-041 §1, §7에서 고쳤다.

- 받을 파일과 크기는 데이터 저장소가 새로 만드는 크기 목록 `bible-sizes.json`에서 읽는다(`common-bible-data#82`, 앱 main에는 데이터 포인터 #585로 들어왔다).
- 새 모듈 `js/offline-save.js`가 받기, 이어 받기, 공간 확인, 끄기를 맡고, 설정의 줄은 `settings-ui.js`가 그린다. 서비스 워커는 받는 요청을 저장하지 않고 넘기고, 크기 목록을 네트워크에서 먼저 받아 DATA_CACHE에 둔다.
- 설정 안내(ⓘ) 넷의 닫기 단추(✕)를 문구의 첫 줄 옆으로 옮겼다.

## 확정 · 근거

- **범위**(사용자 결정 2026-10-31, 2026-11-17): 성서 본문을 모두 받는 기능을 두고 오디오는 넣지 않는다. 교회력 자료도 함께 받고, 받을 자료의 크기를 보인다. 화면에는 「사용량」이라고 쓰지 않는다.
- **화면**(사용자 결정 2026-11-17, 캔버스 시안 70판): 시스템 섹션의 「백업 & 동기화」 위에 「오프라인 저장」 한 줄을 두고 한 줄이 모든 자료를 함께 저장한다. 처음에는 「백업 & 동기화」 아래로 정했다가 캔버스 댓글로 위로 바꾸었다. 크기는 「용량」 같은 말 없이 숫자만 적는다. 끄면 제목 「오프라인 저장 끄기」, 단추 「삭제」와 「취소」의 확인 창을 띄운다. 안내의 끝 문장은 「오디오 파일은 재생할 때 다운로드됩니다.」다. 모든 설정 안내의 ✕를 문구의 위쪽에 맞춘다. 캔버스의 제안 열 가지(검색 자료 함께, 받지 않은 것만 6개씩, 화면을 옮겨도 계속 받기, 켜 둔 동안 고친 파일 다시 받기 등)는 따로 말씀이 없어 그대로 만들었다.
- **브라우저 조사**(2026-11-18, 1차 출처는 `topics/cache-release.md` 「오프라인 저장」): 아이폰 Safari는 7일 동안 열지 않은 사이트의 자료를 지우지만 홈 화면 앱은 그렇지 않다. 사용자가 아이폰에서 Safari 탭과 홈 화면 앱의 설정이 다르게 보이는 것을 확인해, 두 곳이 저장한 자료를 나눠 쓰지 않는다고 확정했다. 그래서 Safari 탭에서만 「Safari에서 7일 넘게 열지 않으면 …홈 화면에 추가한 앱에서 켜면 오래 보관됩니다.」를 넣는다(사용자 결정 2026-11-18, 후보 둘 가운데 권장안). 켤 때 오래 보관을 요청하면 Firefox만 허락 창을 띄우는데, 따로 말씀이 없어 모든 브라우저에서 요청한다.
- **ADR-045 승인**(사용자 결정 2026-11-18): 초안에서 새로 정한 여섯을 그대로 승인받았다. 서버 오류의 줄 아래 글 「일부 자료를 받지 못했습니다. 앱을 다시 열면 이어서 저장합니다.」(후보 둘 가운데 권장안), 「캐시 초기화」가 스위치도 끈다, 공간이 모자라 멈춰도 받은 파일은 남긴다, 시작 알림 「오프라인 저장을 시작합니다」, Safari 문장은 오디오 문장 앞, 스위치는 동기화하지 않는다.
- **크기 목록을 매니페스트와 따로 둔다**: 처음에는 `bible-manifest.json`에 `sizes` 칸을 더했으나, 데이터 PR의 리뷰(`/code-review`)가 매니페스트가 151KB에서 198KB로 커져 이 기능을 쓰지 않는 기기도 앱을 열 때마다 다룬다고 짚었다. 사용자가 리뷰의 지적 넷을 모두 고치기로 해, 크기를 새 파일에 두고 gzip 크기(서버와 같은 수준 6)도 적었다. 데이터 PR은 사용자 지시로 squash 대신 FF로 머지했다.
- **서버 저장소도 고친다**: 서버의 배포 목록(`common-bible-server` `scripts/deploy-manifest.txt`)에 없는 파일은 빌드가 빼므로, `data/bible-sizes.json`을 목록과 배포 뒤 검사에 더하는 변경을 따로 낸다. 그 변경이 들어가기 전에 배포하면 크기 목록이 404라 스위치가 「일부 자료를 받지 못했습니다」에서 멈춘다.
- **일부러 하지 않은 것**: 크기 목록을 셸에 미리 받지 않는다(이 기능을 쓰지 않는 기기도 설치 때마다 받게 된다). 크기 목록을 받지 못하면 받기를 시작하지 않는다(받을 목록과 공간 확인에 크기가 필요하다).

## 검증

- 유닛: `node --test tests/unit/*.test.js` 1,897개 통과. 새 `tests/unit/offline-save.test.js` 16개(받지 않은 것만 받기, 성무일과 독서표 빼기, 6개 넘게 동시에 받지 않기, 서버 오류, 인터넷 끊김과 이어 받기, 공간 부족 두 경로, 끄기와 받는 중에 끄기, 앱을 열 때, 캐시 초기화). `npm run typecheck` 통과.
- e2e(작업 폴더 서버 8093, 서비스 워커를 막고 돌림): `test_settings.py` 50건, `test_install_guide.py`, `test_drive_sync.py`를 합쳐 104건 통과, `test_a11y_axe.py`, `test_a11y_keyboard.py` 통과. 설정 화면과 시스템 섹션, ⓘ 단추와 닫기 단추를 그리는 파일이라 골랐다. 새 시험 8건은 실제 크기 목록대로 1,506개를 모두 받기, 확인 창의 「취소」와 「삭제」, 인터넷 끊김과 이어 받기, 서버 오류, 공간 부족, 안내 문구(데스크톱과 아이폰 Safari), 닫기 단추가 첫 줄 옆인지를 본다. 닫기 단추를 위로 옮긴 뒤에도 기존의 누르는 영역 시험(ADR-041 §7의 수치)이 그대로 통과했다.
- 확인하지 못한 것: 서비스 워커를 거치는 길(받는 요청을 저장하지 않고 넘기기, 크기 목록을 DATA_CACHE에 두기)은 화면 없는 Chromium에서 서비스 워커 설치가 멈춰(known-issues §6.1) e2e로 보지 못했다. dev 배포 뒤 확인한다. 아이폰 실기기 확인도 남았다.
