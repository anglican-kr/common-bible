## 요약

교회력 검토 문서(`docs/design/liturgical-engine-review.md`)를 고쳐 쓰며 내용을 검증하는 작업(known-issues §24)의 11차다. §5 검증 체크리스트의 뒷부분인 §5.10-§5.16(우선순위, 이동 계산, 선택 봉헌, 전례색과 재일, 불변식, 골든 덤프와 외부 대조, 문서 게이트)을 10차와 같은 형식으로 고쳤다. 항목마다 첫 줄에 확인할 사실을 두고 검증, 기준, 체크를 하위 항목으로 나눴다. 체크하지 않은 외부 대조 항목(X-)에는 남은 일을 「지금」으로 적었다. X-1을 체크했고, 테스트에만 있던 번호 하나를 C-6.3-2 항목으로 더했다.

## 확정 · 근거

어긋난 것은 대부분 문서가 낡은 경우였다. 사용자 결정이나 기도서 규칙과 코드가 어긋난 곳은 없었다. 책자와 엔진이 다른 곳 하나를 새로 찾았다(아래 「추수감사주일」).

- **X-1을 체크했다**(사용자 결정, 2026-10-25). 가해의 시작 2025-11-30은 2025 달력 12월 면(X-6)과 2025 책자(X-11)로 확인됐고, 항목이 정했던 RCL 도구와의 대조는 하지 않아도 된다. 검증을 교구 달력과 책자로 고쳤다. 체크의 PR은 이 PR이다.
- **체크 날짜를 머지한 날(한국 시각)로 맞췄다.** #347은 2026-10-15, #349는 2026-10-17이다. 설계서 §8이 이미 이 날짜를 쓴다. 검토 문서는 #347을 10-13으로, #349를 10-16으로 적었고, 10차가 고친 C-5.5-5에도 10-16이 남아 있었다. I-9에 남은 PR #325의 09-13도 09-17로 고쳤다. 같은 09-13이 ADR-037 상단의 상태와 교회력 주제 문서의 A1-a 항목에도 있어 함께 고쳤다.
- **2026-10-24의 세 PR을 체크에 적었다.** #402(기도서 대조, 밀린 prec 7의 기념), #403(연쇄 범위 규칙 폐기), #404(부활 8일 평일의 축일)가 바꾼 항목에 PR마다 무엇을 바꿨는지 적었다. PR마다 테스트와 픽스처의 diff로 건드린 항목을 확인했다.
- **낡은 설명을 고쳤다.**
  - C-6.4-4: 성 토요일의 `rank: null`은 data#32부터 맞지 않는다. 지금은 대축일이다. 항목을 「성 토요일은 홍이고 부활밤은 색에 들지 않는다」로 고쳤다. 「색은 등급과 독립」의 예는 설계서 §6.4대로 주의 변모 주일이다.
  - C-6.1-10: 「격자라면 자」는 틀렸다. 2026-03-29의 격자도 성주간이라 홍이다. 두 날 모두 색으로는 가리지 못하고, 테스트는 `official`의 id로 가른다. 같은 예(「성지주일은 홍이고 격자는 자다」)를 쓴 설계서 §6.2와 본 문서 §4.3 공백 1의 문장도 고쳤다.
  - C-6.5-15: 12.31의 축일을 미는 것은 prec 1이 아니라 성탄 1주일(prec 2)이다. C-6.5-16: 막는 날은 31일이 아니라 12.1-12.30의 30일이다. 둘 다 테스트에 맞췄다.
  - C-6.5-22: 성 토요일의 수태고지를 미는 것은 부활밤이 아니라 성 토요일 행이다(#349).
  - X-5, X-10: 2026년의 이동은 여덟 건이 아니라 일곱 건이다. 안나와 요아킴은 2026-10-24에 축일이 되어 옮기지 않는다. 미결27은 그날 다시 열렸다(잠정).
  - X-10: 병자를 위한 기도일(2.11)은 2026-10-24에 축일이 되어 그날의 지정 전례일이다. 책자의 이름 줄과 다르고, 미결51이 다룬다.
  - X-11: 토마스 모어는 기념일이 되어 C-6.1-12 항목의 사례다.
  - X-9: 선교사 본기도는 data#37이 기도서대로 고쳐 책자와 같다. 순교자 문안은 데이터와 기도서가 「증언하며」이고 책자만 다르다.
  - X-13: pitfalls §22는 교회력 주제 문서로 옮겨 갔다.
  - I-10: 골든 덤프는 지금 909건이다(#402). #349는 건수를 바꾸지 않고 「밀어낸 것」 6건을 바꿨다.
  - §5.16: 교회력 엔진은 #355부터 `<script>` 태그 없이 `import()`로 불러온다. 「지금 동작」 한 줄은 `docs/status.md`가 아니라 교회력 주제 문서에 있다(#371).
  - 그 밖에 테스트가 실제로 보는 것에 맞춘 것: C-6.1-7의 지정 전례일은 늘 격자가 아니다(2025-2050에 여섯 날). C-6.1-12의 「13행 전부 격자, 주일」, C-6.1-13의 12.24(주일이면 대림 4주일), C-6.4-2의 성주간 예외 날(지금 세 날), C-6.5-1c를 잡는 테스트(C-5.6-6도 잡는다), C-6.2-5의 픽스처별 확인이다.
  - 그 밖에 사실을 고친 것: C-6.5-9의 사례가 사라진 이유, C-6.5-14의 C 그룹(지금은 설립 기념일 한 행), C-6.1-9의 「설계서 §2 표」(목록이고 표가 아니다), C-6.1-6의 루시아 본문(공통 독서로 간다), C-6.1-12의 세계평화 기도일 픽스처(이제 기념일을 보지 않는다)다.
  - 낡은 인용 둘: C-6.1-8의 「사다리가 가르지 못하는 것」과 C-6.1-11의 「사계재는 지향」을 설계서의 지금 문구로 바꿨다.
- **빠진 미결을 기준에 더했다.** C-6.2-3에 미결44(기도서 원문의 1.28-2.3 주일과 갈리는 해), C-6.5-5와 X-2, X-11, X-12에 미결45, C-6.1-6에 미결46이다. 셋 다 2026-10-24에 열렸다.
- **테스트가 따로 보지 않는 것을 적었다.** C-6.5-7(실데이터에서 선착순과 서열 순이 갈리는 날), C-6.5-18(해를 넘긴 이동), C-6.5-20(연쇄 범위 폐기의 영향), C-6.5-23(보호 기간 안의 도착), C-6.4-3(사계재 밖 평일의 색)은 실측이나 골든 덤프가 근거이고, 테스트가 확인하지 않는다. seed에 기대는 불변식이 실데이터에서 저절로 성립한다는 것은 §5.14 머리에 적었다.
- **번호를 더했다.** #349가 테스트 이름에 C-6.3-1 뒤에 b를 붙인 번호를 달았는데, 검토 문서에 항목이 없었다. 글자를 붙인 번호는 새로 만들지 않으므로(§5.0) 테스트 이름을 C-6.3-2로 바꾸고 항목을 더했다. 원장 `2026-10-15-liturgical-engine-evening.md`는 옛 번호로 적혀 있다.
- **§5.11 머리의 블록 인용을 단락으로 바꿨다.** 합성 표 항목을 나열하던 목록이 낡았다(C-6.5-7, C-6.5-9가 빠지고 C-6.5-20이 잘못 들어 있었다). 항목마다 검증에 실데이터인지 합성 표인지 적고, 목록은 지웠다.
- **추수감사주일은 책자와 엔진이 다르다**(새로 찾음). 2024, 2026 책자는 11월 셋째 주일을 「연중 33주일 [녹]」으로 싣고 「추수감사주일로 지킬 수 있다」고만 적었다. 엔진은 기도서 주요축일(다)대로 추수감사주일(prec 4)을 그날의 `official`로 낸다. X-10에 적었고, 어떻게 둘지는 사용자에게 묻는다.
- **일부러 두었다.** X-6, X-7, X-8은 남은 대조가 없지만, 체크할지는 사용자에게 묻는다. 데이터의 「1고린 4:3-6」(X-11)은 아직 고치지 않았다. 「좌석 경합」은 그대로 두었다. 부록 A의 예시 줄(`by:t-부활밤`)은 12차 구간이라 그때 고친다.

## 검증

- 사실 대조는 읽기 전용 에이전트 넷에게 구간별로 맡겼다. 받은 주장은 테스트 코드, 엔진(실데이터), 데이터, `git show`, GitHub PR 기록으로 다시 확인했다.
- 교회력 사실 토큰 비교(`--strict-counts --allow-new '^(C-6\.3-2|d1225-dawn|11\.29|#371|prec 1\.5|§5\.0|2026-10-25)$'`)에서 사라진 토큰은 0이다. 줄어든 27종의 이유는 다음과 같다.
  - 체크 id 열둘(C-6.2-4, C-6.2-7, C-6.2-8, C-6.2-11, C-6.2-12, C-6.5-16, C-6.5-17, C-6.5-19, C-6.5-20, C-6.5-21, C-6.5-22, C-6.5-23)과 월일 6.5(체크 id 안의 숫자)는 §5.11 머리의 합성 표 목록을 지운 것이다.
  - 2026-10-13의 여섯과 2026-10-16의 하나는 #347, #349의 날짜이고, 2026-09-13의 둘은 #325의 날짜다(I-9, ADR-037).
  - 31일 하나와 prec 1의 둘은 C-6.5-15, C-6.5-16의 틀린 값을 고친 것이다.
  - 2026-09-19 하나는 C-6.1-9의 「(2026-09-19 정정)」이다. 설계서 §2에 그런 표가 없다.
  - 2025-12-01, 11.30, 12.1, 12.27, 7.27, 미결14는 한 항목 안에서 두 번 적던 것을 한 번으로 모은 것이다. 12.29 하나는 2025-12-29로, 5.12 하나는 §5.12로 적었다.
- 일반 토큰 비교(`--docs 'docs/design/liturgical-engine*' --docs 'docs/decisions/037-*.md' --docs 'docs/topics/liturgical.md' --kinds general --strict-counts`)에서 사라진 여섯은 X-13의 옛 경로 `docs/coding-pitfalls.md`(코드와 경로), 낡은 인용 둘, §5.11 머리의 「검증: 유닛」과 「실제 연도」다. 줄어든 「유닛(실데이터)」와 `official` 하나도 같은 머리와 모은 문장이다. 나머지는 위와 같다.
- 문서 검사 31개가 통과했다. 한정어 없는 참조 경고는 8건 그대로다.
- 테스트 이름 둘을 고쳐 유닛 전체(1365개 통과, 1개 건너뜀)와 `npm run typecheck`를 돌렸다. e2e는 돌리지 않았다. 앱 코드를 바꾸지 않았다.
