# data: 재의 수요일 후 금요일 지정 독서 · 여성선교주일은 기념일로 — 데이터 포인터 · facts · 설계서 (data#27)

**data#27 은 머지됐다**(2026-10-10, fast-forward). 브랜치 커밋 `cce3cbd` 가 그대로 data `main` 이고, data 쪽 빌드 워크플로도 새 커밋 없이 통과했다 — 이 PR 의 `data` 포인터가 그 커밋이다.

data 푸시 직후 앱 `sync-data.yml` 이 돌다가 멈췄다. main 의 설계서 facts 여섯이 새 데이터와 어긋났기 때문이고, 이 PR 이 맞추는 바로 그 여섯이다. 같은 실행에서 main 쪽 엔진 실데이터 테스트는 새 데이터로도 모두 통과했다. 이 PR 이 머지되면 포인터가 이미 data `main` 이라 동기화가 따로 할 일은 없다.

## 요약

교회력 엔진 PR 2(#338) 머지 뒤 사용자 확인(2026-10-10)으로 드러난 데이터 두 가지를 앱에 들인다. 그 대화에서 사용자가 확정한 도메인 규칙 셋도 함께 기록한다.

- **재의 수요일 후 금요일 지정 독서 · 본기도.** 이 날은 「고유명 평일」 여섯 — 재의 수요일 후 목 · 금 · 토, 성주간 월 · 화 · 수 — 가운데 하나다. 여섯 가운데 이 날만 데이터에 레코드가 없었다.
  - 원인: 교구 사이트 기사(archives/3994)는 있는데 수집 태그 「감사성찬례-전례독서」가 빠져 원료에 들지 않았다.
  - data#27 이 실었다: 이사 58:1-9상 · 시편 51:1-4, 16-18 · 마태 9:14-15, 본기도는 재의 수요일 본기도.
  - 엔진은 고칠 것이 없다. PR 2 가 이 날의 격자 후보에 고유명을 달아 두어(설계서 §5.5) 레코드가 들어오자마자 닿는다.
- **여성선교주일은 기념일로만 표시한다.** 해마다 본기도 · 독서가 새로 정해져 고정 본문이 없다.
  - data#27 은 등급을 기념일로 채우고, 그해 한정인 스크랩 본기도를 독서처럼 뺐다(데이터 `coords.VARYING_TEXTS`).
  - 엔진은 그날을 이름 줄 후보(`commemoration` — 승자 자격 없음, → R-6.1-ineligible)로만 내고, 주일 본문은 격자가 낸다.
- **데이터 포인터**를 올리고 설계서 §5.2 facts 여섯을 맞췄다.
  - `readings.total` · `readings.slot.first/psalm/gospel` 923 → 924
  - `readings.set_no.1` 841 → 842
  - `collects.rank_null` 3 → 2
  - 본기도 총수는 327 그대로다(금요일 +1, 여성선교주일 −1). 데이터의 정수 id 34건이 순번으로 밀렸지만, 잠정 순번(ADR-036 §10)이라 앱은 id 를 키로 쓰지 않는다.
