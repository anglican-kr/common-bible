## 요약

문장 교정 반복 실행의 마지막 준비다. 첫 묶음(#444)의 결과를 보고 모델을 정했고, 클라우드 정기 실행을 만들었다. 둘을 스킬(`.claude/skills/prose-batch/SKILL.md`)의 「모델과 정기 실행」에 적었다. 그전에는 「시험 묶음의 결과를 보고 모델을 정한다」로 적혀 있었다.

## 확정 · 근거

- **교정은 Sonnet, 검토는 Opus**(사용자 결정 2026-10-27). 첫 묶음에서 Sonnet은 비유 동사, 화살표, 가운뎃점을 잘 찾아 고쳤다. 하지만 쓰지 않기로 한 말을 뜻과 상관없이 넓게 바꾸는 경향이 있어서, 검토 단계가 23곳을 다시 고쳤다. 그래서 교정은 Sonnet에 맡기고, 실행을 이끌며 바뀐 내용을 검토하는 세션은 Opus로 했다.
- **정기 실행**: 매일 한국 시각 9시, 13시, 17시, 21시(UTC `0 0,4,8,12 * * *`)에 실행한다. 한 번 실행될 때 한 가지 일만 하고 열린 교정 PR은 하나뿐이므로, 새 교정 PR은 하루 4개를 넘지 않는다(사용자 결정 2026-10-26).
- **외부 연결을 붙이지 않았다.** 정기 실행을 만들면 사용자 계정의 외부 연결 13개(Gmail, Google Drive, Notion, AWS 등)가 저절로 붙었다. 이 실행은 공개 저장소의 글과 PR 의견을 읽으므로, 그 안에 숨은 지시가 있으면 메일이나 드라이브를 읽고 쓸 위험이 생긴다. 만든 직후 모두 뗐다.
- **시험 실행에서 첫 교정 PR(#447)이 나왔다.** 정기 실행을 만든 직후 한 번 실행했다. 열린 교정 PR이 없음을 확인하고, 다음 묶음(파일 일곱, 444줄)을 Sonnet 서브에이전트로 교정했다. 그다음 검토하며 약 15곳을 다시 고치고, 검증을 거쳐 #447을 열었다.
  - 서브에이전트는 백그라운드로 시작되었다. 이끄는 세션이 차례를 끝내 실행 상태가 「idle」로 보였으나, 서브에이전트가 끝나자 알림을 받아 이어 갔다.
  - 로컬의 Claude는 이 상태 표시만 보고 실행이 멈췄다고 잘못 판단했다. 그래서 서브에이전트를 기다리게 하는 환경 변수(`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`)를 넣은 새 클라우드 환경 「문장 교정」을 사용자에게 만들게 했다. 정기 실행 API에는 환경 변수를 넣는 칸이 없어 클라우드 환경에 넣어야 했다. 결과적으로 필요하지 않았지만 해가 없어 그대로 쓴다.
  - 그 세션은 #447의 활동을 스스로 구독했다. 사용자가 의견을 달면 그 세션과 다음 정기 실행이 같은 PR을 함께 고칠 수 있어, 정기 실행의 지시에 구독하지 말라는 줄을 넣고 스킬에도 적었다.
  - 환경을 바꾼 뒤의 둘째 실행은 열린 #447을 보고, 검토 의견이 없어 「할 일 없음」으로 끝냈다.
- **교정 PR을 찾는 조건을 「docs: 문장 교정(」으로 좁혔다.** 이 PR의 처음 제목(「docs: 문장 교정의 모델과…」)도 「docs: 문장 교정」으로 시작해, 정기 실행이 이 PR을 교정 PR로 볼 수 있었다. 교정 PR의 제목은 늘 「docs: 문장 교정(<묶음 설명>)」이므로 괄호까지 맞춰야 한다. 이 PR의 제목도 바꿨다.
- **클라우드에는 `gh` 명령 대신 GitHub 도구가 있었다.** 시험 실행은 외부 연결을 모두 뗀 상태에서도 GitHub 도구(`mcp__github__search_pull_requests`)로 열린 PR을 찾았다. 클라우드 세션에 기본으로 들어 있는 도구로 보인다. 스킬에 「`gh`가 없으면 GitHub 도구로 같은 일을 한다」를 적었다.
