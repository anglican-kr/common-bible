## 요약

데이터 저장소 anglican-kr/common-bible-data#75가 546쪽 연중 28주 수요일 해 2의 「요나 2:1-10」을 영어 성경 번호로 보고 공동번역 2:2-11을 읽게 한다. 같은 표기가 519쪽(부활주간 월요일 해 1)에서는 공동번역 번호라 저장값이 2:1-10이다. 앱의 실데이터 시험(`tests/unit/search-worker.data.test.js`)은 번호가 다른 인쇄 표기를 표기만으로 빼고 있어서, data#75의 데이터로 돌리면 546쪽 칸을 「저장 2:2-11, 읽음 2:1-10」으로 짚어 실패한다.

이 PR은 빼는 목록을 표기와 저장값의 짝으로 바꿔 546쪽 칸만 빼고, 519쪽 칸은 계속 대조하게 한다. 같은 재검토의 결과로 ADR-042와 주제 문서의 실물 확인 목록도 고친다. 앱 코드는 바뀌지 않아 사용자에게 보이는 변화가 없다.

## 확정 · 근거

- **사용자 지시**: 사용자가 성무일과와 BCP 대조 보고서의 재검토와, 요나 칸을 고치는 데이터 PR을 맡겼다(2026-11-11). data#75의 데이터로 앱 유닛을 돌리다(`docs/workflow.md`의 데이터 PR 규칙) 이 시험이 깨지는 것을 찾아 이 PR을 더했다.
- **546쪽 「요나 2:1-10」이 영어 번호인 근거**: 전날의 「요나 1:1-17」이 이미 영어 번호로 판정되어 있고, BCP의 같은 날이 Jonah 1:17-2:10이며, 공동번역 번호로 읽으면 물고기가 요나를 뱉어 내는 2:11이 어느 날에도 읽히지 않는다. 대조의 자세한 결과는 데이터 저장소 보고서(`liturgical/prayer-book/reports/2026-11-10-office-readings-vs-bcp.md`)에 있다.
- **표기만이 아니라 짝으로 뺀다.** 표기만 목록에 더하면 519쪽 칸의 대조도 빠진다. 짝으로 빼면 지금 데이터(546쪽 저장값이 2:1-10)에서는 546쪽 칸도 계속 대조한다.
- **새 실물 확인 항목 셋**: 재검토에서 BCP와 숫자 「1」 하나만 다른 세 칸(525쪽 「묵시 19:4-6」, 530쪽 「마태 6:1-16」, 538쪽 「로마 4:7-12」)을 찾았다. 데이터는 인쇄 그대로 두고 원문에 `[메모]`로 확인을 청한다(data#75).
- **머지 순서**: 이 PR을 먼저 머지하고 data#75를 머지한다. 거꾸로 하면 데이터 빌드가 실행하는 앱 동기화(`sync-data.yml`)가 이 시험에서 실패한다.

## 검증

- `node --test tests/unit/*.test.js`: 1,712개 통과. 데이터 포인터가 지금 main의 `7ab0954`일 때와 data#75의 `fcc6531`일 때 모두 돌렸다. 고치기 전 시험은 `fcc6531`에서 「요나 2:1-10」 하나로 실패했다.
- `npm run typecheck` 통과.
- 개수는 시험의 함수로 두 데이터에서 셌다. 성무일과의 표기와 저장값의 짝은 1,957개에서 1,958개로, 대조에서 빼는 것은 81개에서 82개로 늘고, 대조하는 것은 1,876개(다른 파일에 같은 저장값이 있는 317개 포함) 그대로다.
- 돌리지 않은 것: e2e. 앱 코드가 바뀌지 않았다.
