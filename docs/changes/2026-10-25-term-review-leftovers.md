## 요약

낱말 PR 셋(#424, #425, #427)의 서브에이전트 리뷰가 「이 PR 전부터 있던 것」으로 넘긴 거리를 고쳤다. 사용자가 그것들도 작업 범위에 넣기로 했다(2026-10-25). 쓰지 않기로 한 낱말(「단언」, 「확증」, 「소비자」)은 같은 쓰임을 저장소 전체에서 찾아 함께 고쳤다.

## 확정 · 근거

- **사실을 바로잡은 곳**
  - 교회력 주제 문서 「지금 동작」은 성 토요일 행을 「등급 칸이 빈 평일 행, 유효 우선순위 8」로 적었다. 데이터는 2026-10-15부터 대축일(`principal`, prec 1)이다(data#32, 설계서 06장의 저녁 전례 단락). 「데이터 등급이 대축일(prec 1)이라 그날 다른 어떤 후보보다 앞선다」로 고쳤다.
  - ADR-036 「월별 축일 보완 영역」 머리는 「월별 축일 전체와 그 운용은 아직 미반영」이라 적었다. 데이터 몫은 2026-07-27에 채웠다(「미결 사항」 9). 그때 빠져 있던 것과 지금 남은 것(`scope` 오버레이, 설계서 미결36)으로 나눠 고쳐 썼다.
  - ADR-036 §5는 `sanctoral`을 「양력 날짜(MM.DD)에 고정」이라고만 적었다. 같은 ADR §9대로 설과 추석이 음력 날짜에 고정이라는 것을 더했다. 같은 절의 「시간주기」, 「성인주기」 풀이는 「이동 축일」, 「월별 축일」로 바꿨다.
  - ADR-037 §6의 후보 목록에 ④ 이동 축일 행의 규칙 파생이 빠져 있었다. 더했다(설계서 §5.5의 출처 다섯과 같게).
  - ADR-037 §6의 「우선순위가 같은 옮김은 연쇄한다」는 무엇이 연쇄하는지 흐렸다. 설계서 R-6.2-chain-model대로 「옮겨 온 축일은 그날 우선순위가 같은 고유 후보를 밀어내고, 밀린 축일은 이어서 옮겨 간다」로 고쳤다.
  - 범주 사다리(R-6.2-tie-ladder)의 「(규칙일)」, 「(고정일)」 풀이를 뺐다. 엔진은 음력 행(설, 추석)에도 월별 축일 칸을 주는데, 해마다 양력 날짜가 바뀌는 음력 행에 「고정일」은 맞지 않았다(설계서 06장, 엔진 주석, 테스트 이름).
- **확인만 한 것**: 설계서 05장 252행 「표시 순서 ② 「옮겨 지키는 축일」이 정확히 `transferred_in`의 집합이다」를 #424 리뷰가 어긋남으로 보았다. 엔진은 사용자가 켠 선택 봉헌도 `transferred_in`으로 싣는다(`js/app/liturgical-engine.js` 1463행). 그래서 문장이 맞다. 고치지 않았다.
- **쓰지 않기로 한 낱말**(`docs/writing.md` 「용어」)
  - 「단언」: 픽스처의 `assertions[]` 항목을 가리키는 말은 「확인 항목」으로 바꿨다(픽스처 README의 절 제목 「확인 항목(`assertions[]`)」, 테스트 이름 셋, 오류 문구). 테스트 주석에서 확인한다는 뜻으로 쓴 말은 「확인」으로 바꿨다. 51곳.
  - 「확증」: 「확인」으로 바꿨다. 12곳.
  - 「소비자」: 용어 표는 「컨슈머」를 쓰라고 하지만, 우리말로 풀 수 있는 자리라 자리마다 「처음 쓰는 화면」, 「바깥에서 쓰는 모듈」, 「부르는 쪽」, 「테스트」, 「이 값을 읽는 코드」처럼 썼다. 12곳.
  - 픽스처의 「격자 주일 5 에 지므로」는 「보다 후순위라」로 바꿨다(「진다」는 쓰지 않는 말).
- **문장**
  - 설계서 06장 R-6.2-rule-day-stays의 「고정일이 옮긴다」는 목적어 없이 「옮기다」를 썼다. 「옮겨 간다」로 고쳤다. 이 문장은 문서 검사의 기준 문장이라 `tests/unit/docs-crossref.test.js`의 센티널과 설계서 01장의 인용도 함께 고쳤다.
  - 교회력 주제 문서의 「전례일 키 판정 결함 5건 수리」를 완결된 문장으로, 같은 목록의 「성인일로 빠져」를 「월별 축일로 빠져」로, `resolveDate` 설명이 절기 위치까지 `Candidate` 래퍼로 감싸는 것처럼 읽히던 문장을 고쳤다.
  - 설계서 03장과 엔진 머리 주석의 일 목록에서 값 이름만 있던 「격자의 절기 위치」를 「격자의 절기 위치 계산」으로, 설계서 05장의 「이름과 절기 위치 경로」를 「이름 경로와 절기 위치 경로」로 고쳤다.
  - `js/app/calendar.js`의 긴 주석 줄을 나눴다.
- **고치지 않은 것**
  - 범주 사다리 테스트 이름에 마지막 칸 「합성 guard」를 더하지 않았다. 그 테스트는 도착, 이동 축일, 월별 축일의 순서만 확인한다.
  - 코드 주석 전체가 영어 낱말 뒤 조사를 띄어 쓰는 것(pitfalls §31), `docs/writing.md` 「용어」 표의 칸에 문장이 여럿 든 것은 파일 전체의 문체라 따로 다룬다.
  - ADR-036 「검토한 대안 — 우선순위 표현」 마지막 항목에 「설계서」가 다섯 번 나오는 것은 문서 검사가 문서 이름을 요구해서 그대로 둔다.
  - 데이터 저장소의 날짜가 박힌 대조 보고(`liturgical/prayer-book/reports/2026-10-24-vs-data.md`)의 「성인력」은 그때의 기록이다.

## 검증

- 유닛 전체: 1365개 통과, 1개 건너뜀. `npm run typecheck` 통과.
- 문서 검사 31개 통과. 문서 이름 없이 절 번호만 쓴 참조의 경고는 8건 그대로다.
- 교회력 사실 토큰 비교(`--strict-counts`): 사라진 토큰, 줄어든 토큰, 새 토큰 모두 0이다.
- 일반 토큰 비교(`--kinds general --strict-counts`): 사라진 하나는 범주 사다리의 코드 표기다. 풀이를 빼서 바뀌었다.
- 「단언」, 「확증」, 「소비자」는 원장, 보관 문서, `docs/writing.md`를 빼면 남지 않았다.
- e2e는 돌리지 않았다. 코드는 주석, 테스트 이름, 오류 문구, 픽스처 문구만 바꿨다.
