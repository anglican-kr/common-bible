## 요약

전례독서 검색(ADR-044)에서 마지막으로 남았던 날짜와 기간 검색(설계서 §6, 앱 PR 2)을 만들지 않기로 했다. 검색창은 `12월 25일`, `다음 주일`, `2027년 사순절` 같은 말을 날짜나 기간으로 읽지 않고, 날짜와 기간으로 찾아가는 일은 캘린더가 맡는다. 캘린더에서 해와 달, 날을 고르는 판은 다음 PR에서 ADR-038에 적고 만든다. 이 PR은 ADR-044 §4를 고치고 상태를 「구현 완료」로 바꾼다. 화면 동작은 바뀌지 않는다.

## 확정 · 근거

- 시간을 나타내는 말을 모두 알아듣게 하는 것은 품이 많이 들고 끝이 없어, 검색에서 날짜와 기간을 읽지 않기로 했다(사용자 결정 2026-11-17). 설계서의 표현 목록을 보며 `1주일 후`, `1주 후`, `지난 주` 같은 말이 나왔고, 정해 둔 말만 읽으면 받는 말과 받지 않는 말의 경계가 보이지 않았다.
- 검색 화면에 날짜 선택기를 두는 안도 견주었다. 검색어 없이 기간만 고르면 캘린더 목록과 같은 일을 하므로, 선택기는 캘린더에 두기로 했다(사용자 결정 2026-11-17). 월간 화면은 해와 달, 목록은 날까지 고른다(사용자 결정 2026-11-17). 시안은 시안 캔버스의 「캘린더: 날짜 고르기 시안 2」 줄이고, 결정은 다음 PR에서 ADR-038에 적는다.
- `오늘`, `내일`, `어제`가 성서 본문에 나오는 절의 수를 세었다(공백을 지우고 견줌, 358절, 85절, 53절). 「이번 주일」, 「다음 주일」, 「지난 주일」, `12월`은 0절이다. 이 수는 날짜 검색의 시안(시안 캔버스 「앱 PR 2」 줄, 지금은 쓰지 않음)에서 「오늘」을 쳤을 때 Enter로 그날을 열지 묻느라 세었고, ADR-044 §4의 까닭에 남겼다.
- 연도를 붙인 이름 검색의 까닭에서 「기간 검색의 `2027년 대림절`과 같은 해를 가리킨다」를 「줄의 날짜와 캘린더가 양력의 해로 적는다」로 바꿨다. 「검토한 대안」의 B(전례년)는 그때의 이유를 그대로 두고 「그 뒤 만들지 않기로 했다」만 덧붙였다.
- 설계서는 지우지 않고 §6과 관련된 줄에 「만들지 않기로 했다」를 적었다. 설계서를 `docs/archive/design/`으로 옮기는 일은 릴리스 정리 때 한다. ADR, 주제 문서, 코드 주석이 지금 경로를 가리킨다.
- 절기 이름(`사순절` 등)은 지금 「검색 결과가 없습니다」가 나온다. 비슷한 말 표는 같은 날의 다른 이름만 잇는 규칙이라, 넣을지는 비슷한 말 데이터 PR에서 묻는다(주제 문서 「남은 일」).

## 검증

- 문서 검사 `node --test tests/unit/docs-*.test.js` 23개와 `tests/unit/liturgical-fixtures.test.js` 10개 통과, 타입 검사 `npm run typecheck` 통과. 코드는 바뀌지 않아 다른 유닛과 e2e는 돌리지 않았다.
- 사실 토큰 비교(`scripts/docs_facts_snapshot.py --diff origin/main WORKTREE`, 고친 문서마다, `--kinds general` 포함): 사라진 토큰은 ADR-044 상태 줄의 「설계서 §10」, 주제 문서 「남은 일」에서 뺀 지난 내력(`data#80`, 설계서 §10과 §11)과 같은 설계서를 가리키던 짧은 표기(`lectionary-search.md`)뿐이다. 버린 규칙(「절」 없는 절기 이름, 「이번 주일」, 「다음 주일」, 「지난 주일」)은 ADR-044 「검토한 대안」 B에 옮겨 적었다.
- 문장 검사(`tools/prose/prose.py lint --json`을 고친 줄로 거름): 참고 표시(ADR 상태의 줄표, 「Enter」, 「검토한 대안」의 가운뎃점 형식)만 나왔다.
