## 요약

탭 바의 캘린더(데스크톱은 헤더의 캘린더 단추)를 누르면 이번 달로 가던 경우를 고쳐, 마지막으로 본 위치로 돌아가게 했다(ADR-038 §1, ADR-031 §2).

- 다른 탭에서 누르면 캘린더 탭에서 마지막으로 본 화면으로 돌아온다. 앱을 다시 열어도 마지막으로 본 달이 이어진다.
- 전례독서에서 누르면 마지막으로 본 달로 간다. 전에는 이번 달이었다.
- 앞으로 만들 목록 보기도 같은 기억을 쓴다.

## 확정 · 근거

- 사용자 결정(2026-11-07): 위치를 기억하고, 다른 탭에서는 마지막 위치로, 전례독서에서는 마지막 캘린더 보기로 간다. 앞으로 만들 목록 보기도 그렇다.
- 저장은 캘린더 보기만 한다(`bible-calendar-last-view`, 기기마다 따로). 전례독서 화면은 전처럼 앱을 쓰는 동안만 기억한다. 사용자가 말한 것은 캘린더의 위치이고, 오늘의 독서는 시작 화면 설정이 맡기 때문이다.
- 저장은 달을 제대로 그린 뒤에 뷰가 요청한다(`rememberCalendarView`). 그래서 잘못된 주소의 실패 화면은 남지 않는다.
- 일부러 바꾸지 않은 것: 달력에서 탭을 다시 누르면 이번 달로 가는 동작(사용자 결정 2026-10-15). 이번에 정한 경우에 들지 않아 그대로 두었다. ADR-038 「검토한 대안」 C에 재검토 조건을 적었다.
- 다른 곳에서 고칠 일: 목록 보기는 먼 달을 내리므로 스크롤 값으로 위치를 되살릴 수 없다. 목록을 구현할 때 보던 날짜를 함께 남긴다(ADR-038 §1).

## 검증

- 유닛 `node --test tests/unit/*.test.js`: 통과. 더한 시험은 `pickCalendarTabDest` 셋과 저장 하나다.
- 타입 검사 `npm run typecheck`: 통과.
- e2e(작업 폴더 서버, Chromium): `test_calendar_view.py`, `test_tabbar.py`, `test_liturgical_lazy_load.py` 50건과, `test_lectionary_view.py`, `test_settings.py`, `test_a11y_axe.py`에서 탭, 캘린더, 시작 화면, 오늘에 관련된 18건이 통과했다. 더한 시험은 다른 탭에서 돌아오기, 독서에서 다음 달로 넘긴 뒤 돌아오기, 스크롤 복원, 다시 열기(실패 화면과 전례독서를 기억하지 않음, 「오늘」), 시작 화면이 전례독서인 경우이고, 옛 동작을 기대하던 셋을 고쳤다.
- 전체 e2e와 WebKit은 돌리지 않았다. 전체는 13분쯤 걸려 관련 파일만 골랐고(사용자 결정 2026-11-07), 바뀐 코드에 브라우저마다 다른 동작이 없다.
