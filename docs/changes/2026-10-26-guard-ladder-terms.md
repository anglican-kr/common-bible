## 요약

교회력 밖의 문서와 코드 주석에 남은 비유 용어를 정한 말로 바꿨다. 라우팅, 동기화, 북마크의 「가드」는 「검사」로, 디자인 토큰의 「사다리」는 「단계」로, 서비스 워커 주석의 캐시에 「앉은」은 「들어간」으로 바꿨다. 교회력 용어 정리(#432, #434)에서 범위 밖으로 남긴 것들이다. 그러다 사용자가 짚은 표현을 바탕으로 글쓰기 규칙 둘을 더했다. 워크플로 주석의 시크릿 설명은 사실에 맞게 고쳤고, known-issues §24를 해소로 적었다.

## 확정 · 근거

- **가드는 검사로**(사용자 결정 2026-10-26). 경쟁 상태를 막는 「race 가드」는 「경쟁 상태 검사」다. 안전장치 여럿을 묶어 부른 「운영 가드」, 「핵심 가드」는 「안전장치」로 썼다. TypeScript의 type guard는 「타입 검사 함수」다. 코드 이름은 바꾸지 않았다.
- **사다리는 단계로**(사용자 결정 2026-10-26). 디자인 토큰을 작은 값부터 큰 값까지 정해 둔 목록이다. 「스케일」도 괜찮다고 했으나 「단계」를 골랐다. ADR-028의 제목도 「토큰 단계 + HIG 정렬」로 바꿨다. 보관 문서(`docs/archive/`)에 있는 교회력의 옛 「사다리」는 그때의 기록이라 그대로 두었다.
- **시스템이 하는 일은 실제 동작의 동사로 쓴다**(사용자 교정 2026-10-26). 사용자가 워크플로 주석의 「트리거에 걸면」, 「시크릿에 닿는」, 「피해 둔」을 어색하다고 짚었다. 그리고 이런 잘못된 표현에 공통된 틀이 무엇인지 물었다. 영어 개발 문서의 관용구를 낱말만 옮긴 말이라고 답했고, 사용자가 규칙을 바꾸자고 했다. 낱말을 표에 하나씩 더하는 대신 쓸 때마다 물을 질문으로 적었다.
- **영어는 코드에 있는 이름을 가리킬 때만 쓴다**(사용자 결정 2026-10-26). 사용자가 CSS 주석의 띄어 쓴 조사를 짚으며 두 가지를 정했다. 영어는 코드에 있는 것을 가리킬 때만 쓰고, 쓸 때는 조사를 붙인다. 사용자는 「`:has()` 함수로」를 예로 들었다. MDN을 보면 `:has()`는 함수가 아니라 의사 클래스(선택자)라서 「`:has()` 선택자로」로 적었다. 파일 이름, 명령, 제품 이름, 굳은 약어를 예외로 두자는 제안에 사용자가 동의했다. 「stacking context」는 MDN 한국어판대로 「쌓임 맥락」으로 썼다.
- **이 PR에서 새 규칙을 적용한 범위**: 고친 줄에 띄어 쓴 조사는 모두 붙였다. 영어 낱말 규칙은 새로 쓴 글에만 적용했다. CSS 주석 하나, 워크플로 주석 둘, `DESIGN.md`에서 고쳐 쓴 문단이 그렇다. 이미 있는 글 전체(띄어 쓴 조사 약 3,000곳과 코드 이름이 아닌 영어 낱말)는 따로 나눠 정리한다(known-issues §12.4).
- **워크플로 주석의 시크릿 설명**(`engine-data.yml`, `sync-data.yml`). 옛 주석은 `pull_request` 이벤트로 실행하면 포크 PR이 시크릿을 쓸 수 있는 것처럼 적었다. GitHub 문서를 보면 포크에서 온 PR의 `pull_request` 실행에는 시크릿을 주지 않는다. 시크릿을 가진 채 포크의 코드를 실행할 수 있는 것은 `pull_request_target` 이벤트다. 주석을 이 사실대로 고쳤다. 트리거는 바꾸지 않았다(설계서 §9 미결22).
- **known-issues §24 해소**: ADR, 교회력 설계서, 검토 문서의 고쳐 쓰기와 용어 정리가 끝났다. 검토 문서는 나누지 않는다(사용자 결정 2026-10-26).
- `docs/architecture.md`의 동기화 그림에서 「모든 race 가드와」를 「모든 경쟁 상태 검사와」로 바꾸니 상자 테두리가 밀렸다. 「경쟁 상태 검사와」로 줄여 다른 줄과 너비를 맞췄다.

## 검증

- 유닛 전체: 1365개 통과, 1개 건너뜀. `npm run typecheck` 통과. 테스트 이름과 주석만 바뀌었다.
- 문서 검사(`node --test tests/unit/docs-*.test.js tests/unit/liturgical-fixtures.test.js`): 31개 통과. 한정어 없는 참조 경고는 7건 그대로다.
- 교회력 사실 토큰 비교(`--strict-counts`): 사라진 토큰, 줄어든 토큰, 새 토큰 모두 0이다.
- 일반 토큰 비교(`--docs 'docs/*.md' --kinds general --strict-counts`): 사라진 둘은 이번에 바꾼 인용이다(ADR-028의 옛 제목, ADR-037에서 조사를 붙인 인용). 줄어든 23개는 모두 `docs/topics/platform.md`에서 지운 §24 절의 진행 기록(날짜, PR 번호, 사용자 결정)이다. 그 내용은 known-issues §24의 해소 줄과 각 PR의 원장에 있다.
- 동기화 그림의 고친 두 줄은 화면 너비(한글 두 칸)로 세어 다른 줄과 같은 34칸이다.
- e2e는 돌리지 않았다. e2e 파일은 테스트 설명 문자열과 주석만 바뀌었다.
