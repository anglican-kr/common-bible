### `@ts-check` 가 무력이었다

`"use strict";` **뒤**에 있어 tsconfig 의 `checkJs: false` 와 겹쳐 **이 485줄 모듈은 한 번도 타입 검사를 받지 않았다.** 1행으로 올리니 `TS7006` 다섯과, 캐스트가 감추고 있던 `string | null` 이 드러났다.

```
$ npx tsc -p tsconfig.json --noEmit   # ts-check 가 2행일 때
exit 0                                # easterDate("x") 를 넣어도 통과
```

파라미터에 주석을 달고, `addDays` 의 `string|null` 을 좁히는 캐스트 넷은 내부 전용 `shift()` 하나로 모았다 — 캐스트는 `@ts-check` 가 검증하지 않으므로 좁히기를 한 곳에 둔다. **저장소의 다른 24개 파일도 같은 순서**인데 이 PR 범위 밖이라 건드리지 않았다.

### `inSpan` 이 이웃 해에 조용히 틀린 답을 냈다

스팬은 달력년으로 잘려 있는데(C-P-4 가 존재하는 이유) 표를 인자로 받아, 호출부가 루프 밖에서 `spansOf(Y)` 를 뽑아 들고 다니면 답이 갈렸다:

```js
inSpan("2027-01-02", "christmasToBaptism")                  // true
inSpan("2027-01-02", "christmasToBaptism", spansOf(2026))   // false  ← 성탄 기간의 1월 조각이 통째로 거짓
```

§6.5 이동 패스가 「연도 단위로 한 번, 날짜 순으로」 돌며 경계를 넘나드는 구조라 PR 3 에서 정확히 이 모양으로 쓰였을 자리다. **인자를 없애고 연도는 날짜가 정하게** 했으며, 반복 비용은 `spansCache` 가 흡수한다 — §4.10 이 「`anchorCache` 와 같은 연도 캐시를 쓴다」고 적어 둔 것이 빠져 있었다.

**모르는 스팬 이름은 이제 throw 한다.** `inSpan(d, "transferguard")` 가 조용히 `false` 를 내면 성주간 가드가 꺼진 채로 돈다 — §4.10 이 없애려던 바로 그 어긋남이다. 이름은 데이터가 아니라 **코드**라 §2 의 「빈 결과 + 계속 진행」이 적용되지 않는다.

### 정수가 아닌 숫자가 그럴듯한 오답이 됐다

JSON 의 숫자는 NaN·소수일 수 있는데 `typeof === "number"` 만 보고 있었다.

| 입력 | 종전 | 지금 |
|---|---|---|
