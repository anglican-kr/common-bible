## 요약

설정 화면 개편(#493)의 코드 리뷰에서 낮음으로 미룬 다섯 건을 고쳤다(ADR-041 §2, §8, §9).

- 다른 기기에서 바꾼 대체 독서 표시와 외경을 받으면 열려 있는 전례독서 화면과 성서 목록을 바로 다시 그린다. 전에는 「다른 기기에서 변경된 데이터를 불러왔습니다.」가 떠도 다른 화면에 갔다 와야 바뀌었다.
- 외경과 대체 독서 표시를 켜고 끌 때 화면 제목을 알린 뒤에 결과를 알린다. 전에는 결과 알림이 화면 제목에 덮여 스크린 리더 사용자가 결과를 듣지 못할 수 있었다.
- 선택 상자 목록을 연 채 누른 Esc가 페이지까지 와도 팝오버를 닫지 않는다.
- `buildLectionaryModel`(전례독서 화면의 자료를 만드는 함수)의 `showAlternates` 기본값을 없앴다. 빠뜨린 호출은 타입 검사가 잡고, 실행되어도 앱의 기본값처럼 숨긴다.
- 시작 페이지의 값과 이름, 주소를 표 하나(`START_PAGES`)로 모았다. 기도서가 더해지면 이 표에 한 줄만 더한다.

## 확정 · 근거

- **Esc는 재현되지 않았다.** 가상 화면에 브라우저를 띄우고 운영체제 수준의 입력(`xdotool`)으로 재 보니, Chromium 148과 Firefox 150(모두 Linux)은 목록이 Esc를 먼저 처리하고 페이지로 보내지 않았다. 첫 Esc에 목록만 닫히고 다음 Esc에 팝오버가 닫혔다. 그래도 Safari는 재 볼 수 없어, 이 키가 페이지까지 오는 브라우저에 대비해 `:open` 선택자로 목록 상태를 보는 검사를 더했다. 이 선택자가 없는 브라우저(Chrome 133 전, Firefox 136 전, Safari 26.5 전, MDN 호환성 자료)에서 `matches()`를 호출하면 예외가 나므로 먼저 지원 여부를 본다.
- **「포커스가 선택 상자에 있으면 Esc를 무시한다」는 고르지 않았다.** 키보드로 설정을 열면 포커스가 선택 상자에 먼저 가서, 바로 Esc를 눌러도 팝오버가 닫히지 않게 된다.
- **다시 그리는 범위를 값을 쓰는 화면으로 좁혔다.** 외경 토글은 장과 머리말을 뺀 모든 화면을 다시 그리지만, 동기화는 사용자가 누르지 않았는데 일어나므로 내용이 바뀌는 전례독서 화면과 성서 목록만 다시 그린다. 값이 그대로면 다시 그리지 않으므로, 북마크만 바뀐 동기화에서는 읽던 위치와 열린 창이 그대로 남는다.
- **비교 기준은 화면을 그릴 때 읽은 값이다.** `route()`가 시작할 때 값을 기억하므로, 동기화 쪽에 값을 전달하지 않아도 된다.
- **일부러 고치지 않은 것.** 동기화가 화면을 다시 그리면 열린 창이 닫히고 화면 안의 포커스가 돌아오지 않는다. 다른 기기에서 그 값을 바꾼 때에 그 화면을 보고 있을 때만 생겨 그대로 두었다.
- **`dedications`의 JSDoc을 함께 고쳤다.** 선택 인자 표시(`[dedications]`) 뒤에 필수 인자를 두면 타입 검사가 거절한다(TS1016). 기본값 `[]`는 그대로 둔다.

## 검증

- 유닛 `node --test tests/unit/*.test.js`: 1,513건 모두 통과. 타입 검사 `tsc -p tsconfig.json`, `tsc -p tsconfig.worker.json` 통과(원래 폴더의 `tsc`로 실행).
- e2e: 작업 폴더의 앱을 8091 포트로 띄우고 포트만 바꾼 사본으로 `pytest e2e/`를 실행해 453건 모두 통과(리뷰 반영 뒤).
- 고친 부분을 잠시 되돌리면 새 e2e 셋(`test_escape_on_open_select_list_keeps_popover`, `test_toggle_result_is_announced_after_the_view_redraws`, `test_synced_setting_redraws_only_the_view_it_changes`)이 모두 실패하는 것을 확인했다.
- 고친 뒤 Chromium 148과 Firefox 150에서 운영체제 수준의 입력으로 다시 재어 전과 같은 것을 확인했다. 목록을 연 채 첫 Esc는 목록만, 다음 Esc는 팝오버를 닫고, 닫힌 선택 상자의 Esc는 팝오버를 닫는다.
- **하지 못한 것:** 실제 스크린 리더와 Safari, 아이폰으로는 확인하지 못했다. 작업 환경에 없다. 시험은 알림 영역에 마지막으로 남는 글까지 본다. 남은 확인은 `docs/topics/design-system.md` 「남은 일」에 적었다.

## 리뷰 반영

1회차(Copilot 코멘트 하나, `state-machine.js`의 호출 위치).

- **같은 시각의 사본: 재현해 고쳤다.** 드라이브의 사본이 수정 시각은 같고 값만 다르면 병합이 그 값을 남겨 저장값은 바뀌는데, 「다른 기기의 변경」으로 세지 않아 열린 전례독서 화면이 그대로였다. 호출을 `hadRemoteChanges` 조건 밖으로 옮겨 병합 결과를 저장할 때마다 값을 견주게 했다. 값이 그대로면 다시 그리지 않는다. e2e(`test_drive_copy_with_equal_time_redraws_open_view`)는 고치기 전에 실패하고 고친 뒤에 통과한다.
- **다른 탭: 이 변경으로 고쳐지지 않아 그대로 두었다.** `If-None-Match`에 304로 답하고 `ETag`를 공개하는 임시 가짜 드라이브로 두 탭을 재 보니, 한 탭이 올린 뒤 다른 탭의 동기화는 304 응답으로 끝나 비교 함수가 호출되지 않았다. 탭끼리 동기화 캐시를 함께 쓰기 때문이다. 글자 크기와 테마도 다른 탭에 바로 적용되지 않아 동작이 같고, 그 탭에서 화면을 옮기면 새 값으로 그린다.
