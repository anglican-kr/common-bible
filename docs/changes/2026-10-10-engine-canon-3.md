# docs: 교회력 엔진 정본 지도 ③ — 검토 문서 참조화 · 개정 블록 흡수 · Qn 폐지(§6 을 설계서 §9 사제 뷰로)

**리팩터 전용 · 사실 변경 0(스냅샷 첨부).** 리뷰는 **논리적 모순만** 반영한다(사용자 결정 2026-09-20 — 문서 PR 의 Copilot 지적은 모순만, 나머지는 구현하면서 고친다). 리뷰 2회 상한.

## 요약

교회력 설계 문서 리팩토링 「한 사실은 한 곳에」(2026-09-20 승인, PR ⓪~④)의 **③**. ②(#335)가 설계서를 정리했으니 이번엔 **검토 문서(`docs/design/liturgical-engine-review.md`)를 설계서 · 픽스처를 가리키는 문서로 바꾸고, 사제 질문 번호 `Qn` 을 폐지한다.** 내용(사실)은 바꾸지 않았다 — § · 미결 · C/X/I 번호 불변, 설계서 facts 블록 무변경.

- **개정 블록 흡수(편집 원칙).** 검토 문서의 `> **개정 (날짜)**` 블록 셋(§3.1 기간 축 · §3.3 범주 사다리 · §4.3 사계재)을 본문의 **현재 결론**으로 녹였다. 버린 판정은 같은 자리에 「기각 — 날짜 · 이유」로 남겼다 — 예: §4.3 공백 1 「사계재도 사다리로 temporal 이 이긴다」는 2026-09-17 기각(교구 달력 세 해가 어긋남; 재검토 조건은 설계서 미결23). §3 표의 「이 설계의 현재」 열은 「검토 당시엔 … — 지금은 …」으로, 「반영 위치」 열은 실재하는 절 · R- 마커로 고쳤다. C-4.5-4 의 취소선과 `해소/재개` 꼬리표도 「닫힘」으로 바꿨다. 머리말 「§1~§4 본문을 고치지 않는다 — 개정 블록으로 덧붙인다」는 편집 원칙 문장으로 바꿨다.
- **기대값 → 픽스처 id(§5.10~5.13).** C 항목이 되풀이하던 실제 연도의 날짜 · id · 상태 · 색을 `tests/fixtures/liturgical/` 케이스 id 로 가리키게 했다. 어느 케이스를 쓸지는 픽스처의 `checks` 필드(C id → 케이스)로 정했다. C 항목에는 **검증 방법과 픽스처에 없는 단언만** 남긴다. 예를 들어 C-6.1-11 의 「하계재 후보 `findReadings` = 성직자 2세트(시편 99 / 27:1-9)」는 픽스처가 세트 수만 단언하므로 남겼다. §5.0 은 이 형식과 id 문법(설계서 §1.4 가 정본)을 적는다.
- **`Qn` 폐지 — §6 은 설계서 §9 의 뷰.** 14행 Q 표를 지우고, **설계서 §9.1 에서 확인 주체에 사제가 든 미결 열 개**(1 · 6 · 13 · 14 · 17 · 19 · 20 · 26 · 30 · 32)를 `미결n — 묻는 것 — 상태` 로 나열했다. 질문 · 구체 예 · 잠정 답 · 뒤집히면 바뀌는 곳은 ② 가 §9 필드로 옮겨 두었다. 옮기기 전에 Q 표 행마다 §9 항목과 대조했고, 옮겨지지 않은 조각 둘은 이렇게 처리했다.
  - **Q6 의 남은 물음** 「사계재 본문을 감사성찬례에서 실제로 쓰는가」 — §6 「부수 확인」에 「미결23 이 닫히며 정해졌다」로 남겼다.
  - **Q14 의 날짜 둘**(2028-12-13 · 2033-09-14) — ② 가 연도로만 옮겼다. 설계서 미결33 구체 예에 날짜로 적었다.

  옛 번호는 **Q→미결 대응표 한 줄**로 해독한다. 이 표는 검토 문서 §6 에 한 번만 두고, 설계서 §1.4 의 `Qn` 행은 그 표를 가리킨다. ② 까지는 §1.4 에 대응표가 있었는데 ③ 의 §6 에도 두면 같은 사실이 두 곳에 적히므로 옮겼다. 「부수 확인」 셋도 현재 자리로 옮겼다: 주의 변모 주일의 지위는 닫힘(X-10) · 12.25 기본은 미결12 · ADR-036 미결10 은 ④ 의 승계 대상.
- **참조 정리 — 검토 문서 기준.**

  | 항목 | 전 | 후 |
  |---|---|---|
  | 동그라미 참조 | 105 | 0 |
  | `Qn` 참조 | 38 | 0 |
  | 편집 원칙 위반 | 5 | 0 |
  | 한정어 없는 참조 경고 | 234 | 0 |
  | 경고 전체(ADR 몫 포함) | 325 | 91 |

  - 동그라미 참조는 R- 마커 · 픽스처 id · 절 이름 · 보관 문서 절 이름으로 바꿨다. ② 가 발급한 마커 다섯이 대상이다(`§6.2 ①②③` → R-6.2-chain-model · first-come · rule-day-stays, `§6.3 ①②` → R-6.3-friday-fast · holy-week-guard, `§7 ①~⑩` → 픽스처 id 또는 「설계서 §7 이동 패스(부활 절기 · 불변식 · 연도 경계)」). X 항목 안에서 「→ 미결25 ⑦」처럼 미결 참조 뒤에 다음 목록 표시가 붙은 오탐 다섯은 「 · 」로 끊었다.
  - 한정어 없는 참조는 대부분 설계서 절이라 「설계서」를 붙였다(94곳 — crossref 와 같은 해석 규칙의 스크립트로). 자기 절을 가리키는 열 남짓은 손으로 「본 문서」를 붙였다.
- **부록 A/B 「(제안)」 → 채택.** 부록 B 는 「정본은 `tests/fixtures/liturgical/README.md`」 포인터로 줄였다. 제안에서 바뀐 것 셋을 적었다(id 꼴 · `rule` → `canon` + `source` · `applies.since/until` 은 README 에 없음). 격자 id 규칙은 설계서 §5.5 를 가리키고, 실측(`christmas/1/sunday` 주차)만 남겼다. 부록 A(골든 덤프)는 PR 3 에서 만든다. 위치는 ① 이 세운 `tests/fixtures/liturgical/` 로 고쳤다 — 제안 당시의 `tests/unit/fixtures/` 신설안은 그 디렉터리가 생기기 전의 것이다.
- **게이트 켬**(`tests/unit/docs-crossref.test.js`).
  - 동그라미 참조 · `Qn` · 편집 원칙 게이트의 문서 목록에 검토 문서를 더했다. 편집 원칙은 원래 ④ 몫으로 적혀 있었으나 ③ 이 검토 문서의 개정 블록을 다 흡수했으므로 ③ 에서 켰다(「그 PR 이 정리한 문서부터 지킨다」).
  - `Qn` 해석은 Q 표 행 대신 §6 의 대응표로 하고, 대응표가 Q1~Q14 를 전부 덮는지 본다.
  - **새 검사 하나** — 검토 문서 §6 표의 미결 집합 · 상태 첫 낱말이 설계서 §9.1 의 「확인 주체: …사제…」 항목과 같은지 본다. 뷰는 손으로 적으므로 항목이 닫히거나 확인 주체가 바뀌면 여기서 잡힌다.
- 설계서는 다섯 곳만 바꿨다.
  - §1.4 의 `Qn` 행 — 대응표를 검토 문서 §6 으로 옮기고 그곳을 가리킨다.
  - §1.4 의 `①②③…` 행 — 진행 표시.
  - §1.4 끝 문단 — ③ 완료(2026-10-10).
  - §6.1 null-precedence 표의 주의 변모 주일 행 — 「지위 확인 대상(검토 문서 §6 부수)」을 닫힌 결론으로 바꿨다.
  - 미결33 구체 예 — 날짜 둘.
- 픽스처 T-2035-04-02-joseph-first-come 의 `note` 가 가리키던 「§6.2 ②, 검토 문서 §6 Q1 부속」을 「R-6.2-first-come, 설계서 미결17 부속」으로 바꿨다. 단언은 그대로다.

검토 문서 크기는 444 → 427행, 96,457 → 97,362 바이트(+0.9%)다. 바이트가 줄지 않은 것은 「설계서」 한정어 94곳과 픽스처 id(값보다 길다)가 들어갔기 때문이다. 목표는 크기가 아니라 같은 사실이 두 곳에 적히지 않는 것이다.

## 확정·근거

없음 — 리팩터. ③ 에서 정한 것은 표기 규약 셋이다.

- 옛 `Qn` 의 대응표는 검토 문서 §6 한 곳에 둔다(설계서 §1.4 는 가리킨다).
