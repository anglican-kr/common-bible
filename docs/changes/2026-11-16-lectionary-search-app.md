## 요약

전례독서 검색(ADR-044)의 첫 단계로, 검색 워커가 새 전례독서 색인(`lectionary/search-lectionary.json`, ADR-037 §5)으로 전례일을 찾게 했다. 이름으로 찾기(설계서 `docs/design/lectionary-search.md` §4), 구절로 찾기(§5), 책 이름만 친 검색어의 판별(ADR-044 §2)이다. 앱은 아직 색인 주소를 워커에 넘기지 않으므로 화면과 동작은 그대로다.

## 확정 · 근거

- 앱 PR 1을 세 단계로 나눴다(설계서 §10). 한 PR로 하면 검색 워커, 결과 화면, 전례독서 화면을 함께 크게 고치게 되어서다. 사용자는 이 제안에, 화면을 고치는 단계는 구현하기 전에 지금 앱의 모양으로 시안을 만들어 달라고 답했다(2026-11-16).
- 워커는 `init` 메시지에 색인 주소가 있을 때만 색인을 받는다. 결과 메시지에 찾은 전례일(`lectionary`)과 책 이름만 친 검색어(`bookOnly`)를 더했다. 색인을 받지 못하면 `lectionary`는 null이고 성서 검색은 그대로다.
- 구현하며 정한 것은 설계서의 그 절에 「구현하며 정함」으로 적었다. 검색어 전체에서도 숫자를 통째로 맞추기, `N주간`의 정규화, 비슷한 말을 긴 것부터 한 번만 바꾸기(§4.1), 장 끝까지 이어지는 구간이 있으면 「모두 담은」 단계를 쓰지 않기(§5.1), 색인을 3초까지 기다리기(§3)다.
- 번호 없이 「주일」만 쳐서는 번호 붙은 주일을 찾지 않는다. 설계서 §4.1의 정규화가 `대림1주일`을 `대림1주`로 바꾸기 때문이다. 시험을 쓰다 드러나 §4.1에 적었다.
- 데이터 PR(common-bible-data#80)을 만들 때 확인할 일로 남긴 띄어 쓴 책 이름(`요한 1서`)은 문제가 없었다. 구절 표기와 책 이름만 친 검색어 모두 「요한」보다 「요한 1서」를 먼저 맞춘다. 시험으로 남겼다.
- 데이터 PR에서 임시 스크립트로 한 엔진 대조를 앱의 실데이터 시험으로 옮겼다. 2025-2050년에 엔진이 독서 세트 939개를 모두 내고, 색인의 전례일과 다른 곳은 사계재의 지향별 날 16곳과 대림1주일 합침뿐이다.
- 커밋 본문은 문단이나 목록 항목 하나를 한 줄로 쓰기로 했다(사용자 결정 2026-11-16). 이 PR의 커밋 메시지를 보일 때 줄 바꿈 기준을 확인했는데, 저장소에 기준이 없었고 지난 커밋도 접은 것과 접지 않은 것이 섞여 있었다. 일정한 폭에서 접으면 한글은 폭을 세기 어렵고 문장이 중간에서 끊긴다.

- `node --test tests/unit/*.test.js`: 1,781개 통과(새 시험은 워커 29개, 실데이터 6개)
- `npm run typecheck`: 통과
- 실제 색인으로 쳐 봤다. `요한 3:16`은 전례일 5개, `연중 7주`는 7개(`연중17주일`은 나오지 않는다), `루가 1:68`은 즈가리야 송가를 읽는 날 4개다. 검색 한 번에 4ms 안쪽이다.
