# feat: 교회력 전례독서 뷰 A3 — /lectionary 라우트 · 본기도 · 독서 · 관측일 스위처 · 세트/트랙 · 두 독서 나란히 (ADR-038 §3)

## 요약

교회력 엔진(A1 · B1, #325 ~ #345)의 **첫 소비자**인 전례독서 뷰를 더했다 — `js/app/lectionary.js`(신규, `js/app` 모듈 26 → 27). `/lectionary`(오늘) · `/lectionary/YYYY-MM-DD` 에 그날의 감사성찬례 본문을 ADR-038 §3 의 순서로 그린다.

- **헤더** — 날짜(요일 · 전날/다음날 · 오늘) · 대표 관측일 이름 · 전례색(그날의 `colors` 병기 + 대체색 `colorAlt`) · 주기(가해 · 짝수해) · 재일 · 겹친 기간.
- **관측일 스위처** — 후보 **전부**를 칩으로 늘 보이고 `official` 은 초기 선택일 뿐이다. 칩 라벨은 괄호 설명을 뗀 이름 + (주기, 독서 N) + 상태 꼬리(「12월 6일에서 옮겨 옴」 · 「→ 10월 19일」 · 「생략」 · 「기념일」 …). 기념일 칩은 「기념일 — 본문 없음」.
- **본기도** — **고른 관측일의 것만** 보인다(사용자 결정 2026-10-12). 대체안(`collect_no`)은 세그먼트 「본기도 1 · 2 · 3」으로 택1, 송영은 고른 본기도의 `ending`(없으면 A) 하나를 끝에 1회 붙인다. 같은 날의 다른 관측일(성인축일 · 축성일 …) 본기도는 그 칩을 골라야 보인다.
- **독서** — 제1독서 → 시편 → 제2독서 → 복음을 슬롯 **이름**으로 고른다(위치 아님). 렌더는 ADR-035 경로(장 JSON 전부 선로드 → 라우트가 바뀌지 않았는지 확인 → 한 번에 DOM 커밋, `appendVerses(…, {hideCites:true})`). 시편은 계응 조판(◯ · ¶ · 부)이 그대로 살고, 편 끝에 **영광송**을 1회 붙인다. 송가는 장 제목(「즈가리야 송가」)을 병기한다.
- **대안 세트 · 트랙** — `set_total > 1` 은 **세 갈래**(사용자 결정 2026-10-12): 「또는」 대안은 세그먼트 「독서 1 · 2」(대안이 있는 슬롯만 바꾼 완전한 세트를 통째로), 조건부 세트는 조건이 라벨(「…로 지킬 때」, 바탕은 관측일 이름), 괄호 선택 구절 세트는 세그먼트에 올리지 않고 바탕에 합쳐 긴 본문 + 선택 구절 〔 〕 + 「짧게 읽으면 …」. 연중 주일의 독서 1/2 는 토글이고 선택은 **전례년 단위**로 기억한다(`bible-lectionary-track`). 본기도 선택(`?collect=`)은 독서와 독립된 축이라 트랙 · 세트를 바꿔도 남는다.
- **두 독서 나란히** — 선택 봉헌의 당일(8.6 주의 변모 — 「오는 주일(8월 9일)로 옮겨 지키는 경우」) · 목적지 주일(8.9) · 옮겨진 축일의 도착일(12.7 니콜라) · 명절(설 · 추석)에 카드 둘을 나란히 내고 독자가 고른다. 「공식」 표지는 보이되 선택을 대신하지 않는다.
- **상태는 URL** — `?obs=&track=&set=&collect=`. 모든 컨트롤이 링크라 뒤로 가기 · 공유 · 키보드가 그대로 된다.

같이 바뀐 것: `views.js` 의 구분 탭 빌더를 일반 세그먼트 빌더 `buildSegmentTabs` 로 갈라 본기도 · 세트 · 트랙 세그먼트가 같은 CSS 와 슬라이드 인디케이터를 쓴다 · `routing.js parsePath` 가 `/lectionary` 와 쿼리 상태 넷을 파싱하고 `route()` 가 뷰로 보낸다 · `tab-history.js tabOf` · `tabbar.js` 가 `/lectionary` · `/calendar` 를 **캘린더 탭**으로 분류한다(ADR-038 §3 — 탭 버튼은 A2) · `storage.js` 에 트랙 기억 두 함수 · 엔진은 `optionalDestOf` 를 노출만 더했다(규칙 변경 없음) · 등록 세 곳(`index.html` · `sw.js` `SHELL_FILES` · architecture.md §4) · CSS `.lect-*`.

**범위 밖**(지시대로): A2 캘린더 탭 · A4 검색 이원화 · 선택 봉헌을 켜는 설정 UI(설계서 미결15) · 엔진 규칙 변경.

### 사용자 결정 필요 — 잠정 결정과 근거

1. **영광송 본문** — 저장소에 없다던 문구가 데이터 서브모듈 `liturgical/psalter/TEMPLATE.md` 에 참고 원문으로 있었다: 「영광이 성부와 성자와 성령께 ◯ 처음과 같이 지금도 그리고 영원히, 아멘.」 **앱 상수**(`lectionary.js` `GLORIA`)로 두고 계응(선창 ◯ 응답)으로 그린다 — ADR-037 §3 · ADR-038 §3 이 「앱 상수」로 정해 둔 자리다. **사용자 확인 2026-10-12 — 문구 그대로**(pitfalls §21). 송가는 장 JSON 의 `gloria:false`(창조송가 · 참회송가 · 찬양송가)가 아닐 때만 붙인다 — 데이터가 이미 표지를 갖고 있었다.
2. **진입점(A2 전)** — **URL 뿐**이다. 캘린더 탭이 설계된 진입이고 바로 다음 PR 이라, 홈에 임시 카드를 넣었다 걷는 비용을 피했다. 탭 분류(`calendar`)만 먼저 넣어 /lectionary 에서 어느 탭도 활성이 아니다(검색과 같은 꼴). 헤더 홈 버튼은 성서 목록 `/` 이고 A2 가 `/calendar` 로 바꾼다. 버린 안(홈 「오늘의 독서」 카드 · 캘린더 탭 버튼만 먼저)은 ADR-038 「검토한 대안 — A3 와 A2 사이의 진입점」.
3. **PR 분할** — **한 PR**. 둘로 가르면 ①(라우트 · 본기도 · 독서)만 머지된 중간 상태가 `official` 만 그려 「두 독서 나란히」 · 「후보 전부 노출」 결정과 어긋나는 배포본이 된다. 커밋은 코드 → 테스트 → 문서 → 원장으로 갈라 두었다.
4. **보조 라우트 `/lectionary/d/<slug>`** — **A4 로 미룬다**(검색 착지점). 지금은 그 주소가 뷰의 「잘못된 날짜」 안내로 떨어진다. ADR-038 §3 라우트 불릿에 적었다.
5. **뷰가 처음 부딪힌 미결 — 잠정 답대로 갔다**(설계서 §9 항목에 「A3 가 이렇게 구현했다(2026-10-12)」를 적었다):
   - 미결12 — 12.25 는 성탄 낮 · 밤 · 새벽이 성인력의 **별도 관측일**이라 칩 셋이고, 기본은 승자 **성탄 낮**이다. 밤 · 새벽을 기본으로 바꾸려면 데이터 품계가 아니라 뷰의 초기 선택 규칙에 특례가 필요하다.
   - 미결20 — 저녁 전례 표지는 두지 않았다. 성 토요일은 승자 부활밤에 그날 색 **홍**을 보이고(엔진 잠정 답), 성 토요일 후보를 고르면 그 행의 홍이다. 부활밤의 백은 표지(`evening`)가 생겨야 보인다.
   - 미결25 — **고유 독서가 없는 축일(공통만)은 격자(그날의 주일 · 평일) 독서가 초기 독서**이고 제목 · 색은 승자다 — 책자대로(설계서의 잠정 답 제안 그대로). 성인 칩을 고르면 공통 독서가 「선교사 공통 독서」 캡션과 함께 나온다.
   - 미결37 — 송영 B 는 데이터가 배정하지 않으므로 뷰는 레코드의 코드만 받는다(없으면 A). 상수 셋은 데이터 `_meta.endings` 와 글자까지 같다(실데이터 테스트가 대조).
   - 미결38 — `set_note` 는 캡션 그대로, 단 파서 내부 표지 「원본 세트 N」(기사 둘에서 온 세트 — 부활대축일 · 성 토요일)은 숨긴다. 세그먼트 라벨은 「1안 · 2안」.
   - 미결42 — 칩 라벨은 괄호 설명을 전부 뗀 이름(「토마스 크랜머」 · 「바실과 나지안조의 그레고리」) + (주기 — 격자만, 독서 N — 트랙이 있을 때만) + 상태 꼬리. 전체 이름은 `title` 속성.
6. **설계 문서** — 별도 A3 설계서는 쓰지 않았다. 엔진과 달리 알고리즘이 아니라 조립이라 ADR-038 §3 · §3-1 이 정본이면 충분하고, 구현하며 정한 것은 ADR-038 §3 「구현」 블록과 이 원장에 적었다. 뷰 모델의 계약은 `lectionary.js` 의 JSDoc(`LectionaryModel`)이다.
7. **본기도 열거 범위**(ADR 이 「열거」만 적고 범위는 비워 둔 자리) — 고른 관측일 → 같은 날 **함께 지키는** 관측일(`proper` · `transferred_in` · `commemorated`)의 것이 `candidates` 순으로. 밀린 것(`omitted`) · 떠난 것(`transferred_out`) · 켜지 않은 선택 봉헌(`optional`) · 사계재(고를 때만 — ADR-038 §3 「사계재 후보」)는 열거하지 않는다. 송영은 **열거 마지막 본기도**의 코드다. 예: 8.6 은 변모 + 연중 18주간, 12.7 은 니콜라 + 대림 2주간, 부활대축일은 부활대축일 셋 가운데 하나뿐.
8. **두 독서 나란히의 꼴** — 설명을 단 **카드 둘 + 본문 하나**(고른 쪽). 두 본문을 동시에 그리는 안은 길이와 상태(세트 · 트랙 · 대체안과 곱) 때문에 버렸다(ADR-038 「검토한 대안 — 두 독서 나란히의 꼴」).
9. **헤더 색 규칙의 일반화** — 「사계재 칩을 고르면 자색」을 「승자가 아니고 자기 색을 가진 **비격자** 후보를 고르면 그 색 하나」로 일반화했다(부활밤 · 성 토요일 · 생략된 성인이 같은 꼴). 격자 후보는 절기 바탕색을 들고 있을 뿐이라 그날 색 그대로다 — 미결25 의 초기 격자 선택이 성인의 색을 바꾸지 않게.
10. **색 라벨** — 데이터 `_vocab.color` 대로 「적색」이다(책자 표기는 [홍]). ADR-036 §4 가 `_vocab` 을 라벨의 단일 출처로 정했고 실데이터 테스트가 대조하므로, 「홍색」을 원하면 데이터 `_vocab` 을 바꾸는 쪽이 맞다.
11. **날짜 이동**(‹ 전날 · 오늘 · 다음날 ›)을 헤더에 넣었다 — ADR-038 에 없던 것이다. 캘린더가 없는 동안 날짜를 옮길 유일한 길이고, A2 뒤에도 해롭지 않다.

### 사용자 결정 (2026-10-12, PR 열린 뒤 — 하나씩 검토)

위 11항을 사용자가 하나씩 확정했다(coding-pitfalls §21 · ADR-038 §3 「구현」). 그대로 둔 것: 1(영광송 문구 OK) · 2(주소뿐 — A2 는 캘린더 탭) · 3(한 PR) · 4(`/lectionary/d/<slug>` 는 A4) · 5-미결12(성탄 낮) · 5-미결25(평일 독서 — 닫힘) · 5-미결37(A · C 만) · 6(별도 설계서 없음) · 8(카드 둘 + 본문 하나) · 10(적색) · 11(날짜 이동). **고친 것 넷**:

- **헤더 색은 고른 본문의 색을 따른다**(5-미결20 — 뷰만). 부활밤 본문이면 백(승자여도), 성 토요일 후보면 홍, 격자는 그날 색. 규칙: 고른 칩이 자기 색을 가진 비격자 후보이고 그 색이 그날 대표색과 다르면 그 색 하나, 그 밖은 그날의 병기 그대로(사계재 날 성인 [자, 백]). `headerColors` 한 곳 — 엔진의 그날 색과 저녁 전례 표지 물음은 그대로다.
- **본기도는 고른 관측일의 것만**(7 의 「함께 지키는 관측일 열거」 안 기각). `collectsFor` — 대체안은 「본기도 1 · 2 · 3」 세그먼트, 송영은 고른 본기도 뒤 1회. 다른 관측일의 본기도는 그 칩을 골라 본다.
- **칩 라벨은 괄호만 떼고 길면 CSS 말줄임**(5-미결42 — 닫힘): `max-width: clamp(9rem, 60vw, 22rem)` 로 화면 폭에 따라, 전체 이름은 `title`.
- **대안 세트는 세 갈래**(5-미결38 — 닫힘). 사용자 설명 — 「독서 1 · 2 로 나눈다는 것은 어느 슬롯(예: 제2독서)의 대안 본문으로 대체한 전례독서를 하나 더 만든다는 뜻」 — 데이터가 이미 그 꼴이다(ADR-037 §1 완전한 세트 복제). ① 「또는」 대안(파서 표지 「원본 세트 N」이든 표지 없음이든 — 실측 44묶음)은 세그먼트 「독서 1」「독서 2」로 세트를 통째로 고른다 ② 조건부(3묶음)는 조건이 라벨(「…로 지킬 때」 꼴로 통일 — 데이터의 「…로 지키는 경우」도 그렇게 보인다), 바탕은 관측일 이름(「사순 2주일」) ③ 괄호 선택 구절(33묶음 + 성지주일 나해의 겹침 1)은 세그먼트에서 빼고 바탕 세트에 합쳐 **긴 본문을 싣되 선택 구절을 〔 〕 로 묶고 「〔 〕 안은 선택 구절 — 짧게 읽으면 …」 주석**을 단다(`readingOptions` · `optionalVerseTest` · `markOptionalVerses`). 괄호 세트 34건이 전부 바탕과 한 슬롯만 다르고, 「또는」 대안과 연중 주일 트랙 토글이 한 화면에 겹치는 날은 없다(실측 0).
