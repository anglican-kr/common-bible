# docs: ADR-037 미결8 — 파이프라인 입력을 언제 동결할지 기록

ADR-037 §미결에 **8번** 신설. 문서 한 항목만 변경.

## 무엇을 기록하나

`common-bible-data` 는 지금 **입력만 손으로 쓰고 출력은 전부 생성**하는 구조다(스크랩 `articles.json` + 손입력 `articles-supplement.json` + 파서 → `lectionary/*.json`), 그리고 `pipeline.yml` 의 **드리프트 검사**가 그것을 강제한다. 전례독서 데이터가 완성되면 초기 입력은 더 필요 없어지므로, **어느 시점에 입력을 접고 출력을 정본으로 선언할지**를 미결로 남긴다.

## 왜 지금은 아닌가

데이터를 다시 써야 하는 미결이 남아 있고, 그중 하나는 **스키마를 바꾼다**:

| 미결 | 무엇을 바꾸나 | 스키마 |
|---|---|---|
| ADR-036 미결13 **사계재 계절 기계 키** | temporal 4행 + 본문 16건 **양쪽에 필드 추가** | **예** |
| 설계서 미결13 재의 수요일 `transferable` | 규칙 열 값 | 아니오 |
| ADR-036 미결10 분류 3건 | 등급 칸 | 아니오 |
| ADR-036 미결8 본기도 기도서 대조 | `corrections` 추가 | 아니오 |
| ADR-037 미결1 송영 A/B | `ending` 재배정 | 아니오 |

사계재 기계 키는 **923 엔트리 전체 재생성**이다. 입력과 파서가 있으면 한 줄 고치고 돌리면 되고, 없으면 손 마이그레이션이다. 지금 조인이 한국어 이름 부분문자열에 기대고 있어(설계서 §5.4 — 「표기가 바뀌면 조용히 끊어진다」) 그 필드가 들어오는 것은 시간 문제다.

## 동결하면 잃는 것 둘

- **드리프트 검사** — 이 저장소의 유일한 실질 품질 게이트다. 2026-09-13 data PR#25 가 **실제로** 여기 걸렸다(매니페스트 해시 누락). 재생성이 불가능해지면 **모든 손편집이 검증 불가**가 된다. pytest 2862 는 스키마·정합성을 보지 「이 값이 어디서 왔는가」를 보지 않는다.
- **출처 추적** — 레코드마다 `_sources` 가 붙어 있고, `corrections` 10건이 존재하는 이유가 「스크랩에 전사 오류가 있다」다. 기도서 대조(ADR-036 미결8)에서 더 나올 것이므로, 출처를 구별하지 못하면 같은 오류를 두 번 고친다.

## 뒤집는 시점

**「완성됐을 때」가 아니라 「더 안 바뀔 때」**다. 셋이 동시에 참일 것 — ① 스키마를 바꾸는 미결이 닫혔다 ② 사제 확인 대기(설계서 미결13·17 · 검토 문서 Q1~Q11)가 전부 회신됐다 ③ 기도서 대조가 끝나 `corrections` 가 더 늘지 않는다.

**그때도 버리는 것이 아니라 동결**이다 — 입력과 파서를 `archive/` 로 옮기고, 출력을 정본으로 선언하고, 드리프트 검사를 스키마 검증으로 대체하는 ADR 을 낸다. 스키마 마이그레이션이 필요해지면 archive 를 꺼내 **재생(replay)** 할 수 있어야 한다. 선례는 **ADR-036 개정①** — `rule` 문법을 「빌드 시 1회 구조화」로 정해 엔진이 런타임에 파싱하지 않게 한 것과 같은 방향의 한 단계 더다.

## 준비로 지금 할 수 있는 것

`articles-supplement.json` 의 `corrections`(10건)를 별도 파일로 가른다. 그 배열은 supplement 가 아니라 **교정** 메커니즘이고 스키마도 공유하지 않는다(`{ids, day, collect, why}`). 지금 가르면 동결할 때 「무엇이 일회성 원료(archive 행)이고 무엇이 영구 정본(잔존)인가」가 **파일 경계로 이미 드러나 있다.**
