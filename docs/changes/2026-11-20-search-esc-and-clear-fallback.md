## 요약

휴대폰 검색 화면의 위쪽 입력창에 두 동작을 더한다. 입력창에서 Esc를 누르면 키보드만 내리고, 검색어와 결과는 그대로 둔다. 검색어 지우기(⊗)를 누른 뒤 깔때기(책 선택)가 포커스를 받지 못하면 포커스를 홈 탭으로 옮긴다. 둘 다 #612(ADR-048 1단계)에서 정하지 않고 남긴 일이다.

## 확정 · 근거

- 사용자 결정(2026-11-20): ⊗의 대비책과 Esc 모두 권장안대로 한다.
- ⊗의 대비책(ADR-048 §4)
  - 깔때기가 포커스를 받지 못하면 하단 탭 바의 홈 탭으로 옮긴다. 하단 입력창 때 있던 대비책을 옮긴 것이다. #612에서 이 대비책이 빠져, 깔때기가 받지 못하면 포커스가 페이지 맨 앞으로 떨어졌다.
  - ⊗를 누른 순간과, 최근 검색 화면이 입력창을 다시 그린 뒤에 모두 적용한다. 다시 그린 뒤의 처리는 책 선택 시트의 「적용」도 함께 쓰므로, 찾은 뒤의 「적용」에도 같은 대비책이 있다.
  - 위쪽 입력창의 깔때기는 휴대폰 검색 화면에서 늘 보이므로 실제로 일어나기는 어렵다.
- Esc(ADR-048 §5)
  - 키보드를 내린다. 검색어와 결과, 고른 책, 주소는 그대로다. #612가 하단 입력창의 Esc(검색 모드를 닫고 홈으로 가기)를 지운 뒤로는 Esc에 할 일이 없었다.
  - 포커스는 깔때기로 옮긴다(받지 못하면 홈 탭). 포커스를 빼기만 하면 페이지 맨 앞으로 떨어져 키보드 사용자가 자리를 잃으므로, ⊗와 같은 자리로 옮기는 방법을 골랐다.
  - Chrome은 검색 입력창에서 Esc를 누르면 검색어를 지운다. 이 PR 전에는 검색어만 지워지고 결과는 남아 입력창과 결과가 어긋났다. 그 기본 동작을 막는다(Playwright Chromium에서 확인).
  - 한글을 조합하는 중에 누른 Esc는 입력기가 쓰므로 건드리지 않는다.
  - 문서 전체의 Esc 처리(`app.js`)가 다른 단추의 펼침 상태를 되돌리며 포커스를 가져가지 않게, 입력창에서 이벤트를 멈춘다.
- `app.js`의 Esc 처리 주석에서 지운 검색 모핑을 가리키던 말을 고쳤다.

## 검증

- `npm run typecheck` 통과, `node --test tests/unit/*.test.js` 1,960개 통과.
- e2e에 두 시험을 더했다(`test_tabbar.py`).
  - 깔때기를 숨긴 채 찾은 뒤 ⊗를 누르면 포커스가 홈 탭에 있다.
  - Esc를 누르면 깔때기에 포커스와 테두리가 있고, 검색어와 주소, 결과가 그대로다. 찾지 않은 채 친 글자도 남는다. 조합 중의 Esc는 입력창의 포커스를 그대로 둔다.
  - 두 시험은 이 PR 전의 `search.js`에서 실패하고, 고친 뒤에 통과한다.
- e2e `test_tabbar.py`, `test_search.py`, `test_a11y_keyboard.py`를 작업 폴더 서버(8095)에서 돌려 모두 통과했다.

## 리뷰 반영

1회차(코드 리뷰, 다섯 건)
- 고침: 조합 중인지 볼 때 `keyCode`가 229인 경우도 본다. Safari는 조합 중의 Esc를 `isComposing`이 거짓인 채로 보낼 수 있다. 실제 Safari에서 확인하지는 않았다.
- 고침: `focusFunnelOrHome` 함수의 주석을 동작에 맞췄다. 홈 탭도 포커스를 받지 못하면 포커스는 원래 자리에 남는다.
- 다음에 고침(사용자 결정 2026-11-20): 홈 탭을 찾는 선택자가 `tabbar.js`와 겹친다. `docs/topics/routing.md` 「남은 일」에 적었다.
- 고치지 않음: 옛 깔때기만 포커스를 받지 못해 홈 탭으로 옮겼으면, 다시 그린 뒤 새 깔때기가 받을 수 있어도 홈 탭에 둔다. 깔때기는 휴대폰 검색 화면에서 늘 보여 거의 일어나지 않는다.
- 고침(사용자 지시 2026-11-20): 조합 중의 Esc 시험이 포커스만 보았다. `isComposing`이 참인 경우와 `keyCode`가 229인 경우를 모두 보내, 키를 막지 않는지와 포커스, 친 글자, 주소가 그대로인지 본다. `keyCode` 229 확인을 빼거나 조합 중의 키를 막도록 코드를 바꾸면 이 시험이 실패한다.
- 고친 뒤 타입 검사, 문서 검사 23개, e2e `test_tabbar.py` 20개가 통과했다.

2회차(코드 리뷰, 세 건, 사용자 지시 2026-11-21: 셋 다 고친다)
- 고침: ⊗를 누른 순간 옛 깔때기만 포커스를 받지 못해 홈 탭으로 옮기면, 다시 그린 입력창의 깔때기가 받을 수 있어도 포커스가 홈 탭에 남았다. 1회차에서 「고치지 않음」으로 둔 일이다. 홈 탭이 받은 것을 적어 두고(`standIn`), 다시 그린 뒤 포커스가 아직 그 홈 탭에 있으면 새 깔때기로 옮긴다. 리뷰는 ⊗를 누른 순간에는 대비책을 쓰지 말자고 했으나, 그러면 다시 그릴 때까지 포커스가 페이지 맨 앞에 있어 이 방법을 골랐다.
- 고침: 시험이 다시 그린 뒤의 대비책과 「적용」 경로를 보지 않았다. 옛 깔때기와 새 깔때기를 따로 숨기는 시험 둘(`test_tabbar.py`)과, 「적용」 뒤 새 깔때기를 숨기는 시험 하나(`test_search.py`)를 더했다. 깔때기는 스크립트로 만든 스타일시트로 숨긴다(`conftest.py`의 `ADD_STYLE_RULE`). 규칙이라 다시 그린 입력창에도 그리는 순간부터 적용된다.
- 고침: ⊗를 누른 뒤 300ms를 기다리던 시험이 홈 탭에 포커스가 올 때까지 기다린다.
- 홈 탭에서 넘겨주는 처리를 빼면 「새 깔때기가 가져간다」 시험이, 다시 그린 뒤의 대비책을 빼면 새로 더한 두 시험이 실패한다.
- 고친 뒤 타입 검사, 유닛 1,960개, e2e `test_tabbar.py`, `test_search.py`, `test_a11y_keyboard.py` 142개가 통과했다.
