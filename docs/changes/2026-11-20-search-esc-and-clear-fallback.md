## 요약

휴대폰 검색 화면의 위쪽 입력창에 두 동작을 더한다. 입력창에서 Esc를 누르면 키보드만 내리고, 검색어와 결과는 그대로 둔다. 검색어 지우기(⊗)를 누른 뒤 깔때기(책 선택)가 포커스를 받지 못하면 포커스를 홈 탭으로 옮긴다. 둘 다 #612(ADR-048 1단계)에서 정하지 않고 남긴 일이다.

## 확정 · 근거

- 사용자 결정(2026-11-20): ⊗의 대비책과 Esc 모두 권장안대로 한다.
- ⊗의 대비책(ADR-048 §4)
  - 깔때기가 포커스를 받지 못하면 하단 탭 바의 홈 탭으로 옮긴다. 하단 입력창 때 있던 대비책을 옮긴 것이다. #612에서 이 대비책이 빠져, 깔때기가 받지 못하면 포커스가 페이지 맨 앞으로 떨어졌다.
  - ⊗를 누른 순간과, 최근 검색 화면이 입력창을 다시 그린 뒤에 모두 적용한다. 다시 그린 뒤의 처리는 책 선택 시트의 「적용」도 함께 쓰므로, 찾은 뒤의 「적용」에도 같은 대비책이 있다.
  - 위쪽 입력창의 깔때기는 휴대폰 검색 화면에서 늘 보이므로 실제로 일어나기는 어렵다.
- Esc(ADR-048 §5)
  - 키보드를 내린다. 검색어와 결과, 고른 책, 주소는 그대로다. #612가 하단 입력창의 Esc(검색 모드를 닫고 홈으로 가기)를 지운 뒤로는 Esc에 할 일이 없었다.
  - 포커스는 깔때기로 옮긴다(받지 못하면 홈 탭). 포커스를 빼기만 하면 페이지 맨 앞으로 떨어져 키보드 사용자가 자리를 잃으므로, ⊗와 같은 자리로 옮기는 방법을 골랐다.
  - Chrome은 검색 입력창에서 Esc를 누르면 검색어를 지운다. 이 PR 전에는 검색어만 지워지고 결과는 남아 입력창과 결과가 어긋났다. 그 기본 동작을 막는다(Playwright Chromium에서 확인).
  - 한글을 조합하는 중에 누른 Esc는 입력기가 쓰므로 건드리지 않는다.
  - 문서 전체의 Esc 처리(`app.js`)가 다른 단추의 펼침 상태를 되돌리며 포커스를 가져가지 않게, 입력창에서 이벤트를 멈춘다.
- `app.js`의 Esc 처리 주석에서 지운 검색 모핑을 가리키던 말을 고쳤다.

## 검증

- `npm run typecheck` 통과, `node --test tests/unit/*.test.js` 1,960개 통과.
- e2e에 두 시험을 더했다(`test_tabbar.py`).
  - 깔때기를 숨긴 채 찾은 뒤 ⊗를 누르면 포커스가 홈 탭에 있다.
  - Esc를 누르면 깔때기에 포커스와 테두리가 있고, 검색어와 주소, 결과가 그대로다. 찾지 않은 채 친 글자도 남는다. 조합 중의 Esc는 입력창의 포커스를 그대로 둔다.
  - 두 시험은 이 PR 전의 `search.js`에서 실패하고, 고친 뒤에 통과한다.
- e2e `test_tabbar.py`, `test_search.py`, `test_a11y_keyboard.py`를 작업 폴더 서버(8095)에서 돌려 모두 통과했다.
