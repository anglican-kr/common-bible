## 요약

교회력 문서와 코드의 「품계」를 뜻에 따라 「등급」과 「우선순위」로, 「동률」과 「동점」을 「우선순위가 같다」와 「같은 순위」로 바꿨다. 사용자가 #416을 검토하며 두 낱말의 뜻을 물었고, 낱말을 정했다(`docs/writing.md` 「용어」, #416). data 저장소의 같은 낱말은 data#39에서 먼저 바꿨다.

## 확정 · 근거

모두 사용자가 정했다(2026-10-25).

- **「품계」는 뜻으로 나눈다.** 날의 갈래(`rank`. 대축일, 주요축일, 축일, 기념일 등)와 그 분류는 「등급」이다(「성 목요일의 등급」, 「등급 미해소」). 비교하는 순서(`precedence`)는 「우선순위」다(「우선순위 비교」, 「등급 칸이 우선순위와 참회 성격을 함께 정한다」). 「품계 사다리」는 「우선순위표」다. 둘은 일대일이 아니다. 주요축일 하나가 우선순위 셋(3, 4, 6)으로 나뉘고, 축일과 기념일은 둘 다 7이다.
- **작업 이름 「B1 품계 · 이동 · 전례색」은 「B1 우선순위 · 이동 · 전례색」이다.** B1이 하는 일은 우선순위를 비교해 그날의 지정 전례일을 정하는 것이다. 설계서 §6과 §6.1, 검토 문서 §3.3과 §5.10의 제목, pitfalls §19의 제목도 바꿨다.
- **「동률」은 「우선순위가 같다」, 짧게는 「같은 순위」다.** 「동률을 가르다」는 「순서를 정한다」로 썼다.
- **우선순위가 아닌 것이 같은 곳은 그 낱말로 썼다.** 폴백 매칭의 점수(설계서 §5.3, §7)는 「점수가 같다」, 가장 가까운 주일의 계산은 「거리가 같다」, Drive 동기화 병합은 「시각이 같다」다. 동기화 테스트 이름의 「이긴다」도 「앞선다」로 바꿨다(`docs/writing.md` 「용어」).
- **미결 제목 다섯도 바꿨다**(미결1, 6, 14, 17, 23). 「닫혀도 번호와 제목은 그대로 둔다」는 규칙이 있지만, #409가 「승자」를 제목에서도 바꾼 선례를 따랐다. 번호는 그대로다.
- **ADR의 「검토한 대안」 제목 넷**(성 목요일의 등급, 여성선교주일의 등급, 성당축성일 · 영명축일의 등급, 우선순위·이동 엔진의 범위)과 그것을 「」로 가리키는 곳을 함께 바꿨다.
- **데이터 문구를 인용한 곳**(`periods.json`의 `_meta.model`)은 data#39의 새 문구에 맞췄다.
- **일부러 두었다.** 코드 이름(`rank`, `precedence`), 규칙 마커(`R-6.1-ladder`, `R-6.2-tie-ladder`), 「범주 사다리」, 다른 뜻의 「가르다」(파일을 가르다, 요일로 가르다)는 두었다. 머지된 원장과 보관 문서는 고치지 않는다.

## 검증

- `git grep`으로 남은 「품계」, 「동률」, 「동점」이 `docs/writing.md`의 규칙 본문뿐임을 확인했다(머지된 원장과 보관 문서 제외).
- 교회력 사실 토큰 비교(`python3 scripts/docs_facts_snapshot.py --diff main WORKTREE --strict-counts`)에서 사라지거나 줄어든 토큰이 0이다.
- 일반 토큰 비교(`--docs 'docs/*.md' --docs '*.md' --kinds general --strict-counts`)에서 사라지거나 줄어든 것은 위에서 바꾼 「」 인용뿐이다. ADR 「검토한 대안」 제목 넷, 데이터 문구, 「동률을 가르는 순서」, 「사다리가 가르지 못하는 것」이고, 남은 수는 머지된 원장에 있다.
- 센티널 「도착한 축일은 우선순위와 무관하게 자리를 지킨다」를 설계서와 `docs-crossref.test.js`에서 함께 바꿨다.
- 유닛 테스트 1,366개 가운데 1,365개가 통과했다(1개는 원래 건너뛰는 미결13 픽스처). `npm run typecheck`도 통과했다.
- e2e는 돌리지 않았다. 코드는 주석과 테스트 이름만 바뀌었다.

## 갱신한 문서
