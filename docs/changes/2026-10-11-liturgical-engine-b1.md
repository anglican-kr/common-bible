# feat: 교회력 엔진 B1 품계 · 승자 · 전례색 · 재일 — official · 재분류 · 사계재 자 · fastOf (ADR-037 §6 · PR 3 첫째)

## 요약

교회력 엔진 B1(설계서 §6)을 구현하는 PR 3 의 **첫째 GitHub PR** 이다. PR 3 은 둘로 나눴다(사용자 결정 2026-10-10). 이 PR 은 품계 · 승자 · 재분류 · 전례색 · 재일을 맡는다. 이동 패스 · 선택 봉헌 · `transfers` · `optionals` 픽스처 · 1900~2100 불변식 · 골든 덤프는 둘째 PR 몫이다. 설계서 §8 의 PR 3 은 한 단계로 두었다(번호 재부여 없음).

`resolveDate` 의 반환 형태는 그대로다(PR 2 가 고정 — 설계서 §6.5 마지막 단락). PR 2 가 비워 둔 `official` · `color` · `colors` · `colorAlt` 를 채우고, 밀린 고유 후보의 `status` 를 재분류한다.

- **품계 사다리**(→ R-6.1-ladder · R-6.2-tie-ladder) — 정렬 키 `(유효 precedence, 범주 사다리, 고유 본기도, id)` 하나(`compareCandidates`).
  - 유효 precedence: `null` 은 정렬 최하위, 사계재 · 기념일은 9(→ R-6.1-ineligible — 판별은 `kind` 가 아니라 `rank` · 규칙 종류), A 특례(`outranks_sunday`)는 1.5.
  - 범주 사다리: 도착 > temporal 규칙일 > sanctoral 고정일 > 격자 > 합성 guard.
  - **고유 본기도 키**(사용자 결정 2026-10-10): prec 7 축일 동률 다섯 쌍 가운데 3.01 만 갈려 해마다 **삼일절**이 `official` 이다. `id` 순만으로는 해마다 데이빗이었다.
- **승자와 재분류**(`settle`) — 그날 남아 있는 후보와 보호 기간의 `guard` 를 순위대로 세운다.
  - 「밀렸다」는 이동 패스의 `displacer` 와 같은 판정이다 — 앞선 후보 가운데 어느 한쪽이라도 겹침이 해마다 달라지는 것, 실제 후보를 우선한다.
  - 밀린 prec 7 축일(`transferable` 아님)은 `omitted`, 밀린 `commemorate_only`(추수감사주일)는 `commemorated` — 둘 다 `displacedBy` 를 싣는다.
  - 고정일끼리의 겹침은 동시 봉헌이라 진 쪽도 `proper` 다(8.15 광복절 · 9.29 설립 기념일).
  - 성주간 · 부활 8일의 prec 7 은 `guard` 가 생략시킨다. `guard` 는 후보가 아니라 승자가 되지 않는다 — 성주간 평일의 승자는 격자다.
  - `candidates` 의 ① 묶음(교회력 축일 · 재일)은 출처 순이 아니라 품계 순이다.
- **전례색**(`dayColorsOf` · → R-6.4-color-order) — 절기 바탕에 승자 색이 덮고, 성주간 · 부활 8일에는 덮지 못한다.
  - 절기 바탕은 격자 관측일의 색이다: 대림 자 · 청, 대림 3주일 장미 · 청, 사순 4주일 장미, 성주간 전체 홍.
  - E−1 은 승자가 부활밤이어도 홍이다(미결20).
  - **사계재 날은 책자대로 자**(미결26 — 닫음): 승자가 격자면 `color` 자 · `colors` [자], 축일이 이기면 `color` 는 축일 색이고 `colors` 는 [자, 축일 색]이다. 사계재 밖 평일의 병기는 세우지 않는다.
- **재일**(`fastOf(resolved)` → `"major"` · `"minor"` · `null` — → R-6.3-friday-fast) — 승자와 무관하게 그날 남아 있는 후보와 날짜로 판정한다.
  - 사순 주간 40일 가운데 성 목요일만 재일이 아니다(대축일 — ADR-036 §6).
  - 성탄절기 금요일은 `christmasToBaptism` 으로 뺀다.
  - `ResolvedDate` 에 싣지 않으려고 따로 둔 순수 함수다. 공유 타입은 `LiturgicalFast`.
- **픽스처 소비** — `liturgical-engine.data.test.js` 가 `winners.cases.json` 을 케이스 하나당 테스트 하나로 돌린다(28 — 26 실행).
  - 건너뛰는 둘(`W-2026-05-15-matthias-color` · `W-2025-12-29-holy-innocents-color`)은 도착이 승자라 이동 패스가 있어야 맞는다.
  - `expect` 의 모르는 키와 연도 범위 단언은 실패로 다룬다 — 소비자가 조용히 무시하면 그 단언은 아무것도 지키지 못한다.
- **데이터 포인터** — 픽스처 소비가 데이터 오기를 하나 잡았다. 대림 3주일 나해 복음이 「19-26」이었는데, 교구 2026 달력 · RCL 은 「19-28」이다. 데이터 저장소에서 고쳤고(**data#28**), 이 PR 이 그 커밋 `0f1faee` 로 포인터를 올린다.

## 발견한 모순 · 후속

- **데이터 오기 — 대림 3주일 나해 복음** — 사이트 기사 archives/3139 의 「19-26」이 데이터에 그대로 실려 있었다. data#28 이 `readings.SOURCE_FIXES` 로 고친다. **data#28 이 이 PR 보다 먼저 머지돼야 한다** — 이 PR 의 포인터가 그 브랜치 커밋이다(#339 와 같은 순서).
- **픽스처 `record` 둘이 본문 레코드 id 의 앞부분만 적었다**(`d1217-성탄-8일-전` · `d1221-성탄-4일-전`). README 계약은 레코드 id 이므로 정확한 id(`…-t1-s1`)로 고쳤다.
- **#340 의 미결25 문장 「성주간 월~수와 겹쳐도 같다」는 guard 와 어긋났다** — 성주간 월~수의 prec 7 은 생략된다. 실측으로는 고유 독서가 있는 prec 7 축일이 3.16~4.21 에 하나도 없어 해당하는 해가 없다. 그래서 「성주간 월~수에는 이 갈림이 생기지 않는다」로 다듬었다.
  - 같은 문장의 「고유 독서가 있는 축일(10행)」은 엔진으로 세면 13행이다. 수를 지우고 이름만 남겼다 — facts 키가 없는 수는 적지 않는다.
- **중간 상태** — 이동 패스가 없는 동안에는 옮겨질 축일이 기원 날짜에 `proper` 로 남아 승자가 될 수 있다(예: 2025-04-25 마르코). 설계서 §6.5 마지막 단락에 적었다.
  - 그날 색은 가드가 막으므로 이 동안에도 맞다 — 실데이터 테스트가 2035-03-19 · 2025-04-25 를 본다.

  - 비워 둔 `displacedBy`(루가 2026-10-19 · 2038 마르코 / 필립보 · 야고보 · 2043 · 2035 수태고지)를 엔진 계산값으로 검증한 뒤 채운다.
