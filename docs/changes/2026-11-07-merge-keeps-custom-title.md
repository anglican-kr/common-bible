## 요약

같은 장의 북마크에 절을 합치면, 사용자가 직접 지은 제목도 「책 장:합친 범위」로 바뀌었다(known-issues §19.1). 이사 7:14를 「임마누엘의 징조」로 저장하고 1절을 합치면 제목이 「이사 7:1,14」가 됐다. 이제 제목이 그 북마크의 기본 이름과 같을 때만 합친 범위로 다시 짓고, 사용자가 고친 제목은 그대로 둔다. 옛 저장값을 옮길 때의 이름 규칙(ADR-010 「옛 저장값」, pitfalls §38)과 같은 규칙이다. 결정은 ADR-010 「저장, 병합, 확인 모달」과 「검토한 대안」의 「합치기의 제목」에 있다.

## 확정 · 근거

- 고칠 방향은 known-issues §19.1에 2026-10-22에 적어 둔 것을 따랐다.
- **기본 이름을 만드는 식이 네 곳에 있었다.** 이슈에는 셋(저장 대화상자, 합치기, 옛 저장값 옮기기)으로 적혔지만, 목록의 참조 줄(`bookmark-tree.js`)도 같은 식이었다. 넷을 `bookmark-core.js defaultBookmarkLabel` 하나로 모았다.
  - 모으기 전에 넷의 결과가 같은지 확인했다. 성서 목록의 책 75권과 목록에 없는 책 하나, 장 셋, 범위 여섯(「all」, 「16aa」 포함)을 성서 목록이 있을 때와 없을 때로 넣어, 옛 식과 새 함수를 9,348번 견줬다. 모두 같았다.
  - 다른 것은 실제로 생기지 않는 입력뿐이다. 책 식별자가 없는 북마크에서 합치기만 빈 문자열로 이름을 지었다. 합치기 후보는 책 식별자로 찾으므로 이런 북마크는 오지 않는다. 옛 저장값 옮기기에는 장 전체 형식이 없었는데, 옛 표기는 장 전체일 수 없다.
  - 참조 줄까지 모은 것은 구현하며 정했다. ADR-010은 옛 기본 이름을 옮기는 근거로 「목록의 한 행에 이름과 참조가 함께 보인다」를 들어, 기본 이름과 참조가 같은 글자여야 하는 설계다.
- **범위를 바꾸는 일과 이름 규칙을 함수 하나(`changeBookmarkRange`)에 두었다.** 이름은 바꾸기 전 범위의 기본 이름과 견줘야 해서, 범위를 먼저 바꾸면 기본 이름도 다시 짓지 못한다. 합치기와 옛 저장값 옮기기가 이 함수를 쓴다.
- **옛 버전의 다른 형식 기본 이름**(`git log -S`로 찾았다). 2026-04-25 첫 구현(`22efa03`)의 저장 대화상자는 긴 책 이름(`name_ko`, 「이사야 7:14」)을 제안했고, 그때의 합치기는 제목을 바꾸지 않았다. 다음 날(`cb56689`) 짧은 이름으로 바꾸면서 합치기가 제목을 다시 짓기 시작했다. 둘 다 `feat/bookmark` 브랜치에만 있었고, 북마크가 처음 실린 릴리스 1.2.0(2026-04-30, #8 머지 뒤)은 짧은 이름이다.
  - 그래서 긴 이름은 기본 이름으로 보지 않았다. 보수적인 쪽을 골랐다. 사용자가 직접 쓴 「이사야 7:14」를 바꾸지 않고, 그 대가는 그런 이름이 합친 범위를 따라가지 않는 것뿐이다. 재검토 조건은 ADR-010에 적었다.
- **일부러 바꾸지 않은 것.**
  - 빈 제목이나 제목이 없는 북마크는 기본 이름이 아니라서 합쳐도 그대로 둔다. 종전 합치기는 이런 북마크에도 이름을 지었다. 이런 북마크는 가져오기와 동기화로만 들어온다(known-issues §15.8). 옛 저장값 옮기기는 이미 빈 이름을 그대로 두었으므로, 두 길을 한 규칙으로 맞췄다.
  - 성서 목록을 받기 전에는 기본 이름이 책 식별자로 시작한다(「isa 7:14」). 그래서 그때 합치면 짧은 이름으로 지은 제목은 그대로 남는다. 합치기 대화상자는 장 화면에서만 열리고 장 화면은 성서 목록을 받으므로 실제로는 생기지 않는다.

- `npm run typecheck`: 통과.
- `node --test tests/unit/docs-*.test.js`: 통과.
- e2e 새 시험 2건(`test_bookmark.py`의 `test_merge_keeps_a_title_the_user_wrote`, `test_merge_renames_the_default_title`). JS만 main으로 되돌려 먼저 돌렸다. 직접 지은 제목의 시험은 결함대로 실패했고(제목이 「이사 7:1,14」), 기본 이름의 시험은 통과했다. 고친 JS에서는 둘 다 통과한다.
- 고른 e2e 파일은 여섯이고 93건이 모두 통과했다(2분 47초, 작업 폴더의 서버 8091).
