# refactor: SW 캐시를 셸/데이터/오디오 3개로 분리

## Summary

단일 `CACHE_NAME`이 셸과 본문·오디오 데이터를 한 묶음으로 관리하던 구조를 3개의 독립 캐시로 분리한다. 셸만 갱신된 릴리스에서 사용자가 이미 받은 1328장 본문·검색 인덱스·mp3 캐시가 보존된다.

- `SHELL_CACHE` (`shell-49`) — 매 릴리스 bump. JS/CSS/HTML/icons + 코드와 강결합된 `books.json`·`search-meta.json`
- `DATA_CACHE` (`data-1`) — `/data/bible/*`, `/data/search-{ot,nt,dc}.json`. 데이터 포맷 변경 시에만 bump
- `AUDIO_CACHE` (`audio-1`) — `/data/audio/*.mp3`. 인코딩/소스 변경 시에만 bump
- `FONT_CACHE` (`fonts-v1`) — 그대로 유지

`sw.js`에 `cacheNameFor(pathname)` 라우팅 헬퍼 추가, activate 단계는 활성 집합(`KNOWN_CACHES`)에 없는 캐시만 삭제. `scripts/release.py`는 기본 동작에 더해 `--bump-data` / `--bump-audio` 플래그로 데이터·오디오 캐시를 독립적으로 bump 가능.

ADR-001에 개정 블록 추가, architecture.md / coding-pitfalls.md / README·CLAUDE·GEMINI 캐시 명칭과 운영 절차 동기화.
