# feat: 교회력 엔진 — 저녁 전례: 성 토요일의 대표는 성 토요일, 부활밤 · 성탄 밤은 저녁 전례 (R-6.1-evening · 미결20 닫힘)

## 요약

설계서 미결20(성 토요일 하루에 전례가 둘 — 낮 성 토요일 홍 · 밤 부활밤 백)을 사용자 결정으로 닫는다. 캘린더 탭 1단계(#348) 화면에서 성 토요일 칸이 「부활밤」(점은 적색)으로 보여 드러난 물음이다.

- **저녁 전례**(→ 설계서 R-6.1-evening): 부활밤(`t-부활밤` — 성 토요일 저녁)과 성탄 밤(`d1225-성탄-밤` — 12.25 로 정의돼 있지만 전날 12.24 저녁)은 **드리는 날의 후보 맨 끝**에 `evening: true` 로 실리고, 그날의 대표(`official`) · 색 · 재분류(`settle`)에도, 축일을 옮기는 이동 패스에도 참여하지 않는다(이동 패스는 리뷰 반영에서 — 아래). 엔진 상수 `EVENING_LITURGIES` 가 정의 표의 id 와 「정의 날짜에서 드리는 날까지의 날 수」(부활밤 0 · 성탄 밤 −1)를 든다 — `resolveDateIn` 이 낮의 판정에서 빼고 끝에 붙인다.
- **성 토요일의 대표는 성 토요일 행**이다 — 데이터 등급 「대축일」 · prec 1(data#32 — 리뷰 반영의 사용자 결정 「성 토요일은 부활밤에 밀리지 않아」)이라 그날 다른 어떤 후보보다 앞선다. 성격은 평일 그대로라 소재일도 그대로다. 처음 구현은 「등급 칸이 빈 temporal 평일 행 = 유효 8(격자와 동률 → 사다리)」이었고 리뷰 반영에서 지웠다.
- 결과: 2026-04-04 대표 성 토요일 · 적색, 후보 「성 토요일 · 성주간 토요일 · 부활밤(저녁)」. 2026-12-24 대표 대림 평일 · 자색 + 성탄 밤(저녁). 2026-12-25 후보 성탄 낮 · 새벽.
- **이동 패스도 저녁 전례를 순위에 넣지 않는다**(리뷰 반영) — 성 토요일에 걸린 주요축일은 성 토요일 행(prec 1)이 밀어낸다(R-6.3-holy-week-guard — 픽스처 T-2062-03-27 의 수태고지). 옮겨지는 날짜는 그대로이고 골든 덤프(1900~2100 이동)는 「밀어낸 것」 6건만 부활밤 → 성 토요일로 바뀐다. 처음 구현은 「이동 패스는 이 상수를 보지 않아 부활밤이 민다」였다.
- **화면**(리뷰 반영): 캘린더(#348)의 평일 12.24 칸은 이름 없이(저녁 후보는 칸 이름이 되지 않는다), 전례독서의 관측일 칩 줄은 줄바꿈(휴대폰에서도 「부활밤 · 저녁」이 보인다).
- **전례독서 화면**: 칩 꼬리말 「· 저녁」(`statusSuffix`). 성 토요일을 열면 성 토요일 독서(욥기 14 …)가 먼저이고 부활밤 칩을 고르면 백색 · 부활밤 독서(「고른 본문의 색」 — 기존 규칙). 성탄 밤의 독서 · 본기도는 12.24 에서도 정의 날짜(12.25) 키로 찾는다.
- 타입: `Candidate.evening?: true`(`js/types.d.ts`).

## 확정·근거

- **사용자 결정(2026-10-15)**: 「엔진은 "성 토요일"을 기본으로 보여줘야 해. 독서 화면에서 칩으로 부활밤을 보여줄 수 있게 하면 되. 부활밤은 저녁 전례로 보는 게 맞아. 성탄 밤도 12.24 저녁 전례가 되어야 맞겠지」 — 「네가 말한 "권장대로"인 셈이야」. 물은 셋: ① 부활밤을 저녁 전례로 따로 볼지 ② 그날 독서 화면을 열면 먼저 보일 본문(성 토요일 / 부활밤) — 권장대로 성 토요일 ③ 성탄 밤의 날짜(12.24 저녁 / 12.25) — 권장대로 12.24 저녁. coding-pitfalls §25(번호는 #348 의 §24 다음).
- **책자 근거**: 2024 · 2025 · 2026 「전례독서」 — 성 토요일 칸은 「성(주간) 토요일 [홍] · 감사성찬례 없음」, 부활밤은 「부활밤 예식 [백]」으로 따로(2025 · 2026 저녁 칸, 2024 한 줄). 12.24 칸에 「성탄밤 [백]」, 12.25 칸에는 성탄새벽 · 성탄낮만(2024 는 12.24 칸의 한 줄). **2027 검토용 초안만** 12.25 칸에 [성탄밤] · [성탄 새벽] · [성탄 낮] 셋을 실었다 — 확정판이 그대로면 `tools/booklet/` 재대조 때 다시 본다(초안의 차이로 데이터 · 엔진을 고치지 않는다 — §22).
- 이름: 책자는 그날을 「성 토요일」(2024 · 2027 초안) · 「성주간 토요일」(2025 · 2026)로 적었다 — 사용자 요청대로 데이터의 temporal 행 「성 토요일」.
- **사용자 아이디어(결정 전)**: 「시간대에 따라, 일몰 이후 또는 저녁 6시 이후가 되면 저녁 전례로 간주해 전례색을 변경하는 것도 하나의 방법」. 엔진은 날짜 단위로 두고, 뷰의 물음으로 ADR-038 「검토한 대안 — 저녁 전례」 C 에 보류로 적었다 — 같은 날짜 주소가 시각마다 다른 화면이 되는 문제(공유 · 뒤로 가기)와 일몰의 위치 권한이 걸린다. 「오늘」 화면에만, 고른 칩을 주소에 적는 꼴이면 가능하다.
- **기각한 갈래**(설계서 §9.2 미결20 · ADR-038 「검토한 대안」): 승자 부활밤 · 색 홍(이름과 색이 어긋나고 책자와 다르다) · `ResolvedDate` 가 색을 둘 낸다(소비자마다 낮 · 밤을 다시 가려야 한다) · 데이터 표에 저녁 표지 열(데이터 저장소 파서 변경 — 엔진 상수로 시작, 실데이터 테스트가 두 id 의 실재를 지킨다).
