## 요약

휴대폰의 검색 입력창을 검색 화면 위쪽의 입력창 하나로 바꾼다. 탭 바의 검색 원형은 하단 입력창으로 바뀌지 않는다(모핑하지 않는다). 검색 원형은 검색 화면이 아닌 곳에서는 검색 화면으로 가기만 하고, 검색 화면에서는 위쪽 입력창으로 포커스를 옮긴다. 키보드 내리기 단추를 없애고, 위쪽 입력창의 검색어 지우기는 키보드를 내리고 깔때기로 포커스를 옮긴다. 새 ADR-048이 ADR-030 §3의 검색 모핑을 대체한다. 쓰이지 않게 된 CSS는 다음 PR(2단계)에서 지운다.

## 확정 · 근거

- 사용자 결정(2026-11-19)
  - 아이폰에서 최근 검색 화면의 하단 입력창을 누르면 화면이 위로 튀었다가 돌아왔다. 키보드 높이를 기억해 입력창을 미리 올리는 방법(PR #611)이 dev에서 효과가 없자, 입력창을 화면 위로 올리기로 했다. 사용자는 Apple Music도 검색 입력창을 위에 둔다고 보았고, 엄지가 닿기 어려운 불편은 받아들였다. PR #611은 닫았다.
  - 검색 화면이 아닌 곳에서 검색 원형을 누르면 검색 화면으로 가고, 검색 화면에서 누르면 검색 입력창으로 포커스를 옮긴다. 포커스가 입력창으로 옮겨 갈 때까지 키보드는 뜨지 않는다.
  - 키보드 내리기 단추는 없앤다(권장안). 위쪽 입력창의 검색어 지우기는 #610에서 정한 대로 키보드를 내리고 깔때기로 포커스를 옮긴다(권장안).
- 구현하며 정한 것
  - 검색 화면에는 이미 위쪽 입력창(`#search-inpage-bar`)이 있었고 휴대폰에서는 모핑 중에만 숨겼다. 그래서 새로 만들지 않고 모핑을 없앴다. 하단 입력창, 그 검색어 지우기, 키보드 내리기 단추의 마크업과, 모핑, 키보드 위로 올리기, Esc로 모핑 닫기의 스크립트를 지웠다. 쓰이지 않게 된 CSS 규칙은 남겨 다음 PR에서 지운다(`docs/topics/routing.md` 「남은 일」). 맞는 요소가 없어 아무 일도 하지 않는다.
  - 검색 화면에서 검색 원형을 누르면 맨 위로 올린 뒤 포커스를 준다. 입력창이 검색 화면 맨 위에 있어, 결과를 내려 보던 중이면 화면 밖이다.
  - 검색 화면을 그릴 때 위쪽 입력창이 저절로 포커스를 받던 것(검색어가 없는 화면)을 없앴다. 그대로 두면 다른 화면에서 검색 원형을 눌러 왔을 때 포커스가 입력창에 들어간다.
  - 위쪽 입력창은 화면을 다시 그릴 때마다 새로 만들어진다. 그래서 지우기와 책 선택 시트의 「적용」이 다시 그린 입력창의 무엇에 포커스를 줄지 남기는 표시를 하나로 모았다(`_inpageFocusAfterRender`). 지우기는 깔때기, 「적용」은 찾았으면 깔때기, 검색어가 없으면 입력이다(ADR-033 D3). 전에는 「적용」이 검색어가 없을 때 다시 그린 입력창의 저절로 받는 포커스에 기댔다.
  - 데스크톱의 상단 바 검색창은 그대로다.

## 검증

- `npm run typecheck` 통과, `node --test tests/unit/*.test.js` 1,949개 통과. 탭 바 유닛에서 하단 키보드 처리의 시험(키보드 높이, X 단추, 입력창 올리기)을 그 코드와 함께 지웠다.
- e2e `test_tabbar.py` 18개, `test_search.py` 105개를 작업 폴더 서버(8094)에서 돌려 모두 통과했다. 새 시험 `test_search_button_goes_to_search_then_focuses_the_input`은 검색 원형이 다른 화면에서는 검색 화면으로 가기만 하는지, 검색 화면에서는 맨 위로 올리고 입력창에 포커스를 주는지, 다른 탭에 갔다 오면 마지막 검색 화면인지 본다. `test_inpage_clear_lowers_the_keyboard_and_focuses_the_funnel`은 결과 화면에서, 입력 중에, 키보드로 지울 때 다시 그린 입력창의 깔때기에 포커스가 가는지, 포커스 테두리가 그려지는지 본다. 검색 화면에서 포커스 주기와 최근 검색 화면을 다시 그린 뒤 깔때기 포커스를 하나씩 빼면 실패한다.
- 실제 앱으로 시안을 만들어 보였다(지금 화면, 위쪽 입력창, 주소로 연 결과 화면).
- 아이폰에서 키보드가 뜨는 모습과 화면이 튀지 않는지는 dev에 올린 뒤 확인한다.
