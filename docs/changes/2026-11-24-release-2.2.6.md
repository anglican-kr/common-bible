## 요약

버전을 2.2.5에서 2.2.6으로 올린다(`scripts/release.py patch`). 2.2.5 뒤에 화면을 옮겨도 주석 툴팁이 남던 문제(#649), 검색이 결과를 받지 못할 때의 실패 화면(#651), 구글 애널리틱스에 방문이 2건씩 기록되던 문제(#650)의 수정과, 그 작업에서 찾은 문제를 known-issues에 적은 것(#652)이 들어간다.

아래 「릴리스 노트 초안」은 머지한 뒤 GitHub Release에 그대로 쓴다. 「변경 사항」은 `python3 scripts/changelog.py 2.2.5 HEAD`의 출력이고, 끝의 비교 링크만 2.2.6 태그를 가리키게 고쳤다.

## 확정 · 근거

- **버전은 2.2.6이다**(사용자 지시 2026-11-24). 사용자는 네 PR을 2.2.5에 넣으려 했으나, 머지 시점을 정하는 사이에 다른 세션이 2.2.5를 운영까지 냈다. 사용자는 2.2.6으로 내자고 한 뒤, 2.2.5가 운영에 아직 나가지 않았다면 2.2.5의 태그와 Release를 지우고 다시 만들자고 했다. 08:39에 확인하니 운영(`https://bible.anglican.kr/version.json`)이 이미 2.2.5와 앱 커밋 `f2513fe`를 내려 주고 있어, 지우지 않고 2.2.6으로 낸다. 서비스 워커는 셸 캐시의 이름을 버전으로 짓는다(`sw-version.js`의 `APP_VERSION`, ADR-021). 같은 버전으로 다시 내면 2.2.5를 이미 받은 기기가 새 파일을 받지 않는다.
- **노트의 짜임**(구현하며 정함, `docs/writing.md` 「릴리스 노트」). 「버그 수정」 둘이다. 화면을 옮겨도 주석이 남던 것(#649)과 검색 자료를 받지 못했을 때의 화면(#651)은 2.2.5에도 있던 문제다. 「새 기능」과 「기능 개선」은 없다.
- **노트에 넣지 않은 것.** 방문이 2건씩 기록되던 것(#650)은 이용 통계의 수치만 바꾸고 사용자가 겪는 변화가 없다. #652는 문서다.
- **2.2.5의 운영에는 첫 화면의 방문이 2건으로 기록된다.** 2.2.5에는 #650이 없어 구글 태그가 첫 화면을 스스로 한 번 더 보낸다. 주소가 바뀔 때의 기록은 사용자가 애널리틱스 관리 화면에서 2026-11-23에 껐으므로, 화면을 옮길 때의 중복은 없다(#650의 원장. 2.2.5의 조합은 따로 재지 않았다). 2.2.6을 받은 기기부터 화면마다 1건이 된다.
- **릴리스마다 하는 정리**(CLAUDE.md 「지식 베이스 루프」 3번).
  - 2.2.5(2026-11-24) 뒤의 원장은 #649, #650, #651, #652의 것이다. 새 ADR은 없다. ADR-048에 §6을 더했고 ADR-038, ADR-041, ADR-049는 제자리에서 고쳤다.
  - `docs/index.md`와 실제 파일, 링크, 번호 대장은 문서 검사가 본다(통과). 끝나서 `archive/`로 옮길 설계 문서는 없다.
  - `docs/topics/platform.md`가 160줄에서 216줄이 되어 200줄을 넘겼다. #652가 「남은 일」에 여섯 항목(known-issues §61, §62, §63, §65, §76, §77) 51줄을 더했고, #650이 「지금 동작」에 방문 기록 6줄을 더했다. 「남은 일」의 항목은 고치면 지워지고 §61은 사용자가 고치자고 했으므로(2026-11-24), 지금은 나누지 않고 다음 릴리스의 정리에서 다시 본다(구현하며 정함). 그 밖에 200줄을 새로 넘긴 문서는 없다.

## 검증

버전 파일 둘을 2.2.6으로 바꾼 커밋에서 점검했다.

- `node --test tests/unit/*.test.js`: 1,995건 통과(실데이터 시험 포함). 타입 검사 `tsc -p tsconfig.json --noEmit`와 `tsc -p tsconfig.worker.json --noEmit`: 통과. `scripts/test_changelog.py` 32건과 `scripts/test_release.py` 12건: 통과.
- CSP 점검: `python -I tools/csp/csp_sweep.py http://localhost:8091`(서비스 워커 막음)과 `--sw`(켬) 모두 위반 0종. 건너뛴 단계는 이 브라우저에서 할 수 없는 데스크톱 오디오 재생 하나다(2.2.5와 같다). 이 점검은 구글의 주소로 진짜 요청을 보내므로, 점검한 시각(08:50쯤)에 `localhost`의 방문이 통계에 섞였을 수 있다.
- e2e(서버 8091, 구글의 수집 요청은 e2e 사본의 `conftest.py`에서 가로챘다): 버전과 관련된 `test_update_toast.py`와 `test_liturgical_lazy_load.py` 20건 통과.
- 이번 판에서 바뀐 화면의 e2e는 버전을 올리기 전의 같은 코드에서 421건이 통과했다(`test_note_tooltip.py`, `test_navigation.py`, `test_search.py`, `test_a11y_axe.py`, `test_calendar_view.py`, `test_lectionary_view.py`). 네 PR을 머지하기 전에 합친 결과를 만들어 돌렸고, 머지한 뒤 `dev`(`9122fb4`)의 파일이 그 결과와 같은 것을 트리 해시(`bc2fd6f`)로 확인했다.
- 배포한 뒤 `dev`와 운영의 `version.json`이 2.2.6인지 실제 사이트에서 확인한다.
- 실제 아이폰에서는 확인하지 못했다. 주석을 연 채 화면을 옮기는 것과 검색의 실패 화면은 dev.anglican.kr에서 사용자가 본다.
