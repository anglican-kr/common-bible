## 요약

낱말 정리의 앱 PR 셋 가운데 셋째다. 한국어 문장에 쓴 temporal을 「이동 축일」로, sanctoral과 「성인력」을 「월별 축일」(기도서 31-37쪽의 이름)로 바꿨다. 문서마다(설계서는 장마다) 처음 나오는 곳에 「이동 축일(temporal)」, 「월별 축일(sanctoral)」로 영어 이름을 한 번 달았다. 데이터 저장소 쪽은 data#43에서 바꿨다.

## 확정 · 근거

- **낱말**: 사용자가 2026-10-25에 정했고, #420에서 `docs/writing.md` 「용어」에 적었다.
- **바꾼 방식**: 문서, 주석, 테스트 이름, 픽스처 문구의 한국어 문장에서 229곳을 하나씩 보고 바꿨다.
  - 「temporal 기념일」은 「이동 축일 표의 기념일」로, 「성인력 기념일」은 「월별 축일 표의 기념일」로 썼다. 「이동 축일인 기념일」이라 하면 등급 이름(축일, 기념일)이 서로 부딪친다.
  - 「temporal 규칙일」과 「sanctoral 고정일」은 같은 뜻을 겹쳐 쓴 말이라 「이동 축일」, 「월별 축일」로 줄였다. 범주 사다리(R-6.2-tie-ladder)에만 풀이를 남겨 「도착 > 이동 축일(규칙일) > 월별 축일(고정일) > 격자 > 합성 guard」로 썼다(설계서 06장, 엔진 주석, 테스트 이름).
  - 「temporal 지정 전례일」은 「이동 축일인 지정 전례일」로 썼다.
  - 「성인력에 행이 없다」처럼 표를 가리키는 곳은 「월별 축일 표에」로 썼다.
  - 영어 이름은 문서와 코드 파일마다 처음 나오는 곳에 한 번 달았다. 픽스처(`tests/fixtures/liturgical/*.cases.json`)에는 달지 않았다. 케이스마다 따로 읽는 문구라 「파일의 첫 언급」이 없다.
  - 격자를 가리키던 「격자의 절기 위치(temporal)」에서는 괄호를 뺐다(설계서 §5.5의 후보 출처 ①과 그 코드 블록 주석, ADR-037 §6). 이동 축일 행은 따로 ④ 규칙 파생 후보다.
- **바꾼 제목**: ADR-036 §5는 「구분자 `kind`: `temporal`(이동 축일) / `sanctoral`(월별 축일)」로, 「성인력 보완 영역」은 「월별 축일 보완 영역」으로, 「미결 사항」 9의 「성인력 보완」은 「월별 축일 보완」으로 바꿨다. 「성인력 보완 영역」을 인용한 여섯 곳도 함께 바꿨다. 이 제목들로 가는 앵커 링크는 없다.
- **데이터와 맞춘 것**: ADR-036 §4의 `_vocab.kind` 예시를 데이터(`liturgical/coords.py`, data#43)와 같게 「이동 축일」, 「월별 축일」로 고쳤다.
- **바꾸지 않은 것**
  - 코드 이름과 값: `kind: "temporal"`, `temporal-feasts.json`, `sanctoral.json`, `sanctoral_class`, facts 키(`sanctoral.commemoration`), 백틱 안의 파서 이름
  - 표 파일을 이름으로 부른 곳: 설계서 §5.4의 조인 목록(「sanctoral ↔ readings/collects」 등), 「정의 표(sanctoral, temporal-feasts)」(설계서 §5.4, `js/types.d.ts`)
  - 영어로 쓴 주석의 temporal, sanctoral
  - 테스트가 만드는 합성 레코드의 이름 값 「합성 temporal 기념일」. 데이터 값이다.
  - `docs/writing.md` 「용어」의 줄, 머지된 원장(`docs/changes/`), 보관 문서(`docs/archive/`), 「성인 공통」
- **함께 고친 것**: `docs/architecture.md` ADR 목록에서 ADR-036 줄의 「temporal/sanctoral」을 「이동 축일과 월별 축일(sanctoral)을 가르는 `kind`」로 풀어 썼다.

## 검증

- 유닛 전체: 1365개 통과, 1개 건너뜀. `npm run typecheck` 통과.
- 문서 검사 31개 통과. 문서 이름 없이 절 번호만 쓴 참조의 경고는 8건 그대로다.
- 교회력 사실 토큰 비교(`--strict-counts`): 사라진 토큰, 줄어든 토큰, 새 토큰 모두 0이다.
- 일반 토큰 비교(`--kinds general --strict-counts`): 사라진 토큰 다섯은 모두 이 저장소 문서의 문구를 「」로 인용한 것이거나 코드 표기다(범주 사다리 표기, 「temporal > sanctoral」, 「성인력 보완 영역」, 「성인력 참조」, 「성인력 행이 없는 날짜 본문 16건」). 줄어든 하나(「temporal > 격자」)는 보관 문서에 남은 것이다.
- 남은 「성인력」은 `docs/writing.md` 「용어」의 줄 하나다(원장과 보관 문서 제외).
- e2e는 돌리지 않았다. 코드는 주석, 테스트 이름, 픽스처 문구만 바꿨다.

## 리뷰 반영

- 1회차(서브에이전트 리뷰 셋: 뜻, 문장, 엔진 주석과 테스트). 이 PR이 만든 문제만 고쳤다.
  - 사실이 어긋난 곳
    - ADR-036 §11의 「temporal 좌표는 데이터에 박혀 있지 않다」에서 temporal은 절기 주기 전체를 뜻했다. 「이동 축일의 절기 위치」로 바꾸면 이동 축일 행 24행 가운데 18행이 `season`을 갖는 데이터와 어긋난다. 「날짜의 절기 위치」로 고쳤다.
    - ADR-036 §5에 「`kind`의 표시 이름은 「이동 축일」, 「월별 축일」이고, `temporal`에는 주차 있는 일반일(격자 날)도 든다」는 문장을 더했다. 제목만 보면 연중 평일도 이동 축일로 읽힌다.
    - 후보 출처 목록의 「② 날짜(월별 축일) ③ 음력」은 음력 명절이 월별 축일이 아닌 것처럼 읽혔다. 설계서 §5.5, 엔진 주석 셋을 「② 양력 날짜 ③ 음력(둘 다 월별 축일)」의 뜻으로 고쳤다.
    - ADR-036 「월별 축일 보완 영역」 (3)의 「대한성공회 월별 축일은 공통 기도문 체계를 쓴다」는 주님의 축일과 국가일까지 덮었다. 「월별 축일의 성인 축일은」으로 고쳤다.
  - 빠뜨린 곳: 픽스처 하나의 `title`(「temporal 기념일도 …」), ADR-036 §5 본문의 백틱 없는 「temporal.」
  - 영어 이름의 자리: 스크립트가 괄호 안의 첫 언급을 건너뛰어, 여섯 파일(ADR-036, 설계서 04장, 07장, 09장, 테스트 둘)에서 첫 언급이 아닌 곳에 달렸다. 첫 언급으로 옮겼다. 설계서 06장의 괄호 넷이 이어진 구절은 영어 이름을 원래 괄호 안으로 넣었다.
  - 문장: 「축일」이 겹치거나 꾸밈이 흐린 곳(「월별 축일의 주요축일」, 「월별 축일(대축일)일」, 「등급 없는 이동 축일 평일 행」, 「실데이터의 이동 축일 표의 기념일」, 「합성 이동 축일 표의 기념일」 등)과 원장의 문장을 고쳤다.
  - 고치지 않은 것(이 PR 전부터 있던 것): ADR-036 §5 본문의 「시간주기」, 「성인주기」 풀이, ADR-036 「월별 축일 보완 영역」 머리의 낡은 현황 문장, 교회력 주제 문서 「지금 동작」의 성 토요일 우선순위 서술, 범주 사다리의 「(고정일)」이 음력 행에도 쓰이는 것, 픽스처 문구의 「단언」, 「확증」.
