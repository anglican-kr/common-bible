# feat: Drive 동기화 FSM 재설계 (PR 1/4) — 인증 상태 머신 + 디버그 로그

## Summary

ADR-011에서 진단한 **근본 결함 4가지** 해소를 위한 단계적 재설계의 첫 번째 PR.

### 신규 파일

| 파일 | 역할 |
|------|------|
| `js/sync/debug-log.js` | 메모리 ring buffer 2종(recent 200 / errors 20) + 토큰·이메일·파일ID·페이로드 마스킹 + coalescing. `localhost`에서만 `console.debug` 실시간 출력, 배포 시 ring buffer만 동작 |
| `js/sync/transport.js` | GIS wrapper + Drive API fetch 순수 함수 (전역 상태 없음, 토큰 인자로 전달) |
| `js/sync/state-machine.js` | 6-state FSM (DISABLED→INITIALIZING→AUTHENTICATING→IDLE→SYNCING→ERROR). `dispatch()` 단일 진입점으로 구 `feat/drive-sync`의 18개 fix 중 8개 카테고리 구조적 차단 |
| `js/drive-sync.js` | 얇은 facade. 300ms debounce 업로드 타이머. `window.driveSync` API 기존 호환 |

### 수정 파일

| 파일 | 변경 |
|------|------|

| `js/app.js` | save* 함수 7개 scheduleUpload 훅, 설정 팝오버 Drive 섹션(연결/해제/계정 정보/진단 복사 버튼), 연결 해제 모달 핸들러, `initDriveSync` 호출 |
| `sw.js` | `DRIVE_HOSTNAMES` 배열, rev-40 캐시 버전 bump |

### 버그 수정 (구현 중 발견)

- **전역 상수 이중 선언**: `state-machine.js`의 localStorage 키 상수가 `app.js`와 전역 충돌 → 클로저 내부로 이동
- **북마크 포맷 불일치**: `_applyRemote`가 `{_version:1, items}` 래퍼로 저장 → `loadBookmarks()`가 기대하는 bare array로 수정
- **이메일 미조회**: GIS 토큰 콜백에 `email` 없음 → `fetchUserInfo()` 비동기 호출
- **GIS 폴 카운터 미리셋**: `signIn()` 재시도 시 카운터 20 도달로 즉시 포기 → `_startPollingGis()`로 매번 리셋
- **죽은 분기**: TOKEN_FAIL의 `else if (_reAuthCount >= 3)` → `else`로 통합

### 디버그 로그 (진단 UX)

- FSM 전이·네트워크·에러 이벤트 전 구간 로그
- `localhost`에서만 `console.debug` 출력 (Verbose 레벨), 배포 시 무음
- 설정 팝오버 Drive 계정 정보 패널에 **"동기화 진단 정보 복사"** 버튼 — 클릭으로 clipboard 복사, 폴백 시 textarea 노출
