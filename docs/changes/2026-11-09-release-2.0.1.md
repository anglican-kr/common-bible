## 요약

버전을 2.0.0에서 2.0.1로 올린다(`python3 scripts/release.py patch`). 2.0.0 뒤에 전례독서의 인용과 주석 표시(#534)와 전례독서의 읽기 표지 숨기기(#530)가 들어왔다. 이 PR을 머지한 뒤 태그와 GitHub Release를 만들고 dev와 운영에 배포한다(`docs/workflow.md` 「릴리스」).

아래 「릴리스 노트 초안」은 머지한 뒤 GitHub Release에 그대로 쓴다. 「변경 사항」은 `python3 scripts/changelog.py 2.0.0 HEAD`의 출력이고, 끝의 비교 링크만 2.0.1 태그를 가리키게 고쳤다.

## 확정 · 근거

- **판 번호와 배포**(사용자 결정 2026-11-09): 2.0.1로 릴리스하고, 다시 묻지 않고 운영에 배포한다. 이 작업의 판단은 Claude가 PM으로 맡는다.
- **노트의 짜임**(구현하며 정함): 인용과 주석 표시(#534)는 2.0.0에 있던 전례독서를 낫게 한 것이라 「기능 개선」이다. 전례독서의 읽기 표지(#530)와 장 본문의 두 문제(절 끝 인용 뒤의 공백, 설정을 끈 상태의 주석 낱말, #534)는 2.0.0에 있던 문제라 「버그 수정」이다. 새 기능은 없다. 문서와 개발 도구의 변경(#529, #531, #532, #533)은 사용자가 겪지 않아 넣지 않았다(`docs/writing.md` 「릴리스 노트」).
- **릴리스마다 하는 정리**(CLAUDE.md 「지식 베이스 루프」 3번): 2.0.0(2026-11-08) 뒤의 원장은 여섯 개(#529-#534)다. 그 사이 새 설계 문서는 없고(`docs/design/`에서는 기존 문서 하나의 네 줄만 바뀌었다), `docs/index.md`와 실제 파일, 링크, 번호 대장은 문서 검사가 맞는지 본다(통과). 200줄을 넘긴 문서는 2.0.0 때와 같아 이번에도 나누지 않는다.

## 검증

버전 파일 둘을 2.0.1로 바꾼 상태에서 점검했다.

- `node --test tests/unit/*.test.js`: 1,676건 통과. 타입 검사(`tsconfig.json`, `tsconfig.worker.json`): 통과.
- CSP 점검: `python3 -I tools/csp/csp_sweep.py http://localhost:8092`(서비스 워커 막음)과 `--sw`(켬) 모두 위반 0종, 종료 코드 0. 건너뛴 단계는 이 브라우저에서 할 수 없는 데스크톱 오디오 재생 하나다(2.0.0과 같다).
- e2e: 버전과 관련된 `test_update_toast.py`, `test_liturgical_lazy_load.py` 18건 통과. #534는 그 PR에서 바꾼 코드를 지나는 e2e 272건을 돌렸다. 전체 e2e는 돌리지 않았다(`docs/workflow.md` 「작업 중 함정」).
- 배포한 뒤 dev와 운영의 `version.json`이 2.0.1인지, 전례독서에서 칩과 주석이 보이는지 실제 사이트에서 확인한다.

## 릴리스 노트 초안

### 기능 개선

- 설정의 「인용·주석 표시」를 켜 두면 전례독서에서도 다른 성경 구절을 인용한 곳에 출처가 보입니다. 출처를 누르면 인용된 구절이 열리고, 점선 밑줄이 있는 낱말을 누르면 주석이 열립니다. 이 설정은 처음부터 켜져 있습니다.

### 버그 수정

- 전례독서에서 긴 시편의 「(1)」, 「(2)」 같은 부 번호와 아가의 「(신부)」, 「(신랑)」 같은 화자 표시가 따로 한 줄로 나와 본문처럼 읽히던 문제를 고쳤습니다. 성경 본문 화면에는 그대로 있습니다.
- 성경 본문에서 절 끝이 다른 구절의 인용인 곳을 복사하거나 「인용·주석 표시」를 끄면, 다음 절과 띄어 쓰지 않고 붙던 문제를 고쳤습니다. 「없었습니다.그분은」이 이제 「없었습니다. 그분은」으로 보입니다.
- 「인용·주석 표시」를 꺼도 주석이 달린 낱말에서 키보드가 멈추고, 누르면 주석이 열리던 문제를 고쳤습니다.
