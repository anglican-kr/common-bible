## 요약

오프라인 저장(ADR-045)의 ⓘ 설명에서 크기 문장을 빼고, 문서를 지금 동작과 dev 확인 결과에 맞춘다.

- ⓘ 설명을 「성서 본문과 검색 자료, 캘린더와 전례독서에 쓰는 교회력 자료를 기기에 저장해 인터넷에 연결되지 않아도 모두 볼 수 있게 합니다. 오디오 파일은 재생할 때 다운로드됩니다.」로 줄였다(ADR-045 §2). 묶음마다의 크기와 받을 때의 압축 크기를 적던 문장을 빼고, 「모든 장과 모든 날을」을 「모두」로 줄였다. 크기는 줄 아래의 글에 모두의 크기로 남는다. 그 문장만 쓰던 묶음별 합과 압축 크기의 합은 `offline-save.js`의 요약에서 뺐다.
- ADR-045 §1이 받을 파일 목록을 `bible-manifest.json`에서 얻는다고 적었다. 앱은 크기 목록 `bible-sizes.json`을 읽으므로(§8, `js/offline-save.js`) 그렇게 고쳤다.
- 성시 검색(ADR-046, #595)이 검색 자료에 `search-lit.json`을 더해 크기가 바뀌었다. 주제 문서의 크기 표와 ADR-045 §2, §6의 크기 예를 데이터 `56017c8`로 다시 쟀다(모두 17.5MB, 검색 자료 6.3MB).
- 주제 문서 「지금 동작」에 성서 본문이 전례시편(`lps`)과 성무일과 송가(`cant`)의 장 파일을 포함한다고 적었다. 사용자가 두 책이 저장되는지 물어 확인한 것이다.
- known-issues §6.1의 「dev 배포 뒤 확인한다」를 2026-11-18 dev 확인 결과로 바꿨다.

## 확정 · 근거

- dev 확인(2026-11-18, `bible-2.1.0-caf6627`)은 화면 없는 Chromium에 아이폰 사용자 에이전트를 주고 했다. 그때는 `search-lit.json`이 없어 1,506개였다.
- ⓘ 설명을 줄인 것은 사용자 결정이다(2026-11-19). 크기 문장을 뺀 뒤 「모든 장과 모든 날을」도 줄였다. 스위치를 켜지 않아도 한 번 연 장은 열리므로, 한 번도 열지 않은 장과 날도 열린다는 차이를 「모두」 한 낱말로 남겼다. 「오디오 파일은 재생할 때 다운로드됩니다.」는 남긴다. 옛 설명은 ADR-045 「검토한 대안」 「더 긴 ⓘ 설명」에 남겼다.
- 데이터 저장소는 `bible-sizes.json`에 압축 크기(`gzip_sizes`)를 계속 적는다. 앱은 이제 읽지 않지만, 데이터 저장소는 이 PR에서 고치지 않았다.
- ADR-045 「검토한 대안」의 「6.0MB를 덜 받지만」은 2026-11-17의 판단을 적은 것이라 그대로 두었다.
- e2e `tests/e2e/test_settings.py` 설명 글의 「1,506개」는 파일이 늘 때마다 낡으므로 정확한 개수를 빼고 적었다(검사는 처음부터 `len(expected) > 1500`).

## 검증

- 앱 main의 데이터 포인터(`56017c8`)의 `bible-sizes.json`을 `offline-save.js`와 같은 규칙으로 묶어 셌다. 성서 본문 1,492개 9,136,889바이트(이 가운데 전례시편 150개, 송가 13개), 검색 자료 4개 6,258,308바이트, 교회력 자료 11개 2,143,935바이트, 모두 1,507개 17,539,132바이트, gzip 합 4,953,769바이트.
- `node --test tests/unit/*.test.js`: 1,932개 통과. `npm run typecheck` 통과.
- e2e `tests/e2e/test_settings.py -k "offline or info_close"`(작업 폴더 서버 8094): 8개 통과. 설명 시험은 Safari 탭과 아닌 창에서 문장 전체가 같은지 본다.
