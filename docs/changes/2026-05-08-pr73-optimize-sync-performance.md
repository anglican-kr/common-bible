# feat: 동기화 사이클 캐시로 라운드트립 단축 (Phase 2i)

## 요약

운영 환경에서 단일 sync가 ~3.4초 걸리던 문제(한국→Google RTT × 직렬 3-call) 해결. 시나리오별로 **~0.2s ~ ~2.9s**로 단축.

## 진단

```
[+0.458s] SYNC_REQUEST → SYNCING
[+0.995s] FIND_FILE          (+537ms)  files.list
[+2.104s] DOWNLOAD           (+1109ms) files/{id}?alt=media
[+3.876s] UPLOAD_UPDATE      (+1771ms) PATCH multipart
```

핵심 관찰:
- `appDataFolder/sync.json`의 fileId는 영구 — 매 사이클 `files.list`는 낭비
- 원격이 안 변한 사이클(visibility sync 등)에서 본문 다운로드는 의미 없음
- 로컬·원격 둘 다 안 변했으면 사이클 자체가 no-op이어야 함

## 변경 사항

`localStorage`에 sync 사이클 캐시 도입:
- `bible-drive-cache-file-id` — 첫 발견 시 저장. 이후 사이클은 `findSyncFileId` 생략
- `bible-drive-cache-etag` — 마지막 다운로드 ETag. 다음 다운로드에 `If-None-Match` 헤더로 전송
- `bible-drive-cache-synced-u` — 마지막 sync 시점 `maxU`. 로컬 변경 여부 판정

### 분기 매트릭스

| 로컬 | 원격 | 라운드트립 | 예상 | 절감 |
|---|---|---|---|---|
| 미변경 | 미변경 (304) | 1 (download 304) | ~0.2s | **94%** |
| 변경 | 미변경 (304) | 2 (download 304 + upload) | ~2.0s | 41% |
| 미변경 | 변경 (200) | 1 (download 200) | ~1.3s | 62% |
| 변경 | 변경 (200) | 2 (download 200 + upload) | ~2.9s | 15% |

모든 분기에서 `findSyncFileId` 1회가 사라진다. 304 시 본문 전송과 merge 연산이 모두 사라진다. 304 + 로컬 변경 분기는 merge도 생략 가능 — `local === merge(local, remote)`가 보장됨.

### 캐시 무효화

- **다운로드 404** (다른 기기에서 파일 삭제): 캐시 클리어 + `SYNC_FAIL http_404` → 다음 사이클은 `findSyncFileId`로 재생성 폴백
- **업로드 412** (cached etag 기준 race lost): 캐시 클리어 → 다음 사이클은 full download + merge로 충돌 해결
- **`disable()`** (사용자 disconnect): 캐시 클리어 — 다른 Google 계정 로그인 시 stale fileId 재사용 방지
- **`deleteRemoteFile()`**: 캐시 클리어

## 트레이드오프

- **첫 sync는 그대로**: 캐시가 비었을 때만 옛 경로. 사용자가 앱을 처음 켰을 때 한 번만 ~3s, 이후 ~0.2~2s
- **캐시 corruption**: 부분 손상(예: etag만 누락)은 graceful degradation — 단순히 slow path로 빠짐
- **localStorage 의존**: Safari private 모드 등 storage 제한 환경에선 캐시 무효 → 매번 slow path. fileId/etag/maxU는 민감 정보가 아님
