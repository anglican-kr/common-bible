## 요약

교회력 검토 문서(`docs/design/liturgical-engine-review.md`)를 고쳐 쓰며 내용을 검증하는 작업(known-issues §24)의 첫 PR(9차)이다. 머리와 §1-§4(범위, 조사 대상, 방식별 대조, 재검증 결과)를 다뤘다. §3의 표 다섯은 칸 하나에 여러 문장이 들어 있어, 항목마다 굵은 이름을 단 목록으로 풀었다(pitfalls §37). 절 번호, C-, X-, I- 번호, 규칙 마커, 미결 번호는 그대로 두었다.

## 확정 · 근거

어긋난 것은 모두 문서가 낡은 경우였다. 사용자 결정이나 기도서 규칙과 코드가 어긋난 곳은 없었다.

- **검토 문서는 나누지 않고 고쳐 쓴다**(사용자 결정, 2026-10-25). 세 번을 마친 뒤 나눌지 다시 정한다. 장마다 처음 나오는 개발 용어를 풀어 쓰는 일은 검토 문서를 마친 뒤에 한다.
- **낡은 설명을 고쳤다.** 머리의 편집 규칙대로 조사 당시의 관찰은 두고, 그 뒤 바뀐 것을 「지금」으로 적었다.
  - 골든 덤프는 PR 3 둘째(#343)가 만들었다(§1 결론, §3.5).
  - 날짜 범위 불변식은 PR #325부터 유닛 테스트가 확인한다(§3.1).
  - `liturgicalYearOf`는 이미 공개 함수였고, 미결3은 2026-10-15에 닫혔다(§3.1).
  - 기간은 여섯이 아니라 일곱이다. 보호 기간(`transferGuard`)이 빠져 있었고, 기간을 쓰는 곳도 셋보다 많다(§3.1).
  - 12.25의 데이터 행은 셋이지만, 성탄 밤은 12.24 저녁 전례라 12.25의 후보는 둘이다(§3.3).
  - precedence가 null인 temporal 행은 지금 넷이다. 성 토요일은 prec 1이고, 여성선교주일은 기념일이다(§4.3 공백 4).
  - C-6.1-4는 PR #341이 확인한다(§4.3 공백 5).
  - 2026년에 엔진이 옮기는 축일은 일곱 건이다. 안나와 요아킴은 2026-10-24부터 옮기지 않는다(§4.3 공백 6).
  - 남은 체크에 데이터 저장소 몫인 C-4.8-4를 더했다(머리).
- **없는 테스트를 있다고 적은 곳을 고쳤다.** §3.1 「음력」은 데이터 저장소의 `test_calendar_tables.py`에 `korean_lunar_calendar`와 견주는 「26년 일치」 검사가 있다고 적었다. 그런 검사는 데이터 저장소의 이력에 없고, 체크리스트 C-4.8-4도 체크되지 않았다. ADR-036 §9의 문장도 그 라이브러리를 「회귀 검증 도구로 지명」한 것이 아니다. 일반 음력 변환이 필요해지면 라이브러리를 쓰고 KASI 표로 회귀 검증하라는 것이다.
- **인용을 데이터의 실제 문구에 맞췄다.** `periods.json`의 `_meta.model`, 평화통일주일과 가정주일의 `note`다.
- **낱말을 고쳤다.** 판정 어휘 「확증」은 「확인」으로(`docs/writing.md` 「학술 · 법률 문체 낱말」), 「정오표」는 「틀린 것」으로, 「메커니즘」과 「벤치마크」는 「방식」과 「비교」로, 「소비 UI」는 「엔진을 쓰는 화면」으로, 「병기」는 「함께 적기」로 바꿨다. romcal 주석을 옮긴 「평일이 이긴다」는 「앞선다」로 썼다.
- **일부러 두었다.** 2026-09-17 판정을 인용한 「승자의 절기색」은 인용이라 두었다. §5 뒤의 「확증」 둘은 책자로 확인했다는 뜻이라 그 차수에서 본다. 「좌석 경합」은 테스트 이름과 함께 바꿀 일이라 두었다.

## 검증

- 머리와 §1-§4의 날짜, 요일, 건수를 엔진(`LITURGICAL_CORE`, `LITURGICAL_LOOKUP`)과 실데이터로 다시 계산했다. 부활절과 재의 수요일의 범위, 대림1주일의 분포, 보호 기간에 드는 해, 명절이 주일인 해, 1967년과 2024-2027년의 이동, 2027년 평화통일주일이 문서와 같았다.
- 교회력 사실 토큰 비교(`python3 scripts/docs_facts_snapshot.py --diff main WORKTREE --strict-counts --allow-new '^2026-10-25$'`)에서 줄어든 토큰은 0이다. 사라진 「7쌍」은 「prec 7 쌍」을 도구가 건수로 잘못 읽던 것이다. 새 토큰은 다시 계산한 날짜 하나다.
- 일반 토큰 비교(`--docs 'docs/design/liturgical-engine*' --kinds general --strict-counts`)에서 줄어든 토큰은 0이다. 사라진 여섯은 위에서 고친 인용 넷(데이터 문구 셋, romcal 주석 하나), 표의 `\|` 이스케이프를 뺀 코드 하나, 「7쌍」이다.
- 문서 검사 31개가 통과했다. 한정어 없는 참조 경고는 9건에서 8건으로 줄었다(머리의 「§1-§4」를 「§1, §2, §3, §4」로).
- 유닛 전체와 e2e는 돌리지 않았다. 문서만 바꿨다.
