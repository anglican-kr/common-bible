# docs: 「꼴」을 뜻에 맞는 말로 바꾼다

## 요약

사용자 교정(2026-10-20). PR #359 머지 직후 ADR-040을 열어 보고 「문서에서 "꼴"이 무엇을 의미하는 지 이해하기 어렵네」라고 했고, 이어서 「"꼴"이 쓰인 곳을 찾아서 이해하기 쉽게 수정 바람」이라고 했다.

「꼴」 한 낱말이 여러 뜻을 맡고 있었다 — 문자열을 적는 방식, 데이터의 구조, 예(경우), 버린 설계, 일하는 방식. 같은 문서 안에서도 뜻이 바뀌어, 읽는 사람이 자리마다 뜻을 짐작해야 했다. 저장소 전체 144군데(「글꼴」 제외)를 자리마다 뜻에 맞는 말로 바꿨다. 문서 · 코드 주석 · 테스트 이름 · 픽스처의 설명 · 책자 대조 도구에 있었고, 화면 문구도 하나 있었다.

| 뜻 | 바꾼 말 | 예 |
|---|---|---|
| 문자열을 적는 방식 | 표기 | 「앱이 쓰는 꼴」(절 범위) → 「앱이 쓰는 표기」, 「옛 꼴」 → 「옛 표기」 |
| 값 · 객체의 모양 | 형식 | 「`ResolvedDate` 꼴」 → 「`ResolvedDate` 형식」, 「2027 책자 꼴」 → 「2027 책자 형식」 |
| 저장소에 실제로 쓰이는 모양 | 저장 구조 · 구조 | 「실제로 저장될 꼴을 잰다」 → 「실제로 저장될 구조를 잰다」 |
| 규칙에 어긋난 예 · 사정이 같은 날 | 경우 | 「어긋난 꼴」 → 「어긋난 경우」, 「12.13 루시아와 같은 꼴」 → 「…같은 경우」 |
| 버린 설계 | 안 | 「버린 꼴은 「검토한 대안 …」」 → 「버린 안은 …」 |
| 일하는 방법 | 방식 | 「홈과 같은 꼴(ADR-031)」 → 「홈과 같은 방식」 |
| 「X 꼴로 줄인다」 | X처럼 | 「「연중29주」 꼴로 줄인다」 → 「「연중29주」처럼 줄인다」 |

- **화면 문구 하나** — 잘못된 캘린더 주소에 뜨는 안내 「주소는 /calendar/YYYY-MM 꼴이어야 합니다…」를 「…형식이어야 합니다…」로 바꿨다(별도 `fix:` 커밋).
- **고친 줄의 다른 규칙도 맞췄다** — 영어 낱말 · 코드 뒤의 조사를 붙여 썼고(§31 — 점검 도구로 52곳), 마크다운 줄의 숫자 구간 물결표를 하이픈과 「부터 … 까지」로 바꿨다(§32 — 9곳).
- **규칙** — coding-pitfalls §36 신설, CLAUDE.md 컨벤션에 한 줄.
- **덤** — known-issues §15에 가져오기 한도 한 줄을 적었다(사용자 2026-10-20 「사용자에 따라 북마크가 엄청 많을 수도 있다고 보는데, 북마크를 가져오는 방식을 나중에 바꿔야 할 수도 있겠네. 일단 패스」). 가져오기는 메모 없는 절 북마크로 7,132개까지 들이고, 크롬은 같은 북마크를 14,432개까지 저장한다(실측 — Chromium, 앱의 저장 경로, 새 프로필).

## 확정·근거

- **건드리지 않은 것**
  - 머지된 원장(`docs/changes/`) — 기록이라 그대로 둔다(잠금 · CI가 막는다).
  - 「글꼴」(폰트) — 바른 낱말이다.
  - `architecture.md` 표의 줄 수 칸 「~295」 — 「약」 표기다. 칸마다 하나라 취소선이 생기지 않는다.
  - 새 규칙이 그 낱말을 가리키느라 쓴 7곳(coding-pitfalls §36 · CLAUDE.md).
- **데이터 저장소는 따로다.** 그 저장소에는 「꼴」이 많지만 거의 모두 성서 본문이다 — 성서 · 원본 마크다운 · 검색 색인 · 전례시편 본문(「네모꼴」 · 「망하는 꼴을 보게 되리라」 · 「꼴찌」). 본문은 바꾸지 않는다. 우리가 쓴 말은 7곳(6파일 — ADR-039 둘, 파서 두 개의 오류 문구, 전례시편 틀 문서, `readings.py`, 테스트 하나)이고, 그 저장소의 PR로 고칠지는 사용자 확인을 기다린다. 그 파일들 가운데 일부는 `build.yml`의 입력이라, 고치면 빌드와 앱의 자동 포인터 PR이 돈다.
