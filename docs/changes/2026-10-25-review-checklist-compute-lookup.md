## 요약

교회력 검토 문서(`docs/design/liturgical-engine-review.md`)를 고쳐 쓰며 내용을 검증하는 작업(known-issues §24)의 10차다. §5 검증 체크리스트의 앞부분인 §5.0-§5.9(계산 계층과 조회 계층)를 다뤘다. 항목마다 첫 줄에 확인할 사실을 두고, 검증, 기준, 체크를 하위 항목으로 나눴다. 항목 번호와 체크 상태는 그대로 두었고, 빠져 있던 C-2-3 항목 하나를 더했다.

## 확정 · 근거

어긋난 것은 모두 문서가 낡은 경우였다. 사용자 결정이나 기도서 규칙과 코드가 어긋난 곳은 없었다.

- **§5의 고쳐 쓰기 방식**(사용자 결정, 2026-10-25). 둘로 나눠 고친다. 한 줄에 칸을 쉼표로 잇던 항목은 하위 목록으로 푼다. 체크에 적는 날짜는 PR을 머지한 날이다.
- **PR #325의 날짜를 고쳤다.** 32곳의 2026-09-13을 2026-09-17로 바꿨다. #325는 항목에 「PR #TBD (2026-09-13)」라고 적었고, 번호는 #338이 나중에 채웠다. #325는 2026-09-17에 열려 같은 날 머지됐고, 커밋 넷도 모두 그날이다.
- **픽스처 인용 테스트를 고쳤다.** `liturgical-fixtures.test.js`가 항목의 첫 줄만 읽어서, 하위 목록의 인용까지 읽게 했다. 인용 쌍 108개는 고치기 전과 같다.
- **낡은 설명을 고쳤다.**
  - C-4.5-6: 2030년 세례 주일을 「성탄 스팬의 끝」이라 적었다. 미결10이 닫힌 뒤로 세례 주일은 연중시기의 첫날이다. 이 항목만의 테스트는 없고, C-4.5-4와 C-4.5-5의 테스트가 함께 본다.
  - C-4.7-3: 「축일과 재일은 null」은 데이터 레코드에만 맞는다. 엔진은 연중 평일에 온 축일과 재일에도 I/II를 낸다.
  - C-4.7-2: 책자의 평일 독서가 「절기 내내」 II라는 말은 근거(X-10)에 없어 뺐다.
  - C-4.3-8: 같은 경우가 미결33(2024 책자는 앵커 당일부터 셌다)으로 열려 있어 적었다. 기준의 「엄격히 이후」는 설계서 §4.3이 「그날을 빼고 센다」로 바꿔 쓴 말이다.
  - C-4.6-1: 「그해 9주 `doy` 창은 빈다」는 틀렸다. `doy`로 읽은 9주 창은 2052-03-03을 품는다. 비는 것은 월일로 맞출 때의 9주 창이다(설계서 §4.6). 「2052 윤년」이라는 테스트도 없다.
  - C-P-1: 기간 축은 대림과 성탄 앵커를 쓰지 않는다(`spansOf`). 설계서 §4.10과 본 문서 §3.1의 같은 문장도 고쳤다.
  - C-P-3: `ascensionToPentecost`는 엔진에서 쓰는 곳이 없어(설계서 §4.10), 「세 소비자가 같은 함수를 본다」를 뺐다.
  - C-2-1: 「평일 행 성 토요일만 유효 8」은 성 토요일이 데이터에서 prec 1이 되며(data#32) 엔진에서 지운 예외다(PR #349).
  - C-5.5-1: PR 2 때의 「전부 `proper`, `official: null`」은 #341부터 맞지 않는다. 지금의 확인 내용을 함께 적었다.
  - C-5.6-4: 기념일은 셋이 늘어난 것이 아니라, 셋이 새로 되고 둘이 빠져 하나 늘었다(data#37).
  - C-5.6-6: ◐의 「① 이 ② 보다 먼저」는 맞지 않는다. 두 갈래는 순서가 아니라 서로 다른 경우다. 격자 후보가 좌표 폴백보다 날짜 인덱스를 먼저 본다는 근거로 고쳤다.
  - 작은 것: C-4.2-1의 표는 픽스처가 아니라 테스트 파일의 상수다. C-4.8-3의 `MM.DD`는 불러올 때가 아니라 조회할 때 읽는다. C-5.6-3의 합성 케이스는 후보가 셋이다. C-5.3-1의 근거에 ADR-036 §2를 더했다. C-5.4-4의 좁히기는 `season`과 함께 `type`도 본다. C-4.3-4는 실데이터를 읽는 테스트라 「유닛(실데이터)」로 적었다.
- **§3.1의 한 단락을 고쳐 썼다**(사용자 교정, 2026-10-25). 기간을 데이터 파일에 두지 않는 이유를 적은 단락을 사용자가 읽고 이해하기 어렵다며, 기술을 모르는 독자도 알 수 있게 써 달라고 했다. 까닭마다 굵은 이름을 단 목록으로 나누고, 처음 나오는 용어에 풀이를 붙였다. 「보호 기간이 우선순위 비교에 참여한다(가상 점유자 `guard`)」는 낡은 문장이라 성주간의 예로 바꿨다. 가상 점유자는 2026-10-24부터 성주간을 본다. 규칙은 `docs/writing.md` pitfalls §40에 사례로 적었다.
- **빠진 항목을 더했다.** 유닛 테스트 「C-2-3」(계산 범위 밖의 날짜는 null, PR #351)이 있는데 체크리스트에 항목이 없었다.
- **다른 문서의 낡은 서술을 고쳤다.**
  - ADR-036 §2는 「부활7주간 평일」도 승천일 본기도를 쓴다고 적었다. 데이터 저장소가 2026-08-29에 부활7주일과 부활7주간의 고유 본기도를 확인하고, 그 구간을 부활6주 금·토로 정했다. 데이터와 엔진은 그대로이고 ADR의 괄호만 고쳤다.
  - ADR-038 §3은 세계평화를 위한 기도일을 기념일의 예로 들었다. data#37부터 분류 없는 축일이라(미결51) 마틴 루터 킹으로 바꿨다.
- **테스트 이름과 주석을 고쳤다.** 체크한 항목의 테스트 이름에 남은 ◐(C-2-1, C-5.5-3)를 지웠다. 성 토요일이 prec 1이 된 뒤로 실행되지 않던 갈래(C-6.1-7 데이터 테스트)를 지우고, 세계평화를 기념일이라 한 주석을 고쳤다.
- **테스트가 따로 보지 않는 것을 적었다.** C-4.6-4(창의 `anchor`가 인덱스를 정한다)와 C-P-2(이동 계산이 기간 함수만 본다)는 코드로 확인했고, 테스트는 이것을 보지 않는다. 체크는 두었다.
- **일부러 두었다.** X-1은 체크하지 않았다. 가해의 시작은 교구 달력과 책자로 확인됐지만, 항목이 정한 RCL 도구와의 대조는 하지 않았다. 「좌석 경합」은 11차 구간이다.

## 검증

- 사실 대조는 읽기 전용 에이전트 셋에게 구간별로 맡겼다. 받은 주장은 엔진(`LITURGICAL_CORE`, `LITURGICAL_LOOKUP`)과 실데이터, `git log -S`, GitHub PR 기록으로 다시 확인했다.
- 교회력 사실 토큰 비교(`--strict-counts --allow-new '^(C-2-3|2026-06-11|#351|04\.05)$'`)에서 사라진 토큰은 0이다. 줄어든 것은 다섯이다.
  - 2026-09-13의 32개는 PR #325의 날짜다.
  - 01.01 하나는 ADR-038의 예를 바꾼 것이다.
  - #338의 셋, #341과 #343의 하나씩은 한 항목 안에서 같은 PR을 두 번 적던 것을 하위 항목 하나로 모은 것이다(C-2-1, C-4.9-1, C-5.5-3). #341은 C-5.5-1에서 하나 늘었다.
- 일반 토큰 비교(`--docs 'docs/design/liturgical-engine*' --docs 'docs/decisions/03[68]-*.md' --kinds general --strict-counts`)에서 사라진 둘은 §5.0의 옛 형식을 적은 코드와 없는 테스트 이름 「2052 윤년」이다. 줄어든 「엄격히 이후」는 C-4.3-8의 기준이다. 나머지는 위와 같다.
- 문서 검사 31개가 통과했다. 한정어 없는 참조 경고는 8건 그대로다.
- 테스트 파일을 고쳐 유닛 전체(1365개 통과, 1개 건너뜀)와 `npm run typecheck`를 돌렸다. e2e는 돌리지 않았다. 앱 코드를 바꾸지 않았다.

## 리뷰 반영

- 1회차(Copilot 리뷰 1건). C-P-2의 검증에 1900-2100을 적었으나, 테스트는 2026년의 기간 양 끝과 그 바로 바깥 날짜만 본다. 1900-2100은 대조할 때 따로 계산해 본 범위였다. 2026년으로 고치고, 연도를 적지 않은 C-P-3에도 2026년을 적었다. 범위를 적은 다른 항목은 테스트와 맞았다. 본 문서 §5.0의 「검증」 설명에 테스트가 실제로 보는 연도와 범위만 적는다는 규칙을 더했다.
