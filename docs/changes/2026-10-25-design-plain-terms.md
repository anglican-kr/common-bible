## 요약

교회력 설계서와 그 둘레의 문서, 코드 주석, 테스트 이름에서 비유로 만든 용어를 한국에서 쓰는 말로 바꿨다. 정한 기준과 바꾼 말은 `docs/writing.md` 「용어」에 적었다. 「도착」과 「출발」(옮겨 온 축일, 옮겨 간 축일)은 쓰인 곳이 많아 다음 PR에서 바꾼다.

## 확정 · 근거

- **기술 용어의 기준**(사용자 결정 2026-10-25)
  - 기술 용어는 TTA 정보통신용어사전이나 한국에서 널리 쓰는 말을 쓴다. 비유로 만든 용어는 쓰지 않는다. 기능을 설명하려고 비유를 드는 것은 괜찮다.
  - 업계 용어를 모두 쉬운 말로 바꾸거나 모든 기술 용어를 풀어 쓰지 않는다. 문서 앞에 용어집을 두지 않는다. 그래서 처음 계획한 「장마다 처음 나오는 개발 용어 풀어 쓰기」(known-issues §24)는 이 작업으로 바꿨다.
  - TTA 용어사전은 작업 환경에서 접속되지 않아, 바꾼 말은 사전과 대조하지 못했다.
- **바꾼 말**(사용자가 권장안을 골랐다, 2026-10-25)
  - 「좌석」, 「좌석 경합」, 「앉는다」, 「앉힌다」는 「배정」, 「목적지 충돌」, 「배정된다」, 「배정한다」로 바꿨다. 「다음 해 좌석」(`nextYearSeats`)은 「다음 해 배정」이다. 기다리던 「좌석 경합」 케이스 이름 바꾸기(이어 갈 지시문)도 이것으로 끝났다.
  - 「가상 점유자」는 「가드 후보」로 바꿨다(코드 id `guard:`와 같다).
  - 「범주 사다리」는 「범주 순서」로 바꿨다. 우선순위 단계를 가리키던 「사다리」(설계서 §5.5의 「§6.1 사다리」, ADR-036의 「8단계 사다리」)는 이미 정한 말 「우선순위표」로 바꿨다. ADR-036의 명절 「강한 점유권」은 「앞서는 우선순위」로 바꿨다.
  - 「결손」은 「누락」으로 바꿨다. 설계서 §2가 표기가 어긋난 값까지 묶은 두 곳은 「누락과 어긋남」으로 썼다.
  - 칩의 「상태 꼬리」, 「꼬리말」은 「상태 표시」로 바꿨다. 「이름표」는 데이터 파서의 이름 목록이면 「이름 목록」, 화면에 보이는 이름이면 「라벨」로 바꿨다.
  - 비유 동사는 뜻에 맞게 바꿨다. 「흡수한다」, 「견딘다」는 「처리한다」로, 「공통을 탄다」는 「공통을 쓴다」로, 값을 「얹는다」는 「넣는다」, 「붙인다」, 「덧붙는다」로, 무효화를 「탄다」는 「따른다」로 바꿨다.
- **그대로 둔 것**
  - 격자(grid)는 업계에서 쓰는 말이고, 코드 id가 `grid:`라 그대로 두었다.
  - 코드 이름(`nextYearSeats`, `seat`, `ladderOf`, `guard:holy-week`)과 규칙 마커(`R-6.2-tie-ladder`), 머지된 원장은 바꾸지 않았다.
  - 교회력이 아닌 쓰임은 이번 범위 밖이다. 디자인 시스템의 「토큰 사다리」(`DESIGN.md`, ADR-028, ADR-032), 서비스 워커 주석의 「SHELL_CACHE에 앉은」(`sw.js`, ADR-037), 동기화 문서의 「콜백 흡수」가 그렇다.
  - 「갈래」, 「선착순」, 「연쇄」, 「이름 줄」, 「지향」, 「바탕색」, 「칩」은 비유로 만든 용어가 아니어서 그대로 두었다.
- **작업 방식**(사용자 지시 2026-10-25): 커밋하기 전에 커밋 메시지를 사용자에게 보이고 확인을 받는다. `docs/workflow.md` 「커밋과 PR」에 적었다.
- 데이터 저장소의 같은 말(누락, 이름 목록, 우선순위표, 비유 동사)은 데이터 PR에서 바꿨다. 성 토요일 행의 비고가 `temporal-feasts.json`의 `note`로 나가므로 그 파일과 매니페스트가 바뀐다.

## 검증

- 유닛 전체: 1365개 통과, 1개 건너뜀. `npm run typecheck` 통과.
- 문서 검사(`node --test tests/unit/docs-*.test.js tests/unit/liturgical-fixtures.test.js`): 31개 통과. 한정어 없는 참조 경고는 7건 그대로다.
- 교회력 사실 토큰 비교(`--strict-counts`): 사라진 토큰, 줄어든 토큰, 새 토큰 모두 0이다.
- 일반 토큰 비교(`--docs 'docs/*.md' --kinds general --strict-counts`): 사라진 다섯은 모두 이번에 바꾼 인용과 코드 표기다(`(유효 precedence, 사다리 칸, 고유 본기도, id)`, 「사계재와 기념일은 이 사다리에 오르지 않는다」, 「사다리로도 순서를 정하지 못하는 것」, 「사다리로도 순서를 정하지 못한다」, 「엔진이 빈 결과로 견딘다」). 줄어든 「좌석 경합」은 머지된 원장과 「용어」 표에만 남았다.
- 바꾼 곳은 낱말마다 뜻을 보고 문자열을 하나씩 정해 바꿨고, 바꾼 수를 확인했다. 「결손」만 뜻이 한 가지라 파일 단위로 바꾼 뒤 결과 문장을 다시 읽었다.
- 데이터: `python3 -m pytest tests/ -q` 2952개 통과.
- e2e는 돌리지 않았다. 코드는 주석과 테스트 이름만 바꿨다.

- `docs/workflow.md`: 「커밋과 PR」에 커밋 전 메시지 확인.
- `docs/topics/liturgical.md`: 머리의 「범주 순서」 풀이와 본문의 용어.
- `docs/decisions/036-liturgical-calendar-data-model.md`, `037-eucharist-lectionary-data-and-engine.md`, `038-calendar-lectionary-ui.md`, `docs/architecture.md`: 용어.
- `docs/design/liturgical-engine/` 장 파일 일곱(01, 02, 04, 05, 06, 07, 09장)과 `docs/design/liturgical-engine-review.md`: 용어.
- `tests/README.md`, `tests/fixtures/liturgical/README.md`: 용어.
