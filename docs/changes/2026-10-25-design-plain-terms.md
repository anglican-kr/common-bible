## 요약

교회력 설계서와 그 둘레의 문서, 코드 주석, 테스트 이름에서 비유로 만든 용어와 낯선 음차 용어를 한국에서 쓰는 말로 바꿨다. 정한 기준과 바꾼 말은 `docs/writing.md` 「용어」에 적었다. 「도착」과 「출발」(옮겨 온 축일, 옮겨 간 축일)은 쓰인 곳이 많아 다음 PR에서 바꾼다.

## 확정 · 근거

- **기술 용어의 기준**(사용자 결정 2026-10-25)
  - 기술 용어는 TTA 정보통신용어사전이나 한국에서 널리 쓰는 말을 쓴다. 비유로 만든 용어는 쓰지 않는다. 기능을 설명하려고 비유를 드는 것은 괜찮다.
  - 업계 용어를 모두 쉬운 말로 바꾸거나 모든 기술 용어를 풀어 쓰지 않는다. 문서 앞에 용어집을 두지 않는다. 그래서 처음 계획한 「장마다 처음 나오는 개발 용어 풀어 쓰기」(known-issues §24)는 이 작업으로 바꿨다.
  - TTA 용어사전은 작업 환경에서 접속되지 않아, 바꾼 말은 사전과 대조하지 못했다.
  - 번역을 하다 만 듯한 말도 쓰지 않는다(사용자 교정 2026-10-25). 「센티널 문구」처럼 낯선 음차어에 한국어를 붙인 말이다.
- **바꾼 말**(사용자가 권장안을 골랐다, 2026-10-25)
  - 「좌석」, 「좌석 경합」, 「앉는다」, 「앉힌다」는 「배정」, 「목적지 충돌」, 「배정된다」, 「배정한다」로 바꿨다. 「다음 해 좌석」(`nextYearSeats`)은 「다음 해 배정」이다. 기다리던 「좌석 경합」 케이스 이름 바꾸기(이어 갈 지시문)도 이것으로 끝났다.
  - 「가상 점유자」는 「가상 후보」로 바꿨다. 데이터에 없고 엔진이 만든 후보다.
  - 「범주 사다리」는 「범주 순서」로 바꿨다. 우선순위 단계를 가리키던 「사다리」(설계서 §5.5의 「§6.1 사다리」, ADR-036의 「8단계 사다리」)는 이미 정한 말 「우선순위표」로 바꿨다. ADR-036의 명절 「강한 점유권」은 「앞서는 우선순위」로 바꿨다.
  - 「결손」은 「누락」으로 바꿨다. 설계서 §2가 표기가 어긋난 값까지 묶은 두 곳은 「누락과 어긋남」으로 썼다.
  - 칩의 「상태 꼬리」, 「꼬리말」은 「상태 표시」로 바꿨다. 「이름표」는 데이터 파서의 이름 목록이면 「이름 목록」, 화면에 보이는 이름이면 「라벨」로 바꿨다.
  - 비유 동사는 뜻에 맞게 바꿨다. 「흡수한다」, 「견딘다」는 「처리한다」로, 「공통을 탄다」는 「공통을 쓴다」로, 값을 「얹는다」는 「넣는다」, 「붙인다」, 「덧붙는다」로, 무효화를 「탄다」는 「따른다」로 바꿨다.
- **음차 용어**(사용자 결정 2026-10-25, 하네스는 그대로 두기로 했다)
  - 「센티널」(설계서 한 곳에만 있어야 하는 규칙 문장)은 「기준 문장」으로 바꿨다. 문서 검사 테스트의 이름과 주석에만 있었다.
  - 처음에 「가상 점유자」를 바꾼 「가드 후보」도 같은 문제라 「가상 후보」로 다시 바꿨다.
  - 「스팬」은 「구간」, `seed`의 뜻으로 쓴 말은 「이월」, `spill`은 「해 넘김」, 「드리프트」는 「어긋남」으로 바꿨다. 「스팬마다 `[from, to]` 구간의 배열」처럼 구간이 겹치는 자리는 「이름마다」로 썼다.
  - 교회력의 「가드」(성주간과 부활 8일의 색을 지키는 장치)는 「보호」로 바꿨다. 보호 기간(`transferGuard`)과 같은 말이다. 입력을 검사하는 뜻의 「프리로드 가드」, 「정수 연도 가드」, 「skip 가드」는 「검사」로 바꿨다.
  - 「골든 덤프」는 「기준 결과 파일」로 바꿨다. 우리 기준 결과 파일을 가리키던 「덤프」(「덤프 육안」 등)도 함께 바꿨다.
  - 캐시, 폴백, 픽스처, 래퍼, 프리로드, 하네스는 한국에서 널리 쓰는 말이라 그대로 둔다. 「덤프」는 외부 프로젝트와 책자 도구의 엔진 출력을 가리킬 때 그대로 쓴다.
- **그대로 둔 것**
  - 격자(grid)는 업계에서 쓰는 말이고, 코드 id가 `grid:`라 그대로 두었다.
  - 코드 이름(`nextYearSeats`, `seat`, `ladderOf`, `guard:holy-week`, `seed`, `spansOf`, `SENTINELS`, `UPDATE_GOLDEN`)과 파일 이름(`transfers-1900-2100.golden.txt`), 규칙 마커(`R-6.2-tie-ladder`), 머지된 원장은 바꾸지 않았다.
  - 교회력이 아닌 쓰임은 이번 범위 밖이다. 디자인 시스템의 「토큰 사다리」(`DESIGN.md`, ADR-028, ADR-032), 서비스 워커 주석의 「SHELL_CACHE에 앉은」(`sw.js`, ADR-037), 동기화 문서의 「콜백 흡수」, 동기화와 라우팅의 「race 가드」, 스크롤 감지 요소(`#scroll-sentinel`, ADR-025)가 그렇다.
  - 「갈래」, 「선착순」, 「연쇄」, 「이름 줄」, 「지향」, 「바탕색」, 「칩」은 비유로 만든 용어가 아니어서 그대로 두었다.
- **작업 방식**(사용자 지시 2026-10-25): 커밋하기 전에 커밋 메시지를 사용자에게 보이고 확인을 받는다. `docs/workflow.md` 「커밋과 PR」에 적었다.
- 데이터 저장소의 같은 말(누락, 이름 목록, 우선순위표, 비유 동사)은 데이터 PR에서 바꿨다. 성 토요일 행의 비고가 `temporal-feasts.json`의 `note`로 나가므로 그 파일과 매니페스트가 바뀐다.

## 검증

- 유닛 전체: 1365개 통과, 1개 건너뜀. `npm run typecheck` 통과.
- 문서 검사(`node --test tests/unit/docs-*.test.js tests/unit/liturgical-fixtures.test.js`): 31개 통과. 한정어 없는 참조 경고는 7건 그대로다.
- 교회력 사실 토큰 비교(`--strict-counts`): 사라진 토큰, 줄어든 토큰, 새 토큰 모두 0이다.
- 일반 토큰 비교(`--docs 'docs/*.md' --kinds general --strict-counts`): 사라지거나 줄어든 것은 모두 이번에 바꾼 인용과 코드 표기다(「사다리로도 순서를 정하지 못하는 것」, 「사계재와 기념일은 이 사다리에 오르지 않는다」, 「엔진이 빈 결과로 견딘다」, 「seed 받은 완전한 계산 결과만」, 「덤프 육안」, 「절기 스팬」, 「출발 수 = 도착 수 − seed 도착 수」 등). 옛 말은 머지된 원장과 「용어」 표에만 남았다.
- 바꾼 곳은 낱말마다 뜻을 보고 문자열을 하나씩 정해 바꿨고, 바꾼 수를 확인했다. 「결손」만 뜻이 한 가지라 파일 단위로 바꾼 뒤 결과 문장을 다시 읽었다.
- 데이터: `python3 -m pytest tests/ -q` 2952개 통과.
- e2e는 돌리지 않았다. 코드는 주석과 테스트 이름만 바꿨다.

## 갱신한 문서

- `docs/writing.md`: 「용어」에 기술 용어의 기준(번역을 하다 만 말 포함)과 바꾼 말 열네 줄, 그대로 쓰는 말 한 줄, 「경합」 줄, pitfalls §40의 풀이 규칙.
- `docs/workflow.md`: 「커밋과 PR」에 커밋 전 메시지 확인.
- `docs/topics/liturgical.md`: 머리의 「범주 순서」 풀이와 본문의 용어.
- `docs/decisions/036-liturgical-calendar-data-model.md`, `037-eucharist-lectionary-data-and-engine.md`, `038-calendar-lectionary-ui.md`: 용어.
- `docs/design/liturgical-engine/` 장 파일 일곱(01, 02, 04, 05, 06, 07, 09장)과 `docs/design/liturgical-engine-review.md`: 용어.
- `tests/README.md`, `tests/fixtures/liturgical/README.md`, `docs/architecture.md`: 용어.

## 리뷰 반영

1회차(Copilot). ADR-036 §6의 「앞서는 우선순위」 뒤 조사를 「이라」에서 「라」로 고쳤다. 「강한 점유권」을 바꾸며 받침이 없어졌는데 조사를 맞추지 않았다. 다른 바꾼 말은 받침이 같거나 조사를 따로 맞췄다.
