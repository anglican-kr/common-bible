## 요약

앱이 송가 이름을 세 파일에서 따로 읽던 것을 `books.json` 한 곳으로 모은다(ADR-047 §5). 장 화면과 북마크는 이미 `books.json`을 읽었다. 이 PR로 전례독서 화면(송가 장 파일의 제목)과 검색(검색 메타 파일)도 `books.json`의 이름을 읽는다. 장 제목에서 라틴어 이름을 떼던 앱의 규칙(`canticleTitleOf`)은 지워, 그 규칙이 데이터 저장소의 전례시편 파서 한 곳에만 남는다. 화면에 보이는 이름은 바뀌지 않는다.

#598(송가를 이름으로 보이기) 위에 쌓은 PR이다.

## 확정 · 근거

- #598의 코드 리뷰가 송가 이름을 읽는 파일이 셋이라고 짚었다. 처음에는 데이터 시험이 셋을 견주므로 그대로 두자고 답했으나, 사용자가 기준을 하나로 두기를 원해 모으기로 했다(2026-11-19). `books.json`에는 라틴어 이름을 뗀 이름이 들어 있어 상단 바에 그대로 보인다는 것도 확인했다.
- 검색은 앱이 받아 둔 책 목록의 송가 이름을 검색마다 워커에 싣는다(`titles`). 워커는 `books.json`을 받지 않는다. 앱이 책 목록을 받지 못했으면 싣지 않아 송가 결과에 이름만 없고, 검색 화면이 다음 검색 전에 목록을 다시 받는다. 처음에는 워커가 `books.json`을 직접 받게 했다가 리뷰 뒤 바꿨다(아래 「리뷰 반영」).
- 전례독서 화면은 송가 슬롯이 있는 날 장 파일과 함께 책 목록을 받는다(`loadSlotChapters`). 장 파일을 받지 못해도 송가 이름은 보인다.
- 데이터 저장소의 전례독서 라벨에 손으로 적혀 있던 송가 이름 넷도 `books.json`의 이름에서 가져오게 했다(데이터 #86, 사용자 결정 2026-11-19). 만들어지는 라벨은 그대로라 앱은 바뀌지 않고, `topics/liturgical.md`의 설명만 고쳤다.
- 검색 메타 파일의 송가 이름은 데이터 PR(#85)에서 지운다. 이 PR을 먼저 머지해야 한다. 데이터가 먼저 바뀌면 그사이 main의 검색 결과에 송가 이름이 빠진다.

## 머지 순서

#598(머지함), 이 PR, 데이터 #85(검색 메타 파일에서 송가 이름 지우기)의 차례다. 데이터 #86(라벨의 이름)은 만들어지는 데이터가 같아 차례와 상관없다.

- `npm run typecheck` 통과.
- e2e(작업 폴더 서버 8092, 데이터 `fbbb3d8`): `test_search.py`, `test_lectionary_view.py`, `test_liturgical_render.py`, `test_copy.py` 254개 통과. 검색 결과 「즈가리야 송가 1」, 카드 「즈가리야 송가 1-3절」과 「모세송가」, 전례독서 화면의 복사 출처 「즈가리야 송가」, 「성모송가」가 들어 있다.

## 갱신한 문서

- `docs/decisions/047-canticle-names.md` §5: 앱은 송가 이름을 `books.json`에서만 읽고, 검색에는 앱이 이름을 넘긴다. 「검토한 대안」에 「화면마다 가까운 파일에서 이름을 읽는다」와 「검색 워커가 `books.json`을 직접 받는다」.
- `docs/decisions/046-psalter-search.md` §4: 송가 이름을 읽는 곳을 `books.json`으로.
- `docs/topics/search.md`: 앱이 검색마다 송가 이름을 워커에 싣는다.
- `docs/topics/liturgical.md`: 전례독서 화면의 송가 이름, 이름을 읽는 곳이 하나라는 줄.

## 리뷰 반영

1회차(코드 리뷰, 6건). 검토가 다섯을 고쳤고, 사용자가 5번의 설계를 바꾸고 1번의 다시 받기 시험을 더하라고 했다(2026-11-19).

- **설계 변경(5번)**: 앱이 이미 받아 둔 `books.json`을 워커가 한 번 더 받았다. 원장에 적었던 근거 「워커는 앱이 책 목록을 받기 전에 시작한다」는 사실과 달랐다. 워커는 첫 검색 때 만들어지고, 검색 화면은 그 전에 책 목록을 받는다(`ensureBookMap`). 그래서 앱이 검색마다 송가 이름을 싣게 바꾸고(`canticleTitles`), 워커가 `books.json`을 받던 코드(`booksUrl`)를 지웠다. ADR-047 §5와 「검토한 대안」을 고쳤다.
- **다시 받기(1번)**: 워커가 `books.json`을 한 번 받지 못하면 그 세션 내내 이름이 빠지던 문제는 설계 변경으로 워커 쪽에서 없어졌다. 앱 쪽은 실패한 미리 받기를 `loadBooks`가 지워 다음 호출에 다시 받는다(2번). 다시 받기 시험을 셋 더했다. 이름이 실려 오지 않은 검색 뒤 다음 검색에 실려 오면 그 이름을 쓰고 그 뒤에도 지키는 시험(`search-worker.test.js`), 책 목록이 있을 때만 이름을 싣는 시험(`search.test.js`), 실패한 미리 받기 뒤 다시 받는 시험(`views.test.js`)이다.
- **고침**: 미리 받기 실패를 붙들던 `loadBooks`(2번), 빈 이름을 걸러 내지 않던 워커의 `chapterTitle`(3번, 시험 더함), 같은 식을 두 번 쓰던 마지막 독서 구간(6번).
- **없어짐**: `books.json` 요청이 검색 준비를 붙잡던 문제(4번)는 워커가 그 파일을 받지 않게 되어 없어졌다.
- **검증**: 유닛 1,950개, 타입 검사, e2e `test_search.py`와 `test_lectionary_view.py` 205개 통과. 워커는 이제 검색 메타 파일의 이름을 읽지 않으므로, 검색 결과의 「즈가리야 송가 1」과 카드는 앱이 실어 보낸 이름이다.
