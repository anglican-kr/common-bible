## 요약

송가 화면의 상단 바가 「성무일과 송가 6장」이던 것을 「이사야 셋째 송가」로 바꾼다. 송가 고르기 목록과 송가 목록 화면(`/cant`)은 숫자 대신 송가 이름이고, 앞뒤 이동(「← 이사야 둘째 송가」, 「참회송가 →」), 이어읽기, 브라우저 탭 제목, 북마크 기본 이름, 복사한 글의 출처(「이사야 셋째 송가 1-3 (대한성공회 기도서)」), 없는 송가의 안내(「성무일과 송가에는 14번 송가가 없습니다」)도 같이 바꾼다. 결정은 새 ADR-047이다. 송가 이름은 데이터 저장소가 `books.json`의 송가 항목에 둔다(data#84).

## 확정 · 근거

- 실기기에서 송가 화면을 본 사용자가 상단 바에 송가 이름이 나오기를 원했다. 송가에 「장」도 「편」도 붙이지 않기로는 이미 정해 두었다(2026-11-19, `topics/liturgical.md` 「남은 일」에 있던 「송가의 표기」). 함께 정할 여섯 곳(상단 바, 고르기 목록과 목록 화면, 앞뒤 이동, 이어읽기, 북마크 이름, 없는 주소 안내)을 후보와 함께 보였고, 사용자가 모두 권장안으로 정했다(2026-11-19).
- 상단 바의 높이와 글씨 크기를 바꿀지 사용자가 물었다. 가장 긴 송가 이름(9자)이 지금 휴대폰 상단 바의 가장 긴 제목(「성무일과 송가 13장」, 11자)보다 짧아 바꾸지 않았다. 너비 320px에서 글자 크기 22, 24일 때 제목 옆 ⌄가 북마크 단추에 가리고 고르기 목록이 화면 양옆으로 넘치는 것을 찾았다. 「마카베오하 15장」, 「요한묵시록 22장」과 숫자 격자 목록도 똑같아 이 PR에서는 고치지 않았다.
- 송가 이름의 자료는 `books.json`으로 했다. 고르기 목록, 앞뒤 이동, 북마크 이름은 장 파일 없이 이름이 있어야 한다. 검색 메타 파일은 검색할 때만 받고, 앱 코드에 적으면 데이터와 어긋날 수 있다(ADR-047 「검토한 대안」).
- 이미 「송가 6장」으로 저장한 북마크의 이름은 바꾸지 않는다. 사용자가 고칠 수 있는 글이라서다. 그 북마크에 절을 합쳐도 새 기본 이름과 달라 이름을 다시 짓지 않는다.
- `chUnit`은 송가에 빈 문자열을 준다. 고치지 않은 곳이 남아도 「6장」이 아니라 번호만 보이게 하려는 것이다. 단위를 이름처럼 쓰는 곳은 새 `chUnitNoun`(「송가 선택」), 없는 장의 안내는 새 `missingChapterText`로 장 화면과 검색이 같은 문장을 쓴다.

## 머지 순서

데이터 PR anglican-kr/common-bible-data#84(송가 이름을 `books.json`에 두기)는 머지했다. 자동 포인터 PR #599가 main의 데이터 포인터를 그 커밋(`fbbb3d8`)으로 올렸고, 이 브랜치에 main을 합쳤다. 이름이 없는 `books.json`에서는 송가가 「성무일과 송가 6」처럼 번호로 보인다.

## 리뷰 반영

1회차(코드 리뷰, 10건).

- **고침**:
  - 장 화면과 절 선택 막대에서 복사한 글의 출처가 「성무일과 송가 6:1-3」이었다. 「이사야 셋째 송가 1-3」으로 바꿨다. 북마크 이름과 같은 함수(`verseRefLabel`)를 쓴다. ADR-047 §2 표에 복사 출처 줄을 더했다.
  - 모아 읽기 제목에서 끝 송가에 이름이 없으면 「1–7 3」이 되던 것을 「1–7:3」으로 바꿨다.
  - 이름 칸으로 그릴지를 1번 송가의 이름만 보고 정하던 것을, 이름이 하나라도 있는지로 바꿨다.
  - 없는 주소 안내의 조사(「송가를」)를 책 id 대신 받침으로 고른다(`hasBatchim`을 `helpers.js`에 두었다). 낡은 주석 셋, 주소 제목을 두 번 계산하던 곳, 주제 문서 「결정」의 ADR 차례, ADR-047의 「정본」도 고쳤다.
  - 데이터 포인터: data#84 머지 뒤 자동 포인터가 main에 들어와 main을 합쳤다. e2e는 그 포인터로 다시 돌렸다.
- **고치지 않음**: 송가 이름을 읽는 파일이 셋(`books.json`, 검색 메타 파일, 송가 장 파일)이라는 지적. 셋 모두 데이터 파이프라인이 송가 마크다운의 제목에서 만들고 데이터 시험이 서로 견준다. 검색 워커는 `books.json`을 받지 않고 전례독서 화면은 장 파일을 이미 받으므로 한 곳으로 모으지 않았다. 이 사정을 `topics/liturgical.md` 「송가 장 화면」에 적었다.
- **검증**: 유닛 1,946개, 타입 검사, e2e `test_liturgical_render.py`, `test_copy.py`(송가 복사 시험 2개를 더함), `test_bookmark_read.py`, `test_bookmark.py` 73개 통과(데이터 `fbbb3d8`).
