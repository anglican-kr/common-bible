## 먼저 보실 곳

뜻이 달라질 수 있는 고침이다. 숫자, 날짜, 인용, 코드 표기는 바꾸지 않았다(아래 「검증」의 사실 토큰 비교). 줄 번호는 지금 파일의 줄이다.

`docs/architecture.md`

`docs/coding-pitfalls.md`

- 7, 9행: 「한 주제에만 걸리는/걸리면」을 「해당하는/해당하면」으로 바꿨다. 「여러 주제에 걸치는」은 그대로다.
- 50행: 「division 뷰에서 `updatePageMeta()` 빈 호출」을 「구분(division) 화면에서 `updatePageMeta()`를 인자 없이 호출해」로 풀었다.
- 94-96행, 147-149행, 186-189행: 한 항목에 문제가 여럿 든 사례를 굵은 이름을 단 하위 항목이나 목록으로 나눴다. 순서와 내용은 그대로다. 「①②③」은 목록 기호로, 「(a)(b)」도 목록으로 바꿨다.
- 94행: 「스크롤이 맨 위로 눌린다」를 「스크롤 위치가 맨 위(0)로 바뀐다」로 바꿨다.
- 97행: 「치던 글자 · Enter를 누른 세그먼트로 빼앗았다」를 「입력하던 글자와 Enter 입력이 누른 세그먼트로 가 버렸다」로 바꿨다.
- 98, 100, 190행: 「(main부터)」를 「(이전부터 있던 문제다)」로 바꿨다. main에 이미 있던 결함이라는 뜻으로 읽었다.
- 148행: 탭 바의 「스크롤 복원 요청을 먼저 세워」를 「등록해 두었다」로, 「옛 스크롤 위치로 튀었다」를 「옮겨 갔다」로 바꿨다.
- 186행: 「refresh token」을 「갱신 토큰(refresh token)」으로, 「미리 잡아 둔 토큰」을 「미리 받아 둔 토큰」으로 바꿨다.
- 201행: 손으로 넣는 확인을 고른 「이유:」를 「이유는 다음과 같다.」로 풀고, 가운뎃점으로 이은 이유를 문장으로 나눴다.
- 351행: 주소의 앞뒤 쉼표를 「걷기로 했다」, 「반복문으로 걷었다」를 「떼어 내기로 했다」, 「떼어 냈다」로 바꿨다. 같은 줄의 「다른 길로 다시 열었을 것이다」는 「다른 경로로 다시 만들었을 것이다」로 바꿨다.
- 357행: 거부 목록이 「다음 리뷰에서 또 샌다」를 「다음 리뷰에서 빠뜨린 경우가 또 나온다」로 바꿨다.
- 359행: 「잰다(쓰지 않고)」를 「잰다(저장하지는 않고)」로, 「양쪽으로 샌다」를 「어느 쪽으로든 어긋난다」로 바꿨다.

## 결정 대기

정해야 할 낱말이라 고치지 않고 두었다. 권장안은 교정한 에이전트와 검토한 Claude의 의견이다.

- **제목 줄의 가운뎃점과 줄표**: `architecture.md`의 「4.4 인용·주석」, 「4.5 책 이름·헤더 자동 짧게 표시」, 「8. 빌드·배포·릴리스」, 「3. 빌드 타임 — 데이터 파이프라인」 등 줄표 제목 여섯 곳. `coding-pitfalls.md`의 절 제목들(「셸 bump vs 콘텐츠 매니페스트」, 「플랫폼별 quirk 무시」, 「facade」, 「export」, 「vs」 등). 제목을 가리키는 곳이 있어 함께 정해야 한다. 가운뎃점은 「인용과 주석」, 줄표는 「빌드 타임: 데이터 파이프라인」을 권한다.
- **제목 줄의 띄어 쓴 조사**: `coding-pitfalls.md` 245행 「3.01 은」, 293행 「`// @ts-check` 가」. 기계 검사 `particle`에 남은 둘이다.
- **「Generation 카운터」, 「Sequence 번호」, 「Singleton 플래그」**(`coding-pitfalls.md` 28-30행): 후보는 「세대 카운터」, 「순번」, 「단일 실행 플래그」다.
- **「ghost」**(`coding-pitfalls.md` 90행): 끌 때 따라오는 복제 요소다. 후보는 「드래그 그림자」, 「끌려오는 복제 요소」다.
- **「cold-start」**(`coding-pitfalls.md` 181행): 후보는 「콜드 스타트」, 「앱을 처음 여는 경로」다. `architecture.md`는 「콜드 스타트」를 쓴다.
- **「동기 dispatch」**(`coding-pitfalls.md` 196행): 후보는 「동기 전이 호출」, 그대로다.
- **「scrim」**(`architecture.md` 202행), **「elevation」**(부록 A): `DESIGN.md`와 ADR-028의 디자인 용어라 그쪽 결정을 따른다.
- **「dispatch」, 「registry」, 「explode」**(부록 A의 ADR-034, 036, 037): ADR의 코드 개념 이름이라 영어로 두었다.
- **부록 A 상태 꼬리의 가운뎃점**(「· 앱 엔진 B1 …」, 「A1-b … ·」): 상태 표시 형식이라 두었다.

## 요약

문장 교정 반복 실행의 넷째 묶음이다. 진행 목록 「2. 루트 문서와 `docs/`의 나머지」에서 위에서부터 남은 `docs/architecture.md`(322줄)와 `docs/coding-pitfalls.md`(197줄)를 골랐다. 합이 519줄로 400줄 안팎보다 많지만, 둘째 파일만 빼면 322줄이라 둘을 한 묶음으로 했다. 파일마다 Sonnet 서브에이전트로 교정하고, 바뀐 내용을 Claude가 다시 읽어 고쳤다. 330줄 남짓이 바뀌었다.

- **기계 검사의 전후**(2개 파일): `particle` 54에서 2, `tilde` 1에서 0, `term` 1에서 0, `particle?` 5에서 3, `term?` 27에서 26, `verb?` 9에서 1, `english?` 197에서 51, `arrow?` 10에서 0, `dot?` 548에서 48, `dash?` 168에서 4.
  - 남은 `particle` 둘은 `coding-pitfalls.md`의 제목 줄이라 그대로 두었다(「결정 대기」).
  - 남은 `term?`은 화면 이동, 장 이동, 이동 축일, 북마크 선택 모드의 「이동」 단추, 검색 결과가 늦게 「도착」하는 경우라 바른 쓰임이다. 남은 `dot?`와 `dash?`는 제목 줄, 표의 빈 칸 「—」, 부록 A의 상태 꼬리, 「2026-05-09 · 05-10」이다.
- **검토하며 다시 고친 곳은 14곳이다.**
  - 코드 표기를 나눈 곳 셋을 되돌렸다. `verse-spec.js isWellFormedSpec`(두 파일)과 `SYNC_ENABLED_KEY = "1"`이다.
  - 「main부터」를 「이 PR 전부터」로 옮긴 세 곳은 어느 PR인지 흐려 「이전부터」로 고쳤다.
  - 「빈 값으로 호출해」는 「인자 없이 호출해」로, 「참 거짓」은 한 낱말 「참거짓」으로, 「옛 스크롤 위치로 갔다」는 「옮겨 갔다」로, 「이유는 셋이다」는 이어지는 이유가 넷으로 읽혀 「이유는 다음과 같다」로 고쳤다.
  - `architecture.md`의 「(SPA)** 이고」의 띄어 쓴 조사, 「그 초기 형태라 할 수 있다」(주장의 강도가 바뀐 것), 「토글 하나로 켜고 끄는 그리기」, 「등록부(registry)를 역전한다」를 고쳤다.
