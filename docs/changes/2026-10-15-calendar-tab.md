# feat: 캘린더 탭 1단계 — 하단 탭 · /calendar 월간 표 · 데스크톱 입구 · 독서 화면 위 단계 (ADR-038 §1 · §2)

## 요약

ADR-038 의 A2(캘린더 탭)를 세 단계로 나눈 1단계다(사용자 「한 번에 구현하지 않아도 돼, 단계를 나눠서」 2026-10-15). 하단 탭 바의 홈 다음에 캘린더 탭을 더하고 `/calendar[/YYYY-MM]` 에 한 달을 그린다. 날짜 칸을 누르면 그날의 전례독서 화면(`/lectionary/<날짜>` — A3, #346)으로 간다. 주간 · 목록 화면은 2단계다. 엔진 · 데이터는 바꾸지 않았다.

- **탭** — `index.html` `#tab-bar` 두 번째에 `data-tab="calendar"`(이름 「캘린더」, 광학 크기 정규화한 달력 글리프). 다른 탭에서 오면 마지막 캘린더 화면(전례독서 포함)으로 돌아오고, 캘린더 탭에서 다시 누르면 이번 달(ADR-031 홈 탭과 같은 꼴 — `tabbar.js`). 기본 착지 `lastPathForTab.calendar` 는 `/calendar`.
- **데스크톱 입구** — 하단 탭 바가 없는 넓은 화면 · 마우스에서는 헤더 윗줄(검색창 옆)에 캘린더 단추(`#header-calendar`). 모바일은 그 줄이 통째로 숨는다.
- **월간 표** — 새 모듈 `js/app/calendar.js`. 순수 블록 `CALENDAR_MODEL`(`buildMonthGrid` · `calendarDay` · 칸 이름 · 링크 이름)과 DOM 을 갈랐다. 6주 × 7일(일요일 시작) `<table>` 7열 `table-layout: fixed` — 이름이 길어도 칸이 넓어지지 않는다(중단된 1.6.0 달력이 폰에서 넘치던 함정). 이전/다음 달 · 「오늘」 · 칸 전부 링크라 뒤로 가기 · 공유가 그대로다.
  - 칸 = 날짜 + 그날의 전례색 점(엔진 `colors` — 사계재 날 축일이면 자 · 백 둘, 선택 대체색은 그리지 않음) + 이름 하나(엔진 `official`; 격자 평일이면 그날 지키는 사계재 · 기념일, 주일 · 고유명 평일은 격자 이름, 번호 주일은 「연중29주」 · 「대림1주」 꼴 — ADR-038 §2).
  - 대림 1주일 칸에 새 주기 표지 「나해」(링크 이름 · `title` 은 「나해 시작」 — 엔진 `liturgicalYearOf`).
  - 앞뒤 달 칸은 날짜와 색 점만(흐리게), 계산 범위(1583~9999) 밖 칸은 링크 없음. 오늘 칸은 `aria-current="date"` 와 `--accent` 원.
  - 칸의 링크 이름은 「오늘, 10월 15일 목요일, 아빌라의 데레사, 백색」 — 대표 이름 · 전례년 표지 · 색 이름을 글자로(색만으로 전하지 않는다).
  - 캘린더 묶음(정의 표 약 105KB)만 프리로드한다 — 독서 묶음(약 1.6MB)은 독서 화면에서만.
- **전례독서 화면의 위 단계** — 성서 목록으로 가던 집 단추 → 그 날짜가 든 달의 캘린더로 가는 꺾쇠(`lectionary.js buildUpLink` — 모바일에서도 보인다). 이름 · 날짜 · 색 함수(`shortName` · `statusSuffix` · `isGrid` · `CYCLE_LABEL` · `COLOR_LABEL` …)는 `lectionary.js` 에서 export 해 캘린더가 같이 쓴다(복제 없음).
- **디자인** — 전례색 여섯을 DESIGN.md §2 「전례색」 토큰(`--lit-*`)으로 올리고 전례독서 머리의 색 표시도 토큰으로 바꿨다(그전엔 CSS 에 색값을 박아 두었다). 보이는 탭이 넷이 되며 320px 폭에서 탭 넷(240) + 간격 + 검색 원(60)이 dock 안쪽 288px 를 넘어 검색 원이 6px 화면 밖으로 밀렸다 — `#tab-bar` 가 줄어들게(flex-shrink) 하고 슬라이딩 인디케이터가 슬롯 폭을 넘지 않게 했다(`--tab-bar-n`, DESIGN.md §7). 340px 이상은 그대로다.
- **등록** — `index.html` 스크립트 · `sw.js` 셸 캐시 · `routing.js`(`parsePath` 의 `/calendar` · `route()` 분기 — `decodeOrRaw` 를 두 갈래가 함께 쓰게 올렸다) · 실데이터 테스트를 `engine-data.yml` · `sync-data.yml` 에.

## 확정·근거

A3 때처럼 잠정 결정을 날짜 예와 함께 보이고 확인받았다(coding-pitfalls §24 — 결정 전문).

- **사용자 승인(2026-10-15 「시작」 — A2 계획의 잠정안 일곱 일괄)**: ① 월간 칸 이름은 하나 — 그날의 대표(2026-09-29 미카엘, 설립 기념일은 줄에 · 2026-09-18 추계재 · 2027-07-26 야고보) ② 선택 봉헌(「옮겨 지킬 수 있음」)은 월간 칸에 없고 주간 · 목록 줄에(2026-05-17 「부활7주」) ③ 전례년 첫날 표지(2026-11-29 — 설계서 미결3 닫힘) ④ 독서 성구는 달력에 싣지 않는다(설계서 미결41 닫힘) ⑤ 목록은 오늘부터 8주 · 이름 없는 평일 제외(2단계) ⑥ 데스크톱 헤더 입구 ⑦ `calendar.js` 는 정적 import(동적 import 는 lectionary 와 함께 별도 PR — known-issues §6).
- **사용자 결정(2026-10-15 — 1단계 화면을 보고)**: 탭 이름 · 화면 제목 「교회력」 → 「캘린더」(「"교회력"은 "캘린더"로」). 교회력 자체를 말하는 문구(「교회력 자료를 불러오지 못했습니다」)는 그대로.
- **사용자 제안(2026-10-15)**: 화면 폭이 320px 정도면 탭의 기본 착지를 `/calendar/list` 로 — 2단계에서 목록 화면과 함께 넣는다. `/calendar` 주소 자체는 폭과 무관하게 월간으로 둔다(공유한 주소가 기기마다 다른 화면이 되지 않게).
- **확인 대상으로 보고한 세부(2026-10-15)**: 독서 화면 위 단계는 꺾쇠(집 단추는 다른 탭에서 「성서 목록」), 앞뒤 달 칸은 이름 없이, 선택 대체색은 달력에 그리지 않음, 320px 탭 축소. ADR-038 「검토한 대안」에 버린 쪽과 함께 적었다.
- **성 토요일 칸은 이 PR 에서 「부활밤」이다** — 엔진의 그날 대표가 부활밤이라서(설계서 미결20). 사용자가 같은 날 저녁 전례 모델을 정했다 — 「엔진은 "성 토요일"을 기본으로, 부활밤은 저녁 전례로 독서 화면의 칩, 성탄 밤도 12.24 저녁 전례」. 별도 엔진 PR 로 고치고, 그 PR 이 들어가면 캘린더 코드를 고치지 않아도 칸이 「성 토요일」이 된다.
- **아티팩트 댓글(다크 모드에서 오늘 표시가 안 보임)**: 첫 검토 캡처가 2026년 11월 화면이라 오늘(10월 15일)이 표에 없었던 것 — 다크에서도 오늘 원은 밝은 회색(다크의 `--accent`)에 어두운 숫자다(계산된 색 확인). 코드 변경 없음.
- **찾은 기존 결함(이 PR 범위 밖)**: 앱 모듈 24개가 실제로는 타입 검사를 받지 않는다 — 첫 줄 `"use strict";` 다음 줄에 `// @ts-check` 가 있으면 tsc 가 그 파일을 건너뛴다(일부러 넣은 오류를 못 잡는 것으로 확인, 순서를 바꾸면 오류 204건). known-issues §7 · architecture.md §6 에 적었다. 새 `calendar.js` 는 첫 줄이 `// @ts-check` 이고 일부러 넣은 오류가 잡히는 것을 확인했다.
