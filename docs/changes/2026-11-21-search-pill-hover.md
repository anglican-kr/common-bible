## 요약

아이폰에서 검색 결과의 책 알약(「전례시편 155」)을 누르면, 고른 알약의 이름 부분만 바탕이 옅게 남고 × 부분은 강조색 그대로라 알약이 두 색으로 보였다. 원인은 #588과 같다. iOS는 마지막으로 누른 자리에 `:hover`를 남기고, 다시 그린 알약이 같은 자리에 있어 고른 알약의 호버 바탕이 남았다. 검색 화면에서 누르면 같은 자리에 다시 그려지는 컨트롤의 호버 바탕을 `@media (hover: hover)` 안으로 옮겼다(DESIGN.md 「포인터 분기」, ADR-049).

## 확정 · 근거

- 고른 알약이 두 색으로 보이는 것을 고친다(사용자 확인 2026-11-21, 아이폰 캡처). 포커스 테두리였다면 강조색 테두리도 보였을 텐데 캡처에는 바탕만 있었다. 다시 그린 뒤 포커스를 돌려줄 때는 이미 `focusVisible: false`를 넘긴다(`helpers.js`의 `restoreFocusSpot`).
- 같은 쓰임을 함께 고쳤다. 책 알약의 이름 부분과 ×(`.scope-pill-main`, `.scope-pill-remove`), 결과 묶음 알약(`.search-pill`), 쪽 넘기기 링크(`.search-pagination a`)다. 쪽 넘기기는 「다음」을 누르면 다음 쪽의 「다음」이 같은 자리에 다시 그려져 강조색 채움이 남는다. 결과 묶음 알약은 누르면 고른 알약이 되어 채움이 호버 바탕을 덮으므로 지금 보이는 문제는 없지만, 규칙을 맞췄다.
- 키보드 포커스의 바탕(`:focus-visible`)은 그대로 둔다. 마우스로는 올려 둔 동안 바탕이 보인다.
- 같은 자리에 다시 그리는 링크(`data-focus-key`)와 누른 자리에 남는 단추 가운데 전례독서 카드, 독서 세트 고르기, 「오늘」에는 호버 바탕이 없고, 구분 탭의 호버 색은 고른 탭의 색과 같아 누른 뒤 차이가 없다. 전례독서의 본기도 번호와 독서 접기 단추는 리뷰에서 찾아 함께 고쳤다(아래 「리뷰 반영」). 그 밖의 화면의 호버 규칙은 살피지 않았다.

## 검증

- 유닛 `node --test tests/unit/*.test.js` 1966개 통과. 타입 검사는 작업 폴더에 `node_modules`가 없어 돌리지 않았다(CSS와 e2e만 바뀌었다, CI가 돌린다).
- 새 시험 `test_search.py`의 `test_book_pill_and_page_link_leave_no_hover_after_a_tap`: 터치 기기와 마우스로 「전례시편」 알약과 「다음」을 누르고, 다시 그린 알약과 링크에 `:hover`를 켠 뒤 터치에서는 바탕이 없고 마우스에서는 있는지 본다. `:hover`는 개발자 도구 프로토콜(CDP)의 `CSS.forcePseudoState`로 켠다. #588처럼 포인터를 그 자리에 두는 방법은, 터치 환경의 Chromium이 탭 직후 한동안 포인터를 옮겨도 `:hover`를 주지 않아 기다리는 시간에 따라 실패했다. 고치기 전의 CSS로 돌리면 터치 쪽이 실패했다(이름 부분의 바탕이 캡처와 같은 옅은 색 `--bg` 18%).
- e2e(작업 폴더 서버 8093): 처음에 `test_search.py` 113개 통과(3분 12초). 리뷰 반영 뒤의 결과는 「리뷰 반영」에 적는다.
- 디자인 시스템 아티팩트: `bundle.css`의 결과 묶음 알약과 쪽 넘기기 링크의 호버를 같이 옮기고 변경 기록(`lastChange`)을 고쳤다. 책 알약은 아티팩트에 아직 없다.

## 갱신한 문서

- `DESIGN.md`: 「포인터 분기」에 검색 화면의 알약과 쪽 넘기기 링크, 전례독서의 본기도 번호와 독서 접기 단추를 더했다. 「활성 피드백」에 누르는 동안 흐리게 하는 컨트롤을 더했다.

## 리뷰 반영

1회차(코드 리뷰 2026-11-21, 다섯 건 모두 반영, 사용자 지시).

- 전례독서의 본기도 번호(`.lect-collect-num`, 접은 독서의 번호와 알약도 같은 부품)와 독서 접기 단추(`.lect-cards-fold`)의 호버 글자색을 `@media (hover: hover)` 안으로 옮겼다. 번호는 누르면 같은 자리에 다시 그려지고, 접기 단추는 누른 자리에 남는다. 리뷰는 고르지 않은 번호가 고른 번호처럼 보인다고 했지만, 누른 번호는 고른 번호가 되고 고른 번호의 표시는 자기 글자색(`--bg`)을 정하므로 번호에서는 보이는 차이가 없다. 보이는 곳은 접기 단추다. 펼친 뒤 「접기」가 다른 약화 글자(`--text-secondary`)보다 진하게(`--text`) 남는다.
- 터치에서 누른 반응: 호버를 마우스 기기로 옮기며 터치에서는 누를 때의 반응이 없어졌다. 책 알약의 이름 부분과 ×, 결과 묶음 알약, 쪽 넘기기 링크에 누르는 동안의 흐림(`:active { opacity: 0.7 }`)을 더했다. 값은 독서 카드(`.lect-card:active`)와 같다.
- 시험: 상태를 켜고 읽는 일을 `conftest.py`의 `style_in_state`와 `pseudo_session`으로 옮겼다. 상태를 켠 요소에서 그대로 읽어(`Runtime.callFunctionOn`) 켠 요소와 읽는 요소가 어긋나지 않고, 요소를 찾지 못하면 무엇을 찾지 못했는지 알린다. 쪽 넘기기 링크의 전환은 시험 안에서 끄고(`transition: none`) 300ms를 기다리던 줄을 뺐다. 검색 시험은 누르는 동안의 흐림(0.7)도 본다.
- 새 시험 `test_lectionary_view.py`의 `test_collect_number_and_fold_keep_their_color_after_a_tap`: 터치 기기와 마우스로 본기도 번호 2와 접기 단추를 누르고, `:hover`를 켜도 터치에서는 글자색이 그대로이고 마우스에서는 바뀌는지 본다.
- #588의 시험 `test_date_step_leaves_no_hover_circle_after_a_tap`도 `style_in_state`로 바꿨다. 포인터를 그 자리에 두는 방법이라, 다른 시험과 함께 돌리면 터치 쪽이 한 번 실패했다(혼자서는 세 번 모두 통과).
- 디자인 시스템 아티팩트: `bundle.css`에 전례독서의 두 규칙과 누르는 동안의 흐림을 옮기고, README의 「터치 · 움직임」과 변경 기록(`lastChange`)을 맞췄다(41판).
- 검증: 호버 시험 여섯 개를 함께 네 번 돌려 모두 통과했다. `main`의 CSS로 돌리면 검색 시험의 터치 쪽(바탕), 마우스 쪽(누르는 동안의 흐림), 전례독서 시험의 터치 쪽(번호 2의 글자색)이 실패했다.
