## 요약

아이폰에서 검색 결과의 책 알약(「전례시편 155」)을 누르면, 고른 알약의 이름 부분만 바탕이 옅게 남고 × 부분은 강조색 그대로라 알약이 두 색으로 보였다. 원인은 #588과 같다. iOS는 마지막으로 누른 자리에 `:hover`를 남기고, 다시 그린 알약이 같은 자리에 있어 고른 알약의 호버 바탕이 남았다. 검색 화면에서 누르면 같은 자리에 다시 그려지는 컨트롤의 호버 바탕을 `@media (hover: hover)` 안으로 옮겼다(DESIGN.md 「포인터 분기」, ADR-049).

## 확정 · 근거

- 고른 알약이 두 색으로 보이는 것을 고친다(사용자 확인 2026-11-21, 아이폰 캡처). 포커스 테두리였다면 강조색 테두리도 보였을 텐데 캡처에는 바탕만 있었다. 다시 그린 뒤 포커스를 돌려줄 때는 이미 `focusVisible: false`를 넘긴다(`helpers.js`의 `restoreFocusSpot`).
- 같은 쓰임을 함께 고쳤다. 책 알약의 이름 부분과 ×(`.scope-pill-main`, `.scope-pill-remove`), 결과 묶음 알약(`.search-pill`), 쪽 넘기기 링크(`.search-pagination a`)다. 쪽 넘기기는 「다음」을 누르면 다음 쪽의 「다음」이 같은 자리에 다시 그려져 강조색 채움이 남는다. 결과 묶음 알약은 누르면 고른 알약이 되어 채움이 호버 바탕을 덮으므로 지금 보이는 문제는 없지만, 규칙을 맞췄다.
- 키보드 포커스의 바탕(`:focus-visible`)은 그대로 둔다. 마우스로는 올려 둔 동안 바탕이 보인다.
- 다른 화면의 호버 규칙은 이번에 살피지 않았다. 같은 자리에 다시 그리는 링크(`data-focus-key`) 가운데 전례독서 카드, 독서 세트 고르기, 「오늘」에는 호버 바탕이 없고, 구분 탭의 호버 색은 고른 탭의 색과 같아 누른 뒤 차이가 없다.

## 검증

- 유닛 `node --test tests/unit/*.test.js` 1966개 통과. 타입 검사는 작업 폴더에 `node_modules`가 없어 돌리지 않았다(CSS와 e2e만 바뀌었다, CI가 돌린다).
- 새 시험 `test_search.py`의 `test_book_pill_and_page_link_leave_no_hover_after_a_tap`: 터치 기기와 마우스로 「전례시편」 알약과 「다음」을 누르고, 다시 그린 알약과 링크에 `:hover`를 켠 뒤 터치에서는 바탕이 없고 마우스에서는 있는지 본다. `:hover`는 개발자 도구 프로토콜(CDP)의 `CSS.forcePseudoState`로 켠다. #588처럼 포인터를 그 자리에 두는 방법은, 터치 환경의 Chromium이 탭 직후 한동안 포인터를 옮겨도 `:hover`를 주지 않아 기다리는 시간에 따라 실패했다. 고치기 전의 CSS로 돌리면 터치 쪽이 실패했다(이름 부분의 바탕이 캡처와 같은 옅은 색 `--bg` 18%).
- e2e(작업 폴더 서버 8093): `test_search.py` 113개 통과(3분 12초).
- 디자인 시스템 아티팩트: `bundle.css`의 결과 묶음 알약과 쪽 넘기기 링크의 호버를 같이 옮기고 변경 기록(`lastChange`)을 고쳤다. 책 알약은 아티팩트에 아직 없다.
