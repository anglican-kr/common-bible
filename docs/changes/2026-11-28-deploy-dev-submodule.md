## 요약

- `deploy-dev.yml`의 첫 실행(pre-release `2.2.9-3b98832`)이 데이터 서브모듈을 받는 단계에서 `Permission denied (publickey)`로 실패했다. 서버에는 아무것도 올라가지 않았다.
- 데이터 저장소 주소를 배포 키의 호스트 별칭으로 바꾸는 `insteadOf`를 상위 저장소의 로컬 설정(`git -C common-bible config`)에 넣었는데, 서브모듈은 따로 실행되는 `git clone`이 받아서 그 설정을 읽지 않는다. 그래서 별칭 없이 `github.com`으로 접속해 키를 찾지 못했다. `sync-data.yml`처럼 `git config --global`로 넣는다.

## 확정 · 근거

- 로컬에서 재현했다. 가짜 ssh로 접속 주소를 찍어 보니, 로컬 설정만 둔 클론은 `git@github.com`으로, 전역 설정을 둔 클론은 별칭으로 접속했다.

## 검증

- 위 재현. release 이벤트는 태그가 가리키는 커밋의 워크플로를 실행하므로, `2.2.9-3b98832`를 다시 실행해서는 이 수정이 적용되지 않는다.
- 이 PR을 머지해도 2.2.9의 빌드 식별자는 `2.2.9-3b98832` 그대로다. 워크플로와 원장은 배포 목록에 없는 파일이라 앱 커밋을 바꾸지 않는다. 그래서 `prerelease.sh`는 같은 이름의 pre-release가 있다며 멈춘다.
- 사용자 결정(2026-11-28): 실패한 `2.2.9-3b98832`의 태그와 Release를 지우고, 이 PR이 들어간 dev 커밋에 같은 이름으로 `prerelease.sh`를 다시 실행해 CI를 지금 시험한다. "pre-release 태그는 옮기지 않는다"(ADR-052 §4)의 예외다. 그 태그는 올린 지 몇 분밖에 안 됐고 아무 빌드에도 쓰이지 않았다(CI가 배포 전에 실패). 규칙의 까닭(이미 받은 클론과 어긋남)은 그대로라 규칙은 바꾸지 않는다.

## 갱신한 문서

- `docs/workflow.md` "릴리스": 워크플로를 고친 뒤에는 Re-run이 고친 내용을 쓰지 않는다는 것.
