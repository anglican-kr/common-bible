## 요약

성무일과(아침기도와 저녁기도)의 데이터를 정한 결정이 없었다. 사용자가 기도서 508-554쪽 「성무일과 전례독서」를 스캔해 그 내용으로 데이터를 만들어 달라고 했고, 성무일과는 정의된 내용이 없으니 ADR이 필요하다고 짚었다. [ADR-042](../decisions/042-office-lectionary-data.md)(제안됨)가 범위, 레코드 모델, 해 규칙, 성구 문법, 검증 방식을 정한다.

데이터 저장소에는 같은 제안대로 옮겨 적은 원문(`liturgical/prayer-book/office-readings/`), 파서(`parse_office_readings.py`), 산출(`lectionary/office-readings.json`, 레코드 804개), 테스트 26개, 워크플로 변경, 대조 보고서를 만들어 두었다(데이터 저장소 PR anglican-kr/common-bible-data#72). 앱은 이 데이터를 아직 받지 않는다. 사용자에게 보이는 변화가 없고 앱 코드는 바뀌지 않는다.

## 확정 · 근거

- **사용자가 정한 것은 둘이다.** 스캔 24장으로 성무일과 전례독서 데이터를 만들 것, 정의된 내용이 없으니 ADR을 먼저 쓸 것이다(2026-11-10). 그 밖의 결정은 모두 제안이고 사용자 확인을 기다린다.
- **이어받은 기존 결정**: ADR-037의 레코드 모델과 절 단위 실존 검사, 독서는 RCL 계열(미국 성공회 포함)과 맞는 쪽을 따른다는 결정(2026-10-24), 인쇄 오류를 원문에 표시하는 방식(2026-11-05), 기도서 원문은 데이터 저장소 `liturgical/prayer-book/`에 둔다는 결정(2026-10-24).
- **새로 제안한 것**: 옮겨 적은 원문이 파서의 입력이다. 해는 감사성찬례의 `year`와 따로 `cycle`로 두고, 전례년이 시작된 해의 홀짝으로 정한다(기도서 508쪽과 470쪽이 정한 규칙이다). 읽을 칸의 `slot`은 칸의 위치가 아니라 책의 종류로 정한다. 괄호는 두 세트로 펼치지 않고 `optional`로 표시한다. 인쇄 오류는 원문의 `[오자]`, `[번호]` 줄이 바로잡는다.
- **일부러 하지 않은 것**: 날짜에서 줄을 찾는 엔진과 화면, 성무일과 예식문 데이터, 이름 있는 날과 달력 표 잇기. 모두 Phase 4 ADR의 몫이다. 기도서가 설명하지 않은 기호의 뜻과 안내문의 해석은 추측하지 않고 「미결 사항」으로 남겼다.
- **옮겨 적기를 어떻게 확인했나**: 서브에이전트 여덟이 스캔을 서로 보지 않고 두 번 옮겼다. 24쌍 1,367줄이 숫자 하나 다르지 않았다. 같은 방식으로 틀릴 수 있어(「1요한」의 「1」이 앞 칸 끝에 밀려 인쇄된 곳 넷을 두 벌이 모두 밀린 그대로 옮겼다) 미국 성공회 1979년 기도서의 매일 전례독서표(bcponline.org에서 직접 내려받음)와 절 단위로 견줬다. 독서 2,279개 가운데 2,184개가 일치했고, 주요축일의 독서 112개 가운데 99개가 일치했다. BCP와 달랐던 100칸은 옮긴 값을 알려 주지 않고 세 번째로 읽게 했고 모두 같았다.
- **BCP 표의 오타**: BCP 웹 표에도 입력 오타가 있어(줄 앞의 낱개 기호로 한 줄이 빠졌다) 대조 도구가 그런 줄을 놓칠 수 있었다. 고쳐서 다시 견줬다.

## 검증

- 데이터 저장소 `pytest tests/`: 3,330개 통과(main의 3,304개와 새 테스트 26개). 커밋될 산출이 원문에서 다시 만든 것과 같다(테스트 `test_committed_json_matches_parser_output`가 CI의 어긋남 검사와 같은 비교를 한다). 매니페스트에 새 파일을 넣었고 `gen_manifests.py --check`가 통과한다. CI 워크플로(`build.yml`, `pipeline.yml`)는 이 컴퓨터에서 돌리지 못했다.
- 이 PR의 문서 검사 `node --test tests/unit/docs-*.test.js`: 23개 통과.
- 손으로 확인한 것: 스캔 그림에서 509, 512, 515, 518, 519, 520, 525, 542, 554쪽의 표를 직접 보고 옮긴 글과 맞췄다. 512쪽 빨간 안내문은 「…경우가 아니면…」이다.
- 돌리지 않은 것: 앱 유닛과 e2e. 앱 코드가 바뀌지 않았다.
