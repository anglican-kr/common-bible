## 요약

본문 검색이 검색어와 본문의 따옴표 여섯 가지(`"` `'` `“` `”` `‘` `’`)를 지우고 비교한다. 데이터 저장소 #60이 성서 본문을 곱슬 따옴표로 바꿔, 곧은 따옴표로 친 검색어가 바뀐 본문을 찾지 못하게 됐기 때문이다. 결정은 ADR-005 「따옴표를 무시하는 일치」에 적었다. 같은 PR에서 곱슬 따옴표 전환이 끝난 것을 known-issues §3과 `topics/bible-text.md` §3.3에 적었다.

## 확정 · 근거

- **따옴표를 같은 글자로 보지 않고 지운다**(사용자 결정 2026-11-06). 같은 글자로 보면 강조 표시를 고치지 않아도 되지만, 「빛이 생겨라! 하시자」처럼 따옴표 없이 기억한 문구가 본문 `“빛이 생겨라!” 하시자`를 찾지 못한다.
- **홑따옴표도 지운다.** 데이터 저장소의 2026-11-06 조사에서 성서 본문의 `'` 2,271개는 모두 인용부호였고 아포스트로피는 없었다.
- **검색어는 따옴표를 지운 뒤 공백을 다시 접는다.** `"`만 치거나 `" '`처럼 따옴표 사이에 공백만 있으면 빈 문자열이나 공백 한 칸이 남아 거의 모든 절에 일치한다(유닛 테스트를 쓰다 찾았다). 가운데에 홀로 있는 따옴표(`빛이 " 생겨라`)는 공백 두 칸을 남겨 아무것도 찾지 못한다(코드 리뷰에서 찾았다).
- **검색 인덱스는 바꾸지 않는다.** 인덱스에서 지우면 결과 목록의 발췌에서도 따옴표가 사라진다.
- **판정 함수를 두 벌 둔다.** 검색 워커는 모듈을 가져올 수 없는 클래식 스크립트다(`IN_RE`도 같은 방식이다). 두 벌이 글자까지 같은지 유닛 테스트가 본다.
- **일부러 고치지 않은 것.** 장 화면은 본문 조각마다 따로 강조해, 인용 태그 경계의 따옴표를 건너뛰는 일치를 강조하지 못한다. 원래 있던 한계라 `topics/search.md` 「남은 일」에 적었다. 소문자로 바꾸면 길이가 달라지는 문자(`İ`)는 예전 코드와 같은 가정이고, 한국어 본문에는 없다.
- **리뷰.** Copilot 크레딧이 없어 읽기 전용 서브에이전트 둘이 코드와 문서를 따로 리뷰했다(`docs/workflow.md` 「리뷰」, 사용자 2026-11-06). 코드 쪽은 막는 버그가 없었고 공백 접기와 테스트 보강을 받았다. 문서 쪽은 「기각」(금지어), 「검토한 대안」의 자리, 용어(클래식 스크립트, 인덱스), 강조 규칙의 주어를 고쳤다.

## 검증

- 유닛: `node --test tests/unit/*.test.js` 1,528개 통과. 새로 더한 것은 두 사본의 일치, 정규화(가운데 따옴표 포함), 범위 계산, 강조 표시, 결과 발췌의 자르기, 워커의 일치 판정이다.
- 타입 검사: `npm run typecheck` 통과(저장소가 고정한 TypeScript 5.9.3).
- e2e: 이 컨테이너에서 두 번 나눠 돌려 첫 실행 318개, 다시 돌린 실행 444개가 통과했다. 실패 2개는 main의 코드로도 똑같이 실패하는 환경 문제다. 전례독서 제목 가운데 맞춤(320px에서 1.5px 어긋남, 글꼴 차이)과 255자가 넘는 주소(시스템 Python 3.13 서버의 `File name too long`, `docs/workflow.md` 「작업 중 함정」)다.
- 곱슬 따옴표 데이터(데이터 저장소 `de3c765`)로 손 확인: `"빛이 생겨라!"`와 `“빛이 생겨라!”`는 창세 1:3을 찾아 「빛이 생겨라!」를 강조했다. `빛이 생겨라! 하시자`는 「빛이 생겨라!” 하시자」를 강조했다(결과 목록과 장 화면 `?hl=` 모두). `"`는 결과 없음 화면을 보였다. 같은 데이터로 `tests/e2e/test_search.py` 12개가 통과했다.
