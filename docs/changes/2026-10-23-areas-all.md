## 요약

docs 재구성 시리즈의 넷째 PR이다. 북마크 시범(#370)을 본 뒤 사용자가 계속하기로 했다(2026-10-23). 나머지 영역을 모두 영역 문서로 옮겨, 정리 층이 작업 영역마다 한 장이 되게 했다.

- **영역 문서 열 개를 새로 만들었다.** 동기화(`sync`), 라우팅(`routing`), 캐시와 릴리스(`cache-release`), 검색(`search`), 오디오(`audio`), 설정과 디자인(`design-system`), 본문 데이터(`bible-text`), 교회력(`liturgical`), 앱 뼈대(`platform`), 설치와 접근성(`install-a11y`)이다. 북마크까지 열한 개다.
- **글자 그대로 옮겼다**(첫 커밋).
  - status.md 41줄 → 각 영역의 「지금 동작」. status.md는 지웠다.
  - coding-pitfalls 20개 절(§2, 7, 8, 12, 13, 14, 15, 16, 18-25, 27, 28, 33, 34) → 「함정」. 옛 자리에는 절 제목과 대장 줄이 남는다.
  - known-issues 30개 항목 → 「남은 일」. 여러 문단인 하위 절(§2.1, §3.1-3.3)과 한 이슈짜리 절(§20-25)은 `### known-issues §N — 제목`으로 옮겼다. 옛 자리에는 대장 줄이 남는다.
- **남긴 것.** 여러 영역에 걸치는 함정(pitfalls §1, 3, 4, 5, 9, 10, 11, 35, 부록)과 작업 방식 교정(§17, 26, 29-32, 36, 37)은 coding-pitfalls.md에 전문으로 남겼다. 작업 방식 교정은 다음 PR에서 `writing.md`와 `workflow.md`로 옮긴다. 해소된 절과 결정 기록(known-issues §1, 2.2, 4, 5, 8, 9, 14)은 known-issues.md에 그 번호의 이력으로 남겼다.
- **소유 코드.** 모든 `js/` 파일이 정확히 한 영역에 속한다. 여러 영역이 함께 쓰는 뼈대(`app.js`, `helpers.js`, `storage.js`, `types.d.ts`, `pre-fetch.js`, `gtag-init.js`)는 플랫폼 영역에 두었다. 장 화면을 그리는 `views.js`는 라우팅 영역이다.
- **검사.** `docs-wiki.test.js`는 모든 `js/` 파일을 정확히 한 영역이 소유하는지 보고, 제목 형식의 이슈 정의(`### known-issues §N — `)를 알아본다. `docs-crossref.test.js`는 지운 status.md를 참조 문서에서 뺐다.
- **참조.** index.md는 영역 문서 표로 다시 썼다. 두 대장 파일의 머리말은 대장의 역할과 새 번호(known-issues §26, pitfalls §39부터)를 적는다. CLAUDE.md, README.md, tests/README.md, changes/README.md, archive/README.md, architecture.md §11, ADR-036, ADR-038, PR 생성 훅의 안내 문구가 status.md 대신 영역 문서를 가리킨다.

## 확정 · 근거

- 사용자 결정(2026-10-23): 시범 결과를 보고 「머지 후 PR 4 계속」을 골랐다.
- 영역의 경계는 소유 코드로 정했다. 사실은 그것을 구현하는 파일을 소유한 영역에 둔다. status.md의 「캘린더 · 전례독서 모듈은 그 화면에 처음 갈 때 불러온다」는 `routing.js`가 불러오지만 그 화면의 결정(ADR-038 §2)이라 교회력 영역에 두었다. 「주소의 절 범위」는 라우팅, 「북마크 + Google Drive 동기화」는 동기화 영역이다.
- 교회력의 도메인 확정(pitfalls §18-25)은 설계서가 사용자 결정의 출처로 가리키므로 줄이지 않고 글자 그대로 옮겼다. 설계서와 ADR-036/037/038의 구조와 경로는 건드리지 않았다.
- 오디오와 설치 영역에는 status.md 줄이 없었다. 「지금 동작」에 ADR-016, 007, 008의 제목에서 확인한 사실만 한 줄씩 새로 적었다.
- 영역 문서의 문장 정리는 이 PR에 넣지 않았다. 다음 PR들에서 영역마다 한다.

## 검증

- **글자 그대로 옮겼는지**: `docs_facts_snapshot.py --diff main WORKTREE`에 옛 세 파일과 영역 문서를 `--kinds general --from … --into … --drop-file`로 넣었다. 옛 줄 687줄 가운데 653줄이 그대로 옮겨졌고, 빠진 줄은 0이다.
- **일부러 뺀 줄 34줄**(`--drop-file`):
  - status.md 머리말 일곱 줄. 문서의 역할 안내라 `areas/README.md`와 index.md가 맡는다. 사라진 토큰 넷(`docs/architecture.md`, `docs/decisions/`의 코드와 경로)은 이 줄에서 나왔다.
  - 옮긴 줄 열일곱 줄의 링크와 절 번호 앞의 문서 이름(둘째 커밋). 상대 링크 셋은 `docs/` 기준 경로를 `docs/areas/` 기준으로 고쳤다. 문서 이름 없이 「§N」만 쓴 열세 곳에는 어느 문서의 절인지 밝히는 문서 이름(「pitfalls」, 「known-issues」, 「ADR-031」)을 붙였다. 교회력의 pitfalls §21, 22, 25, 34(아홉 곳), 본문 데이터의 known-issues §3.2, 플랫폼의 known-issues §6과 pitfalls §31, 라우팅의 ADR-031 §5다. 옛 파일 안에서는 그 파일의 절을 뜻했지만, 옮기고 나면 교차 참조 검사가 설계서의 절로 풀려 했다. 플랫폼의 「CLAUDE.md 「ADR 워크플로우」 §2」는 「2항」으로 적었다.
  - known-issues.md, coding-pitfalls.md 머리말 열 줄. 대장의 역할로 다시 썼고, 안의 사실(2026-05-03 기준 통계, ADR-034, 2026-06-08)은 새 머리말에 남았다.
- 영역 문서에 문서 이름 없이 쓴 「§N」이 남지 않았다(스크립트로 다시 확인).
- 교회력 사실 토큰 비교(기본): 사라진 토큰 0, 새 토큰 0. ADR-036과 ADR-038은 status.md를 가리키던 한 줄씩만 고쳤다.
- `npm test` 1365개(통과 1364, 실데이터 1 skip), `npm run typecheck` 통과.
