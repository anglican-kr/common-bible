## 요약

기기의 저장 공간이 차서 브라우저가 쓰기를 거절해도 북마크 저장과 동기화가 성공처럼 처리하던 것을 고쳤다(known-issues §15.4, ADR-015 D7).

- 동기화 저장소에 쓰는 함수와 북마크 목록을 저장하는 함수가 결과(`"saved"`, `"full"`, `"failed"`)를 돌려준다.
- 북마크 목록은 동기화 저장소에 먼저 쓴다. 이 쓰기가 거절되면 옛 키에는 쓰지 않는다.
- 목록을 바꾸는 13곳이 한 함수(`commitBookmarks`)로 저장하고, 거절되면 스낵바로 알린다.
- 동기화가 받은 결과를 저장하지 못하면 드라이브에 올리지 않고 알린다.
- 「화면 낭독기」와 같은 뜻의 말을 「스크린 리더」로 맞췄다(사용자 교정).

## 확정 · 근거

- 재현(main `85edd92`, Chromium): 저장 공간이 찬 상태에서 북마크를 저장하면 대화상자가 닫히고 목록에는 아무것도 생기지 않았는데, 스크린 리더는 「북마크를 저장했습니다.」를 읽었다. 동기화 저장소 쓰기만 거절되면 옛 키에만 저장되어 두 사본이 어긋났다.
- 사용자가 정한 것(2026-10-26):
  - 문구는 13곳 모두 한 문구로 쓴다. 저장 공간이 아닌 까닭이면 「북마크를 저장하지 못했습니다.」다.
  - 13곳 모두 알린다. 성공 안내가 있던 곳만 알리는 안은 버렸다.
  - 동기화 저장소에 먼저 쓴다. 옛 키에 먼저 쓰고 거절되면 되돌리는 안은 버렸다.
  - 범위는 동기화 결과까지다. 설정과 읽던 위치는 다루지 않는다(§35).
  - 동기화의 실패 문구는 성공 문구 「다른 기기에서 변경된 데이터를 불러왔습니다.」와 짝을 맞춘다.
  - 글을 적은 대화상자는 닫지 않는다.
- 구현하며 정해 사용자에게 알린 것: 폴더 펼치기와 접기는 화면을 누른 대로 둔다. 되돌리면 저장 공간이 찬 동안 폴더 안을 볼 수 없다. 동기화할 때마다 실패하면 그때마다 알린다.
- 범위를 정한 뒤 찾은 것: main에서는 동기화가 받은 결과를 저장하지 못해도 기기에 남은 옛 문서를 올려, 다른 기기가 올린 북마크가 드라이브에서 사라졌다. e2e로 확인했고, 그 기기가 다시 동기화하면 돌아온다. 옛 키 쓰기가 거절되면 동기화가 「재연결해 주세요」 오류로 멈췄다. 둘 다 이번에 고쳤다.
- 다른 기기의 변경이 없으면 병합 결과를 저장하지 못해도 동기화를 이어 간다. 이때 기기에 저장된 문서는 병합 결과와 같아 잃는 것이 없다. 멈추면 저장 공간이 찬 동안 이 기기의 편집이 드라이브에 올라가지 못한다.
- 지울 때 기기별 「최근 본 시각」을 지우는 일은 저장에 성공한 뒤로 옮겼다. 그전에는 저장이 거절되면 북마크는 남고 그 시각만 사라졌다.
- ADR-040이 「저장이 실패를 알리게 되면 다시 본다」고 적은 대안(저장해 본 뒤 실패하면 되돌리기)을 다시 보았다. 저장해 보는 방식은 이 기기의 한도로만 판단하므로, 모든 기기에 Safari의 한도를 쓰는 지금의 방식(저장하기 전에 잰다)을 그대로 둔다.
- 사용자 교정: 「화면 낭독기」는 표준어가 아니어서 「스크린 리더」로 쓴다. 같은 뜻의 「화면 읽기 프로그램」과 붙여 쓴 「스크린리더」도 함께 바꿨다. 안내를 넣는 칸을 가리키던 「화면 읽기 영역」은 저장소가 이미 쓰는 「라이브 영역」으로 바꿨다. 머지된 원장에 남은 같은 낱말은 고치지 않았다.
- 남은 일로 둔 것(사용자 결정):
  - §34: 옛 버전의 목록을 처음 옮길 때 저장 공간이 모자라면 목록이 계속 비어 보이고, 다음 저장이 옛 목록을 지운다. main에도 있고, 2026-04-25부터 05-04까지 9일 동안 앱을 쓴 기기만 해당한다.
  - §35: 설정과 읽던 위치를 저장할 때는 결과를 확인하지 않는다.
  - §36: 대화상자가 열린 동안 VoiceOver가 실패 안내를 읽는지 확인하지 않았다.

## 검증

- 새 테스트를 먼저 쓰고, 고치기 전 코드에서 실패하는 것을 본 뒤에 고쳤다.
- 유닛 `node --test tests/unit/*.test.js`: 1,410개 가운데 1,409개 통과, 1개는 원래 건너뛴다. 타입 검사 `npm run typecheck` 통과.
- e2e 전체 `pytest tests/e2e/`: 390개 모두 통과(10분 56초). 원래 작업 폴더의 서버(8080)를 다른 세션이 써서, 이 작업 폴더의 서버를 8092에 띄우고 포트만 바꾼 사본으로 돌렸다.
- 새 e2e는 `test_bookmark_save_failure.py`의 10개와 `test_drive_sync.py`의 1개다. main의 코드(8093)에서는 앞의 10개 가운데 9개와 뒤의 1개가 실패한다. 통과하는 하나는 저장 공간이 차도 지우기는 된다는 테스트로, 원래 되던 동작을 지킨다.
- 저장 공간이 찬 상태는 초기화 스크립트로 흉내 냈다(`conftest.py FULL_STORAGE`). 모든 쓰기를 거절하는 방식과, 값이 길어지는 쓰기만 거절하는 방식이 있다. 뒤의 방식이 실제로 저장 공간이 찬 경우와 같다.
- WebKit의 셈을 흉내 낸 저장소(5 MiB, 한글이 든 값은 한 글자 2바이트)에서 실제 저장소 코드를 실행해 북마크 저장, 가져오기의 크기 검사, §34를 확인했다.
- 데스크톱과 휴대폰 크기에서 저장 대화상자가 적은 글과 함께 남고 스낵바가 뜨는 것을 화면 캡처로 확인했다.

## 리뷰 반영

- PR을 열기 전 1회차(서브에이전트 리뷰어 셋): 높음이나 중간 등급의 결함은 없었다. 반영한 것은 아래와 같다.
  - 가져오기의 크기 검사가 새 쓰기 순서와 어긋나, 옛 목록이 크면 검사를 통과하고도 저장이 거절될 수 있었다. 옛 키를 새 목록과 지금 값 가운데 큰 쪽으로 센다. 처음 쓴 회귀 테스트는 새 목록이 영문뿐이라 고치기 전 계산에서도 통과했다. 한글 이름을 넣어, 고치기 전에는 실패하게 했다.
  - 동기화가 받은 결과를 옛 키에 쓸 때 키 하나가 거절되면 나머지를 쓰지 않았다. 키마다 따로 쓰고, 거절된 키를 기록한다. 설정의 옛 키는 앱이 시작할 때 읽는 원본이라는 점을 문서에 바로잡아 적었다.
  - 진단 로그를 복사하면 저장 실패의 까닭이 빠졌다.
  - 저장 공간이 차서 거절되는 쪽은 폴더 펼치기가 아니라 접기였다. 접힘 값이 한 글자 길기 때문이다. 주석, 문서, e2e를 실제 장면에 맞췄다.
  - e2e를 보강했다(새 폴더 대화상자와 드로어의 입력 칸, 골라서 옮기기, 다시 그렸는지와 안내 횟수). 문서의 사실 16건과 글쓰기 19건을 고쳤다.
  - §34는 장을 하나 열면 옮기기를 다시 시도하지 않아 지금 적은 것보다 무겁다는 지적을 실행해 확인하고 적었다.
