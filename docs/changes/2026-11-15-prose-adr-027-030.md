## 먼저 보실 곳

뜻이 달라질 수 있는 고침이다. 숫자, 날짜, 인용, 코드 표기는 바꾸지 않았다(아래 「검증」의 사실 토큰 비교).

- ADR-027: 「element」를 「요소」로, 「source」를 「원본」으로, 코드 이름이 아닌 「range」를 「범위」로, 「footnote anchor」를 「각주 앵커」로 썼다. 「per-parallel tradition」은 「병행 출처마다 붙이는 전통」으로 풀었다. 「그 ref의 cite-sheet가 열리고」는 `docs/architecture.md`가 쓰는 말에 맞춰 「그 출처의 인용 시트가 열리고」로 썼다. 파이프라인 설명 「source, Python parser, JSON, JS DOM 순서로 간다」는 「원본 마크다운, Python 파서, JSON, 앱이 만드는 DOM 순서로 이어진다」로 풀었다.
- ADR-028, 029, 030: 「용어」 표대로 「chrome」을 「UI」로, 「frosted glass」를 「반투명 유리」로, 「pill」을 「알약 버튼」이나 「알약 모양 입력창」으로, 「dock」을 「독」으로, 「hairline」을 「가는 선」으로 썼다. 「elevation」은 ADR-025를 교정할 때처럼 「그림자 단계」(토큰 단계를 가리킬 때)와 「그림자」로 썼다.
- ADR-028 §5: 「솔리드로 두고」를 「불투명하게 두고」로, 「status bar가 따라오지 않는」을 「상태바가 헤더 색에 맞춰지지 않는」으로 풀었다. §8의 「명시 토글을 반영」은 「사용자가 직접 바꾼 테마를 반영」으로 풀었다.
- ADR-028 「적응형 내비게이션」: 「지금 위쪽 헤더의 아이콘 버튼과 검색 FAB가」를 「그때 위쪽 헤더에 있던 …」으로 바꿨다. 지난 계획을 말하는 문장이라 「지금」이 맞지 않았다.
- ADR-028 §10: 「글자 크기 설정이 … 작아지게」 했다」의 낫표를 뺐다. §2를 줄여 쓴 이 문서의 서술이라 인용으로 보지 않았다.
- ADR-029: 「공유 파괴 확인(`bm-confirm`)」의 「공유」를 「공용」으로 바꿨다(두 곳). 여러 곳이 함께 쓰는 확인 창이라는 뜻인데, 바로 앞의 북마크 「공유」 기능과 헷갈린다. 「store를 건드리지 않고 겉을 복사해」는 「`store`를 바꾸지 않고 얕은 복사본을 만들어」로, 「스와이프로 드러내기」는 「용어」 표의 「밀어서 버튼 보기」로 썼다.
- ADR-030 §1: 「`positionTabIndicator()` ← `syncTabBarActive()`」를 「`syncTabBarActive()`가 `positionTabIndicator()`를 호출한다」로 풀었다. 호출 방향은 `js/app/tabbar.js`에서 확인했다.
- ADR-030 §6: 「(visualViewport 높이 감지가 불안정한 것을 피한다)」를 「(`visualViewport` 높이 감지는 불안정해 쓰지 않는다)」로 썼다. X 표시를 `focus`와 `blur` 이벤트에 연결한 까닭이다.
- ADR-030: 「풀바」를 「전체 바」로, 「stadium」을 같은 문서가 쓰는 「캡슐」로, 「sheen/inset」을 `--glass-sheen`과 `--glass-inset`의 뜻대로 「광택과 안쪽 음영」으로 썼다. 「스크림」 대안의 계산식(`--scrim-fade-top = pill 밑변 + pill 높이 × 1.25` …)은 같은 값을 문장으로 풀었다.
- 대안 절의 「채택 안 함 날짜 · 이유:」와 「채택하지 않았다(날짜)」를 이미 교정한 ADR의 표기 「채택 안 함(날짜). 이유:」로 맞췄다.

## 결정 대기

- **squircle**(ADR-029 §2, §3, 대안, ADR-030 §1, 대안): CSS 값(`corner-shape: squircle`)과 같은 낱말이 본문에도 쓰였다. 후보는 「스쿼클」, 그대로 두기다. 권장안은 「스쿼클」이다.
- **scrim**(ADR-030 §2와 대안, 화면 뒤를 흐리게 덮는 장식 층. 요소 이름은 `#tabbar-scrim`): 「용어」 표 아래 규칙이 바꿀 말로 꼽았지만 정한 말이 없다. 후보는 「가림막」, 「배경 가림층」이다. 권장안은 「가림막」이다.
- **FAB**(ADR-028, 029, 030): ADR 022-025 교정 때도 결정 대기로 올렸다. 권장안은 「검색 원형 버튼」이다.
- **인디케이터**(ADR-028 §9의 「구분 탭 인디케이터」, ADR-029, 030의 「원형 인디케이터」): 후보는 「표시」, 그대로 두기다. CSS 이름 `.tab-indicator`와 짝이라 그대로 두었다.
- ADR-029 「북마크 화면」의 「동기화 객체에 두면 열기만 해도 다시 동기화되고 수정 시각이 흐려지므로」: 「흐려지므로」가 「실제 수정 시각과 달라지므로」의 뜻인지 확인해 주시면 고친다.

## 요약

문장 교정 진행 목록 3절(ADR)의 ADR-027, 028, 029, 030을 고쳤다(한글 줄 431줄). 열린 PR #566이 ADR-038을 바꾸고 있어, 이번 묶음은 그 앞에서 끊었다.

- 기계 검사 항목 전체는 376건에서 68건으로 줄었다. `particle`, `tilde`, `term`은 16건에서 0건이 됐다. 남은 것은 ADR 상태 줄의 줄표, 제품과 키 이름(Apple Music, SF Symbols, Enter, Esc), 화면 문구와 화면 이동의 「이동」, 위 「결정 대기」의 낱말이다.
- 기계 검사 밖에서 고친 곳은 약 200곳이다. 비유 동사(「기댔다」, 「바닥을 깐다」, 「녹였다」, 「먹어」, 「가둬」, 「닿으면」, 「피한다」, 「얹고」)를 실제 동작의 동사로 바꿨다. 「A = B」, 「A / B」, 「→」, 「+」, 가운뎃점으로 이은 명사와 수식을 조사와 서술어로 풀었다. 코드 이름에 역따옴표를 달았다.
- 검토 단계에서 고친 곳: 사라진 코드 이름 둘을 되살렸다(ADR-029의 `_setupDragHandle` 괄호, ADR-030 대안의 「처음의 `--radius-pill`과 `corner-shape: superellipse`」). ADR-028의 「하나뿐인 권위 기준」에서 빠진 「권위」를 되살리고, §8의 「실행 모드(…, iOS. `install.js`가 기준)」를 완결된 문장으로 고쳤다. ADR-030의 「노트 자리(자리 표시용)」를 「노트 자리(기능 없이 자리만 둔 버튼)」로 바꿨다. 「채택 안 함」 표기를 네 파일에 걸쳐 맞췄다.
- 제목 26개를 고쳤다. 줄표를 쌍점으로 바꾸고(027 §4, §2, 「선례」, 028 §1, §4, §7, §8, §10, 029 §2, 030 「활성 표시」, §3, 「가로 모드」, §6), 영어 낱말을 한국어로 썼다(027 §1, §2, §1, §3, 「범위 겹침 금지」, 028 §9, 029 §3, 030 §2). ADR 제목 넷은 「+」와 줄표를 조사로 풀었다: 「원본 마크업 DSL의 위치와 `<parallel>` 요소 도입」, 「디자인 시스템의 토큰 단계와 HIG 정렬」, 「적응형 내비게이션 Phase 1의 모바일 하단 탭 바」, 「모핑 탭 바(아이콘 전용, 분리 검색 원형, 검색과 스크롤 모핑)」. ADR-028 「적응형 내비게이션」 절 제목의 줄표는 쉼표로 바꿨다.
- 바꾼 ADR 제목을 인용한 곳을 함께 고쳤다: `docs/topics/bible-text.md`(ADR-027), `docs/topics/design-system.md`(ADR-028), `docs/topics/routing.md`(ADR-029). `docs/topics/routing.md`의 ADR-030 인용 「모핑 탭 바」는 새 제목과도 맞아 그대로 두었다. 링크 앵커로 바꾼 제목을 가리키는 곳은 없었다. `docs/architecture.md` 부록 A의 네 줄은 제목 인용이 아니라 요약이라 그대로 두었다.
