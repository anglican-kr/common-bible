## 요약

기도서 번역인 전례시편과 송가를 「성시」로 묶어 검색한다(ADR-046). 책을 고르지 않은 검색은 성서 본문, 성시, 전례일을 함께 찾고, 성시의 결과는 「성서 본문, 성시, 전례일」 알약의 둘째로 성서와 따로 보인다. 책 선택 시트의 마지막 묶음이 「성시」(전례시편, 송가)이고, 송가 결과는 송가 이름과 절(「즈가리야 송가 1」)로 적는다. `전례시편 23:1`, `송가 11:1-3`도 구절로 읽는다.

색인은 데이터 저장소가 넷째 검색 색인 `search-lit.json`으로 만든다(common-bible-data#83, 데이터 ADR-039 「검색」). 이 PR은 그 색인을 받는 앱 쪽이다.

## 확정 · 근거

- **성시로 묶어 성서와 따로 보인다**: 사용자가 두 책을 「성시」로 묶어 성서와 따로 결과를 보이기로 했다(2026-11-18). 앞서 권장했던 「책을 골랐을 때만 찾기」 대신 기본 검색에서도 찾고 알약으로 나눈다. 세 알약을 두는 계획에 이의가 없었다.
- **이번에 정한 셋**(사용자 결정 2026-11-18, 모두 권장안):
  - 알약 차례는 「성서 본문, 성시, 전례일」이다. 본문을 찾는 묶음 둘을 나란히 둔다.
  - 송가 결과는 「모세송가 1」(송가 이름과 절)이다. 전례독서 화면이 송가를 복사할 때 붙이는 출처와 같다.
  - `전례시편 23:1`은 구절로 읽어 카드와 그 시편을 읽는 전례일을 보인다. `시편 23`은 공동번역 시편 그대로다.
- **전례시편의 장 단위는 「편」**(사용자 결정 2026-11-18, PR 검토 중): 카드는 「전례시편 23편」이다. 처음에는 장 화면과 같이 「장」으로 두었는데, 시편처럼 「편」으로 적기로 했다. 단위를 정하는 함수(`chUnit`) 하나를 고쳐 장 화면의 제목, 장 선택 단추, 장 넘기기, 없는 장의 안내, 북마크의 기본 이름, 문서 제목도 함께 「편」이 됐다. 송가에는 「장」도 「편」도 붙이지 않기로 했고(사용자 결정 2026-11-19), 그 표기는 따로 작업한다(교회력 주제 문서 「남은 일」). 이 PR에서는 송가가 지금처럼 「장」이다.
- **안내 문구**(사용자 결정 2026-11-19, 모두 권장안): 코드 리뷰에서 성시를 빠뜨린 안내 둘을 찾았다.
  - 성서 색인을 받는 동안의 알림은 「검색 중… 현재 성서 본문 12건, 성시 3건」처럼 묶음마다 읽는다. 성시는 결과가 있을 때만 읽는다. 그전에는 성서 본문의 수만 읽어, 성시에만 결과가 있으면 「현재 0건」이었다.
  - 결과 없음과 책 이름만 친 검색의 안내는 「구절과 전례일」 대신 알약의 이름 「성서 본문, 성시, 전례일」로 적는다.
- **제안하고 이의가 없어 그대로 한 것**: 책 이름은 데이터의 이름(「전례시편」, 「성무일과 송가」, 줄인 이름 「송가」)을 그대로 쓴다. 두 책도 5권 제한에 함께 센다.
- **구현하며 정한 것**:
  - 워커는 성서 결과(`results`, `total`)를 그대로 두고 성시를 `psalter`에 따로 담는다. 두 묶음을 같은 쪽 번호로 자르고, 화면은 보이는 묶음의 쪽만 쓴다. 주소에 쪽 번호가 하나뿐이라, 알약을 바꾸면 1쪽부터 보인다.
  - 성시 색인을 받지 못해도 성서 검색은 한다. 앱을 고친 뒤 처음 하는 오프라인 검색에는 성시 색인이 기기에 아직 없다. 성서 색인과 같이 실패로 다루면 그동안 검색이 통째로 「검색에 실패했습니다」가 된다. 검색마다 다시 받는다.
  - 3초가 지나 전례일이 오면 그려 둔 알약 끝에 전례일 알약만 더한다. 알약을 통째로 바꾸면 알약에 있던 포커스를 잃는다.
  - 늦게 온 전례일 색인이 지역 축일이나 연도의 안내만 더할 때, 성시의 목록이 있으면 화면을 다시 그리지 않는다. 성서 본문의 목록과 같다. 처음에는 성서 본문의 결과 수만 보아, 성시에만 결과가 있으면 화면을 다시 그려 목록에 있던 포커스를 잃었다(코드 리뷰에서 찾음). 알약에 적는 결과 수는 `resultGroups` 한 곳에서 센다.
  - 책 이름만 친 검색의 안내 「Enter를 누르면 …을 바로 엽니다」의 조사를 받침으로 고른다. 송가는 첫 송가의 이름(「모세송가를」)이라 받침이 없을 수 있다.
- **일부러 바꾸지 않은 것**:
  - `in:성무일과 송가`는 `in:` 뒤의 공백에서 끊겨 쓸 수 없다. `in:송가`, `in:cant`는 된다.
  - 송가의 후렴(시므온 송가)은 절 번호가 없어 색인에 없다(데이터 ADR-039 「검색」).

## 검증

- 유닛: `node --test tests/unit/*.test.js` 1,928건 통과, `npm run typecheck` 오류 0. 새 시험은 워커의 묶음 나누기, 송가 이름, 받지 못한 성시 색인(`search-worker.test.js`), 실제 성시 색인과 메타 파일로 찾기와 `전례시편 23`의 전례일(`search-worker.data.test.js`), 알약 셋, `group=psalter` 주소와 쪽 링크(`search.test.js`)다. 데이터 서브모듈을 common-bible-data#83의 브랜치 커밋(`5c1f461`)으로 두고 돌렸다. 머지한 커밋(`56017c8`)과 내용이 같다(`git diff` 없음).
- e2e(작업 폴더 서버 8091, 시험 사본): 검색 화면, 책 선택 시트, 키보드 포커스, 탭 바의 검색, 오프라인 저장을 지나는 파일을 골랐다.
  - `test_search.py`, `test_a11y_keyboard.py`, `test_tabbar.py` 전체 128건, `test_settings.py`의 오프라인 저장 7건, `test_a11y_axe.py`의 검색 2건이 통과했다. 새 시험은 `test_search.py`의 9개(10건, 알약 셋의 차례, 성시 알약과 장 화면의 강조, 성시의 쪽 넘기기, 송가 이름, 구절과 책 이름, 시트의 「성시」 묶음(휴대폰과 데스크톱), `in:송가`, 늦게 온 전례일 알약)이다.
  - 기존 시험 셋을 고쳤다. `사랑`은 이제 성시에도 결과가 있어 알약이 없는 경우의 낱말을 `세리`로 바꿨다. 송가는 이제 칩이 되므로 모르는 책 이름 시험에서 뺐다. 쪽 넘기기 알림은 끝에 「성시 N건」이 붙어 끝말 대신 전체 문장으로 본다.
- 전례시편의 「편」을 고친 뒤 유닛 1,929건과 타입 검사를 다시 통과했다. e2e는 전례시편의 장, 카드, 복사를 지나는 `test_search.py`, `test_tabbar.py`, `test_navigation.py`, `test_liturgical_render.py`, `test_copy.py`, `test_lectionary_view.py` 297건이 통과했다. 늦은 전례일을 고친 뒤 유닛 1,929건과 타입 검사, e2e `test_search.py`, `test_a11y_keyboard.py` 111건이 통과했다. 안내 문구를 고친 뒤에도 유닛 1,931건(새 시험 둘은 검색 중 알림과 묶음 이름), 타입 검사, 같은 e2e 111건이 통과했다.
- 휴대폰 크기(390px)로 결과의 알약 셋, 송가 결과, 시트의 「성시」 묶음을 찍어 확인했다. 아이폰 실기기에서는 확인하지 않았다.
- 바꾼 줄의 문장 검사(`tools/prose/prose.py lint --changed origin/main`)를 돌려, 역따옴표 밖의 영어 낱말 두 곳을 고쳤다.
