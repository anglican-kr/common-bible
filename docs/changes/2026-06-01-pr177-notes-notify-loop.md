# fix: 노트 동기화 시 _notify 무한 루프 프리징 (핫픽스)

## 문제
Drive 연결 후 노트 화면에서 "동기화 중" 상태가 되면 **앱이 프리징**되고 다른 화면으로 라우팅이 안 됨(실기기 dev 확인).

## 원인
`renderNotesList`의 `onChange` 콜백은 재렌더 때 **새 리스너를 등록**한다. 그런데 `_notify`가 `_listeners`(Set)를 **라이브 순회**하면, JS Set 반복자가 디스패치 도중 추가된 새 리스너까지 방문 → 무한 연쇄 호출 → 메인 스레드 프리징. Drive 연결 후 첫 sync의 `_setStatus("syncing")` → `_notify`가 방아쇠라 **연결 후에만** 재현됐다.

## 수정
`_notify`가 디스패치 시작 시점의 **스냅샷(`[..._listeners]`)** 을 순회 → 재구독된 리스너는 같은 디스패치에서 호출되지 않음(표준 패턴).

## 검증
- 회귀 테스트(`NOTIFY` 마커): 재구독 리스너가 **1회만** 호출됨을 검증(옛 코드면 무한 루프).
- 전체 유닛 통과, tsc 0 error.

> **Low Risk**
> Test-only change in the visible diff; it documents and guards sync listener dispatch behavior without altering runtime paths in this patch.
> 
> **Overview**
> Adds a **regression unit test** for the notes store **`NOTIFY`** block: when a listener unsubscribes and immediately registers a replacement (same pattern as **`renderNotesList`**’s `onChange`), **`_notify`** must dispatch against a **snapshot** of subscribers so only the listeners present at the start of the call run once.
> 
> Without snapshot dispatch, iterating a live **`Set`** would pick up each newly added listener and can chain into an **unbounded notify loop** (main-thread freeze after Drive sync triggers **`_setStatus("syncing")`** → **`_notify`**). The test fails on the old live-iteration behavior via a call-count guard.
