# fix: 전례독서의 반절을 경계 표대로 그린다

## 요약

전례독서의 반절 참조(「집회 51:12하」 「사무하 7:14상」)를 데이터의 경계 표대로 그린다. 반절 표기 정리 두 작업 가운데 둘째다(첫째는 PR #364). 표는 데이터 저장소 PR #35가 더한 `lectionary/half-verses.json`이고, 원료는 그 저장소의 `liturgical/half-verses.md`다.

종전에는 `lectionary.js trimHalfVerses`가 「그 절이 정확히 두 줄로 그려지면 한 줄을 고른다」고 추측했다. 그래서 전례독서의 반절 참조 59곳 가운데 47곳은 절 전체를 그렸다(known-issues §6). 복사 출처도 정수 구간이라 반절을 잃었다. 성령강림대축일의 「시편 104:24-34, 35하」를 복사하면 출처가 「전례시편 104:24-35」로 35절 전체를 가리켰다.

| 독서 | 종전 | 이 PR |
|---|---|---|
| 창세 12:1-4상(2026-03-01) | 4절 전체(「롯도 함께 떠났다.」까지) | 「…길을 떠났다.」까지, 번호 「4상」 |
| 2고린 5:20하-6:10(2026-02-18) | 20절 전체 | 「하느님과 화해하십시오.」부터, 번호 「20하」 |
| 집회 51:12하-20상(2027-05-29) | 12절은 둘째 줄, 20절은 네 줄 전체 | 12절은 둘째 줄, 20절은 앞의 두 줄 |
| 시편 104:24-34, 35하 복사 | 「104:24-35」 | 「104:24-34, 35하」 |
| 사도 2:14상, 22-32 복사 | 「2:14, 22-32」 | 「2:14상, 22-32」 |

### 변경

- **엔진.** 독서 묶음에 `half-verses`를 더해 함께 싣는다(`liturgical-engine.js LECTIONARY_FILES`). 인덱스는 「책:장:절+a|b」 키로 행을 찾고, 공개 함수 `findHalfVerse`가 행을 돌려준다. 표에 없으면 null이다. 타입 `HalfVerse`는 `js/types.d.ts`에 있다.
- **반절 그리기.** `trimHalfVerses`가 표의 행대로 그린다. 순수 함수 `halfVerseLines`가 남길 줄과 줄 안에서 자를 줄을 정한다. 줄 경계면 버리는 줄과 그 사이의 시행 · 단락 · 연 구분 표지를 걷는다. 줄 안의 경계면 `cutLineText`가 경계 문구를 찾아 앞(하) 또는 뒤(상)의 글자를 지운다. 절 번호, U+2060, ¶, ◯는 문구 검색에서 뺀다. 표에 없거나 「전체」인 반절, 표의 줄이 그려진 줄 수를 넘는 절은 절 전체를 그린다.
- **절 번호.** 자른 절의 번호를 「35하」 「4상」으로 적는다(사용자 결정 2026-10-22). 남은 첫 줄로 번호와 id를 옮기는 것은 종전과 같다.
- **복사 출처.** 자른 절을 article의 `data-halves`(「35b」)에 적고, `copyCitation`이 순수 함수 `halfVerseRanges`로 구간을 가른다. 하로 자른 절은 구간의 첫 절로만, 상으로 자른 절은 끝 절로만 이어진다(「24-34, 35하」 · 「12하-20상」 · 「14상, 22-32」). 장을 넘는 구간(「5:20하-6:10」)도 그대로 잇는다.
- **서비스 워커.** 바꿀 것이 없었다. 데이터 JSON은 처음 쓸 때 `/data/lectionary/` 접두사로 데이터 캐시에 들어가고, `sw.test.js`가 매니페스트의 접두사를 대조한다. 미리 받기(`pre-fetch.js`)는 `books.json`만 받는다.

## 확정 · 근거

이 세션에서 사용자가 정했다(2026-10-22). 사용자의 말과 근거는 pitfalls §21에 적었다.

- 한 줄로 그려지는 절도 줄 안에서 나눈다. 권장안은 절 전체를 유지하는 것이었으나, 사용자가 「줄 안에서 나눌 위치를 정의한다」를 골랐다.
- 경계의 기준은 서울교구 게시글의 본문이다(권장안). 게시글이 절 전체를 싣거나 없는 곳은 문장 경계로 안을 만들었고, 사용자가 다섯 곳을 제안대로 정했다.
- 로마 3:22하는 절 전체를 그린다(권장안). 공동번역은 원 독서표의 22a와 22b 내용이 두 문장에 섞여 있다.
- 반절로 자른 절의 번호는 「35하」로 보인다(권장안).
- 이전 버전 북마크와의 하위 호환성은 다음 PR에서 다룬다. 사용자가 「이전 버전 북마크와 하위 호환성도 고민해야 할텐데, 그건 다음 PR에서...」라고 했다. known-issues §18에 적었다.

## 검증

- **유닛.** `node --test tests/unit/*.test.js`는 1,342건이다. 1,341건이 통과하고, 실데이터 대기 1건은 건너뛴다. 6건이 늘었다.
  - `liturgical-engine.test.js` +1: 반절 경계 표를 독서 묶음과 함께 싣고 찾는다. 프리로드 전에는 `findHalfVerse`가 throw한다. 테스트 표에 반절 경계 표를 더했다.
  - `lectionary.test.js` +4: `halfVerseLines`(줄 경계, 줄 안 경계, 나누지 않는 경우)와 `halfVerseRanges`.
  - `lectionary.data.test.js` +1: 전례독서와 성인 공통의 반절 참조마다 표에 행이 있고, 앱이 그리는 줄에서 그 절을 나눈다(60곳).
  - 새 테스트 8건은 고치기 전 코드에서 실패한다. `npm run typecheck`는 오류가 없다.
- **e2e.** `tests/e2e/test_lectionary_view.py`에 1건을 더하고 1건을 보강했다. 위 표의 다섯 경우에서 그린 글자, 절 번호, 복사 출처를 본다. 고치기 전 코드에서는 2건 모두 실패한다. `pytest tests/e2e/`는 372건이 모두 통과했다(10분 20초).
- **화면 전수 점검.** 반절 60곳 가운데 날짜로 닿는 58곳을 Playwright로 열었다(2025-2030년의 기본 화면, 또는 칩 · 세트 · 트랙을 바꾼 화면). 그린 글자가 표의 경계대로인지, 절 번호에 상 · 하가 붙는지 보았고 58곳 모두 맞다. 날짜로 닿지 않는 두 곳(이사 56:3상, 성인 공통의 사도 2:47상)은 실데이터 테스트가 본다. 스크립트는 저장소에 넣지 않았다.
- **데이터.** 경계 표의 검증(경계 문구가 그 줄에 한 번, 낱말 중간을 자르지 않음, 반절 참조가 모두 표에 있음, 상과 하가 맞물림, 데이터의 반쪽 절과 겹치지 않음)은 데이터 저장소 PR #35의 파서와 `tests/test_half_verses.py`가 맡는다.
- **머지 순서.** 데이터 PR #35가 먼저 머지되고, 데이터 동기화가 앱의 `data` 포인터를 올린 뒤에 이 PR을 머지한다. 포인터가 오르기 전에는 `half-verses.json`이 없어 전례독서 화면이 열리지 않는다. 로컬 시험은 `data`를 데이터 PR의 커밋으로 옮겨 했고, 이 PR은 포인터를 커밋하지 않는다.
