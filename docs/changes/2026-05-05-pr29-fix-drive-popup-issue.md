# fix: iOS Safari 팝업 차단 안내 제거 — FedCM/One Tap (Phase 2d)

## 배경

iOS Safari에서 앱을 열 때마다 "이 사이트에서 팝업 윈도우를 열려고 시도 중입니다." 차단 안내가 떠 동기화 UX가 거칠어지는 문제 보고. ADR-011은 "iOS 17+ FedCM, iOS 16↓ One Tap"을 채택했지만, 실제 Phase 2b 구현은 GIS Token Client 단일 경로였고, 페이지 로드 시점의 자동 `requestAccessToken({prompt:""})` 호출이 사용자 제스처 컨텍스트 밖에서 `window.open()`을 트리거해 iOS가 팝업으로 인식하고 있었음.

## 변경 요약

- **Identity Client 도입** (`js/sync/transport.js`): `google.accounts.id` 래퍼(`initIdentityClient`/`promptIdentity`/`parseIdToken`) 추가. `use_fedcm_for_prompt: true` + `auto_select: true`로 iOS 17+은 FedCM, iOS 16↓은 One Tap으로 자동 폴백 — 둘 다 `window.open()` 미사용.
- **상태 머신 분리** (`js/sync/state-machine.js`): `AUTHENTICATING` 단일 상태를 `IDENTIFYING` → `AUTHENTICATING` 두 단계로 분리. silent 신원 확립이 실패하면 `NEEDS_CONSENT`(신규)에 머물고, 사용자가 "연결" 버튼을 클릭하는 그 사용자 제스처 안에서만 `requestAccessToken({prompt:"consent"})`를 호출해 iOS 팝업 정상 허용.
- **email hint 자동 시드**: ID 토큰에서 추출한 email을 즉시 `bible-drive-sync-email`에 저장 → 후속 silent 토큰 갱신의 hint로 사용.
- **401 재인증**도 IDENTIFYING 단계를 거쳐 silent FedCM 갱신을 먼저 시도.
- **`signIn()` 흐름** (`js/drive-sync.js`): `NEEDS_CONSENT`/`ERROR`/`IDENTIFYING` 상태에서 클릭 시 `USER_CONSENT_REQUEST` 이벤트 dispatch.
- **e2e 스텁 확장** (`tests/e2e/test_drive_sync.py`): `accounts.id.initialize`/`prompt` 시뮬레이션. `__gisForceIdentityFail` 토글로 FedCM 미지원 시나리오 회귀 가능.
- **ADR-011 / CLAUDE.md**: Phase 2d 개정 블록과 동작 매트릭스 표 추가.

## 동작 매트릭스

| 환경 | 페이지 로드 동작 | iOS 팝업 차단 안내 |
| --- | --- | --- |
| Android Chrome | FedCM/세션 쿠키로 silent identity → silent token | 발생 안 함 |
| iOS 17+ Safari | FedCM mediated UI로 silent identity → silent token | 발생 안 함 |
| iOS 16↓ Safari (사전 동의 있음) | One Tap UI로 identity → silent token | 발생 안 함 |
| iOS 16↓ Safari (사전 동의 없음) | identity 실패 → NEEDS_CONSENT, 사용자 클릭 대기 | 발생 안 함 |
