  - 「외경」의 상태 설명(구약에 포함, 별도 섹션에 표시)은 이름 오른쪽 같은 줄에 있다(2026-11-06, ADR-023 §2).
  - 선택 상자(`makeSelectRow`, `.settings-select`)는 전례독서 섹션의 소속교회가 쓴다(2026-11-09, ADR-041 §9). 브라우저 기본 `<select>`라 OS마다 익숙한 고르기 화면이 뜬다. 포커스를 팝오버 안에 두는 코드(`trapFocus`)도 선택 상자를 센다. 목록을 연 채 누른 Esc는 목록만 닫고, 팝오버는 다음 Esc에 닫는다(2026-11-06).

  - 창이 낮아 팝오버가 잘리면 얇은 스크롤 막대가 보인다(2026-11-06). 앱의 다른 곳은 스크롤 막대를 숨긴다. macOS에서 스크롤 막대를 평소 숨기는 설정이면 스크롤하기 전까지 보이지 않는다.

- **디자인 시스템** (2026-06-02, ADR-028).
  - 디자인 값의 권위는 `DESIGN.md`(루트) 하나다. 색, 모서리 반경, 그림자 깊이(elevation), 간격, 글자 크기, 컨트롤 크기, 움직임의 값을 단계마다 이름을 붙여(토큰) `css/style.css`의 `:root`에 두었다. 이 목록을 토큰 단계라고 부른다. 화면마다 그때그때 적었던 값(ad-hoc 값)은 모두 가장 가까운 토큰으로 맞췄다.
  - 간격은 8pt 단위로 잡는다. 글자 크기는 rem 단위로 잡아, 설정에서 글자 크기를 바꾸면 함께 커지고 작아진다.
  - Apple의 디자인 지침(HIG)과 일부러 다르게 한 곳이 둘 있고, 그 이유를 문서에 적어 두었다. 본문은 성경을 읽기 좋도록 세리프(Serif) 글꼴을 쓴다. 반투명 유리는 화면 아래쪽에 떠 있는 막대(탭 바, 오디오 바, 절 선택 바)와 검색할 때 본문을 덮는 막(스크림)에만 쓰고, 헤더에는 쓰지 않는다.
  - 설정에서 고른 테마색(`--theme`)은 절 번호, 단락 기호, 내비게이션에서 지금 고른 탭과 검색을 알리는 표시에만 칠한다. 나머지 UI(단추와 막대)는 중립적인 차콜색으로 고정했다.
  - 자세한 내용과 개정 이력은 ADR-028 §7과 §9에 있다.
- **읽기 화면 헤더의 스크롤 그림자** (2026-05-30, ADR-025).
  - 본문을 스크롤해 맨 위를 벗어나면 헤더 아래에 그림자가 서서히 나타난다. 헤더 아래의 1px 가는 선은 그대로 둔다.
  - 맨 위를 벗어났는지는 IntersectionObserver(요소가 화면에 보이는지 알려 주는 브라우저 기능)가 `#scroll-sentinel`을 지켜보아 알아낸다. 그림자는 `#sticky-group`에 그린다.
  - 헤더에는 반투명 유리를 일부러 쓰지 않았다. iOS 26에서 헤더가 반투명하면 화면 맨 위의 상태 표시줄(status bar) 색이 본문과 어긋나기 때문이다. 자세한 내용은 ADR-025에 있다.

## 함정

### pitfalls §8 — 글꼴을 불러오는 방식을 잘못 알면, 캐시를 비운 뒤 첫 실행에서만 글꼴이 틀린다

앱은 웹 글꼴을 내려받아 쓴다. 브라우저가 글꼴을 언제 불러오고, 늦게 도착하면 어떻게 하는지를 잘못 알면 회귀가 생긴다. 이런 회귀는 캐시를 비운 직후의 첫 실행에서만 보여서 찾기 어렵다.

**사례:**
- `351deef`: `font-display: optional`은 글꼴이 100ms 안에 도착하지 않으면 그 세션 내내 시스템 글꼴을 쓰게 하는 설정이다. 그래서 캐시에 글꼴이 없는 첫 실행에서는 의도한 글꼴이 보이지 않다가, 앱을 다시 시작해야 나타났다. 늦게라도 도착하면 바꿔 그리는 `swap`으로 바꿨다. 글꼴이 바뀌는 순간 글자가 한 번 바뀌어 보이는데(FOUT), 런치 스크린이 그 구간을 가린다.
- `d61f879`: 글꼴 규칙(@font-face)을 `media="print" onload` 방식으로 나중에 끼워 넣었더니, 화면이 처음 그려진 뒤(first paint)에 글꼴이 적용돼 FOUT이 생겼다. 화면을 그리기 전에 글꼴 규칙을 먼저 받도록 화면 그리기를 막는(blocking) `preload as="style"`로 바꿨다.

**규칙:**
- 글꼴 규칙은 **화면이 처음 그려지기 전(first paint)에 문서에 있어야** FOUT이 없다.
- 글꼴 전략은 **네트워크가 빠를 때와 느릴 때, 캐시에 글꼴이 있을 때와 없을 때**를 곱한 네 가지 조합으로 확인한다. DevTools의 네트워크 속도 제한(throttling)과 「캐시 비우고 강력 새로고침」으로 재현한다.
- 관련 ADR은 `007-launch-screen-optimization.md`다(결정 5와 「검토한 대안」의 `display=optional`).

### pitfalls §14 — CSS에서 `display`를 지정하면 `[hidden]`으로 숨긴 요소가 다시 보인다

HTML 요소에 `hidden` 속성을 붙이면(`<button hidden>`) 화면에서 숨겨진다. 브라우저 기본 스타일에 `[hidden] { display: none }` 규칙이 있기 때문이다. 그런데 우리 CSS가 ID 셀렉터로 `display: flex`(또는 block, grid 등)를 지정하면, 그 규칙이 더 구체적이어서(specificity가 높아서) 기본 규칙(`[hidden]`)을 덮어쓴다. 그러면 JS에서 `el.hidden = true`로 숨겨도 화면에서 사라지지 않는다.

**사례 (Phase 2h 단계 6):**

- 검색창의 지우기 단추(X, `#search-clear`)와 검색 기록 단추(▾, `#search-history-toggle`)에 `display: flex`가 지정돼 있었다. 그래서 JS의 `$searchClear.hidden = true`가 단추를 숨기지 못해, 검색어가 비어 있어도 X 단추가 계속 보였다. 게다가 `dataset.clearHidden="true"`일 때 기록 단추를 지우기 단추 자리로 옮기는 규칙이 있어서, 두 단추가 정확히 같은 자리에 겹쳤다. 문서 순서상 지우기 단추가 뒤에 있어 위에 그려지므로, 사용자에게는 X만 보이고 ▾는 그 뒤에 가려져 "버튼 모양이 이상"하게 보였다.
- 수정: `#search-clear[hidden], #search-history-toggle[hidden] { display: none; }` 규칙을 따로 더했다. 같은 셀렉터에 `[hidden]`을 붙여 구체성을 같거나 높게 만들었더니, 숨기려는 뜻이 다시 적용됐다.

**규칙:**

- ID처럼 구체성이 높은 셀렉터로 `display: ...`를 지정한 요소를 `hidden` 속성으로 숨길 수 있다면, **같은 셀렉터에 `[hidden] { display: none }` 규칙을 반드시 함께 둔다**.
- 점검: `el.hidden = true`로 숨긴 뒤 DevTools에서 `getComputedStyle(el).display`가 `none`인지 본다.
- 앱 전체에서 한 번에 막으려면 `:where([hidden]) { display: none !important; }` 같은 규칙도 쓸 수 있다. 하지만 `!important`는 일부러 덮어쓴 다른 규칙까지 깨뜨릴 수 있어 쓰지 않는다. 셀렉터마다 `[hidden]`을 보강하는 편이 안전하다.
