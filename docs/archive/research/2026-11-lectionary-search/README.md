# 전례독서 검색: 조사 기록 (2026-11-15)

전례독서 검색(ADR-038 A4)을 설계하기 전에 한 조사의 원자료다. 사용자 지시로 다른 전례독서 사이트와 앱의 검색, 구절 질의를 맞추는 방식, 기간 질의, 한국어 처리, 검색 화면의 사례를 조사했다. 특정 시점의 기록이라 갱신하지 않는다. 그 뒤에 정한 것은 설계서 `docs/design/lectionary-search.md`와 ADR-038 §4에 있다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `report.md` | 웹 조사 보고서(클라우드 세션). 발견 12개, 한계, 남은 물음, 반박된 주장 5개, 출처 21개 |
| `report-followup.md` | 보충 조사 보고서(같은 날 사용자 컴퓨터의 세션). 첫 조사가 다루지 못한 두 질문, 곧 다른 전례독서 사이트와 앱의 검색, 검색 화면과 접근성의 사례 |

## 첫 조사가 다루지 못한 것과 보충 조사

첫 조사(`report.md`)는 조사 질문 다섯 가운데 둘에 검증을 통과한 근거가 없었다. 다른 전례독서 사이트와 앱의 검색과, 검색 화면과 접근성의 사례다. 조사가 끝난 뒤 Vanderbilt RCL(`lectionary.library.vanderbilt.edu`)과 W3C(`www.w3.org`)를 다시 열어 보니, 그 클라우드 세션의 네트워크 정책이 두 호스트를 막고 있었다.

사용자 지시로 같은 날 사용자 컴퓨터의 세션에서 두 질문을 다시 조사했다(`report-followup.md`). 조사 에이전트 셋이 나눠 조사했고, 설계 판단에 쓰는 주장은 원문을 다시 열어 확인했다. 첫 조사와 달리 주장마다 세 번 투표하는 검증은 거치지 않았다.

## 설계서에 반영한 것

설계서 `docs/design/lectionary-search.md`는 「조사 발견 N」으로 보고서의 발견 번호를 가리킨다. 구절 판정을 지금처럼 엄격하게 두기(발견 1), 겹침으로 맞추고 포함은 순서에만 쓰기(발견 2, 3), 기간을 엔진으로 펼쳐 거르기(발견 5), 기간의 연도를 양력 해로 읽기(발견 6), 상대 날짜를 정해 둔 낱말만 받기(발견 7), 다음 날짜를 엔진의 실제 계산으로 구하기(발견 8), 초성 검색을 직접 구현할 수 있다는 판단(발견 9), 외부 구절 파서와 한국어 검색 라이브러리를 들이지 않기(발견 9, 10)다. 보고서의 남은 물음 가운데 한 장짜리 책과 오늘이 주일일 때의 상대 날짜는 설계서의 미결 10, 11이 되었다.

보충 조사는 「보충 N」으로 그 보고서의 절 번호를 가리킨다. 반영한 것은 이렇다. 천주교의 구절 표기와 이름(보충 4)으로 빈 곳 하나(§2의 7), 정규화 규칙 하나(`제N주간`), 미결 13을 더했다. 다른 역색인이 글자로 맞춰 겹치는 독서를 놓치는 사례(보충 2)로 겹침 맞추기의 근거를 더했다. 실제 날짜를 보이는 역색인이 Sundays and Seasons 하나뿐이고 기간 검색어를 받는 곳은 없다는 사실(보충 2, 3)을 §6, §7에 적었다. 검색 화면(§9)은 탭을 링크로 만들기(보충 6), 결과 수와 0건의 알림(보충 5), 범위와 해석 보이기, 결과 없음 화면(보충 7), 결과 목록의 구조와 문서 제목(보충 8)의 근거로 다시 썼다. 사람들이 고른 검색 범위를 잊는다는 근거(보충 7)와 2026-11-07의 권장안이 ADR-038 §4의 탭과 어긋나, 설계서의 미결 12가 되었다.

## 앱의 코드와 데이터에서 직접 잰 것

설계서 §2, §3, §5, §7의 숫자는 웹 조사가 아니라 데이터 저장소 `8e6f972`(2026-11-11)와 앱의 교회력 엔진으로 직접 잰 것이다. 재는 방법은 이렇다.

- 색인(`lectionary/search-lectionary.json`)의 이름 목록에 사람들이 칠 법한 이름 51개를 넣어, 부분 문자열, 공백을 지운 부분 문자열, 낱말을 나눠 모두 드는지의 세 방식으로 결과 수를 셌다. 보고서의 「52개 이름 시험」은 이 시험이고, 실제로는 51개다.
- 구절 질의 일곱 개(`요한 3:14-21`, `이사 9:2-7` 등)를 포함, 겹침, 독서가 질의 안에 드는 경우의 세 방식으로 셌다.
- 엔진의 계산 블록과 조회 블록을 유닛 테스트와 같은 방법(`vm`)으로 Node에서 실행해, 2025-2050년의 모든 날에 `resolveDateIn`과 후보마다 `findReadingsIn`을 호출했다. 걸린 시간과, 독서 세트마다 오는 날짜를 모았다.
- 전례일 이름 1,473개(색인의 제목, 라벨, 별칭과 월별 축일, 이동 축일, 성인 목록의 이름)를 검색 워커의 구절 판정(`tryVerseRef`)에 넣어, 구절로 읽히는 것이 있는지 보았다. 워커 코드를 `vm`으로 실행하고 데이터 저장소의 `search-meta.json`을 넣었다.
