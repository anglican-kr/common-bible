# 기기 시계에 기대지 않는 동기화: 조사 기록 (2026-10-30)

북마크 동기화가 기기 시각끼리 비교해 생기는 문제(known-issues §38, §39)를 고치기 전에 한 조사의 원자료다. 사용자 지시로 코드를 고치기 전에 조사했고, 그 결과로 PR #456을 만들었다. 특정 시점의 기록이라 갱신하지 않는다. 그 뒤에 정한 것과 지금 동작은 ADR-011(Phase 2c 「수정 시각」과 「같은 수정 시각」, Phase 2i, 「검토한 대안」), `docs/topics/sync.md`, 원장 `docs/changes/2026-10-31-sync-clock.md`에 있다.

## 보고서의 권장과 그 뒤에 정한 것

- **채택했다**: 권장 조합 「가」의 1단계. 새 수정 시각은 기록마다 그 기록의 이전 수정 시각보다 늦게 기록하고(보고서의 후보 1), 드라이브 파일이 그대로일 때(304) 올릴 변경은 문서 지문으로 판단한다(후보 3). 문서 전체의 가장 늦은 시각을 기준으로 하는 방법은 채택하지 않았다(사용자 결정 2026-10-30, 2026-10-31).
- **보고서에 없던 것을 더했다**: 수정 시각이 같으면 드라이브의 사본을 남긴다(폴더의 펼침 상태는 이 기기의 값). 리뷰에서 찾은 문제를 고친 것이다(ADR-011 「검토한 대안 — 같은 수정 시각」).
- **정하지 않았다**: 2단계의 서버 시각 보정(후보 2)은 넣기로 했다가 취소했다(2026-10-30). 3단계의 삭제 기록 정책, 쓰기 보호(후보 5, 7)도 정하지 않았다(known-issues §39, §42).
- **채택하지 않았다**: 기록마다 파일을 나누기, 변경분만 담은 파일을 올리기, 버전 벡터, 쓰기 차례 번호. 이유와 다시 볼 조건은 ADR-011 「검토한 대안 — 수정 시각」에 있다.
- 보고서의 「결정이나 시험이 필요한 질문」 가운데 `version` 필드와 Drive v2의 `etag` 시험은 하지 않았다. 사용자 기기의 실제 시계 오차도 재지 않았다.
