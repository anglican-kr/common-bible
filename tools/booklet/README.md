# tools/booklet — 「전례독서」 책자 ↔ 엔진 대조

서울교구가 해마다 내는 「전례독서」 책자(PDF)의 감사성찬례 독서를 교회력 엔진이 낸 독서와 날짜마다 대조한다.
2027 책자(검토용)로 처음 돌렸다(2026-10-13 — 원장 `docs/changes/2026-10-13-liturgical-engine-booklet-2027.md`).
책자 PDF 와 산출물은 저장소에 넣지 않는다.

```bash
# 저장소 루트에서. OUT 은 산출물 작업 폴더(커밋하지 않는다) — 안 정했으면 임시 폴더를 만든다
OUT="${OUT:-$(mktemp -d)}"; mkdir -p "$OUT"
python3 -I tools/booklet/extract.py "<책자>.pdf" "$OUT/booklet.txt"
python3 -I tools/booklet/parse_booklet_2027.py "$OUT/booklet.txt" data/books.json "$OUT/booklet.json" data/lectionary/eucharist-readings.json
node tools/booklet/engine-dump.mjs 2026-11-29 2027-12-31 "$OUT/engine.json"
python3 -I tools/booklet/compare.py "$OUT/booklet.json" "$OUT/engine.json" "$OUT/report.md" "$OUT/detail.json"
```

| 파일 | 하는 일 |
|---|---|
| `extract.py` | pypdf 로 쪽마다 텍스트를 뽑는다(`===== PAGE n =====` 표식) |
| `parse_booklet_2027.py` | 2027 책자 형식의 텍스트를 날짜별 JSON으로 — 감사성찬례 칸만(아침 · 저녁기도는 앱 범위 밖). 날짜 줄은 「다음에 올 날짜 + 요일 글자」로 검증하고 성탄 세 세트 · 「또는」 줄바꿈 · 반절 줄바꿈 · 쪽 바닥 이름을 따로 다룬다. 위첨자는 하위 절 번호라(에스델 그리스어 부분 「에스 4:17¹²⁻¹⁶」) 엔진 라벨처럼 괄호에 보통 숫자로 적는다(「4:17(12-16)」). **해마다 형식이 달라** 다른 해에는 머리 주석대로 고쳐 쓴다 |
| `engine-dump.mjs` | `liturgical-engine.js` + `lectionary.js` 모델 블록을 vm 에 올려(`tests/unit/lectionary.data.test.js` 와 같은 조합) 날짜별 후보(이름 · 별칭) · 독서 세트 · 뷰 초기 선택을 덤프한다. 인자는 엔진의 `parseDate` 로 검사한다 — 날짜가 YYYY-MM-DD 가 아니거나 없는 날짜 · from > to · 출력 경로 없음이면 사용법을 표준 오류로 내고 1로 끝난다(루프가 날짜를 문자열로 비교해, 그대로 받으면 「2027-1-31」 은 9월 30일까지 · 뒤바뀐 범위는 0일을 오류 없이 덤프한다). **`js/app/lectionary.js` 가 없는 체크아웃**(전례독서 뷰 #346 이전)에서는 `view: null` 로 덤프하고 표준 오류로 경고한다 — 그러면 `compare.py` 가 승자(`official`)로 비교하고 보고서 머리에 「뷰 없음 N일」을 적는다. 뷰의 초기 선택(고유 독서 없는 축일은 그날 평일 독서 — 설계서 미결25)과 달라 집계가 크게 바뀌니 뷰 대조로 읽지 말 것(2027 책자 · 데이터 `cda718f`: 뷰 있음 같음 338 · other 6 / 없음 275 · 71) |
| `compare.py` | 슬롯별로 책자의 「또는」 대안과 엔진 대안(초기 선택 후보의 트랙 · 세트에 걸친 라벨 하나하나)을 짝지어 보고서(`report.md`)와 날짜별 상세(`detail.json`)를 낸다. 돌 때마다 판정기의 합성 사례를 먼저 확인한다(자기 점검 — 어긋나면 AssertionError) |

판정은 날짜별 최악 슬롯으로 — 슬롯마다 책자 대안 하나와 엔진 대안(라벨) 하나를 짝짓는다. 라벨의 변형을 한데 모은 합집합과 비교하지 않는다 — 그러면 송가 이름이 붙은 라벨 하나(「루가 1:68-79(즈가리야 송가)」)도 대안 여럿처럼 보여 책자가 「일부만」 실은 것이 된다. 짝의 수준은 그대로 같음 · 표기만(상/하 · 송가 이름 · 한글/라틴 반쪽 · 괄호 선택 절 「(1-9)10-18」=「1-9, 10-18」) · 절 집합 동치(「4, 5」=「4-5」) 셋이다. 양쪽 대안이 모두 짝을 찾으면 `=`(모두 그대로 같음) 또는 `≈`, 책자 대안만 모두 찾으면 `⊂`(그대로 같음 — 엔진 대안이 더 있다) 또는 `≈`(표기도 달라 비고에 「책자 대안이 적다」). 아니면 `other` 책자 대안이 모두 다른 후보(평일)의 대안과 짝을 찾는다(선택 후보와 같은 수준으로 — 절 집합 포함) · `⊃` 엔진 대안은 모두 찾고 책자가 더 · `partial` `≠` 실질 불일치. 책자의 괄호 선택 절 한 줄은 엔진의 두 세트(선택 절을 넣은 것 · 뺀 것)를 함께 적은 것이라, 넣은 쪽이 짝을 찾았을 때만 뺀 세트도 짝으로 센다 — 엔진에 뺀 세트만 있으면 차이로 남는다.

같다고 잘못 말하지 않는 쪽으로 둔다 — 구분자(쉼표 · 괄호 · 숫자 사이 공백)는 지우지 않고(「1:1,3」 · 「1:1(3)」 ≠ 「1:13」), 장을 넘는 범위는 시작 · 끝의 장과 절을 함께 본다(「18:21-19:2」 ≠ 「17:21-19:2」 — 장 길이를 모르니 「18:21-35, 19:1-2」 와도 다르게 나온다). 엔진 라벨의 괄호 안은 온전한 출처(책 이름 + 장:절 — 「이사야 첫째 송가(이사 12:2-6)」 의 「이사 12:2-6」)일 때만 따로 대안으로 세우고, 괄호 앞 토막은 숫자가 없을 때(송가 이름)만 세운다 — 「에스 4:17(12-16), 17(23-25)」 의 「12-16」 · 「에스 4:17」 은 없는 독서다. 숫자에 붙은 괄호가 앞 절을 바로 잇지 않으면(하위 절 번호 「4:17(12-16)」) 절 집합으로 읽지 않는다 — 구분자로 읽으면 없는 절 「4:12-16」 이 생긴다. 이름 · 이동 표기 · 색 표는 보조다 — 축성일 · 사계재 · 공휴일은 엔진이 싣지 않아 잡음이 섞인다. 관측일 이름은 엔진의 이름과 별칭(`aliases` — 「고난주일」 · 「승천」 · 「삼위일체」)으로 맞춘다.

검토용 초안의 독서 · 색 · 이름 차이로 데이터를 고치지 않는다(사용자 결정 2026-10-13, `docs/coding-pitfalls.md` §22) — 확정판으로 다시 본다.
