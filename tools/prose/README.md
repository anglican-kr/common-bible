# 문장 교정 도구

문서와 코드 주석의 한국어 문장을 교정할 때 쓰는 도구다. 문장 교정 반복 실행(`docs/workflow.md` 「커밋과 PR」)이 쓰고, 사람이 직접 실행해도 된다. 앱은 이 도구를 쓰지 않는다.

## 명령

- `python3 tools/prose/prose.py lint`: 저장소 전체를 검사해, 검사마다 건수를 세고 문제가 많은 파일을 보인다.
  - 파일을 주면 그 파일만 본다. `--detail`은 찾은 곳을 하나씩 적고, `--json`은 JSON으로 낸다.
  - `--changed origin/main`은 그 브랜치에서 갈라진 뒤 더하거나 고친 줄만 본다.
- `python3 tools/prose/prose.py same-code main`: main과 작업 트리를 견줘, 주석과 문서 말고도 바뀐 파일을 적는다. 그런 파일이 하나라도 있으면 종료 코드 1로 끝난다. 두 리비전을 견주려면 `same-code A B`로 쓴다.
- 테스트: `python3 -m unittest tools/prose/test_prose.py`

## 검사하는 것

검사 이름이 `?`로 끝나면 사람이나 에이전트가 문맥을 보고 판단한다. 나머지 셋(`particle`, `tilde`, `term`)은 찾은 곳을 모두 고친다.

| 검사 | 찾는 것 |
| --- | --- |
| `particle` | 영어 단어 뒤에 띄어 쓴 조사와 용언(pitfalls §31) |
| `particle?` | 띄어 쓴 조사일 수도, 따로 쓰는 낱말일 수도 있는 말(이, 나, 도, 만, 면, 일, 한, 해) |
| `tilde` | 숫자 구간의 물결표(pitfalls §32) |
| `term` | `docs/writing.md` 「용어」 표에서 쓰지 않기로 한 말과 「꼴」 |
| `term?` | 한 가지 뜻으로만 쓰지 않기로 한 말(「도착」, 「이동」, 「켜다」 등) |
| `verb?` | 몸의 움직임이나 공간을 빌린 동사(「닿다」, 「걸다」, 「앉다」 등) |
| `english?` | 역따옴표 밖의 영어 낱말 |
| `arrow?`, `dot?`, `dash?` | 문장 속 화살표, 가운뎃점, 줄표 |

- 역따옴표 안의 코드, 「」와 『』 안의 인용, 링크 주소, 펜스 코드 블록, 문서 머리의 설정 블록(frontmatter)은 보지 않는다.
- `english?`는 대문자 약어, 허용 목록에 있는 제품 이름, 괄호 안의 영어를 세지 않는다. 한글이 영어보다 많은 줄만 본다. 코드 주석은 영어로 써도 되기 때문이다(CLAUDE.md 「컨벤션」).
- 코드 파일은 주석만 본다. JS와 CSS의 주석, 셸과 YAML의 `#` 주석, HTML 주석, 파이썬의 주석과 설명 문자열(docstring)이 그렇다. 문자열과 테스트 이름은 보지 않는다.
- 머지된 원장(`docs/changes/`, 그 안의 `README.md`는 본다), 보관 문서(`docs/archive/`), 기도서 원문(`docs/reference/`), 데이터 저장소(`data/`)는 보지 않는다.
- `docs/writing.md`는 쓰지 않을 말을 인용하는 문서라서 `term`, `term?`, `verb?`를 보지 않는다.

## 주석 말고 바뀐 것을 찾는 방법

`same-code`는 파일마다 주석을 지운 코드끼리 견준다.

- JS와 CSS는 주석을 지우고 공백을 하나로 모은다.
- 파이썬은 구문 트리(`ast`)를 만들어 설명 문자열을 비운다.
- 셸과 YAML은 `#` 주석과 빈 줄을 지운다.
- 마크다운은 견주지 않는다.
- 그 밖의 파일(JSON 등)은 글자까지 같아야 한다.

그래서 테스트 이름이나 픽스처의 `note`를 고치면 「주석 말고도 바뀌었다」로 나온다.

## CI

`.github/workflows/prose.yml`이 모든 PR에서 그 PR이 고친 줄만 검사한다. 경고만 내고 실패하지 않으며, 필수 검사도 아니다. 경고는 처음 10건만 PR의 바뀐 줄에 표시하고, 전체 목록은 실행 결과의 작업 요약(Summary)에 적는다. GitHub가 한 단계에서 표시하는 경고 수를 제한한다고 알고 있지만 문서에서 확인하지 못해서 10건으로 정했다.

## 진행 목록

`progress.md`는 교정할 파일을 순서대로 적은 목록이다. 문장 교정 반복 실행(`.claude/skills/prose-batch/SKILL.md`)이 위에서부터 묶음을 고르고, 교정 PR마다 상태를 「대기」에서 PR 번호로 바꾼다. 파일이 새로 생기면 그 절의 알맞은 자리에 「대기」로 더한다.

## 한계

- 맞춤법 검사기가 아니다. 규칙으로 적은 틀만 찾는다. 뜻이 흐린 문장, 번역 투, 비유로 새로 만든 낱말은 사람이나 에이전트가 읽어야 찾는다.
- JS의 정규식 리터럴은 바로 앞 글자를 보고 짐작한다. 짐작이 틀리면 그 줄의 주석을 놓치거나, 코드 일부를 주석으로 볼 수 있다.
